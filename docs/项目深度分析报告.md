## 1. 项目总览与定位

**一句话定位**：借鉴《小黑屋》极简文字风格与渐进式叙事，用完整 RPG 系统（战斗/探索/成长/设施/任务/经济）做"剑与魔法"题材的探索向文字 RPG，Unity 6（URP 2D + uGUI），全内容 JSON 数据驱动，全项目中文编码。

**当前规模（远超 README 描述的垂直切片）**：

| 维度 | 数量 | 说明 |
|------|------|------|
| 代码 | 95 个 C# 脚本 | Core 3 / Data 3 / Domain 7 / Events 5 / Services 26 / UI 41 / Editor 2 / Tests 1 |
| 剧情 | 85 节点 + 6 区域路由 | 第一章完整闭环（序章→决战→终章） |
| 地图 | 6 地点（2 城镇 + 4 荒野） | 灰烬镇/风谷村小地图共 19 节点 + 设施内部图 |
| 探索区域 | 4 区域 × 5 层 + Boss | 橡木林/古战场/黑石山/大草原，含岔路/通路/Boss 层 |
| 敌人 | 29 种（26 敌 + 3 助战伙伴） | Lv1~6，五行/物理弱点/行动表 AI |
| 物品 | 140 种 | 武器17/防具38/食物25/药剂10/材料27/宝石9/饰品2/任务4/图纸3 |
| 技能 | 20 个（玩家 13 + 敌人 7） | 含五行术法、Buff 挂载、武器规则 |
| Buff | 10 种 | 增益/减益/异常/护盾/控制 |
| 词缀 | 46 条 | 6 品质 × 9 属性阶梯，暗黑式随机词条 |
| 配方 | 67 个 | 铁匠铺/厨房/药房三线制作 |
| 任务 | 14 个（7 主线 + 7 支线）+ 每日悬赏 | 主线按章节轨道，日常按天随机 |

**开发节奏**：8/15 模块化框架设计 → 8/16 角色系统/地图/编辑器 → 8/17 战斗系统/三级导航/音效 → 8/20 探索系统落地 + 主线第一章完整内容。约 5-6 天从框架到可玩第一章，产出效率极高。

## 2. 游戏框架分析（架构）

### 2.1 四层单向依赖架构

```
表现层（uGUI 面板，41 个）          ← 只订阅事件 + 调服务入口，逻辑永不碰 UI
应用层（Services，26 个）            ← 业务规则/状态机，只发事件 + 调领域
领域层（Domain，7 个，纯 C#）        ← 玩家档案/战斗单位/五行/品质，零 UnityEngine
数据层（DataService + 18 个 JSON）   ← 全量加载 + 跨引用校验
```

**装配（GameBootstrap）**：组合根按依赖顺序构造全部服务并注册进 ServiceRegistry，`DefaultExecutionOrder(-100)` 保证先于面板 Awake；数据校验失败则阻止游戏进入（输出完整错误清单）——"配置错误不静默崩溃"是独立项目里罕见的高标准。

### 2.2 事件驱动信息链路

- **EventBus**：类型化事件总线，`订阅<T>/发布<T>`，发布时快照订阅表 + 单订阅者异常隔离。事件全为 `readonly struct`（不可变，防误改）。
- **日志即事件**：任何系统发 `日志事件(类型,文本)` 即进左侧日志栏——全局兜底输出通道，UI 未接线的面板也降级发日志，保证可玩性。
- **导航事件**：逻辑层只发 `打开对话事件/打开战斗事件/打开探索事件/打开功能面板事件…`，面板管理器（路由器）统一订阅并路由到对应面板。逻辑层完全不知道 UI 存在。

### 2.3 数据驱动体系

- 所有内容 JSON（中文键名），运行时 `Resources.Load` + JsonUtility 反序列化为字典缓存。
- 中文枚举字符串运行时解析（规避 JsonUtility 中文枚举坑），`数据解析.枚举<T>` 统一处理。
- **DataService.重新校验()**：启动全量跨引用校验——剧情选项目标/战斗敌人组/助战组/地图连接/物品槽位/区域事件表/Boss 组/配方材料，错误写入校验清单阻止进入。这个"数据门禁"是内容驱动项目的生命线。
- 加新内容 = 加 JSON 条目，零代码（剧情/区域/配方/词缀均如此）。

### 2.4 设施插件架构（三块积木）

```
facilities.json 定义（标识/逻辑类型/数据/地点）
  + 设施逻辑子类（商店设施/训练场设施/制作设施…实现 教学/买卖/训练/恢复/睡觉/制作 接口）
  + 功能面板（设施功能面板基类子类）
设施工厂（反射实例化 + 注入环境）→ 加新设施 = 写一个子类 + 一条 JSON，路由与面板基类零改动
```

设施逻辑完全复用：`买卖逻辑`（商店/武馆兵器/学堂魔法物共用）、`训练逻辑`（训练场/武馆/学堂共用）——用组合代替继承，避免重复。

### 2.5 编辑器工具（地图设计器）

画布式图编辑器：拖节点/连线/属性表单，反写 map.json（.bak 备份），支持三层（大地图/小地图/设施内部）。运行时地图交互（拖拽/缩放/单击/双击）由地图面板基类统一提供。**注意**：设计文档标记该工具为"计划未执行"，但代码中 `地图编辑数据.cs`/`地图设计器窗口.cs` 已存在——计划与实现状态不一致，需核对。

### 2.6 领域层纯度

`玩家档案`/`战斗单位` 零 UnityEngine 依赖（手写 `夹/Min/Max` 替代 Mathf），可整体序列化存档，可 EditMode 快速单测——但 `品质.cs` 仍泄漏 UnityEngine（Color），`效果结算` 直接操作档案而非返回变更集，GDD-改进版已列为 P1 待修。

### 2.7 框架评价

**亮点**：
- 分层极干净，单向依赖贯彻到底，"逻辑永不调 UI"从框架 spec 一路执行到战斗/探索/任务每个子系统
- 数据门禁（启动全量校验）+ 装配门禁（校验失败阻止进入）双保险，内容风险前置
- 全中文命名 + 详尽注释，可读性在独立项目中属于顶尖水平
- 领域纯 C# 与 UI 解耦，为测试与复用留了空间
- 事件全是不可变 struct，语义严谨

**问题**：
- 72 处 `ServiceRegistry.Get` 隐式服务依赖（GDD-改进版已列 P1）
- 目标路由是字符串前缀上帝 switch（`战斗:`/`设施:`/`探索:`/`区域:`/`地图:`…），DialogueService 与 DataService 两处重复维护合法前缀清单
- EventBus 订阅缺少 IDisposable 生命周期管理，面板大多不显式解绑（探索面板是唯一例外）
- 面板路由的"功能标识"switch、探索按钮动作字符串 switch 都是隐式约定
- 测试严重缺失：仅一个冒烟测试（1+1=2），纯 C# 领域层本应最好测

## 3. 信息链路总览（事件图）

```
玩家操作（按钮/右键/滚轮）
  │
  ├─ UI 面板（表现层）
  │     ├─ 调服务方法（战斗.玩家普攻/探索.搜索/地图.移动/买卖.尝试购买…）
  │     └─ 发布导航事件（打开X事件）
  ▼
事件总线 EventBus ──► 服务订阅（自动存档器/日常任务/任务/探索回调）
  │
  ├─ 状态变化事件：生命/魔力/精力/金币/经验/属性/背包/时间/地图位置
  ├─ 系统事件：战斗开始/回合开始/行动轮换/伤害/治疗/状态变化/目标变化/战斗结束
  │          任务进度/任务完成/日常任务变更/日志
  └─ 导航事件：打开对话/战斗/探索/大地图/小地图/节点内部/功能面板/设施/结局/角色/任务
  ▼
UI 订阅刷新（HUD/日志/战斗面板/角色面板/任务面板/买卖面板/侧边栏…）
```

**关键链路示例——战斗**：
```
玩家点[攻击] → 战斗面板.开始选目标("普攻") → 点敌方卡牌 → 战斗.玩家普攻(目标)
  → BattleService 执行攻击 → 造成伤害（命中/暴击/弱点/护盾/抗性管线）
  → 发布 伤害事件 + 日志事件 → 战斗面板 演出队列入队（受击动画+飘字）
  → 行动完成 → 推进 → 行动轮换事件（敌方）→ 面板停顿 0.8s → 战斗.继续() → 敌人AI
  → 敌方死亡 → 结算单个敌人（金币/经验/掉落/任务进度/探索计数）→ 战斗结束事件 → 结算覆盖层
```

**关键链路示例——探索**：
```
地图双击荒野节点 → 地图服务.进入当前() → 检查区域剧情路由（命中→进剧情节点；未命中）
  → 发布 打开野外面板事件 + 探索服务.进入区域(区域, 返回节点)
  → 探索服务 层状态机（初始化层→显示当前层）→ 发布 探索显示事件 → 探索面板渲染
  → 点[探索] → 搜索()（扣 1 精力）→ 抽事件（权重池：遭遇/发现/资源/选择/无事）
  → 遭遇 → 显示[战斗][逃跑] → 战斗遭遇() → 战斗.开始战斗(组, "__探索胜利", "__探索返回")
  → 战斗胜利 → 探索服务.战斗胜利()（计数/通路深入/Boss 通关）→ 继续搜索/深入/返回
```

**关键链路示例——剧情**：
```
对话面板 点选项 → 剧情选项数据.目标 → DialogueService.处理选项(目标)
  → 节点跳转 / __结束(结局) / 战斗: / 设施: / 探索: / 区域: / 地图:
  → 进入节点()：主线阶段更新（检查阶段任务+自动存档）→ 效果结算 → 构建选项（物品条件过滤）
  → 发布 显示剧情事件 → 对话面板打字机渲染 → 无选项自动目标 0.8s 连播
```

## 4. 世界设定与叙事

**世界观核心**（从 story.json 提炼）：
- **"余烬"母题**：灰烬镇在龙灾余烬中重建，一切围绕"火"——熄灭的圣火、守火人的余烬、沉睡的龙。
- **守火人传说**：千年前守火人一族守护圣火，北方战争陨落，圣火熄灭；守火人留下圣剑与余烬，独迎黑暗未归。古战场埋着"余烬不灭，火种西撤"的军令；亡灵骑士执念"我仍在守，但火已熄"。
- **核心命题**："龙不会死，它只是在沉睡，火必须被重新点燃。"——继承与责任的主题贯穿。
- **双结局预留**：点燃圣火 vs 弑龙（结局_点燃圣火/结局_屠龙），叙事抉择已设计。

**叙事手法亮点**：
- 序章即氛围：石屋醒来→巨鼠→空镇→老守卫尸体，三步立起"世界发生了什么"的悬念
- 第一章人物弧光完整：老李（牺牲与传承）→ 小烛（成长与陪伴）→ 韩如炎/巴隆（阵营感）→ 守火人幻影（世界观揭示）
- 伏笔埋设：黑石山的低吟（终章）、哥布林王统一打制的刀（部落异常）、家里出现的守火人幻影（身世悬念）
- 文案质量高：环境描写克制、对话有个性、数值提示自然融入叙事（"获得 60 铜"）

**叙事问题**：
- 死节点链阻断主线：`龙之羊皮纸` 只产自不可达节点（哥布林胜利→研究羊皮纸→镇长府_交差 无入边），导致**黑石山区域、龙巢、双结局当前全部不可达**（GDD-改进版已标记 P0）
- 6 个空壳 NPC 只有静态文案无话题选项
- 序章"镇子空了"与后续"镇上有人经营设施"存在叙事矛盾（GDD-改进版已规划修正）
- `酒馆_购买/防具` 死节点（`购买:` 前缀分支未实现）

## 5. 主线剧情系统

### 5.1 工作流程

```
剧情节点（story.json：文本/效果/战斗/选项/下一节点/主线阶段）
  ├─ 效果 → 效果结算（生命/魔力/精力/金币/经验/物品/学技能/接任务 → 发事件）
  ├─ 选项 → 条件过滤（需要物品）→ 分支目标（节点/战斗:/设施:/探索:/区域:/地图:/__结束）
  └─ 下一节点 → 自动目标 0.8s 连播（剧情链）
主线阶段（9 段状态机：序章→待见镇长→穿越橡木林→抵达风谷村→特训→深入调查→骑士团→决战→完成）
  ├─ 节点进入时更新 → 检查阶段任务 + 自动存档
  ├─ 地图地点.解锁阶段（风谷村/大草原门禁）
  └─ 区域剧情路由（区域+阶段+需要物品/任务全命中 → 自动开剧情，阶段前进防重复）
```

### 5.2 设计亮点

- **主线阶段状态机**：一段字符串贯穿存档/解锁/任务/自动剧情四套机制，是"叙事进度"的唯一权威——这个设计很聪明，比 bool 标记堆强得多
- **区域剧情路由**：进入地点自动触发剧情，天然解决"玩家逛到哪剧情跟到哪"的开放世界叙事难题，且阶段前进后自动防重复
- **剧情内嵌战斗**：`战斗:组:胜利节点:助战组` 四段式，助战伙伴（老李/小烛/韩如炎）以 AI 单位加入我方——剧情战斗的演出感与难度控制都到位
- **主线任务自动纳入**：`主线_` 前缀 + 目标=主线阶段 → 阶段达到自动接取，无需逐节点剧情指定，杜绝"忘接主线"

### 5.3 信息链路

```
对话面板点选项 → DialogueService.处理选项(目标) → 分支派发
  → 地图:小地图 → 地图服务.回到城镇地图 → 打开小地图事件 → 小地图面板
  → 战斗: → BattleService.开始战斗（内部先发 打开战斗事件）→ 战斗面板
  → 探索:/区域: → 探索服务 + 打开探索事件 → 探索面板
  → 设施: → 找设施节点 → 节点内部 → 功能面板
```

### 5.4 问题

- 死节点：`酒馆_购买/防具/消息`、`训练场`、`休息`、`哥布林胜利`、`研究羊皮纸`、`镇长府_交差` 无入边（GDD-改进版 P0 已列）
- `第一章_村医_对话` 接取 `支线_采集草药` 但 quests.json 只有 `支线_采集止血草`——**引用断裂，接取空任务**（数据层校验唯一漏网）
- 结局可达性断裂（见 §4）

## 6. 战斗系统

### 6.1 回合制流程

```
开始战斗（敌人组/胜利节点/返回节点/先手模式/助战组）
  → 投影：玩家档案→战斗单位；敌人数据→战斗单位；助战→我方 AI 单位
  → 发布 战斗开始事件 → 战斗面板布阵
  → 回合开始：开始时机持续伤害 → 速度队列排序（先手优先级+速度）
  → 行动轮换：玩家回合等输入；敌方/助战回合 AI 行动（面板停顿 0.8s）
  → 回合结束：结束时机持续伤害 → buff/冷却计时 → 下回合
  → 战斗结束：胜利（金币/经验/掉落/任务）或失败（掉 10% 金币回城满状态）
  → 离场回写：生命/魔力/精力 + 道具消耗统一扣档案
```

### 6.2 伤害管线（全项目唯一伤害公式权威）

```
命中判定（攻方命中率 vs 目标闪避）
  → 暴击判定（×1.5）
  → 真实伤害分支（无视一切）
  → 物理/魔法分流（物攻/魔攻）
  → 弱点判定（物理=武器种类命中敌人弱点；魔法=五行克制）
  → 目标分支：
      敌方有护盾：弱点系数（弱1.0/非0.5）→ 扣盾 → 护盾归零破防晕眩 → 破防易伤×1.5
      我方/无盾：抗性倍率 → 抗性百分比（非线性封顶50%）→ 防御减免
  → 下限 1 → 应用 → 伤害事件
```

### 6.3 机制深度（远超"文字游戏"预期）

- **护盾/破防**：敌人护盾=防御×系数，弱点决定扣盾效率，破防晕眩+易伤窗口——"找弱点破盾"成为战斗目标
- **五行克制**（金→木→土→水→火→金）+ **武器种类弱点**（剑/匕首/斧…）+ **武器规则**（通用/专向/弱向）——物理系靠换武器（可战斗中切换主副手），魔法系靠五行术法，战术分化明确
- **BP 增幅点**（八方旅人式）：命中弱点/造成破防奖励 BP，蓄力 1~3 级提升下次攻击倍率——把"进攻弱点"的正反馈做成资源循环
- **敌人 AI**：行动表+权重+条件+目标策略（随机/残血/低防），敌人可治疗同伴（AI 选友方目标）
- **Buff 系统**：增益/减益/异常（持续伤害，开始/结束时机）/护盾/控制（眩晕跳过行动），叠层+计时
- **技能体系**：倍率/固定/附加三种伤害方式；物理系耗精力、魔法系耗魔力；熟练度每级+10% 伤害 -5% 消耗；冷却管理；品质倍率
- **道具战斗内使用**：恢复/增益/减益，消耗清单离场统一回写
- **逃跑**：速度差概率公式
- **助战机制**：剧情伙伴自动 AI 出手，玩家倒下即败——伙伴既增演出又保玩家主体性

### 6.4 UI 交互（战斗面板）

```
行动选择 → [攻击][技能][道具][逃跑]（+可选的 切换武器/增幅）
  → 子菜单（技能行：名称/消耗/数值；道具行：品质/名字/数量，冷却与可用过滤）
  → 卡牌选目标（文字血条卡牌 + 蒙版高亮可选/不可选着色）
  → 执行 → 演出 → 结算
右键 = 反悔回动作栏
信息条 = 回合数 + 行动序旋转显示（当前金▶/下一步我方亮青/已行动淡删除线/其余灰）
演出：演出片段队列+单驱动协程——受击震颤/飘字（暴击红放大、魔法蓝、闪避灰小字）/
     阵亡右倾倒下淡出/敌方行动强调+跳跃/技能名先飘后结算/回合横幅
```

**评价**：演出系统是纯文字游戏的"视觉化"关键——信息条行动序 + 卡牌动画 + 飘字，把回合制战斗的节奏感做出来了，先动画后判定的队列设计避免事件同帧挤爆，非常专业。

### 6.5 战斗评价

**亮点**：机制密度在文字 RPG 里罕见（护盾/破防/五行/弱点/BP/武器规则/Buff/AI/助战全齐），且全部数据驱动、可扩展；演出节奏打磨精细。
**问题**：
- 数值基线偏慷慨（升级满状态，见 GDD-改进版 P1：改 50% 回血以保住探索血线张力）
- 伤害公式无随机浮动（GDD-改进版 P1：启用 `攻×倍率-防/2+随机`）
- 敌人技能化不足：大部分敌人仍是"行动表=普攻"，Boss（沉睡之龙）是"大号杂兵"无二阶段（GDD-改进版 P1）
- 多目标战斗（2vN）已支持但内容里少见；技能书定价/技能收费未启用（金币出口缺位）

## 7. 探索系统

### 7.1 核心循环（深度分层区域）

```
进入区域 → 层1（描述）→ 反复[探索]（扣 1 精力）
  ├─ 普通层事件表（权重池：遭遇[战斗三形态]/发现[地点剧情]/资源[是/否]/选择[宝箱陷阱]/无事）
  ├─ 岔路层 → 先选 安全小路/危险捷径 → 锁定本层事件表
  ├─ 通路机制：搜满阈值(默认3)后每次搜索掷通路概率(0.5)
  │    → 通路事件：[强行突破]（必然战斗，胜后深入）/[悄悄绕行]（70%无事 30%战斗，然后深入）
  └─ Boss 层 → 打败 → 区域标记通关（可再刷，Boss 普通化）→ 通关文案
张力：HP/MP/精力 带入不恢复 → 血线+精力双下降 → "再搜 or 见好就收"；精力 0 只能返回
战斗三形态：遇见[战斗][逃跑] / 被偷袭（敌方先手强制战）/ 偷袭（我方先手可选，可绕开）
```

### 7.2 数据模型

```
区域：标识/危险度/通关文案/层[]
层：编号/描述/搜索阈值/通路概率/事件表 或 岔路{安全,危险} 或 Boss+通关后表
事件表：遭遇[{敌人组,权重,形态}] + 发现[{节点,权重}] + 资源[{效果,文本,权重,消耗精力}]
       + 选择[{文本,选项[{文本,战斗/效果/节点}]}] + 无事文本[]
```

### 7.3 信息链路

```
地图双击荒野 → 地图服务.进入荒野（查区域剧情路由）→ 打开野外面板事件
  → 探索服务.进入区域(区域, 返回节点) → 初始化层 → 显示当前层 → 探索显示事件 → 探索面板
  → 面板固定三按钮（探索/是/否），文本随情景填充，动作字符串路由（搜索/战斗/逃跑/偷袭/绕开/资源:是/岔路:安全/选择:索引…）
  → 遭遇战斗：先显示[战斗][逃跑]选项，玩家点战斗才 开始战斗（先选项后开战——GDD-改进版 P0 已修正的时序）
  → 战斗结果节点 "__探索胜利"/"__探索返回" → 探索服务.战斗胜利()/战斗逃跑()
  → 返回 → 探索服务.返回() → 地图服务.打开大地图
```

### 7.4 评价

**亮点**：
- 探索状态机干净完整（进入/选岔路/搜索/通路/深入/返回/Boss通关），全部数据驱动
- 精力系统是"探索资源管理张力"的核心载体，与 HP/MP 形成三重血线
- 通路概率+搜索阈值的"软推进"设计优于固定进度——每次搜索都有意义，且有"就差一点"的赌博感
- 战斗三形态、选择类事件（宝箱陷阱）、岔路风险决策——事件多样性够
- 通关可再刷（Boss 普通化）给刷取留了后路
- **时序修正已落地**：遭遇先出选项再开战，解决了"战斗在后台静默打完"的旧问题

**问题**：
- 精力恢复途径有限（回家/食物），长期探索的续航偏严苛，前期可能劝退
- 古战场 regions 数据（GDD-改进版 P0 标注补齐）——实际已存在（5 层+亡灵骑士），需确认是否最终版
- 低概率移动事件（地图移动中遇敌/商人）未实现（代码有注释占位）
- 区域间缺乏差异化机制（除事件表不同外，层结构同构），"危险度"目前只影响文案

### 8.3 信息链路

  ├─ 进入：城镇→小地图（先查区域剧情路由）；荒野→探索；节点内部→NPC 对话/功能物→设施工厂→功能面板

```

### 8.4 评价

**亮点**：三级导航完整落地，设施内部图（NPC+功能物）让"逛城镇"有探索感；交互手感（光标锚点缩放、边缘钳制）打磨到位；双击检测 0.3s 区分单击/双击很实用；地图设计器反写 JSON 大大降低内容维护成本。
**问题**：无"移动事件"（移动中遇敌/商人）——大地图移动只是"点一下换位置"，缺乏旅程感；地图无"已通关"角标（GDD-改进版 P2 已列）；城镇内 NPC 分布稀疏（部分节点只有 1 个互动物）。

## 10. 成长与经济系统

### 10.1 成长链路

```
经验升级（每级 +3 自由属性点 + 满状态）
  ├─ 4 大属性加点（体力+5生命/力量+2物攻/智力+2魔攻+3魔力/敏捷+1%暴击+1%闪避+2速度）
  ├─ 训练场花金币直接训练属性
  └─ 派生数值：物理伤害=力量+装备+词缀；最大生命=50+体力×5+等级×5+装备+词缀
技能学习：武馆/学堂教学（属性前提）→ 熟练度 1~5 级（每级 +10% 伤害/-5% 消耗）
装备：8 槽（主手/副手/头盔/盔甲/靴子/手套/饰品1/饰品2），6 品质 × 倍率
词缀（暗黑式）：掉落/制作生成，品质决定条数（普通1→传奇4），9 属性
强化三件套：
  合成（2~5 件同装备，40%~80% 成功，品质+1 + 词缀追加/升级）
  附魔（材料→随机词条，30% 装备损坏）
  镶缀（宝石→指定属性词条，25% 宝石碎裂）
```

### 10.2 经济模型

```
产出：战斗金币/探索资源/贩卖/任务奖励/日常悬赏
消耗：买卖/训练/熟练训练/制作材料/合成/附魔/镶缀
货币：三进制（1金=100银=10000铜），内部统一铜币存储与运算，显示省略零单位
```

### 10.3 评价

**亮点**：成长链路完整且自洽——属性/技能/装备/词缀四条线并行；词缀系统（生成/合成/附魔/镶缀）已形成"装备终局玩法"，暗黑式随机词条 + 三强化通道的组合在文字 RPG 里相当罕见；三进制货币设计（内部铜币，显示金银铜）为数值膨胀留了空间。
**问题**（经济系统是当前最大短板）：
- **金币出口缺位**：教学免费 + 睡觉免费 + 恢复免费 + 训练便宜 → 中后期金币通胀（GDD-改进版已列：技能收费/恢复点/强化/词缀重铸）
- **合成食物定价倒挂**：配方食物（7000~13000 铜）远超治疗药水（300 铜）且恢复量更低，性价比严重倒挂
- 旧剧情文案价格（木剑 5 银/铁剑 25 银/链甲 80 银）与 items 价格（300/8000/15000 铜）不符——文案未随三进制换算更新
- 升级满状态 + 战斗失败只掉 10% 金币回城满状态 → 风险惩罚过轻，"死亡无痛"削弱探索张力
- 装备品质倍率已实现但掉落分布未按区域等级做品质覆盖（GDD-改进版 P2）

## 11. 任务系统

### 11.1 三层任务

```
主线（7 个，主线_ 前缀）：按主线阶段轨道自动接取/完成（目标类型=主线阶段），章节分组展示
支线（7 个，支线_ 前缀）：击杀（击败X）/收集（获得X），完成自动发奖
日常悬赏（按游戏内天数随机生成一批）：装备/食物/药剂范围收集委托 + 通用击杀/收集委托
  → 接取（悬赏板认领）→ 进度（击杀联动/背包持有）→ 回委托栏提交结算（收集扣道具）
```

### 11.2 信息链路

```
接取：QuestService.接取 / 日常任务服务.接取 → 任务进度事件 → 系统任务面板/日常面板刷新
进度：BattleService 击杀 → QuestService.记录击败 → 日常任务服务.记录击杀（联动）
完成：主线阶段前进 → 检查阶段任务 → 发放奖励（金币/经验/物品）→ 任务完成事件
提交：日常 → 日常任务服务.提交（收集校验+扣道具）→ 结算发奖
展示：系统任务面板（主线 Tab 章节可折叠/支线 Tab 仅已接取/日常 Tab 仅已接取 + 详情区 + 行动按钮）
```

### 11.3 评价

**亮点**：主线任务"自动纳入"机制（阶段达到自动接取）杜绝了传统 RPG"忘接主线"问题；日常任务按天刷新 + 按设施范围生成（与配方/物品数据联动）是长线内容的低成本引擎；任务与剧情/战斗/探索三向联动。
**问题**：
- 支线自动完成即发奖，无交付制仪式感（GDD-改进版 P2：改交付时发放）
- 日常任务跨天刷新依赖游戏时钟，但睡觉不推进时间 → 日常刷新节奏过慢
- 无任务追踪/引导（HUD 不显示当前目标，GDD-改进版 P2 已列 [追踪]）
- 支线数量偏少（7 个），且部分依赖死节点链（清除哥布林）

## 12. UI/UX 体系

### 12.1 三级 UI 结构

```

L2 常驻 UI：HUD 顶栏 / 左侧日志 / 右侧侧边栏 / 底部状态栏 / 游戏时钟

### 12.2 交互范式

- **面板基类**：显示/隐藏 = DOTween 过渡动画（上下分层滑入 + 0.2s 队列延迟 + OutBack 回弹；侧边面板右滑入；侧边互切上下滑）；`回退()` + `取消文本` 全局返回协议
- **全局返回**：右键或侧边栏取消按钮 → 当前面板.回退()——"哪里都能退"的统一语义，各面板覆写（战斗=取消选目标/小地图=离开城镇/探索=撤离/对话=跳过打字机/结局=回主菜单）
- **日志即反馈**：所有操作结果进左侧日志栏（时间戳+彩色徽章+数字提亮），按类型着色（系统灰/操作金/反馈绿/反馈坏红/内心紫/战斗橙/探索青/任务土金）
- **HUD 数值脉冲**：生命/魔力/金币变化时 DOPunchScale"萌"一下，数值感强
- **悬停反馈**：所有按钮自动挂悬停缩放/音效
- **音效**：按钮成功/错误音全自动挂钩（场景扫描+动态注册），本帧失败标记防重

### 12.3 视觉语言（"余烬"）

炭黑背景/面板底、羊皮纸白正文、余烬金强调、血烬红危险、苔绿成功、暮紫内心、钢蓝选中——统一的暖暗色调 + 富文本着色体系（日志色/品质色/战斗色全 Token 化）。

### 12.4 评价

**亮点**：全局右键回退 + 侧边栏取消的双通道返回是文字 RPG 交互减负的正确解法；日志面板作为"全项目输出通道"的设计（任何系统发日志即进栏）是文字游戏的灵魂；面板过渡动画的排队感打磨精细；未接线降级（详情区退日志/旧样式回退）保证场景改造前可玩。
**问题**：
- 两套面板范式并存：新版（商店/角色/任务/制作/探索：专属结构+行模板）vs 旧版（训练/教学/恢复/睡觉：通用创建行）
- 订阅生命周期管理缺失（仅探索面板 OnDestroy 解绑）
- 日志面板主菜单下 `玩家.档案` 无空判可能 NRE；战斗面板核心按钮无空判
- 侧边栏 Update 每帧轮询取消文案（廉价但可事件化）
- 新手引导缺失：属性派生公式无 tooltip、训练收益无排序（GDD-改进版 P2）

## 13. 游戏玩法分析

### 13.1 核心循环（现状实测）

```
剧情/对话 → 地图导航（大地图→小地图→节点内部）
  → 设施强化（买卖/训练/教学/制作/悬赏）
  → 探索（分层区域：搜索/事件/通路/Boss）→ 战斗（弱点/护盾/BP/五行）
  → 成长（属性/技能/装备/词缀/熟练度）→ 返回镇子 → 下一章
```

GDD-改进版目标循环（含收费与时间压力）尚未完全闭环，但骨架已立。

### 13.2 张力设计

- **探索张力**（已实现）：HP/MP/精力三重血线带入不恢复 → "再搜 or 见好就收"
- **战斗张力**（部分实现）：弱点/破防/BP 的"找弱点击破"正反馈循环已成型
- **经济张力**（未实现）：金币出口缺位 → 无"攒钱变强"的长期目标感
- **时间张力**（未实现）：睡觉免费无时间联动 → 日常/昼夜节奏没跑起来

### 13.3 内容量评估（~4-6 小时主线目标）

- 第一章主线完整闭环（~1.5-2 小时量级），85 剧情节点量扎实
- 4 区域 × 5 层探索 + 4 Boss（狼王/亡灵骑士/幼龙/野猪王）+ 14 任务 + 140 物品 + 67 配方
- 距离 GDD-改进版"10+ 小时全内容"目标：需补古战场/黑石山主线接入（龙之羊皮纸链路）、支线扩量、空壳 NPC 话题、图鉴/成就

### 13.4 玩法亮点总结

1. **探索"软推进"设计**（阈值+概率）是教科书级文字游戏机制
2. **战斗机制密度**（护盾破防/五行/弱点/BP）远超同类，且数据驱动可扩展
3. **剧情阶段状态机** + 区域路由 = 开放世界叙事的低成本正解
4. **词缀三强化通道**（合成/附魔/镶缀）给装备终局玩法
5. **日志即一切输出**——文字游戏的沉浸感核心

## 16. 总体评价

### 评分（独立游戏开发者视角）

| 维度 | 评分 | 评语 |
|------|------|------|
| 架构设计 | ★★★★☆ | 四层单向依赖+事件驱动+数据门禁，独立项目罕见的高标准；欠服务注入收敛与测试 |
| 战斗系统 | ★★★★☆ | 机制密度超出题材预期（护盾/破防/五行/BP/弱点）；数值与 Boss 待打磨 |

| 剧情叙事 | ★★★★☆ | 第一章人物弧光完整、文案质量高；结局可达性断裂是硬伤 |
| 经济系统 | ★★☆☆☆ | 当前最大短板：金币出口缺位+定价倒挂，但三进制货币与词缀经济有底子 |

### 总结

这是一个**框架完成度远高于内容完成度**、**系统深度远超题材平均水平**的文字 RPG 项目。作者（或团队）展现出极强的工程纪律：四层架构、事件驱动、数据门禁、插件式设施——这些在独立项目中几乎都是"教科书里才有人这么干"的实践。战斗的机制密度（护盾/破防/五行/BP/武器规则）和探索的张力设计（精力/通路概率/岔路）证明设计者有扎实的 RPG 设计功底。

**当前最优先的事**不是加新系统，而是：
1. **修通主线闭环**（羊皮纸链路，1 天）——否则游戏"通关不了"
2. **让经济循环转起来**（金币出口+收费化，3 天）——否则游戏"没有目标"
3. **给 Boss 与数值上强度**（二阶段+数值基线，3 天）——否则战斗"没有记忆点"

完成这三步，这个项目就能从"框架演示"变成"真正能玩的独立游戏"。以目前的工程底子，剩下的内容扩量（古战场/黑石山/支线）只是时间问题。
