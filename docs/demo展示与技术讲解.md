## 三、技术力分析（面试讲解用）

### 3.1 八个"能撑 3 分钟"的技术点（算法与架构层）

每个点：**卖点 / 关键实现 / 数字 / 代码证据 / 可能被追问什么**。
（**玩法功能系统**在 §3.2 —— 那七个才是玩家真正在玩的东西。）

#### ① A\* + 索引二叉堆：换容器，但结果一个字节都不许变

- **卖点**：开放表从「`List` + 每次出队线性扫描取最小」换成**索引二叉堆**，O(n²) → O(E log V)；同时用一个巧劲**逐字节保留旧路径结果**。
- **实现**：3 个 `int[总格数]`（`代价/估/父`）+ `byte[] 状态`（0 未入 / 1 开放 / 2 关闭，**兼当闭集**，避免 `HashSet` 装箱）；堆键 = **(估, 首次入队序)**，且**入队序只在第一次入堆时分配** —— 于是"并列取最先入队的"与老实现严格等价（老实现里 `List` 顺序恒等于入队顺序）；已在堆里的节点键变小走**减键上浮**，不重插。
- **数字**：大世界 **100×100 = 10000 格**；启发 = 曼哈顿，四向、代价恒 1（可采纳且一致）；老实现单次可达**百万级比较**。
- **证据**：`Assets/Scripts/Domain/网格/网格寻路.cs:27-57`、`:48-51,136`、`:84`、`:217`。
- **追问**：
  - *"为什么不用泛型 `PriorityQueue`？"* → Unity 的 .NET Standard 2.1 面不一定有；我需要**减键**与**稳定的并列规则**，泛型堆给不了；自写索引堆 40 行，还能被离线断言钉住。
  - *"启发要满足什么？"* → 四向单位代价下曼哈顿**既可采纳又一致** → 首次出堆即最优，闭节点不必重开。
  - *"为什么禁斜走？"* → 斜穿让"不可穿过"的判定与视觉都变糊；四向还让代价恒 1、启发可采纳。
  - *"改容器凭什么保证结果不变？"* → 因为离线验证器断言的是**具体路径**；我把"并列取最先入队"写进键里，并留了 ⚠ 注释。

#### ② Flow Field（BFS 积分场）：多动因 + 与噪音机制同构 ★最强的一段

- **卖点**：**多动因 → 少目标**的教科书场景。一次 BFS 算完整张场，每个敌人各读自己那一格 = **O(1)**；敌人 16 → 160，**成本不变**（A\* 是线性乘上去的）。
- **实现**：`距[]`（到源最少步数，−1 未达）+ `方向[]`（"朝源走的下一格"）；方向取 4 邻中距最小者，并列按**固定顺序（右/下/左/上）**打破 → **距严格递减 → 结构上不可能成环**；源格被占（噪音点可能落在柜子上）时按**切比雪夫环 1..8 吸附**到最近可走格；`可达()` 是**早退 BFS**（不算方向、不建整张场），专供"连通性硬保证"。
- **数字（今天当场实测，`Tools/大世界敌人验证`）**：
  - 流场 **一次 BFS（服务所有动因）= 0.149 ms**
  - A\* 单点查询 = **3.684 ms**
  - **16 只敌人各自 A\* ≈ 58.9 ms / 次**（≈ 395×）
- **证据**：`Domain/网格/流场.cs:103-148`（BFS）、`:167-187`（方向场）、`:150-165`（吸附）、`:82-99`（挡表）、`UI/探索/探索图层.流场调试.cs`（F2 叠层）。
- **★ 诚实拆解（这段一定要讲）**：
  > "这 20 倍里**有一部分不是算法的功劳** —— A\* 那 3.5 ms 大半花在 `网格数据.占位`（对全部实体线性扫描：10000 格 × 4 邻 × 600 实体 = 千万级）；流场把占格物足迹**一次摊平成位图**（`建挡表`）→ **3.481 ms 降到 0.144 ms**。
  > 所以**单动因场景若 A\* 也预摊平，其实会赢**。流场真正不依赖实现质量的胜点只有两条：**① 随动因数量摊薄；② 它和噪音机制是同一个数据结构。**"
- **设计上的那半句（更值钱）**：追踪玩家 = 以玩家格为源；追踪噪音 = 以噪音格为源；"被噪音吸引靠近"本质就是**朝源走的梯度下降** → **一套机制实现两件事**（`docs/设计-大世界.md` §4.8）。
- **追问**：
  - *"为什么不是 Dijkstra？"* → 每格代价恒 1，BFS 就是 Dijkstra 的退化情形，省掉堆。
  - *"为什么不做增量/脏标记？"* → 目标格键控缓存 8 个就够（玩家场每步重算 0.15 ms，噪音场静止可长期复用，障碍变就整体清空）；增量的复杂度大于收益。
  - *"怎么保证敌人不转圈？"* → 方向场由"距严格递减"构造，**无环是结构性质**；验证器断言⑧还逐字节比对 `距[]/方向[]` 并检查"方向恒指距−1 的邻格"。
  - *"敌人算不算障碍？"* → **唯一的开关**，两种用法都真实存在：追踪场里敌人透明（否则一只堵窄口会让后面全判不可达、16 只一动缓存全废）；连通性校验里敌人是"活的墙"（用透明场校验等于自欺）。

#### ③ 确定性工程：可复现的战斗

- **实现**：
  - **30Hz 固定步长累加器**：`步长 = 1/30 s`，余量 `ref` 跨帧带过（不丢、不累积误差），**单帧上限 8 步**（≈0.27 s，超出直接丢 —— 宁可慢一点，也不要"一帧补几百步"雪崩）。
  - **可播种随机源**：一场战斗 = **初始状态 + 种子**；种子 = `确定性随机.派生(世界种子, "战斗" + 场次)`，开局打日志 —— 玩家报 bug 带这个数就能重放。
  - **FNV-1a 分段哈希**派生（跨平台一致，**刻意不用 `string.GetHashCode`**，并加段分隔避免 `("ab","c")` 与 `("a","bc")` 撞）。
- **证据**：`Domain/战斗/固定步长.cs:17-30`、`Domain/战斗/随机源.cs`、`Domain/网格/确定性随机.cs:12-40`、`Services/战斗/BattleService.cs:149`。
- **追问**：
  - *"为什么不用 `FixedUpdate`？"* → 时间源不可控，而且我要战斗在**面板隐藏/挂机**时也照常推进；自己的累加器还能在离线验证器里直接跑。
  - *"取整为什么用银行家舍入？"* → 改成 `(int)(v+0.5f)` 会让数值**悄悄偏 1 点**；有断言钉着（`Domain/战斗/伤害计算.cs:72`）。
  - *"随机数为什么不能想掷就掷？"* → **掷点次数是契约**：无敌 0 / 闪避 1 / 真伤 1 / 普通 2 次；次数一变，全局随机序列跟着变，别处战斗结果也会变。

#### ④ 四层程序化生成："同一个种子跑两次、指纹逐字节一致"

- **管线**（全是纯 C# 静态生成器，离线验证器与游戏共用同一份）：
  - **大世界** `生成(种子, 模板, 取名)`：造壳 → 营地 → 区域 → 敌人 → 障碍 → **保证连通**（6 段）。
  - **区域**：**地块制**（非 BSP）——内区切 2×2 地块、街宽 2、1 栋/地块、按种子洗牌；**每撒一只敌人/障碍当场校验，破了立即 Remove**。
  - **建筑**：楼层表 + 全楼共用一部楼梯（楼梯坐标全楼一致）。
  - **房间**：中空大房 + **约束摆放** + 最多 5 次重掷 + 环形保底。
  - **种子链**：`世界种子` → `派生(世界种子,"区域:"+标识)` → `派生(区域种子, 楼标识)` → `派生(…,"F层#序")`。
- **约束摆放不是回溯**，是**贪心 + 采样**：划区块 → 大件优先排序 → 区块配额轮转 → 块内锚点洗牌试 ≤60 次 → 失败件全图补位；规则是**对象字段**（`大件优先/避开区块心/距墙/通道格`）而不是脚本，"摆什么"由回调注入。
- **"数学上切不断地图"**（很漂亮的一条）：占格物彼此**切比雪夫 ≥2** 就凑不出 8 连通屏障，而 4 连通网格的割集必是 8 连通屏障 → **生成期免逐格校验**；反例是 2×2 临时建筑（它就是一整块屏障）→ 所以"搜索放临时建筑"必须**试放 + 校验**；敌人会移动让前提失效 → 所以运行时加 `玩家能回营地` **早退 BFS 硬保证**（破了就整体撤销这一步）。
- **★ 最有价值的教训**（写进了注释和门禁）：
  > "**共用谓词有盲区**：`门口保护` 被生成期与验证期共用，把谓词改坏会让**两边同时变宽** —— 实测：改成半残 → 两个验证器**全绿（假绿）**；改成恒 `false` → 大世界炸、区域验证**仍然全绿**。
  > 结论：**谓词本身必须有一条不依赖模拟的真值表自检**。现在 `大世界敌人验证` 第⑨项就是那张表（9 真 / 6 假），**自检不过就不跑模拟**。"
- **追问**：
  - *"怎么测生成器？"* → 5 个 dotnet 控制台验证器，**直接链接游戏的 `.cs`**，跨几百颗种子扫"指纹一致 + 几何不变量"，红了就 exit ≠ 0。今天实测：世界 50、区域 1400、建筑 3500 层、房间 9200 房、户型 2000。
  - *"怎么保证不出死路？"* → 三层：生成期"唯一出口结构周围八格必须留空" → 撒完**统一兜一次**连通（不是每撒一个就整图校验，10000 格会慢到不可用）→ 运行时敌人移动后的早退 BFS 硬保证。

### 3.2 玩法功能系统（七个技术点）

> 上一节是**算法与架构层**；这一节是**玩家真正在玩的东西**。它们的共同点是：**规则都在数据里、判定都是纯函数**，所以能离线核对。

#### ⑨ 塔科夫式网格背包：几何、合法性、唯一入口

- **卖点**：占格是**数据**（`形状宽/高`，默认 1×1）、判定是**纯函数**、跨面板搬运**只有一个入口**。
- **实现**：`可放置` = ①越界 ②`覆盖格合法`（**逐格必须可用** ＋ 有"块"概念时必须**同一块**）③与已有堆叠**包围盒相交**（`Domain/网格/网格服务.cs:71-86`）；换位用 `可放置忽略两个`（两件互换时**双方都不算占格**，`:89-103`）；移动自己时用 `排除` 参数忽略自身。
- **渲染/交互侧**：拖拽投影**三色**（可放 / 可合并 / 禁放）+ `上次判定列/行/旋转/有效` **脏标记** → 不是每帧重算；`R` 键旋转 90°（宽高互换）；全局格 90px。
- **唯一入口**：`容器服务.跨网格转移`（`Domain/容器/容器服务.cs:345`）—— 背包、仓库、容器、搜索面板全走它。
- **踩过的坑（面试可讲）**：曾有"**装备凭空消失**" —— 跨会话搬运后 `物品堆叠.列/行` 仍是**旧网格坐标**（≥0），而 `放入网格堆叠` 第一句是 `if (堆叠.列 >= 0) return true;` → 直接返回、什么都没做，东西已从来源列表摘掉 = **两个列表都不在**。修法：新增 `移出会话/放入会话`，搬之前把坐标复位成 −1（回滚路径也走它们）。
- **追问**：*为什么用包围盒相交，不用占用位图？* → 背包只有 6×10 量级，O(物品数) 的包围盒判定比维护位图更简单，而且**没有"位图与物品列表不同步"这类 bug**；脏标记让每帧成本≈0。

#### ⑩ 嵌套容器与"独立口袋"

- **模型**：容器**就是物品**（塔科夫式），打开后包成一个 `网格服务` 视图 → **主背包与容器视图共用同一套判定与转移函数**（不是两套代码）。
- **防护**：`嵌套上限 = 3`、**禁自己套自己**、递归检测**循环引用**（`UI/物品/网格/物品网格面板.交互.cs:189-200`、`239-255`）；拖入前先算"目标容器深度 + 被拖物的嵌套深度"是否超限。
- **"独立口袋"几何**：一个容器可以是**多个矩形块**，物品**不得跨块**（就是 `覆盖格合法` 里的"同块"判据）；块与块的**缝隙**在 UI 上要按偏移**反算**回格坐标。
- **追问**：*为什么限制 3 层？* → 两栏 UI（背包 + 一个容器）下 3 层已经快到玩家位置感的极限；更重要的工程理由：**环检测必须有上限**，否则坏档能构造出无限递归。

#### ⑪ 装备与配件：把"槽位规则"变成数据

- **装备**：7 槽（主手/副手/头部/胸部/腿部/脚部/手部）+ **3 个穿戴容器位**（弹挂/腰封/背包）；兼容规则 = **主副手互通、其余严格**；负重上限 = `50 + 力量×5 + 体质×2 + 装备 + 配件 + 知识`。
- **配件**：7 种槽位（枪口/瞄具/弹匣/枪托/握把/刃口/插板），**按武器种类开槽**（`Data/配件槽.cs`）；聚合口径 `副属性 = 本体 + 配件`，且**只算装在"已装备"物品上的**；**耐久归零 → 本体与配件加成一起失效**。
- **硬规则**：**配件不是装备、没有耐久** —— 数据里给配件配 `最大耐久 > 0` 直接判**校验错误**（因为"拆出来的配件显示损坏"是玩家实测报过的 bug，根因是兜底规则漏到了不该管的地方）。
- **一个设计决策**：装备"随机词缀"整条链被砍 → 换成**真物品配件**（占格 / 有重量 / 可换），效果来自物品自己的加成字段 → **可正可负 = 取舍**（消音器 潜行 +8、攻击 −2、命中 −2）。词缀概念**留给了敌人**（8 条 Tier 1 属性型，开战逐只掷、可播种）。
- **追问**：*为什么不做随机词缀？* → 两个理由：① 玩家要的是"改装取舍"而不是"数值抽奖"；② 词缀是**不可复现的数值来源**，和"存档只存种子或内容"那条口径直接冲突（要么进档、要么每读一次档数值就变）。

#### ⑫ 事务化的制作会话

- **两步式**：`开始制作_会话`（校验材料/工具/图纸/家具等级/精力 → 扣行动点 → 返回上下文）→ 动画（**10 游戏分 = 1 现实秒**，同步推进时钟）→ `结算制作_会话`（扣饱水 → 推时间 → 扣料 → 产物入输出区）。
- **原子性**：输出区放不下 → `会话回滚` 把**材料 + 精力 + 时间 + 饱食/水分全数返还**（`Services/世界/工作台制作服务.cs:259-274`）；关闭面板时输入剩料与输出成品自动返还，背包满则**拒绝关闭**。
- 匹配是**材料集合 + 数量**（跨穿戴容器与仓库计数），不是放置式；多份数 = 各材料可做份数取**最小值**；`需要工具` **持有即可、不消耗**。
- **追问**：*为什么要做"事务"而不是"放进去就开始"？* → 放置式要么允许中途反悔（那它还是事务），要么在玩家手滑时**吞材料**。"开始/结算"把**事务边界**写在函数名上，回滚路径只有一处，测试也只需要打这一处。

#### ⑬ 概率与节奏：搜索不是"打开就有"

- **容器级**：整层黑布倒计时（默认 5s）→ 逐件揭开（每件时长 = 条目配置，或 `价值 × 0.08` 夹在 0.5~2.5s）。
- **抽取**：权重随机 + 数量区间 + **每件生成后 45% 概率收尾** + 总尝试上限 `max(列×行×2, 12)` → 分布**稀疏**、不塞满（实测平均 6.4 件/容器、**没有 ≤3 的薄容器**）。
- **世界层双约束**：**局部枯竭**（半径内翻过越多次，成功率越低：60% → 12%）+ **越翻越累**（行动点 10、14、18…）→ 产量阀门。
- **追问**：*为什么不给"连败保底"？* → 单容器保底会变成"必出货"，把翻箱的紧张感抹平；我把保底放在**世界层**（每趟行动点有限 → 玩家必须选择"去哪翻"）。
- **书籍**（不是抽奖）：级别→难度（低 44% / 中 33% / 高 22% / 顶 11%），成功率 = 基础 + 智慧×1% + **失败叠加 12%/次**（宽容机制），已习得配方在池里**权重 ×0.2** 降权；**知识书必成、一本读一次即崩解**。

#### ⑭ 时间驱动的三条链 + "归谁管"字段

- `腐坏 / 生长·晾晒 / 净化` 全部由 `世界时间管理器` 的 `推进()/跳时()` 驱动（**两条时间流都覆盖** —— 否则逐帧与整点结算会**双扣**）。
- **最有价值的一条设计教训**：`生长时间 + 成熟产物` 只说了"多久变成什么"，**没说在哪件家具上** → 于是**种子扔晾晒架上也发芽、生肉扔种植箱里也变肉干**（两边都"能用"、都不报错）。补 `物品数据.转化用途`（值 = 家具 `功能类型`）之后，推进器 / 网格 / 面板**三处共用同一条判据**。
- 净水器 = **三分区容器 + 时间驱动自动净化**（缺料或净水区满则**冻结进度**，条件恢复继续，不浪费）。
- **追问**：*同一个机制被第二件家具复用时要注意什么？* → 先问"**数据里有没有字段说清这件归谁管**"。原来 `生长推进` 和 `腐坏结算` 各写了一份"种植箱/晾晒架"**名字白名单** —— 这类白名单写两份就一定会漂。

#### ⑮ 成长与知识阶梯

- 技能槽**固定 6**：`切换入槽`（同技能已在别的槽 → **两格对调**）、`卸下槽`（**写空串、长度恒定**，不是 `RemoveAt` —— 否则槽号会整体前移）。
- 升级：`经验 = 等级 × 25`，升级给 **3 点自由属性**、只回 **50%** 生命/行动点。
- 知识：**累计门槛** `{100,200,300,400,500,700,900,1200,1600,2000}`（精通 10 级）；书 100 经验/本、天赋「学霸」×1.15；界面上"当前经验 53/100"是**减掉本级基准之后**的级内进度，**存储口径始终是累计**。
- **追问**：*为什么槽位不用 `List` 增删？* → 槽号是玩家心智模型的一部分（"我的急救在 3 号位"）；写空串保持长度恒定，换槽逻辑就永远不涉及下标漂移。

> 这七块**全在纯 C# 或纯数据里**，所以能被离线核对：`数据引用核对.ps1` 覆盖配件槽位/弹匣/物品用途/成本比；`存档验证` 覆盖容器内容与战局快照。
> ⚠ **但要诚实**：物品/容器/制作/搜索**目前没有专门的离线行为验证器**（不像战斗有 122 条断言）—— 它们靠"数据引用核对 + 挂机试玩"。这是 §5 可以补的一块。

### 3.4 质量工程：这套"验证 + 门禁"怎么讲

| 层 | 是什么 | 盯什么 | 为什么值钱 |
|---|---|---|---|
| **离线验证器**（9 个 dotnet 控制台） | 战斗 / 存档 / 大世界敌人 / 世界·区域·建筑·房间·户型 | 战斗数值与步长、存档往返与迁移、生成器几何与连通、**确定性（同种子逐字节一致）** | 它们**链接游戏的那份 `.cs`**，验的不是副本；不开 Unity，几秒出结果 |
| **离线编译校验** | `编译校验.ps1`：在 `Library/Bee/artifacts` **递归找最新的 `Assembly-CSharp.rsp`** + Roslyn `csc.dll` | 语法/类型错误（游戏与 Editor **两遍都编**） | 不打开 Unity 也能编译（今天实测：**168 + 2 个源文件，双 exit 0**） |
| **结构门禁** | `目录核对`（`.cs`↔`.cs.meta` 配对：漏 meta → 场景 Missing Script 而**编译不报**）· `分层核对` · `重复代码扫描` | 结构与分层 | 把"编译器不管的约定"变成红灯 |
| **数据门禁** | `数据引用核对`（611 行，含"零来源/无用途一票否决"）· `格子池区间核对`（80 组几何反例；`checked==0` 判**空跑假绿** exit 2） | 数据完整性 | 加物品没有出口就过不了门禁 |
| **接线门禁** | `存档接线核对`(10 段) · `战斗接线核对` · `探索接线核对` | **静默毁档/静默不刷新**的源码形状（"读档未对齐整点""Dictionary 进了存档 DTO"） | 每条都做过**负向测试**（注入缺陷必须报红） |

**★ 一个真实的教训**（我修好之后才知道，值得主动讲）：
> `Tools/战斗验证` 自刀74（buff 从"回合制"改"秒制"）起**一直编译不过** —— 7 处引用已删除的 `持续回合 / 剩余回合 / 回合结束()`。
> 没被发现的原因：`编译校验.ps1` 只编**游戏与 Editor** 程序集，**不编 `Tools/` 下的验证器**；而"改 Domain 之后要跑验证器"只是**纪律**，没有自动化。
> **已于本次修好并复绿（122 条断言 exit 0）**，但这件事正好说明 §五 #1 那条（把门禁挂到 CI）为什么是现在最该做的事。

**三句话总结**：
1. 门禁把"编译器不管的约定"（meta 配对、分层方向、JSON 引用、文档路径、静默毁档接线）全变成**可执行的 0/1 判据**；
2. 判据都做过**负向测试**并带**防空跑自检**，所以绿灯是真绿；
3. 单次成本 <1 分钟，换掉的是"打开 Unity 跑一遍再手点"的十几分钟和不可复现的漏检。

> "我做的是一个单机末日生存 RPG，3.3 万行 C#，326 次提交，按五层分架构：`Data → Domain → Services → Events → UI`。重点讲三件事。
>
> **第一，寻路。** 玩家点格子走 A\*，我把开放表从线性扫描换成索引二叉堆，并且用'估价值 + 首次入队序'当堆键，**逐字节保留**了老实现的路径结果 —— 因为我的离线验证器断言的就是具体路径。
> 但真正有意思的是敌人：**多动因高频寻路用流场**，一次 BFS 建整张积分场加方向场，所有敌人各读自己那一格，是 O(1)。今天实测：流场一次 0.149 毫秒服务全部 16 个敌人，而它们各自跑 A\* 要 59 毫秒。
> 不过我不会说'流场比 A\* 快 400 倍' —— 这里面有一部分**不是算法的功劳**：A\* 那次主要慢在我的网格查询是**对实体线性扫描**，摊平成位图之后是 3.48 毫秒降到 0.14 毫秒。**单动因场景如果 A\* 也预摊平，其实它会赢。** 流场真正的胜点只有两条：随动因数量摊薄，以及它跟我的噪音机制**共用同一个数据结构** —— 追踪玩家是以玩家格为源，追踪噪音是以噪音格为源，而'被声音吸引靠近'本质就是朝源走的梯度下降。
>
> **第二，玩法系统的规则我尽量都放进数据与纯函数。** 网格背包的占格来自 `形状宽高`，合法性判定是"越界 + 逐格可用 + 同一容器口袋 + 包围盒不相交"四条的纯函数；所有跨面板搬运只有一个入口函数，所以不会出现"东西在两个列表里都不在"。制作做成两步事务：输出区放不下就把材料、精力、时间、饱水**全量回滚**。搜索的节奏也是纯函数：每件 45% 收尾 + 尝试上限 + 世界层"越翻越累"，所以能离线逐点断言。
>
> **第三，确定性。** 战斗跑在 30Hz 固定步长上、单帧最多补 8 步防雪崩；一场战斗等于初始状态加一个种子，我能逐帧复现玩家报的任意一场。为此领域层是**零 UnityEngine 依赖**的纯 C#，9 个离线验证器能**直接编译游戏那份源码**跑几千条断言 —— 包括'同种子跑 60 步后所有敌人位置逐字节一致'。
>
> **第四，工程化。** 我项目里'约定'很多（meta 必须配对、不许越层、JSON 引用必须存在、文档路径不能漂），而**编译器一样都不管**。所以我写了 10 个 PowerShell 门禁，其中离线编译校验是**不开 Unity** 直接调 Roslyn。就在准备 demo 的时候，我靠它发现自己的战斗验证器因为一次接口改动已经**红了好几天** —— 这件事让我确定下一步就是把这些门禁挂到 CI 上。
>
> 我做的不好的地方也很清楚：没有 CI、没有 Profiler 曲线、剧情和任务系统我砍掉了、情报系统还是悬空的。"
