## 〇、先分清三件被绑在一起的事

`格子探索服务.回安全屋清战局()` 原来是这么写的：

```csharp
protected virtual void 回安全屋清战局()
{
    视野记忆.Clear();   // ← 地理知识（静态布局）
    清战局();           // ← 派生类清：容器战局 / 门锁态 / 本趟搜索计数…
}
```

**这是两种性质完全不同的记忆，却共用了一个重置时机：**

| | 是什么 | 会变吗 | 该什么时候清 |
|---|---|---|---|
| **地理记忆**（雾 / `已探索`） | "这地方长什么样" —— 街道、楼在哪、去过哪 | **永远不变**（布局种子固定） | 不该清（同一存档内） |
| **内容状态**（容器内容 / 门锁 / 已翻标记） | "这个柜子我翻过没有" | 每趟都变（`搜索服务` 用的是普通 `System.Random`） | **回安全屋清**（现状正确） |
| **危险感知**（`已察觉`） | "我看没看见那只丧尸" | 每次进门都不一样 | **每次进门清**（现状正确） |

第三条是关键前提：`已察觉` 只吃**当前可见**（`房间探索服务.cs:89-98`），不吃 `已探索`。
→ **所以迷雾改永久不会给玩家任何先手优势**，战斗平衡不动。

现在的设计其实已经是"**内容重掷 + 布局固定**"，分界画对了 —— 只有雾被错误地划到了"内容"那一边。

## 一、拍板结论

| 层 | 决定 | 理由 |
|---|---|---|
| **大世界**（100×100） | **永久保留（随档）** | ① 布局 100% 种子固定 → 重看**信息量为零**；② 代价极大（5 游戏分钟/格，从 87 天里扣）；③ 这层的职责是**导航与调度**，不是战术探索 |
| **区域**（32×22） | **永久保留（随档）** | 同上。街上敌人位置**也是种子固定的** → 重看同样学不到东西 |
| **房间**（16×10） | **保持每次重看** | ① 只有 160 格，8~15 步就摸完 —— **便宜**；② 战术与紧张所在地；③ ★ **技术硬理由**：记忆键是"每个房间实例"，而临时建筑**每趟新增实例** → **无界增长**，进档会无限膨胀 |

技术上正好对得上：大世界 1 张图（10000 格 → 位图 **1668** 字符 Base64）、区域 7 张（704 格 → **120** 字符 ×7）
—— **有界且很小**（合计约 2.5 KB 存档文本）；房间无界，只适合留在内存。

还有一条：**寻路不看雾**（`算路径` 只查 `可通行`）。雾在这游戏里**不是通行闸门，纯粹是信息层**。
所以"重看"换不来任何新决策，只是在抹掉玩家本来就合法拥有的知识。

## 二、怎么存的

```
玩家档案.迷雾记忆 : string[]          // JsonUtility 不支持 Dictionary，所以用 string[]
  每条 = "{键}|{Base64(位图)}"
  键   = "{层标签}|{种子}#{标识}"      // 大世界 / 区域 / 房间 各自的标签
```

- 位图口径**行优先**（`idx = 行 × 列数 + 列`），与 `网格数据.编码` 的 `列*1000+行` **不是一回事**（别混用）。
- **键里带种子** → 换了图 / 换了种子**自动失配**（记忆自然作废），不必另写失效逻辑。
- 位图编解码是纯函数（`迷雾位图`，零 UnityEngine）→ **能离线断言对称性**。
  这一点很重要：位图最容易在"最后一格 / 最后一个字节"上差一位，而那种错在游戏里只表现为
  "某几格记忆莫名丢了"，**试玩几乎不可能发现**。

### 三个钩子（`格子探索服务`）

| 钩子 | 作用 |
|---|---|
| `迷雾随档保存`（默认 `false`） | 大世界 / 区域 覆写 `true`；房间层**必须**保持 `false`（无界） |
| `层标签`（默认 `"格子"`） | 存档键的层前缀，防不同层的"种子#标识"撞名 |
| `装回迷雾记忆()` | **会话缓存（视野记忆）∪ 存档里的永久记忆** —— 两条来源都读，三层共用同一入口，不会出现"某一层忘了读档" |

`刷新视野()` 里：**真的多看了格子才落盘**（站着不动跨过 6:00/18:00 也会刷视野，那时没必要重写位图）。
写的是内存里的 `玩家档案`，PlayerPrefs 只在玩家存档时才落盘 —— 所以每步写一次也不心疼。

## 三、顺手修掉的一个真 bug：敌人被画在"记忆层"里

可见性规则原来在三个面板里**各写了一遍**，而且**已经漂了**：

| 层 | 原写法 | 结果 |
|---|---|---|
| 房间 | `else if (类型 == 敌人) 显示 = 亮;` | 敌人只在全亮里画 ✅ |
| 区域 | `else 显示 = 亮 \|\| 档 == 暗记忆;` ← **敌人落进 else** | **敌人在记忆层里也被画** ⚠ |
| 大世界 | 同上 | 同上 ⚠ |

现在每次回安全屋都清雾，这个不一致还不明显；**一旦雾改永久，它就会让街区退化成"纯绕路题"、再没有伏击**
（你一眼就能看见全城/全街区的敌人）。

修法：把规则抽成 **`Domain/网格/网格可见性.cs` 一份**（放 Domain 而不是 UI：它是"档"的语义，不是"颜色"，
而且放这儿能被离线断言当表格钉住），三个面板都改成调它。修正后的表：

| 实体 | 亮 | 暗记忆 | 暗中轮廓 | 全黑 |
|---|---|---|---|---|
| 玩家 | ✓ | ✓ | ✓ | ✓ |
| **敌人** | ✓ | ✗ | ✗ | ✗ |
| 墙 / 门 / 楼梯 / 建筑 / 区域 / 临时建筑 / 界外 | ✓ | ✓ | ✓ | ✗ |
| 容器 / 尸体 / 障碍 | ✓ | ✓ | ✗ | ✗ |

### 连带的第二个地雷：`是玩家` 是按阵营判的

```csharp
public enum 网格阵营 { 玩家, 敌人, 中立 }   // ← 第一个成员就是"玩家"
public bool 是玩家 => 阵营 == 网格阵营.玩家;  // ← 阵营缺省值 = 玩家
```

也就是说"**忘了写阵营**"的实体（容器/障碍/敌人…）会被当成玩家：`网格数据.玩家()` 会返回它、
`约束摆放` 会跳过它、三个面板会把它的点击关掉。现在全仓库恰好每处都写了阵营，所以没炸 ——
但那是**走运**，不是设计。（写可见性断言时就是这么被咬出来的：测试实体没写阵营，整张表全错。）

改成按类型判：`public bool 是玩家 => 类型 == 网格实体类型.玩家;`（另加 `是敌人`），
行为在现有代码里逐处等价，但再也不看运气。

## 四、★ 关于 ③：夜晚"压暗地形记忆"和"抹掉记忆"有什么区别

**现状（抹掉）**：`有记忆(时段) => 时段 == 白天`（`视野规则.cs:77`）；`档()` 的夜晚分支是
`在弱视野圈 ? 暗中轮廓 : 全黑` —— **完全不看 `已探索`**。

所以夜晚在屏幕上：中心 3×3 全亮 → 外面**一格厚**的一圈（5×5 减 3×3）看得见墙/楼轮廓 → **其余全黑，
包括你白天刚走完整条街**。同一趟出行里，18:00 一过，地图整片变黑。

| | 抹掉（现状） | 压暗（建议） |
|---|---|---|
| 夜里能不能看出"这边我去过" | **完全看不出** —— 去过 50 次和没去过一样 | 看得出（极暗轮廓） |
| 夜里能不能看见墙/楼在哪 | 只在弱视野 5×5 圈内；圈外全黑 | **所有去过的地方都留轮廓** |
| 夜里能不能看见敌人/容器 | 看不见 | **同样看不见** ← 紧张感完全不变 |
| 夜里能不能找路 | 只能靠记忆试错；100×100 上等于瞎走 | 能靠地形轮廓走 —— 但看不到危险 |
| 永久记忆有没有意义 | 没有：一天里有一半时间被抹掉 | 有：白天夜晚都认得路 |

**结论：这两个选项在"危险"这一维上一模一样（都看不见敌人和容器），差别只在"认不认得路"。**
"晚上看不清危险"是紧张感；"晚上连路都不认得"是挫败感 —— 后者换不来任何决策，只让你原地打转。

**而且它是 ① 的前提**：雾改永久之后，如果夜晚照旧抹掉记忆，就会出现
"你花一整天摸清了全城，18:00 一到地图又全黑" —— 那"永久记忆"就只值半天。

### 两种改法（都还没做，等你选）

**3a 最小改法（推荐，两行）**：夜晚让"去过的地方"也用 `暗中轮廓`（和弱视野圈同一级）：

```csharp
if (当前时段 == 时段.夜晚)
{
    if (规则.在弱视野圈(列, 行, 玩家列, 玩家行, 当前世界.视野边长 / 2)) return 视野档.暗中轮廓;
    return 已探索过(列, 行) ? 视野档.暗中轮廓 : 视野档.全黑;   // ← 只多这一行
}
```

- **不新增档、不新增参数**；`暗中轮廓` 本来就只画墙/楼，所以**敌人和容器照样看不见** ——
  与现有设计意图（`房间网格面板` 的注释："夜晚弱视野里看不见要翻的东西"）**完全一致**。
- 代价：夜里"去过的地方"亮度和弱视野圈一样，可能显得偏亮 → 试玩觉得太亮再上 3b。

**3b 更暗一级**：新增 `夜暗记忆` 档 + `视野.json` 一个"夜晚记忆压暗"参数，让记忆比弱视野圈更暗。
多一个档就要三个面板 + 迷雾层都认它，改动大一档 —— **等 3a 手感不够再说**。

## 六、验证（离线）

`Tools/大世界验证` 新增「迷雾规则自检」一段（**不跑种子，验的是纯规则**）：

| 断言 | 为什么 |
|---|---|
| 10 类实体 × 4 档 的可见性表逐格核对 | 三层共用一份规则，不能漂 |
| ★ **敌人在 `暗记忆` / `暗中轮廓` 里不许被画出来** | 这条原来**真的是错的**（大世界/区域），单独再喊一次 |
| 玩家在**任何**档下都画 | 令牌被藏起来 = 玩家消失 |
| 位图往返：大世界 100×100 / 区域 32×22 / 房间 16×10 三种尺寸，随机集合 + **四角 + 最后一格** | 位图最容易在边界差一位，而试玩发现不了 |
| 界外格码被丢掉 | 不该有，但不能因此错位 |
| 坏 Base64 / `null` → 空集，不抛异常 | 坏档不该让游戏进不去 |

  房间 16×10：54 格 → 位图 28 字符（往返一致）
