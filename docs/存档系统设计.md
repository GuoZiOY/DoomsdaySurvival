| 项 | 结论 |
|---|---|

## 1. 结论先行：`缺少存档系统` 的真身是三个静默 bug

存档链路的 bug 有一个共同特征 —— **不报错、不崩溃、只在玩家身上发生**。这也是它能在
"数据校验很硬、生成层有 5 个验证器"的项目里活到现在的原因。

### 1.1 🔴 读档即死（最严重，本刀的核心）

`世界时间管理器.上次结算分钟`（整点结算基准）是**纯运行期字段、初值 0**，而 `驱动.Update` 每帧无条件
`推进()`，`推进()` 里是：

```csharp
// 旧代码（世界时间管理器.cs:56-63）
while ((int)(玩家.游戏分钟数 / 60f) > (int)(上次结算分钟 / 60f))
{ 上次结算分钟 += 60f; 结算时间段(60, true); }
```

`同步整点基准()` 的调用方只有 制作面板 / 快速测试 / 睡觉 / 战斗推进 —— **读档路径一个都没有**。
于是读一张第 5 天的档（游戏分钟数 = 7200）而基准还是 0：

* 同一帧里补算 **120 次** `结算时间段(60, true)`；
* 饱食/水分归零（每次 -2）→ 再按 `饱食≤0 扣 1/小时 + 水分≤0 扣 2/小时` 扣血 → **生命归零**；
* `腐坏结算(60)` 跑 120 次 → **仓库与随身食物全部腐坏**。

**这不是"可能"，是必然。** 顺带：`上次天 = -1` 让 `检查跨天()` 在读档首帧必触发 →
**存档里的天气被 `Random.Range` 重掷掉**，并消耗掉收音机的 `预知天气`。

修复三件套：
1. 载荷新增 `存档数据.整点基准`（**本刀最核心的一个字段**）；
2. `世界时间管理器.读档后对齐(存档基准分钟)`：基准取存档值（保相位），天取**当前天**（不重掷天气）；
3. `PlayerService.读档/新游戏` → `对齐世界时间(...)`；`推进()` 里再加一道 `整点结算.需要重对齐` 的**自愈兜底**
   （某个入口将来再忘一次时，出声 + 自愈，而不是静默变成读档即死）。

### 1.2 🔴 `天赋冷却` 从来没随过档

`玩家档案.天赋冷却` 原文是 `Dictionary<string, float>`，注释还写着"随档保存" ——
**而 JsonUtility 不支持 Dictionary**（同一个文件里 `迷雾记忆` 上面就写着这条）。
它每次存档都被静默丢掉 → 读档后 `钢铁意志`（冷却 10 游戏天）/ `医者仁心`（5 游戏天）的冷却清零 →
**存档-读档就能反复触发同一张免死牌**。

修法：换成 `List<天赋冷却条>` + `玩家档案.天赋冷却就绪/记天赋冷却`（纯数据，不依赖解析器）。

### 1.3 🔴 安全屋"已拆墙"从来没进过档

`安全屋管理器.拆除墙()` 是**就地改写** `安全屋户型.格所属块 / 格可用`，而档案里只存了 `户型种子`。
读档 → 户型按种子重建 → **墙全部复活**；而 `玩家档案.家具` 是进档的 →
出现"家具落在已恢复的墙格里"（摆不下 / 卡住 / 拆不掉）这种坏档。

修法：档案新增 `已拆墙`（`"{列},{行}"`，按拆除顺序），户型生成后 `重放拆墙()`（幂等，重放不写档不发日志）。

### 1.4 🟡 另外三处（顺带修在同一刀里）

| 缺陷 | 症状 | 修法 |
|---|---|---|
| **未开局时间在走** | `驱动.Update` 无条件推进 → 在标题界面干坐 10 现实分钟 = 世上过去 300 游戏分钟，还会把天气掷掉 | `驱动` 加"未开局（`档案.当前节点` 为空）不推进"守卫 |
| **新游戏/读档不清战局** | `搜索服务.已生成/已搜索/尸体定义/尸体序号` 只挂在"回安全屋"事件上 → 同进程内跨局残留（"新游戏里翻过的柜子是空的""上一局打死的尸体还躺在街上"） | `格子探索服务.作废本趟战局()`（public 口子）+ `PlayerService.作废上一局世界态()`（三层 `离开()` + `作废本趟战局()`） |
| **战斗中禁存档只在 UI 层** | `侧边栏面板` 只是隐藏了按钮，代码层没有守卫 | `侧边栏面板.存档()` 加运行期守卫（按钮显隐是第二层） |
| **版本号读了从不检查** | JsonUtility 对"同键但结构变了"的档**不抛异常**（未知字段忽略、缺失补默认）→ 坏档以"关键值是 0"静默进游戏（`0` 会让派生结果退化） | `存档版本.检查(版本)`：比本作新 → **明确拒收**并给玩家可读的原因（进 `存档摘要.损坏原因`，UI 看得见） |

## 2. v4 存档的覆盖度（勘察结论）

`SaveService`（v4）= **一个 PlayerPrefs 键 `last87days_save_v4` + 一份 `玩家档案` JSON**，覆盖式、单槽。

| 状态 | v4 是否进档 | 说明 |
|---|---|---|
| 角色 / 五维 / 生命 / 伤病 / 技能 / 任务 | ✅ | 在 `玩家档案` 里 |
| 背包 / 装备 / 仓库 / 嵌套容器 / 家具 | ✅ | 同上（`物品堆叠` 递归） |
| 游戏分钟数 / 天气 / 预知天气 | ✅ | 同上 |
| `世界种子` / `户型种子` | ✅ | 世界**结构**是种子的纯函数，所以结构"不用存" |
| 大世界 / 区域 迷雾（永久记忆） | ✅ | `迷雾记忆` = `string[]` 位图 |
| **整点结算基准 / 跨天标记** | ❌ | **见 §1.1 —— 这才是"读档即死"** |
| **天赋冷却** | ❌ | **见 §1.2（JsonUtility 存不下 Dictionary）** |
| **安全屋 已拆墙** | ❌ | **见 §1.3** |
| 玩家在哪一层 / 哪一格 | ❌ | 文档承认（`玩家档案.cs` 注释"那套等大世界存档那一刀再落"） |
| 敌人位置 / 敌人 AI 态 / 门锁 / 柜子进度 / 尸体 | ❌ | 一趟出行的临时态，口径是"回安全屋重置" |
| 战斗中状态 | ❌ | 设计上就存不了 → 因此战斗中禁存档 |
| 多槽位 / 磁盘备份 / 存档 UI | ❌ | 只有一个键、一个"保存"按钮、一个"继续" |

**结论**：v4 的覆盖度对"结构由种子重建"这个设计是**自洽**的；它缺的不是"更多字段"，
而是 §1 那三个静默 bug，以及"一个存档游戏该有的外形"（槽位 / 文件 / 面板 / 版本 / 备份）。

## 3. 设计

### 3.1 分工（这是"离线覆盖为零"的解药）

```
Domain/存档/存档模型.cs     纯 C#：存档规格 / 存档头 / 存档数据 / 存档摘要 / 版本检查 / 迁移链 / 档案指纹
Domain/时间/整点结算.cs     纯 C#：整点结算次数 + 自愈判据（世界时间管理器.推进() 用的就是这一份）
Services/存档/存档文件.cs   Unity IO：磁盘路径 / 原子写 / .bak / 唯一允许出现 persistentDataPath 的地方
Services/存档/SaveService.cs 组装载荷 → 落盘；读文本 → 校验 → 迁移；列槽位摘要
Services/存档/自动存档器.cs  关键点自动存 → **只写自动槽**
UI/浮层/存档面板.cs         槽位列表 + 保存 / 读取 / 删除（二次确认）
```

判据：**能离线测的那一半必须搬进没有 UnityEngine 的那一半**。
`Tools/存档验证` 通过 `<Compile Include>` 直接链接 `存档模型.cs` / `整点结算.cs` / `玩家档案.cs` ——
验的就是游戏跑的那份源码，不是副本。

### 3.2 载荷（v5）

```csharp
[Serializable] class 存档数据 {
    存档头 头;          // 版本 / 保存时间 / 角色名 / 职业 / 等级 / 游戏天数 / 位置 / 是否自动
    玩家档案 玩家;       // v4 那一份，原样
    float 整点基准;      // ★ 刀64 的核心字段（见 §1.1）
}
```

* **跨天标记故意不进档**：它完全可由 `玩家.游戏分钟数` 推出，多存一份只会多一个"两份数据不一致"的机会。
* `存档头.位置` 现在恒为 `"安全屋"` —— 真实位置是**刀65**的事；留字段是为了让面板/摘要不用跟着改第二遍。
* **版本探测单列一个 `存档探测` 类型**：`存档数据.头` 带字段初始化器（`= new 存档头()`），
  于是把 **v4 的 JSON** 直接读成 `存档数据` 时 `头` 不为 null，会被误判成 v5 而跳过迁移。
  `存档探测` 两个字段都不写初始化器 → v4 读出来 `头 == null`、`版本` 是根上那个 4。

### 3.3 文件与槽位

| 项 | 决定 | 为什么 |
|---|---|---|
| 位置 | `Application.persistentDataPath/存档/槽N.json` | 与游戏资源目录分开 → 重装游戏不碰玩家的档；文本 JSON 可直接打开看 |
| 槽位 | `槽0.json` 自动 + `槽1..3.json` 手动 | 自动档**绝不覆盖**手动档（v4 是同一个键，自动存档毁了手动档就没救） |
| 原子写 | 写 `.tmp` → `File.Replace` → 旧文件成 `.bak` | 最坏情况是"这次没存上"，而不是"档变成半截 JSON" |
| 删除 | 删正式文件 + `.tmp`，**`.bak` 故意留下** | 玩家后悔时还能手动改回来 |
| v4 迁移 | 装配期一次性：旧键存在 **且** 槽1 无文件 → 搬进槽1 | **不覆盖**玩家已有的新档；**迁移后不删旧键**（兜底） |
| 路径唯一出口 | 只有 `存档文件.cs` 能出现 `persistentDataPath` | 路径散开就会写出两个互不相认的存档目录（门禁段[4]守着） |

### 3.4 存档面板为什么是**运行期代码搭**的

本作其余面板都是"全静态场景搭建 + Inspector 拖引用"。这个面板是刀64 新增的，而**代码改动没法替 Unity
在场景里建物体、拖引用** —— 手搭方案会留下"面板在代码里存在、场景里不存在"的半成品（按钮永远打不开）。
所以自建一套最小 uGUI 层级：不改场景、不依赖任何 `SerializeField`，挂上就能用。
代价：风格与手搭面板不完全一致。将来若要并进 `面板管理器` 的静态路由，只需保留 `存档面板.打开()` 这个入口。

## 4. 验证（三道关，别互相替代）

| 关 | 在哪 | 验什么 |
|---|---|---|
| **行为**（离线） | `Tools/存档验证`（net10） | 版本真值表 · 迁移幂等 · 槽位规格 · **整点结算**（含"基准 0 + 第 5 天 = 120 次"这条把 bug 变成断言的用例）· **玩家档案 每一个标量字段都被指纹覆盖**（反射自动扫） |
| **形状**（源级） | `Tools/存档接线核对.ps1` | 载荷字段不许是 Dictionary/HashSet/元组/裸委托 · 读档必须对齐整点基准 · 未开局冻结 · `persistentDataPath` 单一出口 · SaveService 无死 API · 自动槽独立 · 面板入口唯一 · 拆墙进档 |
| **真 JsonUtility** | 游戏内 快速测试面板 →「存档」→ **★ 存档往返自检** | 真 `SaveService` + 真 `JsonUtility` + 真原子写盘：存 → 读 → 比指纹（内存 + 磁盘两段），不一致时打印**第一个不同的字符位置** |

### 4.1 本刀验证过程中被抓出来的东西（记下来，因为它们证明验证有效）

1. **`整点结算.单次上限` 一开始写成 `24+2 = 26`** —— 被"基准 0 + 第 5 天 = 120 次"这条断言当场抓出来。
   26 会把 120 截成 26，**等于把"读档即死"这件事藏起来**。改成 `365*24`（防呆上限，不是语义上限），
   并补了一条"上限必须远大于任何合法补算"的断言。
2. **`存档指纹` 漏了 `仓库列` / `仓库行`** —— 被"标量字段全覆盖"（反射 + 突变）断言抓出来。
   这正是 `天赋冷却` 那类退化的自动克星：**给 `玩家档案` 加字段却忘了进指纹**。
3. **`SaveService.最近手动槽()` 是死 API** —— 被门禁段[5]抓出来（改用 `private`，对外只给 `最近可读槽()`）。

### 4.2 负向自检（门禁必须会失败）

一次注入三个真缺陷，确认门禁全部报出，然后逐个还原、确认重新通过：

| 注入 | 预期报错 | 实测 |
|---|---|---|
| `玩家档案` 加一个 `Dictionary<string,float>` 字段 | 段[1] 载荷类型 | ✅ 报出（并指出字段名与类型） |
| `PlayerService.读档` 把 `对齐世界时间(存档数据.整点基准)` 换成 `对齐世界时间(0f)` | 段[2] 读档对齐 | ✅ 报出 |
| `自动存档器` 写死手动槽号 `1` | 段[6] 自动槽 | ✅ 报出 2 处 |

## 5. 与刀65 的分界（位置 + 整趟战局）

本刀**不做** C2，理由与已探明的事实（刀65 的输入）：

| 事实 | 出处 | 对刀65 的含义 |
|---|---|---|
| 四层生成器**零无种子随机**，实体标识是"模板标识 # 局部序号"、**无成员计数器** | `大世界生成器` / `区域生成器` / `建筑生成器` / `房间生成器` | 结构可以只存增量、按**稳定标识**回填 |
| **柜子内容来自无种子 `System.Random`** | `搜索服务.cs:14` | ⚠ 内容**不可复现** → 必须真快照 |
| 一次性临时建筑的内部用 `UnityEngine.Random` 播种、标识依赖 `搜索次数` | `大世界探索服务.cs:189/253` | ⚠ 同样不可复现 |
| **三层世界的敌人同时在跑**（进楼/进区域时上层 `当前世界` 并不清空） | `世界时间管理器.cs:53-55` | 要存"所有活着的层"，不只是当前层 |
| `网格实体.容器定义` 是指向 DataService 模板的**共享引用** | `房间生成器.cs:166` | 快照前必须置空、读后按 `定义标识` 回填，否则整张搜索表被复制进存档 |
| `敌人AI态` 缺 `[Serializable]`，实例表是 `Dictionary<网格实体, …>` | `大世界敌人AI.cs:45`、`格子探索服务.cs:649` | 要补 attribute + 拍平成"标识 → 态"的数组 |

## 6. 已知边界（诚实清单）

* **本刀不做位置/战局** → 读档仍落在**营地门口格**（`打开默认世界()` 用 `世界种子` 重建同一座废城）。
  所以"退出即丢整趟出行"这件事**本刀还没解决**，它是刀65。
* **本刀不做存档面板的场景化**（运行期代码搭，见 §3.4）。
* **不验数值手感**：`整点基准` 只保证"不重复结算"，不保证"生存消耗速率合不合口味"。
* **`.bak` 只保留一份**：连续两次覆盖会覆盖掉再上一份。真正的"多版本回滚"要靠手动多槽。
* **槽位列表把整份文件读进来**（JsonUtility 没有"只解析一部分"）。文件小的时候无所谓；
  刀65 战局快照进档后如果单档涨到 MB 级，需要把 `存档头` 拆成独立的 `.head.json`（届时再看实测）。
* **`位置` 字段恒为 "安全屋"**（刀65 才写真值）。
* **`SaveService.往返自检()` 不验版本迁移语义**（那是离线验证器的事），也不验数值。
* **主菜单「继续」现在打开存档面板而不是直接读最近档** —— 玩家多一次点击，换"看得见有哪些档"。
