# 设计-家具与网格架构讨论

> 版本：v35（`705d2d2`）｜ 主题：新家具体系（冰箱先行）+ 网格面板继承链架构
> 日期：2026-09-01 ｜ 类型：头脑风暴 / 设计讨论记录（含 用户想法、提问、异议 与 解答、设计、决策）

***

## 一、背景与目标

### 1.1 现状

安全屋家具 8 种：床 / 工作台 / 储物箱 / 收音机 / 灶台 / 门 / 厕所 / 医疗站。
生存需求覆盖：休息（床）、制作（工作台）、存储（储物箱）、情报（收音机）、烹饪+取暖（灶台）、防御（门）、卫生（厕所）、医疗（医疗站）。

### 1.2 目标

以"冰箱"为第一个落地样例，建立一套**可容纳多样化家具**的通用架构，覆盖：

- 纯存储家具（冰箱：限定内容 + 延长保质期）

- 特殊网格家具（种植箱：作物网格；制作面板改造：输入/输出网格）

## 二、设计讨论记录（按主题）

### 主题 1：家具缺口分析（头脑风暴）

**我的分析**：按末日生存逻辑给家具缺口分级——

- **P0 生存刚需**：水系统（水箱/雨水收集/净化）、食物生产（种植/鸡笼/陷阱）、装备维修（工具架/维修台）

- **P1 防御纵深**：封窗加固、陷阱、瞭望预警（配合夜间入侵事件）

- **P2 成长社区**：书架研究、电力照明、幸存者工作位

**用户决策**：逐条深入讨论；聚焦 水系统 / 食物生产 / 装备维修 三个 P0 方向。

### 主题 3：用户新想法——"家具打开 = 网格面板"

**用户想法**：打开水箱、雨水收集器、种植箱时，像打开网格面板那样，弹出一个网格面板来存储/显示内容。

**我的评估（赞成）**：

1. 统一交互心智：所有可操作家具 = 打开一个面板
2. 零新交互代码：直接复用 网格面板基类 / 容器服务 / 容器面板
3. 塔科夫世界观一致：水/种子/作物都是"物品进网格"
4. 未来所有家具走同一模式（冰箱/工具架/弹药架…）

**关键点（必须解决）**：储物箱 = 全局共享仓库，而新家具必须**每实例独立网格**（水箱A≠水箱B）。
好消息：家具实例本就是 `物品堆叠`，`容器服务.打开(堆叠)` 已支持对任意物品堆叠开网格视图。

**决策**：

| 分叉      | 用户决策                      |
| ------- | ------------------------- |
| 新家具存储方式 | ✅ 每实例独立网格                 |
| 种植箱生长   | ✅ 物品替换（时间推进时 种子→幼苗→成熟 替换） |

### 主题 4：冰箱设计与保质期系统

**冰箱定义（用户口述）**：另类的"仓库"，只能存放 食物 或 材料·食物原料，并**延长保质期**。

**现状确认**：项目中**没有保质期/腐坏机制**（需新增）；容器面板 已是通用浮动容器面板（任意物品堆叠→网格视图），复用路径清晰。

**设计定稿**：

```
标识 冰箱 | 功能类型 仓库 | 占格 2×2 | 最大等级 3
建造材料  铁皮2 + 金属零件2 + 管道胶带1
升级1     铁皮2 + 金属零件2 + 电线1
升级2     铁皮3 + 金属零件2 + 硅胶管1
容器规格  是容器 | 3×3 → 4×4 → 5×5（随等级）
允许放入  饮食 或 材料·食物原料（容器允许类型 扩展 多类型+种类过滤）
效果      保质期延长倍率 [3, 5, 8]（随等级）
```

**保质期机制（新增）**：

- `物品数据.保质期`（游戏小时，0 = 永不变质）→ 生肉/蔬菜/鸡蛋/土豆/面包/牛奶/果汁等易腐品配置

- `物品堆叠.新鲜分钟`：实例剩余保质期，获得时初始化为 保质期×60

- 时间推进时（世界时间管理器.结算时间段）遍历背包/仓库/容器/冰箱内物品，按 常温速率 扣减；冰箱内按倍率减速

- 新鲜分钟 ≤ 0 → 变质

**决策**：

| 分叉      | 用户决策                         |
| ------- | ---------------------------- |
| 变质表现    | ✅ 变"腐坏食物"（可丢弃，价值低，后续可做堆肥/分解） |
| 冰箱保质期倍率 | ✅ 等级递增 3 / 5 / 8             |

### 主题 5：物品转移方案（用户异议）

**用户异议**："我们没有考虑到如何转移物品？"

**约束确认**：面板管理器是**单面板系统**（安全屋面板 与 背包面板 互斥，一次只显示一个）；容器面板 是 Canvas 顶层浮动面板（可与任何面板共存）。

**方案 A · 持有面板右区替换**：右键冰箱 → 切到持有面板，右区 3 位仓库换成 冰箱网格（1 装备 + 2 穿戴 + 冰箱 同屏）。

- 用户进一步异议：这样**家具A ↔ 家具B 互转**必须经 背包(1)+穿戴(2) 中转，两步繁琐，背包成唯一枢纽。

**方案 B · 浮动多容器面板**（Canvas 顶层，可多开）：

- 每个家具打开 = 一个浮动面板（与弹药箱打开完全一致）

- 家具A、B 面板同时开 → 直接互相拖拽（事件下方面板 已支持最上层容器判定）

- 背包↔冰箱：按 F1 切到持有面板，浮动面板仍在上层，同屏拖拽

- 新代码几乎为零（容器面板.创建 现成）

- 代价：手动关面板；多面板叠放靠"点谁置顶"

**结论**：倾向 方案 B（更贴合现有容器交互、解决家具间互转、改动最小）。

### 主题 6：家具面板框架（用户异议与修正）

**用户异议**：方案 B 不能全靠动态容器面板——有些家具有**额外信息文本、功能按钮**（净水器的"净化"、种植箱的生长进度、收集器的水量），要手动搭建其家具面板。

**设计：家具面板组件（可扩展）**

```
家具面板（组件，挂手动搭建的面板根）
├── 标题（家具名）
├── 信息区（可选：净水器温度/种植箱生长进度/收集器水量）
├── 按钮区（可选：净化/收获…）
└── 网格区（物品网格面板——共用，跨面板拖拽现成）
```

- 打开方式：右键家具"打开" → 按家具标识加载面板 → 注入家具实例（数据源 = 容器服务.打开）→ 浮动显示

- 加载策略：`Resources.Load($"Prefab/家具面板_{标识}")` → 找不到回退 `Prefab/家具面板`

- 动态兜底：预制体缺失时代码动态生成 标题+网格+关闭 基础 UI（冰箱可立即跑通，不阻塞）

### 主题 7：网格面板继承链分析（第一轮）

**用户要求**：重新详细分析 网格面板基类 及其子类。

**现状：两条完全不同的线**

```
[网格语义继承线]（继承 面板基类）
网格面板基类 (abstract：渲染/拖拽/交互骨架 + 语义钩子)
├── 物品网格面板 (sealed partial：背包/仓库/容器/穿戴/搜索)
└── 家具网格面板 (sealed：安全屋房间网格——摆放/移动/升级家具)

[宿主面板线]（MonoBehaviour，不继承 面板基类；内含 物品网格面板）
容器面板 / 搜索面板 / 仓库面板 / 装具区
```

**第一轮识别 3 个歧义**：

1. **命名歧义**：`家具网格面板`（房间网格） vs 未来"家具面板"（冰箱容器）名字几乎一样、职责天差地别
2. **继承 vs 组合**：新面板易被误判为继承 网格面板基类；正确应为 宿主（组合 物品网格面板）
3. **与 容器面板 高度重复**：浮动宿主逻辑（标题/关闭/拖拽/屏幕/防重/网格注入）90% 相同

**建议（第一轮）**：抽取 `浮动容器面板基类`，容器面板 + 家具容器面板 共享。

### 主题 8：特殊网格家具（用户追问，扩展讨论）

**用户追问**：

- 种植箱使用的网格会比较特殊（作物网格）

- 制作面板想改造成"输入面板 / 输出面板"：材料放输入面板 → 点制作 → 输入材料按需消耗 → 输出面板出现成品

**核心认识：所有家具的"网格"底层都是物品堆叠网格**，差异在"语义/限制/交互"：

| 网格    | 实体           | 差异点                | 能否用现有钩子表达                     |
| ----- | ------------ | ------------------ | ----------------------------- |
| 冰箱    | 物品           | 允许放入限制（饮食\|食物原料）   | ✅ 目标允许放入                      |
| 种植箱   | 种子/幼苗/成熟（物品） | 只放种子 + 时间替换 + 右键收获 | ✅ 目标允许放入 + 生长逻辑 + 右键实体        |
| 制作·输入 | 材料（物品）       | 只放配方材料、可拖入、制作扣减    | ✅ 目标允许放入                      |
| 制作·输出 | 产物（物品）       | 只读（禁拖入/禁拖出）        | ✅ 允许开始拖拽=false + 目标允许放入=false |

**结论**：不需要新"网格框架"。`网格面板基类` 的钩子设计本就为"子类表达不同语义"而生。唯一缺口：**物品网格面板 是 sealed，需开放继承**，特殊语义用子类（种植箱/制作输入/制作输出网格面板）。

**三层架构（定稿方向）**：

```
第1层 网格框架    网格面板基类 (abstract)——渲染/拖拽/交互骨架
第2层 语义子类    物品网格面板（开放继承）
                   ├── 种植箱 / 制作输入 / 制作输出……
                   └── 家具网格面板（房间摆放）
第3层 宿主外壳    浮动容器面板基类 (abstract)——标题/关闭/拖拽/防重 + 托管第2层网格
                   ├── 容器面板（弹药箱）——托管 物品网格面板
                   ├── 家具容器面板（冰箱/水箱）——托管 物品网格面板
                   └── 制作面板（改造）——托管 输入网格 + 输出网格 + 制作按钮
```

***

### 主题 9：网格面板继承链分析（第二轮，深入）

**用户要求**：重新详细分析（仍有歧义和异议）。

**深入剖析 4 个深层歧义**：

**歧义1 · 继承身份错位：`网格面板基类`** **是网格组件，却继承"可切换面板"身份**

- `面板基类` 的面板身份（显示/隐藏/回退/取消文本）是给 面板管理器 切换用的

- `网格面板基类` override 的只是 `刷新(object)`（选中=null+请求刷新）+ 回退/取消文本 + 借用静态工具

- 证据：物品网格面板 嵌在 容器面板（宿主 MonoBehaviour）里，却带着整套"可切换面板"协议，从未被当作可切换面板

- **异议**：它继承"可切换面板"身份，只为借用静态工具和刷新钩子，身份错位、形同虚设

**歧义2 · 基类语义混合：物品菜单与家具菜单虚方法全塞进基类**

- 基类同时声明 `菜单使用/装备/打开/丢弃/打开拆分/拆分/查看详情`（物品）+ `家具升级/家具拆除`（家具）

- 两个子类各 override 一半，另一半是空壳

- **异议**：单一职责被破坏，基类膨胀；未来加 种植箱（收获）/制作输出（查看）还要继续塞方法。这些应属于**子类各自的公开方法**，而非基类统一虚方法

**歧义3 · 数据模型双语义：`物品堆叠`** **同时是"物品"和"家具"**

- 背包里是物品；家具网格面板里是家具实例（标识含等级后缀、数量恒1、列/行=房间位置）；冰箱容器内容也是物品堆叠

- 一个类三层复用，靠"属于哪个面板"区分语义

- **评价**：一致性很好（家具=物品堆叠 让 容器服务/网格算法 全复用），保留但需明确

**歧义4 · 宿主与网格的"面板身份"重叠**

- 容器面板（宿主）有 面板根/关闭/拖拽移动/防重

- 内部 物品网格面板（继承面板基类）又有 显示/隐藏/回退/取消文本

- 同一棵 UI 树上两套"面板身份"，网格的面板基类身份形同虚设

- **异议**：这是"继承冗余"的活证据

**修正后的继承链（建议）**：

```
[网格组件线] —— 去掉"可切换面板"身份，只做网格
网格面板基类 (abstract，继承 MonoBehaviour)
├── 物品网格面板（物品语义）→（未来）种植箱/制作输入/制作输出
└── 家具网格面板（房间摆放语义）

[宿主线] —— 面板壳，托管一个网格组件
浮动容器面板基类 (abstract MonoBehaviour)
├── 容器面板（弹药箱）
└── 家具容器面板（冰箱）← 新
```

**具体修正**：

1. 网格面板基类 改继承 MonoBehaviour（去面板身份）；`刷新(object)` → `注入数据(object)`；回退/取消文本 归属宿主
2. 基类只留"网格+交互钩子"，`菜单使用/家具升级` 等语义方法下沉到子类公开方法；右键菜单 改为调用子类语义
3. 宿主线独立：容器面板/家具容器面板 继承 `浮动容器面板基类`，显隐/关闭/防重/标题归宿主，网格注入归内部物品网格面板

**落地影响（待改）**：

- 网格面板基类：改 MonoBehaviour + `注入数据`，移除 菜单\* 虚方法

- 物品网格面板/家具网格面板：不再 override 刷新/回退/取消文本；菜单方法变公开方法

- 右键菜单.cs：`?.菜单使用()` 改为按子类公开方法调用

- 持有面板/安全屋面板/容器面板：驱动从 `刷新(object)` 改 `注入数据(object)`

- 改动面中等（涉及 右键菜单/持有面板/安全屋面板/装具区）

## 三、最终架构结论（三层）

```
第1层 网格框架    网格面板基类（abstract）——渲染/拖拽/交互骨架，不含面板身份
第2层 语义子类    物品网格面板（开放继承）→ 种植箱/制作输入/制作输出；家具网格面板（房间摆放）
第3层 宿主外壳    浮动容器面板基类（abstract）→ 容器面板/家具容器面板/制作面板（托管第2层网格）
```

职责原则：

- 宿主管壳（显隐/关闭/标题/防重），网格管格（渲染/拖拽/交互）

- 网格组件不再伪装成"面板"；物品/家具语义接口不再混在基类
