## 二、文档规矩（防止再膨胀 —— 本轮刚把 5.4 MB 砍到 ~0.3 MB）

1. **只写"现在是什么样"。** "当初怎么一步步改成这样"属于提交信息，不属于文档。
2. **一次性报告不进仓库。** 审计/体检/评估做完，结论压成 `优化实施进度.md` 里的一句话 + 代码注释；报告本身删掉（git 历史里还在）。
3. **分工**：代码注释放**为什么**（读代码的人才会看到）；文档放**是什么**与**口径**（字段约定、数值档位、不变量、拍板结论）。
4. **过时即改。** 改了行为就顺手改对应文档那一段；不允许"文档停在旧版本"——那比没文档更坏，因为它骗人。
5. **单份超过 ~50 KB 就该拆或砍。** 已经发生过一次（`优化实施进度` 曾到 182 KB）。
6. **反直觉的决定要写下来并说明理由**，否则后人会"顺手改回去"。目前有三条属于这类：
   - `玩家档案.当前节点` 同时兼当"是否已开局"标志 → 存档/自动存档/侧边栏都靠它守卫，**不能删**。
   - 迷雾生命期**分层**：大世界/区域随档永久，房间层每次重看（房间记忆键是"每个房间实例"，临时建筑每趟新增 → 无界增长）。**不要统一**。
   - **战斗中不存不读**（用户口径）。战斗态不进存档 → 战局快照也不处理战斗。
