# 区域层：建筑形状与规模设计（方案待拍板）

> 目标：**楼更大**，**形状不限于矩形**（L 型 / U 型 / T 型 / 十字 / 回字 / 凸），更符合现实城区。
> 现状：`网格实体` 用 `列/行/宽/高` 描述一个矩形；`区域生成器` 按地块制把一栋楼摆进一个地块。
> 本文只设计，不动代码 —— 先拍板，再落刀。

---

## 〇、一句话方案

**一栋楼 = 一个实体（包围盒）+ 一张逐格"占地掩码"**；形状用**可读的字符画**写在数据里，
运行时把掩码"贴"进地块，视觉逐格画楼体、只在朝外的边描线。

```jsonc
// 数据怎么写（掩码：'#' = 楼体，'.' = 这块包围盒里的空地/凹口）
{
  "标识": "西街便利店",
  "名称": "便利店（西街店）",
  "占地": [
    "######",
    "######",
    "##..##",     // ← 凹进去一块（现实里：后院/天井/塌了的那半边）
    "##..##",
    "####.."
  ],
  "门": { "边": "下", "偏移": 2 }     // 门开在下边、从左数第 2 格（不写 = 自动挑这条边最宽段的中点）
}
```

为什么不是"拆成若干矩形块"（`块: [{x,y,宽,高}, …]`）：那样一栋 L 型楼会变成 2~3 个实体 ——
名字要挑一个显示、块之间要判"是不是同一栋"（不然内部会画接缝线）、间距/重叠/验证全要按组算。
**掩码单实体**这些麻烦一次都没有，且能表达任意形状。

## 一、运行时表示（Domain 改动最小）

| 改动 | 内容 |
|---|---|
| `网格实体` | 加 `public bool[] 形状掩码;`（**null = 纯矩形**，向后兼容）+ `public int 掩码列;`（掩码宽，用来换算索引） |
| `网格实体.覆盖(列,行)` | 矩形判定之后再查掩码：`在包围盒内 && (掩码==null \|\| 掩码[(行-行0)*掩码列 + (列-列0)])` —— **两行** |
| 其余 | `占位/可通行/格上实体/间距/可达集/连通分量` 全部自动跟着对 —— 它们都走 `覆盖()` |

**单格口径不变**：掩码只影响"哪些格属于这栋楼"，`宽/高` 仍然是包围盒（间距计算用它，够用）。

## 二、规模：比现在大，但**不到 12×7**

现状 4×3 = 12 格。目标区间（**包围盒**上限 9×6，只有"地标楼"才用；常见 6×4~8×5）：

| 档 | 包围盒 | 格数 | 楼体格数（形状不同会少） | 建议用途 |
|---|---|---|---|---|
| 小 | 4×3（现状） | 12 | 12 | 门面房、小仓库、报亭 |
| 中 | 5×4 / 6×4 | 20~24 | 18~24 | 便利店、药店、居民楼一层 |
| **大** | **7×5 / 8×5** | 35~40 | 30~40 | 公寓楼、超市、学校 |
| 特大 | 9×6 | 54 | 45~50 | 地标（商场/医院/工厂），一片区域最多 1 栋 |

**宅基地（地块）与楼的比例**：楼占宅基地 **50%~65%**，剩下是楼前空地/后院/侧巷（走位与将来放"垃圾箱/车"的地方）。
地块尺寸由区域尺寸自动算，示例：

| 区域 | 地块布局 | 每块宅基地 | 楼能长到 |
|---|---|---|---|
| 西区 32×22 | 2×2 | 14×8 | 8×5（40 格） |
| 西区 32×22 | 3×2 | 8×8 | 5×5（25 格） |
| 东区 28×20 | 2×2 | 12×7 | 7×5（35 格） |

（`地块列数/行数` 是 `区域生成器` 的常量，改一个数就能换"4 栋大楼 / 6 栋中楼"的手感。）

## 三、视觉：逐格画楼体 + 只在朝外的边描线

现在的画法是"一张 `建筑(宽,高)` 贴图拉伸铺满包围盒" —— 非矩形会露出矩形底 ✗。改成：

| 元素 | 画法 |
|---|---|
| 楼体 | **按掩码逐格**摆一块"单格立面"贴图（`区域贴图.楼体格()`，新增：楼层线 + 窗，**不带楼顶压边**） |
| 楼顶 | 只在"上邻格不是本栋楼"的那一行画楼顶压边（或整栋顶部一条亮边） |
| 轮廓 | **只在相邻格不是本栋楼的边描暗边** —— 直接复用房间层那套 `建墙边` 的写法（墙上已经验证过） |
| 名称 | 标在楼的**最大连通块的中心格**（L 型的重心会落在凹口里，所以取最大块） |
| 门 | 保持现状：门口格上画一扇门（现在是楼体子物体，位置算相对包围盒） |

代价：一栋 10×6 的楼 ≈ 60 个 Image（4~6 栋 ≈ 200~350，可接受；房间层整幅地板+雾就上千个了）。

## 四、形状库：**参数化配方**（不是一次性死掩码）

数据里写**配方名 + 尺寸 + 参数**，掩码在加载时生成（确定性 ⇒ 同种子同布局不受影响）；
特殊形状可以退回**手写掩码**。

```jsonc
// 写法 A：配方（推荐 —— 一条配方能出无数个尺寸/朝向变体）
{ "外形": { "形状": "L", "宽": 8, "高": 5, "转角": "左下", "切角宽": 3, "切角高": 2 } }

// 写法 B：手写掩码（一次性的怪形状 / 美术指定）
{ "外形": { "掩码": ["#####", "##...", "##..."] } }
```

### 配方一览（`#` = 楼体，`.` = 凹口/空地）

| 形状 | 参数 | 示意图（8×5 或 7×5） | 现实感 |
|---|---|---|---|
| `矩形` | 宽 高 | `########`×5 | 门面、仓库 |
| `L` | 宽 高 **转角**(左下/右下/左上/右上) 切角宽 切角高 | `######`<br>`######`<br>`###...`<br>`###...`<br>`###...` | 街角楼（最常见） |
| `T` | 宽 高 翼宽 翼边(上/下) | `#######`<br>`#######`<br>`..###..`<br>`..###..` | 临街主楼 + 后翼 |
| `十字` | 宽 高 臂宽 | `...#...`<br>`.#####.`<br>`#######`<br>`.#####.`<br>`...#...` | 商场 / 医院 |
| `U` | 宽 高 **口朝向**(上/下/左/右) 凹口宽 凹口深 | `##...##`<br>`##...##`<br>`##...##`<br>`#######` | 带前院/内院（凹口必须通街） |
| `工字` | 宽 高 腰宽 | `#######`<br>`#######`<br>`..###..`<br>`..###..`<br>`#######` | 双栋连体（前楼+后楼+连廊） |
| `阶梯` | 宽 高 **方向**(上窄/下窄/左窄/右窄) 台阶数 | `..###..`<br>`.#####.`<br>`#######` | 逐层退台的办公楼 |
| `斜角` | 宽 高 切角长 切角位置(单角/双角) | `..####`<br>`.#####`<br>`######` | 街角切角楼 |
| `细长条` | 宽(≤3) 高（或反向） | `###`<br>`###`<br>`###`<br>`###` | 沿街一排门面（宽 2~3、长 6~9） |
| `凹字` | 宽 高 凹口宽 凹口深 | `#######`<br>`##...##`<br>`##...##`<br>`#######` | 围合院落（= 回字去掉一边，**凹口要通街**） |
| ~~`回字`~~ | —— | —— | **默认非法**：内院完全封闭，玩家会以为能进去（要说得通得再加"内院入口"机制） |
| ~~`U`/`[`（三面围合）~~ | —— | —— | **按拍板删掉**：壁厚 1 的 U 形在区域图上更像"一圈围墙"而不是楼，读起来和 `凹` 是一回事（见 §八） |

> 参数里的"转角/朝向/方向/翼边"这些**枚举**，就是为了让同一形状在四个方向都能用 ——
> 一片区域里放两栋 `L` 不同转角，看起来就是两栋不同的楼。

### 尺寸与形状的搭配建议

- `细长条` 只给小尺寸（宽 2~3），别做 8×2 之外的长条；
- `十字 / 工字 / 回字` 需要**至少 7×5**，否则细得不像；
- `L / 斜角` 在 5×4 以上才好看（4×3 的 L 就是缺一个角的小方块）；
- 一片区域里**形状不重复**更好看：4 栋 → `L / 矩形 / T / 工字`；6 栋 → 再加 `U / 阶梯`。

## 五、验证（`Tools/区域验证` 加断言，离线可证）

新增不变量：

1. **掩码是矩形字符画**（所有行等长）、只含 `#`/`.`；
2. **掩码至少一个连通块**；`#` 的格子数 ≥ 一个下限（别出现"1 格楼"）；
3. **入口格**：在掩码内 + 朝外（四邻里至少一个是街道/空地）+ **从区域入口可达**（走得到门口才进得去）；
4. **凹口可达性**：掩码的凹口（`.` 且被 `#` 围住）不允许形成"封闭死角"——
   规则：每个凹口格必须与街道连通，否则报警（回字那种内院直接判非法）；
5. **同栋不重叠**（掩码层面，不只包围盒）+ 楼与楼之间街道宽 ≥ 1（保证连通）；
6. **整片连通分量 = 1**（原有断言，现在按掩码算）；
7. 确定性：同种子两次生成指纹一致。

`区域验证` 的 ASCII 直接就能看出形状（`B` = 楼体、`+` = 门、`.` = 空地），一眼核对。

### 6.1 配方在哪计算

`建筑外形.掩码(外形数据)` 返回 `bool[] + 宽高`（纯函数，零 UnityEngine ⇒ 离线验证器和游戏跑的是同一份）；
`区域生成器` 只做"把掩码贴进宅基地 + 算入口格 + 校验"，**不认识任何具体形状**；
DataService 只校验"参数合法 + 掩码连通 + 凹口通街"。加新形状 = 在 `建筑外形` 里加一个 `case`，其它层一行不用改。

## 七、要你拍板的四件事（按你这轮的修正更新）

| # | 问题 | 我的建议 |
|---|---|---|
| 1 | **尺寸上限** | 常规 **4×3 ~ 8×5**（12~40 格），只有地标楼能到 **9×6**（54 格）。12×7 那种取消 |
| 2 | **第 1 刀先做哪些形状** | 只做 **`矩形` + `L`**（含四朝向），跑通机制；第 2 刀再铺 `T / 十字 / U / 工字 / 阶梯 / 斜角 / 细长条` |
| 3 | **地块数** | 先保持 **2×2**（4 栋、宅基地 14×8，楼能长到 8×5）；试玩后你觉得"楼太少/太空"再换 3×2 |
| 4 | **门的位置** | **自动**（按 `门.边` 找该边最长连续段取中点）+ 允许 `门格: [列,行]` 手写覆盖 |

另：§4 的"回字/全封闭内院"我建议**直接判非法**（玩家会以为能进去）；如果你想要"围合院落"，
得额外做"内院从某条缝通街"的规则 + 门里再套门，那是另一个话题，先不进这一刀。

## 八、落地结论（已实现 —— 按拍板收敛后的最终口径）

> 这一节是"实际做成了什么样"；上面 §二/§四/§七 是当时的**提案**（形状库列了 9 种、尺寸上限 9×6），保留下来看思路，**以本节为准**。

### 8.1 配方库：4 个（`矩形 / L / 凸 / 凹`）

`建筑外形.全部形状` = `矩形 / L / 凸 / 凹`；数据里写错名字会被 `建筑验证` 拦下（报"能写：矩形 / L / 凸 / 凹"），不会静默当矩形。

- **`[`（三面围合 / U）已删**：壁厚 1 的 U 形只有一圈薄墙，在区域图上读起来就是"凹"，留着只是多一个 case 让人纠结；要"围合院落"用 `凹` 就够。
- `T / 十字 / 工字 / 阶梯 / 斜角 / 细长条` 全部**不做**（`建筑外形` 里加一个 `case` 就能回来）。
- `朝向 0/90/180/270` + `左右镜像` 是**通用层**，任何形状都白送；靠它把开口转向街道。
- `凹` 的凹口**必须通街**：`区域验证` 的"可站格连通分量 = 1"就是这条的守门人（凹口朝北会当场炸）。

### 8.2 尺寸：从 6×5 全部放大一档

| 楼 | 形状 | 包围盒 | 楼体格 | 掩码实样（`#` 楼体 / `.` 空地） |
|---|---|---|---|---|
| 便利店（西街店） | `L` | **10×6** | 45 | 前三行满 + 后三行 `#####.....`（缺右下 5×3） |
| 公寓（西区A栋） | `矩形` | **10×6** | 60 | 全满 |
| 临街门面房 | `凸` | **11×6** | 48 | 前三行 `...#####...` + 后三行满 11 |
| 围合住宅楼 | `凹` | **11×7** | 62 | 前四行满 + 后三行 `###.....###`（朝向 180 = 天井朝街） |

**上限由地块决定**：地块 = (内区宽 − 街道) ÷ 地块列数 × (内区高 − 预留底行 − 街道) ÷ 地块行数 → **西区 14×8 / 东区 12×7**（`区域验证` 每颗种子都会打）。
所以能放的最大包围盒是 **12×7**；写更大不会报错，而是被 `区域生成器` **缩到地块大小**（所以 `建筑验证` 在 `宽>12 / 高>7` 时打一条提示）。
楼占宅基地约 55%~65%，剩下的留给楼前空地/侧巷；楼大了街就相对窄了 —— 要更空就改区域尺寸或 `区域生成器.地块列数/行数`。

### 8.3 落在哪些文件

| 位置 | 状态 |
|---|---|
| `Data/建筑外形.cs` | 4 个配方 + `生成 / 画 / 连通 / 顺时针 / 左右翻 / 夹` + `认得出 / 形状清单`；`生成(形, out 宽, out 高)`，朝向 90/270 自动对调宽高 |
| `网格实体.形状掩码 / 掩码列` + `覆盖()` | 占位、可通行、可达集、连通分量、间距、门口格**全部自动跟随形状**（Domain 只改了这两行） |
| `区域生成器` | 只做"掩码贴地块 + 夹进地块 + 选门口格（掩码最靠下那行的最长连续段中点）"，**不认识任何具体形状** |
| `区域网格面板` | 按掩码**逐格**铺楼体 + 只在"邻居不是本栋楼"的边描线；**楼自己不接点击**（图形 raycastTarget = false）→ 点哪一格就落到那一格的交互层：点楼体 = 走到楼边、点**门那一格** = 走到门口（走上去就进楼）、点凹口 = 走进天井；右键那一格 = 楼的菜单（菜单贴着被点的那格弹）。楼不悬停放大 |
| `Tools/区域验证` | 掩码连通 / 门口格在楼体上 / 可站格连通分量 = 1 / 确定性；另有"建筑外形自检"把每个形状画成 ASCII |
| `Tools/建筑验证` | 外形核对：形状名认不认识、掩码连通、朝向是不是 90 的倍数、尺寸有没有超地块 |
