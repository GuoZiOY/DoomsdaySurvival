# 五大区域内容设计（警察局区 / 医院区 / 工厂区 / 居民区 / 商业区）

> 版本：v51 ｜ 前置：大世界网格化（100×100）+ 区域可重复刷 + 街上遭遇 已落地
> 本文是**内容设计**：口径 → 五区定位 → 每区的建筑/房间/容器池/敌人/解锁 → 实施清单
> 数据落点：`区域模板.json` / `建筑模板.json` / `房间模板.json` / `搜索_地图类型.json` / `世界.json`

## 〇、先定几条口径（让五个区"不一样"，而不是换个名字）

1. **每区一个明确的"你来这儿拿什么"** —— 资源定位不重叠，玩家才有"该去哪"的判断。
2. **危险度梯度 1→5**，敌人组跟着强度走（现有敌人 9 种够用：野猫/流浪狗/变异鼠/拾荒者/拾荒者弓手/重装拾荒者/感染者/狂暴感染者/巨型变异体）。
   但 ⚠ **`敌人组` 只能从 `encounters.json` 现成的 9 个组里挑**（写成敌人名是不生效的，`数据引用核对.ps1` 会拦）：

   | 敌人组 | 成员 | 大致强度 |
   |---|---|---|
   | `流浪狗群` | 流浪狗×2 | 1 |
   | `野狗野猫` | 流浪狗×1 + 野猫×2 | 1 |
   | `鼠群` | 变异鼠×4 | 1 |
   | `街头遭遇` | 拾荒者×1 + 拾荒者弓手×1 | 2 |
   | `弓手小队` | 拾荒者弓手×2 + 拾荒者×1 | 3 |
   | `重装护卫` | 重装拾荒者×1 + 拾荒者×1 | 3 |
   | `感染者伏击` | 感染者×2 | 2 |
   | `感染潮` | 感染者×2 + 狂暴感染者×1 | 4 |
   | `变异体Boss` | 巨型变异体×1 + 感染者×2 | 5 |

   再配合 `敌人数量最小/最大` 调实际人数。⚠ 这两个数**不是"几个人"也不是倍率**，而是对
   "组展开后的人头列表"做裁剪：`房间生成器.抽敌人()` 里是
   `要 = 夹(展开人数, 最小, 最大)`（`展开人数` = 组里每个成员按 `数量` 摊平后的人头总数），
   取前 `要` 个；`要` 比展开人数多时才从组里循环补抽。
   所以：`变异体Boss`（展开 3 人）配 `1~1` → 只出 1 只巨型变异体；配 `2~3` → 3 人全上。
   要"更狠"就得往组里加成员（改 `encounters.json`），光调区间只会截断。
3. **深房间上锁** —— 形成"先搜外围、再进核心"的节奏；钥匙投放机制（v49）已经做好，直接写 `门[].锁` 即可。
4. **解锁条件只用 `天数`** —— `情报` 没实现（判校验错误）、`前置区域` 已随"不要通关概念"删掉。
   想让某区"后期才去"，就写 `天数 ≥ N`。以后要做"钥匙/情报解锁"，再加物品与情报系统。
5. **能用现有建筑就不新造** —— 居民区/商业区直接复用现有 4 个建筑模板；
   把新内容（新地图类型 + 新房间 + 新建筑）留给**医院/警察局/工厂**这三个真正新的场所。

### 五区一览

| 区域 | 危险度 | 资源定位 | 建筑 | 要新造内容吗 | 解锁 |
|---|---|---|---|---|---|
| **居民区** | 1 | 基础补给 / 生活用品 / 种子 | 复用 `西区公寓A` ×2、`围合住宅楼` ×2 | ❌ 只加区域模板 | 无 |
| **商业区** | 2 | 食物 / 饮水 / 容器 | 复用 `西街便利店` ×2、`临街门面房` ×2 | ❌ 只加区域模板 | 无 |
| **医院区** | 3 | **医疗品**（抗生素/血浆/手术缝合包） | 新造 `市立医院`（2 层 3 房间） | ✅ 新地图类型`医院` | 天数 ≥ 3 |
| **警察局区** | 4 | **弹药 / 武器图纸 / 情报** | 新造 `城西分局`（2 层 3 房间） | ✅ 新地图类型`警察局` | 天数 ≥ 6 |
| **工厂区** | 5 | **建材 / 能源 / 火药** | 新造 `纺织厂`（2 层 3 房间） | ✅ 新地图类型`工厂` | 天数 ≥ 10 |

> 五区在大世界上的占地形状刻意不同，方便一眼认出来：
> 居民区 `矩形`、商业区 `L`、医院区 `凸`、警察局区 `凹`（天井朝街）、工厂区 `矩形`（最大块）。

## 一、居民区（危险度 1 ｜ 无解锁）

**定位**：最安全的练手区，也是**种子 / 生活用品**的主要来源（配合安全屋种植箱）。

- 区域尺寸：`32×22`（与现有西区同规格），街道障碍 3，棋盘 `街头`
- 建筑：`西区公寓A` ×2 + `围合住宅楼` ×2（4 个地块，正好摆满）
- 敌人：靠**房间模板自带**的敌人组（鼠群 1~2）——区域层暂时没有街上敌人（见 §六 待办）

**为什么这样**：零新内容，纯排列。它的价值是"新存档第一天就能去、风险最低"，
用现有房间模板的 `居民房_*` 池子（玄关/客厅/厨房/杂物间）产出种子与日用品。

## 二、商业区（危险度 2 ｜ 无解锁）

**定位**：**食物与饮水**的主力（便利店/门面房的货架与冰箱），也是容器（背包/弹药箱）的来源。

- 区域尺寸：`32×22`，街道障碍 3，棋盘 `街头`
- 建筑：`西街便利店` ×2 + `临街门面房` ×2
- 敌人：房间模板自带（感染者伏击 1~2）

**为什么这样**：同上，零新内容。与居民区分工：居民区给"能用的东西"，商业区给"能吃的喝的"。

## 五、工厂区（危险度 5 ｜ 天数 ≥ 10）

**定位**：**建材 / 能源 / 火药**。最危险（巨型变异体出没），但只有这儿能批量拿建材、燃料与火药。

### 5.1 建筑：`纺织厂`（2 层）

| 项 | 值 |
|---|---|
| 尺寸 | `16×10` |
| 楼梯边 | `左`（又要跟前面区分开） |
| 外形 | `矩形 12×7`（**全图最大块**，地块上限就是 12×7） |
| 棋盘 | `工厂`（现有棋盘里有 `工厂`，正好用上） |

> ⚠ **楼梯边 不能和首间房的 入口边 同边**。这条现在是 `DataService` 的**校验错误**（v51 刀9）。
> 原因：`建墙()` 会把楼梯那一面墙内缩 1 格用来做楼梯间，而 `开门()` 按整条边摆大门，
> 于是正门正好落进楼梯间的延伸格里，楼梯间围不起来（`建筑验证` 会报"邻居不是墙"）。
> 本楼首间 `工厂_车间` 的 入口边 = `下`，所以 楼梯边 只能取 `上/左/右`，这里取 `左`。

```
楼层 1F：工厂_车间（首间）→ 门[左, 锁: 仓库钥匙] → 工厂_仓库
楼层 2F：工厂_办公室（首间，无门）
```

> ⚠ **内门所在边 不能和 入口边 同边**。同理，门开在入口那一面时排不开（`房间验证` 会报
> "内门 0 扇 ≠ 模板声明 1 扇"）。所以 `工厂_仓库` 的 入口边 取 `上`、内门 取 `右`。

## 七、大世界上的摆位（`世界.json`）

100×100 的城，营地固定在 `(50,50)`。五区按"离营地越远越危险"排：

### 9.1 落数据时踩到的三个"排不出来"

这三个都不是手感问题，是**几何上排不出来**：

1. **`楼梯边` 和首间房 `入口边` 同边** → `建墙()` 把楼梯那面墙内缩 1 格，`开门()` 却按整条边摆大门，
   大门正好落进楼梯间的延伸格里，楼梯间围不起来（`建筑验证`：`楼梯间(8,10) 的邻居 (7,10) 不是墙 —— 没围起来`）。
   原来只报 `校验警告`，会被顺过去 → 改成 `校验错误`。
2. **内门 `边` 和 `入口边` 同边** → 门排不开（`房间验证`：`内门 0 扇 ≠ 模板声明 1 扇`／`有 1 扇门排不开`）。
   `工厂_仓库` 因此把 `入口边` 从 `右` 改成 `上`。
3. ★ **内门 `边` 和 `楼梯边` 同边**（v51 刀15 用户实测报的 bug：「门有概率生成在楼梯那一列上，导致无法交互」）。
   **根源与 1 是同一件事**：`造空房()` 的顺序是「加楼梯间 → 开门」（`房间生成器.cs:222-223`），
   而 `开门()` 取的是 `边格(…, 内缩 0)` —— 在楼梯那一侧，内缩 0 **正好是凸出去的那一行/列**。
   那一侧的外线整个属于楼梯间：**楼梯格 + 它两侧的墙 + 其余填"界外"**。门落在上面三种结局都是坏的：

   | 门的落点 | 后果 |
   |---|---|
   | 楼梯格本身（`位 == 号`） | 带锁的门占格 → **站不上楼梯**（上不了楼）；无锁也变成"一格两个实体" |
   | 楼梯两侧（`位 == 号±1`） | 顶掉楼梯间的**侧墙** → 楼梯间围不住（`建筑验证` ③' 会报"没围起来"） |
   | 那条线上的别处 | 掉进 **`界外`** → 那扇门走不到、也进不去 |

   而且它是**种子相关**的（门位在边上抖一下），所以表现为"有概率" —— 用户的原话就是这个。

   **四层一起修**（缺一层都会再犯）：
   1. **数据**：`临街门面房` 的 `药店_柜台` 内门 `右→上`（楼梯边 = 右）；`纺织厂` 的 `工厂_车间` 内门 `左→右`（楼梯边 = 左）。
      ⚠ 第 2 处**是刀9 自己引入的**：那一刀为了让 `纺织厂` 避开"楼梯边 == 入口边"，把 `楼梯边` 从 `下` 改成 `左`，
      却正好撞上 `工厂_车间` 内门的 `左` —— **修一个冲突时撞出了另一个**（同类冲突要一起看，别只盯一处）。
   2. **生成器**（`房间生成器.开门`）：`边 == 楼梯边` 时**直接不开**并记 `门开不出`（响亮），
      绝不静默产出一张坏图。大门同理。
   3. **静态校验**（`DataService`）：首间房（`i == 0`，每层都有楼梯）的 `入口边`/内门 `边` == `建筑.楼梯边` → **`校验错误`**。
      原来只查了大门，漏了内门 —— 这正是这个 bug 能上线的原因。
   4. **守门人**：`建筑验证` 新增断言「楼梯那一列/行只允许 楼梯/墙/界外」；
      `Tools/数据引用核对.ps1` 新增第 10 段（同一判据的离线版，不开 Unity 也能看见）。
      ⚠ 断言必须**遍历实体**而不是用 `格上实体()` —— 后者只返回第一个，"门压在楼梯格上"正是"一格两个实体"，用它会漏。

   **负向测试**（证明断言真会响，本项目被"空断言"咬过两次）：临时关掉生成器保护 + 把门改回冲突的边 →
   `建筑验证` 报 **100 处失败**（每种子一次，位置随种子变）、`数据引用核对.ps1` 报 1 处；还原后双双 0。

## 十、刀12：区域层街上敌人 + 街口（区域出口格）

> 这一刀把上面 §八「没做的」第一条补上了，顺手把「出区域只能按 Esc」也改成"走到街口就走出去"。
> 目标不是加难度，是**让副本内部也有它自己的危险** —— 之前五区的危险全在楼里，街上反而比大世界还安全，说不通。

### 10.1 街上敌人（每片区域自己的一批）

| 区域 | 危险度 | 街上敌人 | 理由 |
|---|---|---|---|
| 东区 | 1 | `流浪狗`×2 + `野猫`×1 | 新手区：只有野东西，背包空着也打得过 |
| 居民区 | 1 | `变异鼠`×3 + `野猫`×1 | 同上；鼠群贴居民楼的直觉 |
| 西区 | 2 | `流浪狗`×2 + `拾荒者`×1 | 开始出现人 |
| 商业区 | 2 | `拾荒者`×2 + `流浪狗`×2 | 有货的地方就有人抢 |
| 医院区 | 3 | `感染者`×3 | 感染源。往里走之前先在街上付点代价 |
| 警察局区 | 4 | `拾荒者`×2 + `拾荒者弓手`×2 | 有枪的地方，拾荒者也在盯着 |
| 工厂区 | 5 | `狂暴感染者`×2 + `重装拾荒者`×1 | 全图最硬的街面 |

**落地口径**（全部与「一场遭遇 = 一个敌人」那条铁律一致）：

- 数据形状 **`区域模板.敌人[]`**（`{定义标识, 数量}`）—— **与 `世界模板.敌人` 是同一个类**
  （`撒敌人项`，数据模型里共用一份）：两边都是"往自由格上撒 N 只占格敌人"，没有第二套语义。
- **`占格 = true`**：占格才触发遭遇 —— `格子探索服务.检查遭遇` 判的是**正交相邻**，
  不占格玩家会从它身上走过去（距离 0 ≠ 1），**永远打不起来**。这是个隐蔽的坑（`大世界生成器` 那边也有一条同样的注释）。
- **`挡视线 = false`**：街上看得见对面（方形视野本来就不做遮挡，见 `网格视野` 文件头）；
  敌人不该比障碍更"遮"。
- **留空规则与障碍完全共用**（`区域生成器.可撒占格物`）：不压区域入口（含四邻）、不压**街口**（含四邻）、
  不挡任何楼门（含四邻）。⚠ "含四邻"不是讲究：这三处都是**只有一个出口**的格子，旁边被占格物堵上就是死格
  （刀2 障碍堵死区域门口、刀6 临时建筑切断地图，都栽在这一课上）。
- **每撒一只都跑一遍 `区域生成器.校验`，破了就当场撤回** —— 街上多一只敌人绝不能把哪条路堵死。
  （区域只有 704 格 / 40 来个实体，所以敢逐只校验；大世界 10000 格就不敢，那边是"撒完统一兜一次"。）
- 显示名由 **`格子探索服务.补敌人显示名()`** 从 `enemies.json` 补上（Domain 不认识数据服务）。
  这个方法这刀从 `大世界探索服务` **上移到基类** —— 房间/区域/大世界三层都调，一处改三层都变
  （顺带治好一个小毛病：房间层原来一直播报的是"拾荒者扑了上来"，而它的真名是"敌对拾荒者"）。

**服务层**（`区域探索服务`，三行钩子，流程一行没重写）：

```
抵达后检查()      => 检查遭遇()                    ← 走完一步先看有没有撞上
遭遇胜利节点       => "__区域胜利"
遭遇返回节点       => "__区域返回"
遭遇日志前缀       => "区域"
战斗收尾之后()     => 事件.发布(new 回到区域事件())   ← 否则战斗面板留在最上面，回不到街区
```
`BattleService.返回()` 加两行把 `__区域胜利/__区域返回` 分派给 `区域探索服务`。

### 10.2 街口（区域出口格）

**是什么**：`区域生成器.开街口()` 把**边界墙上正对入口的那一格**打通，放一扇**不占格的门**（`网格实体类型.门`）。
走上去 = 离开这一片，回大世界（`区域探索服务.抵达格()` 里第一个判的就是它，优先于任何建筑）。

**怎么"离开"**：与房间层"走大门出楼"**一一对位** —— 服务只发意图，UI 那侧负责清态 + 切面板：

```
区域探索服务.抵达格()  →  事件.发布(new 离开区域事件())
                              ↓
                    区域面板 订阅 → 回退()  →  区域探索服务.离开()（清区域态）
                                            →  面板管理器.返回上一面板()（回大世界面板）
```
（`区域面板.回退()` = Esc 那条路；两条路汇到同一个函数，所以"从大世界进来的"回大世界、
"快速测试面板直接进来的"回测试面板，两边都对。）

**为什么放在这一格**：① 就在入口正下方 —— 玩家一进来就看得见"街口在身后"；
② 边界墙**其余格照旧是墙**（点了报"那边过不去"）→ 出口只有这一个，不会迷路；
③ 它与入口格天然相邻 → 连通性不可能被破坏。

**为什么门要 `占格 = false`**：它是个"能站能走的门洞"，玩家得走上去才出得去。
（对比楼门：楼门是**长在楼身上**、靠 `网格数据.占位()` 的"带门洞占格物豁免"放行的那一格，两回事。）

**可见性**：`区域网格面板` 把街口与楼/墙归为一档（**只要不是全黑就画**）——
它是唯一的出路，不能黑着找不到。障碍/敌人则仍是"只在亮或白天记忆里画"。

顺带把 `区域网格面板` 的实体渲染补齐了：`门`（街口）= 复用 `区域贴图.入口()` 那张门贴图 + 名字；
`敌人` = 圆盘 + 剪影 + 名字（与房间层同一套画法）。之前这两种类型会掉进"通用色块"分支。

### 10.3 安全屋的「门」= 唯一选项「出去」

用户要求：**安全屋的门只给一个选项「出去」，点一下就到废城**。

- 新增 **`大世界探索服务.出门()`** 作**唯一入口**（`打开默认世界()` + 统一失败提示）。
  安全屋面板的「出门」按钮/`回退()` 与 门的右键菜单**都调它** —— 免得两处各写一遍失败提示、改一处忘一处。
- `右键菜单.显示家具()`：`定义标识 == "门"` 时**只给一条「出去」**，不给 升级/拆除/详情
  （门是基础家具、位置固定不可拖拽，菜单上多一行"拆除"反而让人以为能把门拆掉）。

### 10.4 ★ 顺手修掉一个"打完架就卡死"的面板栈 bug

做街上遭遇时才发现：**在房间里打完一场架之后，按 Esc 出不去**（服务那侧的 `离开()` 跑了、`当前世界` 清了，
面板却切不走 → 卡在一张空网格上）。

根因在 `面板管理器.显示()` 的"上一个面板"记账：

```
房间 → 战斗   这一步就把 上一个面板 记成了【房间自己】   ← 当时只排除了"从瞬时面板切走"，没排除"切到瞬时面板"
战斗 → 房间   当前是瞬时面板 → 不覆盖 → 上一个面板 仍是【房间自己】
房间按 Esc    返回上一面板 → 显示(房间) = 当前面板 → 早退 → **切不走**
```

修法（v51 刀12）：瞬时面板**两头都不占** `上一个面板` —— `if (!上下互切 && !当前瞬时 && !目标瞬时)`。

为什么这一刀必须顺手修：大世界层不受影响（它的 Esc 是直接发 `打开营地事件`，不走 `上一个面板`），
但**区域层走的就是 `返回上一面板`** —— 街上遭遇一落地，玩家打完第一只就会撞上这个坑。
即"新功能把一个一直藏着的 bug 踢出来了"，不修就等于新功能自带一个卡死。
