## 三、★ 一条被证伪的高危推测（方法论记录）

审计报告 **01 #23** 曾给出 **🔴🔴** 结论：

> 四个离线验证器 target `net10.0`，游戏是 Unity 6（.NET Standard 2.1 面）→ `System.Random` 带种子的算法不同 → **"验证过的布局"和"游戏里的布局"不是同一套**。

**如果成立，本项目所有"绿灯"都要作废**。于是当场做了判定实验（同一批种子，两边各取前 6 个 `Next(100)`）：

| 种子 | .NET Framework 4.x（Windows PowerShell 5.1） | net10.0（CLR 10.0.2） | |
|---|---|---|---|
| 1 | 24,11,46,77,65,43 | 24,11,46,77,65,43 | ✅ |
| 12345 | 6,7,77,51,79,82 | 6,7,77,51,79,82 | ✅ |
| 20260913 | 56,90,63,20,50,99 | 56,90,63,20,50,99 | ✅ |
| 2147483646 | 20,52,6,34,75,68 | 20,52,6,34,75,68 | ✅ |

**逐位一致** → `new Random(seed)` 在 .NET 6+ **刻意保留了旧的 Knuth 算法**（变的是无参 `Random()`），而 Mono/Unity 用的正是这一族。
**结论：#23 不成立**，离线验证与游戏**是同一套布局**。

### 后续：这条已经被"在 Unity 上跑实"了（比推理更强）

`docs/评估/01` 的作者随后直接用 **Unity 自带的 `mcs` + `mono`** 编译并运行了同一份源码来对比（实测加载的是
`MonoBleedingEdge/lib/mono/net_4_x-win32/mscorlib.dll`），结果：

- **6 颗种子（1 / 7 / 12345 / `int.MaxValue` / 98760 / 4242）× 4 种取数（`Next(int,int)` / `Next()` / `NextDouble()` / `NextBytes()`）逐字符一致**；
- **IL2CPP 那条路也查了**：它用的是 `il2cpp/build/deploy/System.Private.CoreLib.dll`（FileVersion **8.0.424**，即 .NET 8），元数据里含 `CompatPrng` / `Net5CompatSeedImpl` / `xoshiro` → **与 net10 同源**；
- 顺带测出 Unity 版本 = **6000.4.8f1**。

**所以：这条路彻底封了，不需要"编辑器里 5 行盖章"了**（原文要求的动作已经完成）。
**但"给战斗注入可播种随机源"仍然要做** —— 理由**换了**：不是为了跨版本一致性（已实测同源），
而是为了**可复现**（`UnityEngine.Random` 是全局静态、无法播种，见 §二 D16）。原报告里"换掉 `System.Random` /
把 csproj 降到 netstandard"的建议已被其作者自行更正，**不要排进路线图**。

**而这一轮出现了两次"自己抓自己"，都值得记进纪律**：
- 本文作者的对照脚本第一版**自己写错了**（Int32 溢出 + 参考实现有偏），第一次跑出来的是"✗ 不一致" —— 差点把一个假警报升级成头号问题，是**换用两个真实运行时对拍**才纠正的。
