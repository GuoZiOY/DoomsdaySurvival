### 刀15 的口径说明

- **#8 的 `类型` 白名单是"能阻断进游戏"的改动**，所以下手前做了安全检查：
  实测全部 269 件物品的 `类型` 取值 = 武器56/防具59/材料91/饮食24/医疗18/任务品9/弹药7/容器3/书籍2，
  **9 种，全部在我写的白名单里**（`DataService.合法物品类型`）。新增物品类型时必须同步加白名单（脚本会拦）。
  同时删掉了两处死分支：`物品.类型 == "技能书"`（类型里没这个值，它是 `书籍种类` 的值）。
- **#11 删了 `消耗道具` 死字段**（声明 + 开始战斗的 Clear + 结算回写的 foreach）：
  全仓库 0 写入，真正的消耗是 `扣战斗容器` 直接改容器。并在 `结束战斗` 里**显式**清
  `Buffs/技能冷却/眩晕/无敌/防御姿态` —— 原来靠"战斗单位每场重建"侥幸正确，现在写成承诺。
- **#14 是平衡改动，不是修 bug**：9 只敌人各配 2 条行动项（权重偏保守，普攻仍占多数），
  目的是让 v46 宣称的"敌人读条大招 / 可被撞断"这条功能**第一次真的在数据上跑起来**。
  顺带在 `Tools/数据引用核对.ps1` 加第 9 段：`行动` 必须是"普攻"或 `skills.json` 里真实存在的技能
  （写错的后果是 AI 静默落回普攻，玩家只觉得"这怪从不放招"，不会报错）。
  ⚠ **数值可能偏强/偏弱，需要试玩调权重**（见 §四 P7）。
- **#5 没有直接删事件，改成"按分钟粒度发"**：审计建议是"删掉 `BattleService.cs:163`"，
  但 `自动存档器` 靠这个事件做**跨天检测**（`检查跨天`），战斗跨午夜时删掉它就漏了自动存档。
  所以改成：`if ((int)游戏分钟数 != 上次发事件的分) 才发` —— 60fps 下从"每秒 60 次"降到"每游戏分钟 1 次"
  （战斗里 1 现实秒 = 1 游戏分钟 → **每秒 1 次**，降 60 倍），跨天检测粒度不变。
  同时 `格子探索服务.时间变化响应` 改成**先比时段、没变就直接 return**（原来无条件 `刷新视野()`）。
- **#6 没有重构闭包，改成"补重接"**：最小风险的做法是在 `PlayerService.接线解析器` 里
  把 `搜索服务` 和 `容器服务` 一起重接（它俩都是闭包捕获 `档案` 的，而 新游戏/读档 会整体替换实例）。
  更彻底的"读档不替换实例"留在档3 第 30 条。
- **#16 先报"校验警告"而不是"校验错误"**：判错误会让 `GameBootstrap` 中止装配 → 整个游戏进不去。
  当前能确认"所有被加载的 DTO 都有 `标识`"（装配日志里 敌人 9 / 物品 269 / 技能 21 都非空就是证据），
  所以这个守卫是给**将来新增 DTO** 用的。等哪天在 Unity 里验过"没有任何 加载异常"，再升级成 错误。
- **#18 连带改了验证器**：`Tools/大世界验证` 里"期望敌人数"原来也是 `Math.Max(1,…)`，
  必须与生成器同时改成 0 —— 否则数据里写 0 会出现"生成 0 只、期望 1 只"的假失败。

### 实施中另外发现（尚未处理，先记账）

- 🟡 `Domain/战斗单位.cs` 的私有工具 `Random(int 上限) => new System.Random().Next(上限)` ——
  **每次调用 new 一个** `System.Random`，同一帧内连续调用会拿到高度相关的序列（种子来自时间）。
  影响的是"敌人 AI 抽行动/掉落随机"的质量。安全修法：改成一个 `static readonly` 单例字段
  （别用 `Random.Shared` —— Unity 的 .NET Standard 2.1 面不一定有）。**留作下一批**（不动随机行为，只提高质量）。

## 五、别忘了几件"已确认但不是故障"的事（避免重复排查）

  上逐字符一致（报告 01 用 Unity 自带 `mcs`+`mono` 实跑；Unity 版本 6000.4.8f1）。
  **不要去换 `System.Random`**；要做的只是"给**战斗**注入可播种随机源"（为了可复现）。
- **`当前节点` 不能删**（`玩家档案.cs:286`）：它是存档"是否已开局"的守卫。要做的只是把它拆成独立布尔。

- **`战斗沙盒面板` 是瞬时面板**、两头都不占"上一个面板"（v51 刀12 修的账）→ 改动面板路由时别破坏它。
