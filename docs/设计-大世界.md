## 一、世界结构（100×100 网格 + 区域副本）

### 1.1 拍板口径

| # | 问题 | 定版 |
|---|---|---|
| 1 | 表现形式 | **格子网格 100×100**（不再用节点网图） |
| 2 | 走一格成本 | **5 游戏分钟/格**（楼里/区域里 1 分钟/格）；表现 0.30 秒/格 |
| 3 | 一格代表什么 | 一片街区/空地。**两套尺度并存**：大世界一格 ≈ 一条街，进区域后换成区域自己的 32×22 格 |
| 4 | 区域占地 | **多格形状掩码**（复用 `建筑外形` 的 矩形/L/凸/凹 + 朝向/镜像） |
| 5 | 区域副本里是什么 | **一片街区** —— 复用现有 `区域网格`（32×22 摆 4 栋楼 + 街道障碍 + 区域迷雾）→ 建筑（楼层）→ 房间 |
| 6 | 种子固定作用域 | **每存档一个 `世界种子`**（沿用 `玩家档案.户型种子` 做法） |
| 7 | 区域「可重复刷」 | **回安全屋就重置** —— 每次从安全屋出发外头都是新的一批；布局种子永不变（**不是**计时刷新） |
| 8 | 大世界搜索 | **有代价的一次性建筑**：扣行动点 + 游戏分钟 → 半径内生成 0~1 个临时建筑 → 进探索，**一次性、不刷新** |
| 9 | 100×100 渲染 | **视口虚拟化 + 大世界免建底格/格线** |

层级从「四层」变「五层」，但**只有最外面一层是新的**：`大世界（新）→ 区域 → 建筑 → 房间`。

```
大世界 · 100×100（令牌 / A* / 逐格推进 / 三态迷雾 / 相机跟随 —— 全继承 格子探索服务）
  ├─ 区域副本（多格形状掩码占地，如 6×5）：布局种子固定 → 同存档永远同一套楼
  │     解锁条件（未解锁 → 可见但进不去 + 提示）→ 走到门口那一格 → 区域网格 32×22 → 建筑 → 房间
  ├─ 临时建筑（搜索在半径内生成，一次性，不刷新）→ 走上去 → 建筑 / 房间（复用同一套）
  └─ 营地 = 安全屋面板
```

### 1.2 ★ 区域怎么"可重复刷"

> 不需要标记区域已通关，也不需要重置计时。**每次从安全屋出发新的，回来后重置。**

这条早就是 v48/v49 的规矩，不用写新代码：内容状态（容器战局 / 已翻标记 / 尸体容器 / 门锁态 / 楼层缓存）进出房间/换房都**不清**，**回安全屋**（打开营地事件）才清。

| 要的效果 | 靠什么 |
|---|---|
| 同一存档里那片区域**永远同一套楼** | `区域布局种子 = 派生(世界种子, "区域:" + 区域标识)` |
| 每次出发**资源/敌人/门锁都是新的** | `打开营地事件 → 回安全屋清战局()` |
| 想再刷一遍 | 走回安全屋门口再走过去（赶路 5 游戏分钟/格就是要付的成本） |

**被有意收掉的（没有"通关 / 前置区域 / 重置小时"）**：

| 收掉的 | 为什么 |
|---|---|
| `区域模板.重置小时` + 逐帧重置计时 | "何时刷新"不需要计时器 —— 时机就是回安全屋。多一个计时器就多一套随档状态、多一条时间流 |
| 「两把钥匙」（布局种子 + 战局代次进内容键） | 回安全屋本来就把所有内容键清干净了，第二把钥匙完全多余。**一把钥匙（布局种子）就够了** |
| `前置区域` 解锁 + 「标记区域已通关」 | 本作没有"通关"概念（资源反复刷），留着就是一道永远打不开的门 |
| `区域模板.稀有度`（资源档） | 好资源靠它自己 `建筑[]` 列什么楼表达（纯数据） |
| `副本状态` / `已解锁区域` / `已发现情报` | 解锁条件完全挂在现有档案状态上（`游戏天数` / `持有物品`） |

> **术语纪律**：用户给的词（"副本"）是**比喻**，不是要求照搬原型。先问"你要的是哪个**效果**"。

**这条链要真的清干净**：清战局的**唯一**时机是 `打开营地事件`，而玩家**不一定从楼里走出来** —— 他可能**从大世界直接走到安全屋门口**回去，那条路**不经过 `离开世界()`**。于是"所有本趟的表都必须在 `清战局()` 里清"是**硬约束**：`搜索.清空战局()` / `已解锁门` / `楼层缓存` / `敌人身上的钥匙` / `已察觉` / `本次战斗来自本层` 全在 `清战局()` 里清。
这是把「**回安全屋 = 这一趟彻底结束**」这条**不变量**补成真的 —— **靠巧合成立的东西不算保证**。
连带：`放钥匙()` 原注释「重玩会变」在种子固定后不再成立 —— 钥匙每次都在同一处，注释已改对。

### 1.3 种子派生链（一条线管到底）

```
玩家档案.世界种子                                   ← 新游戏随机（沿用 户型种子 做法，读档恢复）
  └─ 区域布局种子 = 派生(世界种子, "区域:" + 区域标识)   ← 永远固定
       └─ 楼种子 = 派生(区域布局种子, 楼标识)
            └─ 层种子 = 派生(建筑种子, "F{层}")
                 └─ 房间种子 = 派生(建筑种子, "F{层}#{序号}")
  └─ 临时建筑种子 = 派生(世界种子, "临时:" + 序号) 或 当场随机   ← 一次性，无需固定
  └─ 世界敌人 = 派生(世界种子, "世界敌人") / 街上敌人 = 派生(区域种子, "街上敌人")
```

- **没有第二条链**：`战局代次` 随"重置计时 + 两把钥匙"一起作废。
- `区域探索服务.进入区域(标识, 种子)` 原来是**外面传种子**（含 `Random.Range`）→ 改由 `大世界探索服务` 传 `派生(世界种子, 区域标识)`，否则同一片区域每次进去都不一样。
- **存档兼容**：`世界种子` 走"缺省 0 → 惰性初始化补随机"（与 新鲜/生长/净化分钟 同一手法，**无需升档版本**）。

### 1.4 时间链与实体类型

- `格子探索服务.移动游戏分钟` 由 `const 1` 改 `public virtual int`，大世界覆写 **5**（全仓库只有 `推进一步()` 用它）。
- `网格实体类型` 追加 `区域`、`临时建筑` 两个枚举，**追加在末尾**不插中间。

### 1.5 ★ 区域 = 占格 `true` + 只有门口那一格能走

否决"整片能踩过去 / 踩任意一格就进副本"的理由：**那会让"路过"等于"进入"** —— 横穿一片街区就被拖进副本，玩家没法单纯赶路。改成与"楼门长在楼上"同一套直觉：**整块挡路、门口那一格**能站能走。代价是 `网格数据.占位()` 的门口格豁免从"只认建筑"扩到"建筑 + 区域"。

**门口格取法 = `建筑外形.底边中点`**（掩码最靠下那一行里最长连续段的中间那格）：区域层的楼门与大世界层的区域门共用这一条（`掩码 == null` 按纯矩形处理）。

**点击链路**（与另两层同一条，不需新代码）：区域块整块 `raycastTarget = false`（营地同理）→ 点在块上哪一格都落到那格的交互层 → 左键：点块体 = 占位是区域 → A* 寻路到"相邻格"走到块边；点门口那格 = 占位 `null` → 直接走过去 → 抵达格 → 进副本 → 右键：菜单「走到门口 / 查看」。
门口**解锁状态**直接画在那格上：进得去 = 金色、锁着 = 红色；锁着时走上去只收一句提示（`大世界探索服务.未解锁缘由`），**人停在门口** —— 与 v49「走到门口停下 + 右键开门，不自动切」同一套手感。

### 1.6 100×100 渲染：视口虚拟化

逐格建图与格数成正比：底格 10,000 + 分隔线 20,200 + 地表 10,000 + 迷雾 10,000 + 交互 10,000 张（+10,000 组件）→ **≈60,200 张 + 10,000 组件**（区域层 32×22 合计 ≈4,278 张）。

| 开关 | 位置 | 默认 | 大世界覆写 | 省下 |
|---|---|---|---|---|
| `建底格` | `网格面板基类` | `true` | `false` | 10,000 张底格 |
| `建格线` | `网格面板基类` | `true` | `false` | 20,200 条格线 |
| `格子池化` | `探索图层` | `false` | `true` | 地表/迷雾/交互 由 3×10,000 → 3×~450 |

- 地表层本来就逐格盖满，**底格与格线在探索层根本看不见**，关掉无视觉代价；对房间/区域层**零影响**。
- `格子池化` 附带条件：**网格装得下窗口时一律走全格**（房间层 16×10 → 池 = 全格，**房间层零变化**）。
- 池容量 `= min( (ceil(窗宽/格)+1+池边距*2) × (ceil(窗高/格)+1+池边距*2), 列×行 )`；1720×960 / 格 90 → **25×16 = 400 槽**（≈1,200 张图，比区域层还轻）。池不够用时**不崩溃**：先 `Debug.LogWarning` 报"边上会缺格"并给出该调哪个数，再少画几格。

**池化最关键的一处：两套判据必须一致**。池化把"格坐标"与"池槽下标"解耦，同一个问题出现两份算法：**点击判据** `在窗口内(c,r)` 与**建池判据** `窗口格区间(外扩)`。不一致的表现是**"看得见却点不到"**或**"点了错一格"**。所以 `窗口格区间()` 是**唯一**范围算法（`更新池` 与自检共用），重建时跑 `自检池覆盖()` 逐格对一遍，不一致就 `Debug.LogError` 报出哪一格。

**池容量是"刚好够"**（`Tools/格子池区间核对.ps1`）：

| 窗口 | 池容量 | 最坏区间格数 | |
|---|---|---|---|
| **1720×960（默认）** | 400 | **384** | OK |
| 1280×720 | 260 | 260 | OK（贴边） |
| 2560×1440 | 714 | 714 | OK（贴边） |
| 900×600 | 180 | 180 | OK（贴边） |

> 区间类的东西**不要靠手算**（手算得 286、实测 384，`floor` 两端各能多进一格）。

**物品层的账要分开算**：`格子池` 只管地表/迷雾/交互三层。**物品层（实体框）没被池化**，按"实体数"算：区域层 ≈550（边界墙 104 / 障碍 3 / 4 栋楼），**大世界 ≈2,600**（边界墙 400 / 障碍 200 / 2 片区域 + 1 营地）。所以刻意砍了两笔纯装饰：① **边界墙不描转角边**（≈1,000 个多余 GameObject）；② **障碍不挂名称标签**（200 个 TMP 文本既费又糊，想知道是什么就右键「查看」）。
> ⚠ 池化路径下**不支持** `建格装饰`（会随重排累积）。大世界要画区域门口的"门"标记，应走**效果层上的单个 Image**。

`Assets/Resources/Data/世界.json`：

```jsonc
{ "世界": [ {
  "标识": "废城", "名称": "废城", "描述": "……", "列": 100, "行": 100,
  "营地": { "列": 50, "行": 50 },                 // 安全屋/起点
  "区域": [ { "区域模板": "警察局区",

  "障碍数": 120,                                   // 街道障碍（废墟/车障），撒完校验连通
```

**解锁条件**（`条件` 字段，全部满足才解锁）：

| 条件 | 标识含义 | 现有数据支撑 | 能不能用 |
|---|---|---|---|
| `天数` | 活到第 N 天 | `玩家档案.游戏天数` | ✅ |
| `物品` | 持有某物品 | `玩家档案.持有物品()` | ✅ |

`玩家档案` **只加了一个** `public int 世界种子;`（新游戏随机，读档恢复）。

### 1.8 不破连通（活的墙）

- **障碍撒不破连通**：障碍强制"彼此切比雪夫距离 ≥2"，而 **4 连通网格的割集必须是一条 8 连通屏障**（对偶）—— 障碍之间永远 8 不相邻，**数学上不可能切断开阔地**。
- **但临时建筑能**：2×2 临时建筑本身就是一整块 8 连通的墙，和地图边界 / 障碍 / 区域凑在一起**真能把地图切成两半** → `搜索落点` 改成 **洗牌候选 → 逐个试放 → 跑连通校验 → 破了就撤掉换下一个**（失败率约 5%；试放完必定撤掉，**世界状态原样还给调用方**）。
- **敌人也占格**，与障碍**共用一条判据**：不压区域/营地 · **不碰任何门口格及其紧邻八格** · 与其他占格物隔 ≥1 格。
- 连通兜底统一成 `保证连通()`：破了**先撤障碍（装饰）、还破再撤敌人（能打的）**，两个计数分开报。

> ★ **一条规则上了两次同一课**：凡是"**三面被围、只有一个出口**"的格子（门口格 / 楼梯口 / 门内侧），留空规则必须保护它**和它的出口**；断言也必须查**可达性**而不是可通行性。**"可通行" ≠ "走得到"**。

### 1.10 一条"断路"的修法（语义，不是接线细节）

退役节点网图服务时把「营地 → 进大地图」那条路一起带走了 → **从安全屋没有任何路回到废城**。
修法：`安全屋面板.回退()` 由 `返回上一面板` 改成 **「出门」**（调 `大世界探索服务.打开默认世界()`），`取消文本` 改 **"出门"**。
> `返回上一面板` 的目标取决于**你怎么走到安全屋的**（从大世界走回去碰巧对，从别处打开就指向角色创建）。**"出门"是确定的语义，不该靠"上一个面板"碰巧对。**

## 二、搜索规则（三条约束）

> 起因：玩家反馈「搜索出来的随机建筑还需要更多条件限制，**避免玩家一出安全屋就一直搜索制作安全屋**，而不去区域里探索」。

### 2.1 拍板结论

| 项 | 决定 |
|---|---|
| ① **局部枯竭**（用户提的） | **做** —— 取代"离营地 15 格"的距离门槛 |
| ② **越翻越累** | **做** |
| ③ **楼型白名单 + 禁区清单 + 允许地图类型** | **做** |
| ④ 临时建筑矮化成 1 层棚屋 | **不做**（先看①②③手感，不够再谈） |
| 距离门槛 / 每趟每天硬上限 / 冷却计时器 | **不做**（分别被 ① 取代、与 ② 重叠且会变成"数着次数玩"、项目已在"重置计时"上栽过一次） |
| 枯竭随档永久保存 | **不做**（会把地图逐渐耗尽，与"回安全屋重置"冲突） |
| 搜索的昼夜/天气修正 | **不做**（字段留了口子：加一个乘数即可） |

### 2.2 问题量化（动手前实测）

| 项 | 当时的值 |
|---|---|
| 搜索代价 / 出现概率 / 搜索半径 | 10 行动点 + 30 游戏分钟 / 60% / 4 格 |
| 行动点上限 | `100 + 体质×2 + 等级×2` ≈ **110** → 一趟约 11 次 |
| 睡觉 | **行动点回满**，跳到次日 6:00 |
| 临时建筑楼型 | **从 `数据.建筑模板` 全表等概率抽** —— 含 `市立医院`／`城西分局`／`纺织厂` |
| 营地周围敌人 | 营地 (50,50)，13 只敌人撒在 9600 格里，半径 4 内期望 ≈ **0.06 只** |

一天的产量：11 次 × 60% ≈ **6.6 间楼/天**；每间楼 2 层 3~4 间房、每间约 4.8 个容器 → **每天约 104 个容器位**，代价只有 330 游戏分钟（一天 1440 分钟）+ 睡一觉。
对比：进一片区域拿 4 栋楼 ≈ 60~76 个容器位，**还要走路、打街上敌人、过 `天数≥3/6/10` 的解锁门** → 门口刷搜索 = **每天白拿一趟区域探索，零风险、零解锁门槛**。

**三个互相独立的洞**：① **零风险**（营地半径 4 内基本没敌人）；② **奖励越级**（全表等概率抽 → **第 1 天就能刷出市立医院**〔抗生素/血浆〕、**城西分局**〔手枪弹/步枪弹/军刀图纸〕、**纺织厂**〔火药/电路板〕，把三个区的解锁门**整个架空**；这个洞与"刷不刷"无关，走远点照样能刷出来）；③ **以量取胜没有惩罚**（`搜索次数` 只当种子，搜第 10 次和搜第 1 次一样容易一样好）。

### 2.3 目标

① **门口的零风险水龙头关掉**（搜索变成"在路上"的动作）；② **奖励天花板压回去**（枪弹/血清/图纸/火药这类**区专属产出只在区域里出**）；③ **"多搜"收益递减**（一趟里第 1 间划算、第 5 间不值得）；④ **不改玩法内核** —— 还是"翻出一间能进去探索的临时建筑"，只是它从**主粮仓**变成**路上的小补给**。

### 2.4 ★ ① 局部枯竭

**规则**：一次成功的搜索以**翻出来的那间临时建筑**为中心，把周围 `枯竭半径` 格标成**"已翻过"**。站在"已翻过"里再搜，成功率掉到 `枯竭概率`；**枯竭格本身也不给放新建筑**。

| | 距离门槛 | 局部枯竭 |
|---|---|---|
| 玩家感受 | "凭什么这儿不能搜" —— 一条看不见的线 | "这一带我翻过了" —— **自解释** |
| 对站桩刷 | 关掉，但只是换到 15 格外继续站桩 | **直接让"站着不动"变成无效动作** |
| 与玩法气质 | 像规则补丁 | 像世界本来的样子 |

**自带一个漂亮的连锁**：翻出的建筑一定落在搜索半径（4 格）内 → 你必然走进枯竭区里去开它 → **出来时还站在枯竭区里** → 再搜就是白费。"找到 → 进去 → 出来 → 再搜"本身就把玩家逼着挪地方，不需要任何额外提醒。

**实际走多远才恢复**（`枯竭半径 = 8`、`半径 = 4`）：刚翻出时玩家离建筑 d ≤ 4 → 搜索范围（9×9）**整块**都在枯竭区里（d+4 ≤ 8）→ **几何上就搜不出**；走到 d ≥ 5 才重新有干净候选格（概率仍是 12%）；走出 d > 8 才回到 60% → **走 5~7 格（25~35 游戏分钟）**。

**记忆存哪 / 何时清**：存在 `大世界探索服务` 的**本趟列表**（`本趟翻出的`），`清战局()`（= 回安全屋）清掉。
⚠ **必须和实体分开记**：临时建筑**进去一趟就塌了**（`清掉用过的临时建筑`），但"这一带翻过了"得留着 —— 挂在实体上会随坍塌一起忘掉。
跟着回安全屋清 → 同一片街区下一趟又能翻。**局部枯竭不是产量阀门，是"别站桩"的阀门**（产量上限由 ② 卡）。

### 2.5 ★★ ② 越翻越累 —— 这一条才是产量阀门

**先说清一个反直觉的事实**：**产量上限是行动点卡的，不是地点卡的**。
> 搜索一次 10 点、行动点上限 ≈ 110 → **一趟就是 11 次**，跟你在哪儿搜没关系；11 × 60% ≈ 6.6 间/天。

所以**只做局部枯竭**的后果是：站桩刷 → 变成 **"走直线刷"**（每走出枯竭区就又能搜出一间，一天照样 ~6.6 间、**~104 个容器位**，只是你整天都在走路）。而**大世界上只有 13 只敌人**撒在 9600 格里 —— 走一天的直线几乎碰不到东西，花掉的只是 87 天里的一天。
即：局部枯竭能把搜索从"免费"变成"要付出一整天"，但**它没法把 6.6 降到 3**。要压产量必须给**代价**加码：

```
第 N 次搜索的行动点 = 行动点 + (N-1) × 每多一次多花行动点
```

- 次数从 1 起，且**不管上一次成没成功**（失败不涨价 = 等于没约束）。
- 实测（`行动点 = 10`、`每多一次多花行动点 = 4`）：**第 1 次 10 点 → 第 5 次 26 点；110 点一趟最多 5 次**（不加价是 11 次）。
- 为什么用**行动点**递增而不是"概率递减"：概率递减的表现是"你搜了、什么也没翻到"（花了时间还是空的，手感差）；行动点递增的表现是"精力不够了"（清楚、可预期、HUD 上看得见）。

### 2.6 ★ ③ 楼型白名单 + 禁区清单 + 允许地图类型

- **白名单**（`搜索.临时建筑`）：临时建筑只能出这几个楼型，按权重抽。实测 = **4 个普通楼型**。
- **禁区清单**（`搜索.禁区楼型`）：显式写出**区专属楼型**。白名单里一旦出现它们 → **校验错误**（不是警告）。以后新增区专属楼忘了加也会被交叉核对抓出来。
- **允许地图类型**（`搜索.允许地图类型`）：白名单楼型的房间容器池**只许**引用这些地图类型。
  > 为什么还要这层：白名单只保证"楼型不是区专属"，防不住"有人把医院房间塞进便利店"—— 那样照样能拉出抗生素/血浆。这条把"奖励越级"从数据层面彻底焊死。

界线天然干净（已核对）：4 个普通楼型的容器池**只用** `居民房/便利店/药店/街区`，3 个区专属楼型**全用到** `医院/警察局/工厂`。

### 2.7 数据字段与分层

```jsonc
"搜索": {
  "行动点": 10, "游戏分钟": 30, "半径": 4, "出现概率": 60,
  "枯竭半径": 8,            // ① 翻出过一间 → 以它的占地为中心、这么大一块算"已翻过"（0 = 关掉）
  "枯竭概率": 12,           // ① 站在"已翻过"里时的成功率
  "每多一次多花行动点": 4,   // ② 第 N 次 = 行动点 + (N-1)×它（0 = 不加价）
  "临时建筑": [             // ③ 白名单 + 权重（空 = 兜底：全部楼型里滤掉禁区）
    { "建筑模板": "西街便利店", "权重": 3 }, { "建筑模板": "临街门面房", "权重": 3 },
    { "建筑模板": "西区公寓A",  "权重": 2 }, { "建筑模板": "围合住宅楼", "权重": 2 } ],
  "禁区楼型": ["市立医院", "城西分局", "纺织厂"],
  "允许地图类型": ["居民房", "便利店", "药店", "街区"]
}
```

`数据模型.世界搜索参数` 加同名 6 字段 + 新类 `临时建筑候选{建筑模板, 权重}`。**全部字段都有缺省值** → 老档/老 JSON 不填也能跑（`枯竭半径 = 0` + 空白名单 = 行为退回原版）。

| 层 | 内容 |
|---|---|
| **Domain**（`大世界生成器`） | `搜索落点` / `能放临时建筑` / `放临时建筑` / `临时建筑列表` / `临时建筑门口格`。**纯几何、确定性** → 可逐种子断言 |
| **Domain**（`搜索规则.cs`） | 代价 / 成功率 / 枯竭判定 / 白名单挑选（**纯函数，零 UnityEngine**）；**只有"掷"留在服务层**（掷点当参数收）→ 曲线可逐点扫 |
| **Service**（`大世界探索服务`） | `搜索()`：校验并扣**行动点 + 游戏分钟** → 掷出现概率 → 调 Domain 找落点 → 挑楼型 → 落地 + 播报 |
| **UI** | 临时建筑画成一间 2×2 小楼（木/铁皮贴图 + 门口那格）；**右键自己脚下那一格 → 「在附近搜索」** |

> 入口走右键而不是加按钮：加按钮要场景接线（引用位），右键复用现成的交互层 + 右键菜单，**零接线就能玩**。

### 2.8 预期效果

| | 改动前 | 改动后 |
|---|---|---|
| 能不能站桩刷 | 能 | **不能**（一处一趟最多出 1 间：枯竭盖住整个搜索半径） |
| 一趟搜索次数（110 行动点） | 11 | **5** |
| 每间楼容器位 | ≈15.7 | ≈15.7（这刀不矮化） |
| 每天期望间数 | 6.6 | **≈3.0**（要边走边搜；每间之后得走出枯竭区） |
| **每天容器位** | **≈104** | **≈47** |
| 第 1 天能刷出枪弹/血清/图纸 | 能 | **不能** |
| 代价 | 330 分钟 + 睡一觉 | 330 分钟 + 睡一觉 + **来回赶路 5~7 格/次** |

"≈3.0"的口径：5 次尝试 × 60%，前提是**每次翻出之后都走出枯竭区**（这正是要的：把搜索和移动绑在一起）。玩家确实可以"5 次都失败"或"5 次都成功"—— 但**同一处只可能出 1 间**，想多拿就必须多走。

### 2.9 验证

| # | 断言 | 为什么 |
|---|---|---|
| ⑨ | 搜索落点**永远不在"已翻过"里** | 局部枯竭的几何保证 |
| ⑩ | 玩家站在**刚翻出的那一间的门口格**上再搜 → **必须搜不出** | "站桩刷"被彻底堵死的证据（成立条件 `枯竭半径 ≥ 半径+1`，门口格在占地外一格） |
| ⑪ | 枯竭区在远处时，落点必须与"没有枯竭"时**逐字节一致** | 局部枯竭不许影响远处 |
| ⑫a | 代价单调递增；**加价生效 → 一趟可搜次数严格变少** | 这条约束存在的意义就是"次数变少" |
| ⑫b | 非枯竭成功率 == 出现概率；枯竭成功率**只许更低** | 数据写反了不许变成"越翻越多" |
| ⑫c | 建筑自己那格必在枯竭区；超出 `枯竭半径` 一格必在区外；`半径 = 0` 时彻底关掉 | 边界别算错 |
| ⑬ | **掷遍所有掷点也抽不到禁区楼型**，且白名单里每个楼型都抽得到 | 奖励越级 + 权重别被吃掉 |

`Tools/数据引用核对.ps1` 交叉核对：白名单楼型存在 / **不在禁区清单里** / 权重为正；禁区楼型存在；允许地图类型存在；**白名单楼型的房间容器池 ⊆ 允许地图类型**；枯竭半径/枯竭概率/加价 的区间 + `枯竭概率 < 出现概率`；两条防刷约束**都关着**时打一行警告。
> **这条断言做过反向验证**（把 `市立医院` 故意塞进白名单 → 工具立刻报两条错，还原后恢复通过）：断言必须证明它**会响**，不然就是摆设。

实测：

```
—— 搜索自检（以营地门口为玩家位置）——
  翻出 5 间 / 附近太挤 0 次 / **枯竭挡住 25 次** / 失败 0 处
—— 搜索规则自检（纯函数）——
  代价：第 1 次 10 点 → 第 5 次 26 点；行动点 110 一趟最多 **5** 次（不加价 11 次）
  概率：不在枯竭区 60% → 站在枯竭区 12%
  楼型：白名单 4 个（总权重 10）；禁区 3 个 —— 掷遍 10 个点，一个都没抽到
```

「5 种子 × 6 次尝试 → 只翻出 5 间」= **每种子恰好 1 间**，其余 25 次全被枯竭挡住 —— 正是"一处一趟只出 1 间"。

## 三、迷雾与永久记忆

> 起因：玩家问「迷雾，是要每次都要重新看，还是依旧保留弱视野？大世界、区域、房间。」

### 3.1 三件被绑在一起的记忆，性质完全不同

`格子探索服务.回安全屋清战局()` 原来把两种性质完全不同的记忆共用了一个重置时机：

```csharp
protected virtual void 回安全屋清战局()
{
    视野记忆.Clear();   // ← 地理知识（静态布局）
    清战局();           // ← 派生类清：容器战局 / 门锁态 / 本趟搜索计数…
}
```

| | 是什么 | 会变吗 | 该什么时候清 |
|---|---|---|---|
| **地理记忆**（雾 / `已探索`） | "这地方长什么样" —— 街道、楼在哪、去过哪 | **永远不变**（布局种子固定） | 不该清（同一存档内） |
| **内容状态**（容器内容 / 门锁 / 已翻标记） | "这个柜子我翻过没有" | 每趟都变（`搜索服务` 用普通 `System.Random`） | **回安全屋清**（现状正确） |
| **危险感知**（`已察觉`） | "我看没看见那只丧尸" | 每次进门都不一样 | **每次进门清**（现状正确） |

关键前提：`已察觉` 只吃**当前可见**，不吃 `已探索` → **迷雾改永久不会给玩家任何先手优势**，战斗平衡不动。
现在的设计其实已经是"**内容重掷 + 布局固定**"，分界画对了 —— 只有雾被错误地划到了"内容"那一边。

### 3.2 拍板结论

| 层 | 决定 | 理由 |
|---|---|---|
| **大世界**（100×100） | **永久保留（随档）** | ① 布局 100% 种子固定 → 重看**信息量为零**；② 代价极大（5 游戏分钟/格，从 87 天里扣）；③ 这层的职责是**导航与调度**，不是战术探索 |
| **区域**（32×22） | **永久保留（随档）** | 同上。街上敌人位置**也是种子固定的** → 重看同样学不到东西 |
| **房间**（16×10） | **保持每次重看** | ① 只有 160 格，8~15 步就摸完 —— **便宜**；② 战术与紧张所在地；③ ★ **技术硬理由**：记忆键是"每个房间实例"，而临时建筑**每趟新增实例** → **无界增长**，进档会无限膨胀 |

技术上正好对得上：大世界 1 张图（10000 格 → 位图 **1668** 字符 Base64）、区域 7 张（704 格 → **120** 字符 ×7）—— **有界且很小**（合计约 2.5 KB 存档文本）；房间无界，只适合留在内存。
还有一条：**寻路不看雾**（`算路径` 只查 `可通行`）。雾**不是通行闸门，纯粹是信息层** → "重看"换不来任何新决策，只是在抹掉玩家本来就合法拥有的知识。

### 3.3 怎么存的

```
玩家档案.迷雾记忆 : string[]          // JsonUtility 不支持 Dictionary，所以用 string[]
  每条 = "{键}|{Base64(位图)}"
  键   = "{层标签}|{种子}#{标识}"      // 大世界 / 区域 / 房间 各自的标签
```

- 位图口径**行优先**（`idx = 行 × 列数 + 列`），与 `网格数据.编码` 的 `列*1000+行` **不是一回事**（别混用）。
- **键里带种子** → 换了图 / 换了种子**自动失配**（记忆自然作废），不必另写失效逻辑。
- 位图编解码是纯函数（`迷雾位图`，零 UnityEngine）→ **能离线断言对称性**。这点很重要：位图最容易在"最后一格 / 最后一个字节"差一位，而那种错在游戏里只表现为"某几格记忆莫名丢了"，**试玩几乎不可能发现**。

| 钩子（`格子探索服务`） | 作用 |
|---|---|
| `迷雾随档保存`（默认 `false`） | 大世界 / 区域 覆写 `true`；房间层**必须**保持 `false`（无界） |
| `层标签`（默认 `"格子"`） | 存档键的层前缀，防不同层的"种子#标识"撞名 |
| `装回迷雾记忆()` | **会话缓存（视野记忆）∪ 存档里的永久记忆** —— 两条来源都读，三层共用同一入口，不会出现"某一层忘了读档" |

`刷新视野()` 里**真的多看了格子才落盘**（站着不动跨过 6:00/18:00 也会刷视野，那时没必要重写位图）。写的是内存里的 `玩家档案`，PlayerPrefs 只在玩家存档时才落盘 —— 每步写一次也不心疼。

### 3.4 可见性表（三层共用一份规则）

可见性规则原来在三个面板里**各写了一遍，而且已经漂了**：房间层 `else if (类型 == 敌人) 显示 = 亮;`（敌人只在全亮里画 ✅）；区域/大世界层 `else 显示 = 亮 || 档 == 暗记忆;` ← **敌人落进 else** → **敌人在记忆层里也被画** ⚠。
现在每次回安全屋都清雾，这个不一致还不明显；**一旦雾改永久，它就会让街区退化成"纯绕路题"、再没有伏击**（一眼就能看见全城/全街区的敌人）。
修法：把规则抽成 **`Domain/网格/网格可见性.cs` 一份**（放 Domain 而不是 UI：它是"档"的语义不是"颜色"，且能被离线断言当表格钉住），三个面板都改成调它。修正后的表：

| 实体 | 亮 | 暗记忆 | 暗中轮廓 | 全黑 |
|---|---|---|---|---|
| 玩家 | ✓ | ✓ | ✓ | ✓ |
| **敌人** | ✓ | ✗ | ✗ | ✗ |
| 墙 / 门 / 楼梯 / 建筑 / 区域 / 临时建筑 / 界外 | ✓ | ✓ | ✓ | ✗ |
| 容器 / 尸体 / 障碍 | ✓ | ✓ | ✗ | ✗ |

### 3.5 连带的第二个地雷：`是玩家` 是按阵营判的

```csharp
public enum 网格阵营 { 玩家, 敌人, 中立 }   // ← 第一个成员就是"玩家"
public bool 是玩家 => 阵营 == 网格阵营.玩家;  // ← 阵营缺省值 = 玩家
```

"**忘了写阵营**"的实体（容器/障碍/敌人…）会被当成玩家：`网格数据.玩家()` 会返回它、`约束摆放` 会跳过它、三个面板会把它的点击关掉。现在全仓库恰好每处都写了阵营所以没炸 —— 但那是**走运**，不是设计。
改成按类型判：`public bool 是玩家 => 类型 == 网格实体类型.玩家;`（另加 `是敌人`），行为逐处等价，但再也不看运气。

### 3.6 ★ 夜晚「压暗地形记忆」和「抹掉记忆」的区别

**现状（抹掉）**：`有记忆(时段) => 时段 == 白天`；`档()` 的夜晚分支是 `在弱视野圈 ? 暗中轮廓 : 全黑` —— **完全不看 `已探索`**。
于是夜晚屏幕上：中心 3×3 全亮 → 外面**一格厚**的一圈（5×5 减 3×3）看得见墙/楼轮廓 → **其余全黑，包括你白天刚走完整条街**。同一趟出行里，18:00 一过地图整片变黑。

| | 抹掉（现状） | 压暗（建议） |
|---|---|---|
| 夜里能不能看出"这边我去过" | **完全看不出** —— 去过 50 次和没去过一样 | 看得出（极暗轮廓） |
| 夜里能不能看见墙/楼在哪 | 只在弱视野 5×5 圈内；圈外全黑 | **所有去过的地方都留轮廓** |
| 夜里能不能看见敌人/容器 | 看不见 | **同样看不见** ← 紧张感完全不变 |
| 夜里能不能找路 | 只能靠记忆试错；100×100 上等于瞎走 | 能靠地形轮廓走 —— 但看不到危险 |
| 永久记忆有没有意义 | 没有：一天里有一半时间被抹掉 | 有：白天夜晚都认得路 |

**结论：这两个选项在"危险"这一维上一模一样（都看不见敌人和容器），差别只在"认不认得路"。**
"晚上看不清危险"是紧张感；"晚上连路都不认得"是挫败感 —— 后者换不来任何决策，只让你原地打转。
**而且它是 ① 的前提**：雾改永久之后若夜晚照旧抹掉记忆，就会出现"你花一整天摸清了全城，18:00 一到地图又全黑" —— 那"永久记忆"就只值半天。

**两种改法（都还没做，等拍板）**：
- **3a 最小改法（推荐）**：夜晚让"去过的地方"也用 `暗中轮廓`（和弱视野圈同一级），**不新增档、不新增参数**。`暗中轮廓` 本来就只画墙/楼，所以**敌人和容器照样看不见** —— 与现有设计意图（"夜晚弱视野里看不见要翻的东西"）**完全一致**。代价：夜里"去过的地方"和弱视野圈一样亮，可能显得偏亮 → 试玩觉得太亮再上 3b。
- **3b 更暗一级**：新增 `夜暗记忆` 档 + `视野.json` 一个"夜晚记忆压暗"参数，让记忆比弱视野圈更暗。多一个档就要三个面板 + 迷雾层都认它，改动大一档 —— **等 3a 手感不够再说**。

### 3.7 验证（离线）

`Tools/大世界验证` 的「迷雾规则自检」**不跑种子，验的是纯规则**：

| 断言 | 为什么 |
|---|---|
| 10 类实体 × 4 档 的可见性表逐格核对 | 三层共用一份规则，不能漂 |
| ★ **敌人在 `暗记忆` / `暗中轮廓` 里不许被画出来** | 这条原来**真的是错的**（大世界/区域） |
| 玩家在**任何**档下都画 | 令牌被藏起来 = 玩家消失 |
| 位图往返：100×100 / 32×22 / 16×10 三种尺寸，随机集合 + **四角 + 最后一格** | 位图最容易在边界差一位，而试玩发现不了 |
| 界外格码被丢掉 | 不该有，但不能因此错位 |
| 坏 Base64 / `null` → 空集，不抛异常 | 坏档不该让游戏进不去 |

实测：大世界 100×100：2815 格 → 位图 **1668** 字符；区域 32×22：204 格 → **120** 字符；房间 16×10：54 格 → **28** 字符；三者往返一致、四角+末格都在、界外被丢、坏档不崩；失败 0 处。

**两个"接口已留好、就等这一刀"的地方**：① **砸锁 = 预留的"巨响惊动敌人"接口**（`开锁方式 { 钥匙, 撬锁, 砸锁 }` 已占位）→ 噪音系统一落地就能启用；② **`装备管理器.潜行值`（敏捷×2 + 意志 + 配件潜行）全仓库零消费者** → 噪音的"听得见吗"判据就是它的第一个真实用途。

**三个后果**：① **街上等于没人**（16 只撒在 10000 格，密度 0.16%，横穿全图 500 游戏分钟 ≈ 16.7 现实分钟，路上大概率一只碰不到，危险度全压在区域副本内部）；② **赶路是纯跑腿**（敌人不动 → 最优解恒为"直线抄近路"，没有"绕开/清掉/引开/趁夜摸过去"的决策，而大世界恰好是**唯一有昼夜与永久迷雾**的那一层）；③ **沉没属性**（潜行装上去毫无意义）。

### 4.3 三态状态机

```
  ┌──────────────────────────────────────────────┐
  │  静默：蜷在出生点不动；感知半径 ×0.6（蛰伏迟钝） │
  └───┬───────────────────────────────▲──────────┘
 定时(每 N 步概率 p) 或 听到小噪音       │ 到家 + 定时
  ┌───▼───────────────────────────────┴──────────┐
  │  巡逻：在出生点 巡逻半径 内走动（带"归家偏置"） │
  └───┬───────────────────────────────▲──────────┘
 看见玩家 / 听到大噪音(= ≥ 噪音阈值)     │ 到达目标格没找到人
  ┌───▼───────────────────────────────┴──────────┐
  │  追踪：沿流场朝目标格逼近；相邻 → 遭遇（交给战斗）│
  └──────────────────────────────────────────────┘
```

| 迁移 | 触发 |
|---|---|
| 静默 → 巡逻 | 定时（每 N 步掷一次，概率 p）；或听到小噪音（听见但 < 噪音阈值） |
| 静默 / 巡逻 → 追踪 | ① **看见玩家**（§4.5 视觉）② 听到**大噪音**（强度 ≥ `噪音阈值` 且在听觉半径内） |
| 巡逻 → 静默 | 回到出生点附近 + 定时 |
| 追踪 → 巡逻 | ① 到达目标格却**没看见玩家**（噪音引来的空跑）② 丢失目标超过 `警觉步数` |
| 追踪（追玩家）→ 巡逻 | 超出 `追击上限`（离出生点太远，不恋战） |

**"回巢"不是第四个状态，而是巡逻的偏置**：**巡逻步进 = 带"归家偏置"的局部随机步进** —— 从 4 邻可走格加权选一格，权重偏向**离出生点更近**的格；离家 ≤1 格时权重趋于均匀（变成真巡逻）。一条规则同时表达三件事：在家门口溜达、从远处走回来、被小噪音吸引时往噪音方向偏。**不需要 A\*、不需要额外状态、不需要额外数据。**

**追踪的"目标格"是泛化的**：追**玩家** → 目标格 = 玩家当前格（实时更新 → 流场每玩家步重算）；追**噪音** → 目标格 = **噪音发生的那一格**（静止不动 → 这个流场**算一次就能一直用**）。⚠ 这个泛化是选 Flow Field 的直接原因之一：**噪音吸引和追踪玩家共用同一套数据结构。**

**静默态要有"窗口"**：它不是装饰性待机，职责是给玩家一个**第一次接近的空档** —— 感知半径 ×0.6 + 完全不移动 → 玩家能在它没站起来之前摸过去或先手打它。否则 16 只全部巡逻，玩家每次接近都是"被发现 → 挨先手"。

### 4.4 噪音系统（本设计的核心）

```
噪音事件 = (列, 行, 强度 0~100, 层)
```

**不累积、不扩散、不做热力图** —— 每次行为丢一个事件，当场结算一次，结算完就丢。
> 理由：热力图/扩散场（scent diffusion）每 tick 要跑全图 10000 格并衰减，还要处理"局部极大值把敌人卡住"；而本作敌人只需要"朝那边走"，一次性事件就够，且**离线可断言**。

**玩家行为 → 噪音强度**（⚠ 这张表是"设计真源"，不等于"已经接线" —— 哪些真的接了由**代码里的 `噪音强度` 类**说了算，并由 `Tools/探索接线核对.ps1` 第 11 段盯着：每个常量必须有调用方）：

| 行为 | 强度 | 已接 | 备注 |
|---|---|---|---|
| 走一格（点格 / 方向键） | 3 | ✅ | 最轻 —— 连贴脸的敌人都只是"听见"，不会锁定 |
| **大世界「搜索」** | **30** | ✅ | **翻箱倒柜**；成败都响（动作做了，声音不取决于翻出什么） |
| 开枪（枪械） | 90 | ✅ | **全街区广播**；位置取**敌人那一格** |
| 弓弩攻击 | 25 | ✅ | 安静但非无声 |
| 近战攻击 | 15 | ✅ | 闷响 |
| 搜索容器（首次） | 15 | ⏳ | **房间系数 0.35** → 感染者只听得见 **1 格**（贴脸）。E3/E4 连调用点一起加回 |
| 搜索容器（重复翻） | 8 | ⏳ | 翻过的地方动静小 |
| 撬锁 | 22 | ⏳ | 金属摩擦 |
| **砸锁** | **50** | ⏳ | 房间内 ≈3 格；**本刀未启用**（§4.1 第 4 条） |
| 敌人倒下 / 破坏门家具 | 40 / 70 | ❌ | **明确不要**（同格冗余 / 全仓库没有这个动作） |
| 制作 / 阅读 / 睡觉 / 种植 / 净化 | 0 | — | 安全屋内，且不该被惩罚 |

**三档可读**：**≤10** 只有贴脸才听得见 → 潜行路线可用；**15~30** 附近一圈的敌人被惊动 → "翻箱倒柜有代价"但可控；**≥50** **枪声是"全街区广播"** → 带枪的代价第一次真实存在。

| 条件 | 结果 |
|---|---|
| 听得见 且 **强度 < 噪音阈值** | **吸引靠近**：静默 → 巡逻；已在巡逻 → **巡逻方向朝噪音点偏置** |
| 听得见 且 **强度 ≥ 噪音阈值** | **直接进入追踪**（目标格 = 噪音格） |

- **"吸引靠近"不改状态机目标**，只改巡逻的方向权重 → 敌人是"过去看看"不是"锁定你"；到达噪音点附近没发现人 → 继续巡逻（不会永远蹲在噪音点上）。
- **"过阈"是硬升级**：跨过阈值就锁定，朝噪音格走，撞上玩家就开打。

### 4.5 判据（都能离线验）

```
潜行削弱 = 1 − min(0.6, 玩家.潜行值 / 100)          // 封顶 −60%，防"堆成隐身"
实际强度 = 事件.强度 × 层系数 × 潜行削弱             // ★ 潜行作用于**强度**，不是作用于半径
听觉半径 = 敌人.听觉半径 × 实际强度 / 基准(50)
听得见   = 切比雪夫(敌, 噪音点) ≤ max(1, 听觉半径)
过阈     = 听得见 && 实际强度 ≥ 敌人.噪音阈值        // 过阈才"直接进追踪"，否则只是"吸引靠近"
层系数   = 大世界 1.0 / 区域 0.65 / **房间 0.35**    // 房间只有 16×10 —— 不折系数的话"50 强度的声音传 10 格"覆盖整间房
视觉半径 = 敌人.感知半径 × (夜晚 ? 0.5 : 1.0)        // 与玩家视野 7/3 同向
         × (作息不匹配 ? 0.5 : 1.0)                 // 昼行者在夜里、夜行者在白天
         × 潜行削弱
看得见   = 切比雪夫(敌, 玩家) ≤ max(1, 视觉半径)
```

**★ 潜行作用于"强度"而不是"半径"这条判据**：两种写法在"半径多大"上等价，但在**阈值判定**上完全不同，差别正好是玩家会骂的那件事：

| 写法 | 后果 |
|---|---|
| 削半径（原设计） | 潜行再高，你发出的**强度**没变 → `强度 ≥ 噪音阈值` 照样成立 → **"再轻手轻脚，翻个柜子也会被直接锁定"** |
| **削强度**（现在） | 潜行把"你发出的声音"整体变小 → **半径和过阈判定一起变好** |

而且它更符合直觉：**潜行 = 我发出的动静更小**，不是我身上带了个消音罩。
⚠ `潜行值` 基线不是 0：`装备管理器.潜行值 = 敏捷×2 + 意志 + 配件潜行`，裸装（敏捷 5 / 意志 5）= **15** → 默认玩家本来就有 15% 削弱。
**玩家永远比敌人看得远**（玩家 7 > 敌人基础 6）→ 这是**设计意图**（先手，§4.6）。**不做遮挡**：与"方形视野不做遮挡"口径一致。

**已接的 4 种行为的实测效果**（感染者 听觉 10 / 阈值 60；流浪狗 听觉 14 / 阈值 30。`听距(感染者)` = 10 × 实际强度/50，`听距(狗)` = 14 × 实际强度/50）：

| 行为 | 潜行 15（**裸装默认**） | | | 潜行 60（**上限**） | | |
|---|---|---|---|---|---|---|
| | 感染者 | 流浪狗 | 锁定？ | 感染者 | 流浪狗 | 锁定？ |
| 走一格 3 | 1 格 | 1 格 | 否 / 否 | 1 格 | 1 格 | 否 / 否 |
| 大世界搜索 30 | 5 格 | 7 格 | 否 / 否 | 2 格 | 3 格 | 否 / 否 |
| 弓弩 25 | 4 格 | 5 格 | 否 / 否 | 2 格 | 2 格 | 否 / 否 |
| 近战 15 | 2 格 | 3 格 | 否 / 否 | 1 格 | 1 格 | 否 / 否 |
| **开枪 90** | 15 格 | **21 格** | **是** / **是** | 7 格 | 10 格 | **否** / **是** |

→ 三条可读结论：① **枪声的代价是真的**（裸装 21 格内的狗全扑过来）；② **潜行能把感染者从枪声里摘出去**（潜行 60：36 强度 < 60 阈值 → 只"过来看看"不锁定），但**摘不掉狗**（36 ≥ 30）；③ **"随便搜一下"不会招来锁定** —— 即便最敏感的狗，搜索 30 也要在 7 格内（潜行 60 压到 3 格）。

**传播范围**：大世界 ✅ 主战场（100×100，噪音是"赶路张力"的来源）／区域 ✅（32×22 街区，枪声把整条街引过来）／房间 ✅ 仅本房间本层（效果是"翻柜子前先看清屋里有几只"）／**跨层 ❌ 第一阶段不做**。

**逐敌人给值的草案**（"选怪谱"就靠这张表）：

| 敌人 | 听觉半径 | 噪音阈值 | 作息 | 性格 |
|---|---|---|---|---|
| 感染者 | 10 | 60 | 不眠 | 迟钝：小动静不理，枪声才来 |
| 流浪狗 | 14 | 30 | 昼行 | **敏感**：一点动静就扑过来 |
| 尸犬 | 12 | 35 | 夜行 | 夜里难缠 |
| 变异鼠 | 8 | 45 | 夜行 | 视野差、听觉一般，但快 |
| Boss | 6 | 90 | 不眠 | 守在自己房间，巡逻半径 0 |

→ 白天开枪会招来一街的狗；砸锁会引来感染者；而"小动静"对感染者等于没有。同一套系统天然长出了"什么时间、用什么手段、会招来什么"的决策。

**反制手段**：① **潜行**（已有，封顶 −60%）；② **投掷诱饵**（**已拍板：不做，E3 再说**，最经典的潜行玩法）。⚠ 已核对 `Assets/Resources/Data` 全表，**没有**玻璃瓶/易拉罐/砖块这类可投掷物（只有一处 recipe 描述文字提到"铁罐"）；真要做得新增 1 件物品，并同步进搜刮表 + 过 `[物品用途]` 门禁（零来源/无用途是硬失败）；③ **选时机**：夜行/昼行作息 + 7 种天气（雾天视野减半）→ 同样的路，不同时间难度不同。

### 4.6 与战斗 / 分层的接缝

**先手要上移到基类**：现状只有房间层"≥3 格看清过 → 玩家先手"。改：把 `已察觉` + `刷新视野之后()` 从 `房间探索服务` **上移到 `格子探索服务`（三层共用）**。
> **为什么是设计必需**：① 玩家视野 7 > 敌人感知 6 → **玩家理应能先手**；② 噪音让"谁先发现谁"成为核心决策，如果看清了还挨先手，玩家就没有动机用视野与潜行。副作用：`遭遇先手` 从"层语义"变成"层 + 距离"语义。

**三层共用遭遇与战斗收尾**（原全在 `房间探索服务`，现都在 `格子探索服务`），派生只填"这一层的语义"：

| 钩子 | 房间层 | 大世界层 |
|---|---|---|
| `遭遇胜利节点` / `遭遇返回节点` | `__房间胜利` / `__房间返回` | `__大世界胜利` / `__大世界返回` |
| `遭遇日志前缀` | `房间` | `大世界` |
| `遭遇先手(敌)` | ≥3 格看清过 → 玩家先手（`已察觉`） | 基类默认（敌人先手） |
| `胜利之后(尸位)` | 把"挂在敌人身上的钥匙"塞进尸体 | 无 |
| `战斗收尾之后()` | 发 `回到房间事件` | 发 `回到大世界事件` |

**连锁收口（上移后必须一起改，否则出隐蔽 bug）**：① **派生不许再订阅 `战斗结束事件`**（基类构造已订阅，会**触发两遍**）；② `BattleService.返回()` 要认三层的节点名；③ "战后自动弹尸体搜索"的判断要覆盖三层（字段从 `本次战斗来自房间` 改名 **`本次战斗来自本层`**，因为它现在属于基类、三层共用）。

**集群只做"战后堵路口"，不做"多打一"**：战斗发生时按 §4.4 丢一次噪音事件（开枪 90 / 近战 25）→ 战斗结束回大世界时，听见的敌人已经在往这边走（枪战尤其明显）。真正的多打一（`敌人组` 展开）**留作后续**。

**逃跑之后必须留痕**：`战斗逃跑()` 会把玩家退回遭遇前格 → 补一条：**逃跑后敌人保持追踪且 `警觉步数` 不清零**（否则"逃跑 = 免费重置"，逃跑成了万能解）。

**夜间视野与噪音的联动（顺带收益）**：夜晚玩家视野掉到 3，但敌人视觉也 ×0.5、夜行敌人反而 ×1.0 → **同一片街区，白天和夜里是两套难度**。这是"什么时候出门"的第一个真实决策，且不需要任何新机制（作息字段 + 已有昼夜系统）。

### 4.7 驱动源必须是"游戏时间"，不是"玩家走了一步"

| | 第一版（**错**） | 现在 |
|---|---|---|
| 驱动 | 写在 `大世界探索服务.玩家走了一步()` 里 —— 玩家走一步，敌人才走一步 | 挂在 `世界时间管理器.推进() / 跳时()` 上（与 `净化推进` / `生长推进` / `阅读推进` **同一个模式**） |
| 后果 | **站着不动，世界就冻结** | 挂机时按世界时钟继续走 |
| 当时怎么想的 | 把它当"回合制对齐"的取舍写进了文档 | **本作是即时制** —— 这是 bug，不是取舍 |

**节拍口径**：`间隔 = 移动步频 × 每格游戏分钟(5)` = 感染者 15 游戏分钟 / 狗 10 / 鼠 5。玩家在大世界走一格正好消耗 5 游戏分钟 → **走路时与旧口径逐格等价**（走 3 格 ≈ 感染者 1 步）；挂机时世界时钟 30 游戏分钟/现实分钟 → 感染者约 30 现实秒一步（慢，但**不冻结**）。
**累加用整数分钟**（攒够整分钟才算）：与帧率无关，同样的总分钟数 = 同样的步序 → 可离线复现、可断言。一次推进可能跨过好几个节拍（`跳时` 制作 100 分钟就是这样），所以是 `while` 不是 `if`。
**两条门禁盯着它**（`探索接线核对.ps1` 第 11 段）：① 正向：`推进()` **和** `跳时()` 都必须喂时间（只做 `推进()` 的话"制作/阅读期间世界冻结"）；② **反向**：`玩家走了一步()` 里不许再出现 `驱动敌人`（同一个 bug 的入口）。验证器另有断言：**挂机 120 游戏分钟必须有敌人移动过**。

### 4.8 寻路算法选型

| 维度 | 本作的事实 |
|---|---|
| 网格 | 100×100 = **10000 格**，4 连通，**每格代价恒 1** |
| 动因 / 目标 | 大世界 **16 只**；目标**少数几个**（玩家格 + 若干静止噪音格） |
| 更新频率 / 粒度 | 玩家走 1 格（0.3 现实秒）→ 玩家格变（噪音格不变）；敌人每 3 个玩家步走 1 步（离散，不是每帧） |
| 硬约束 / 分层 | **必须确定性**（逐种子断言"同种子同轨迹"）；Domain 层，**零 UnityEngine**，与离线验证器跑同一份 |

| 算法 | 10k 格 / 16 敌 / 单目标 的实际代价 | 确定性 | 结论 |
|---|---|---|---|
| **A\* 每敌每次** | 开放表是线性扫描，单次可达百万级比较 ×16 | ✅ | ❌ **不可用** |
| **Flow Field（BFS 积分场）** | **一次 BFS = 10000 格 × 4 邻 ≈ 4 万次松弛**；每敌取方向 O(1) | ✅ | ✅ **选它** |
| Scent diffusion（逐 tick 扩散衰减热场） | 每 tick 全图 10000 格 + 衰减；4 连通梯度爬升**会卡在局部极大值 / 来回抖** | ⚠ | ❌ 本作不需要"气味残留"，只要"朝那边走" |
| JPS（跳点搜索） | 为 **8 连通**设计；4 连通下收益小、复杂度高得多 | ✅ | ❌ 性价比不划算 |
| HPA\*／分层 | 10000 格根本用不上（1000×1000 才值得） | ✅ | ❌ 过度设计 |
| Dijkstra + 二叉堆（修好 A\*） | 单次 ≈ 4 万次松弛 + 堆操作 | ✅ | ⚠ **备选**，但仍不如流场 |

**为什么选流场**（不是"更快一点"，而是"当前 A\* 实现撑不起多动因高频寻路"，且流场结构上更对）：① **多动因单目标 = 流场的教科书场景** —— 一次积分场算完 16 只各读各的格向量，**O(1)/敌**，敌人从 16 涨到 160 成本**不变**（A\* 是线性乘上去的）；② **它和噪音机制天然是同一个数据结构**（最强的理由）：追踪玩家 = 以玩家格为源的积分场，追踪噪音 = 以噪音格为源的积分场，而"被噪音吸引靠近"本质就是**朝源走的梯度下降** → **一套机制同时实现"噪音吸引"和"追踪"**；③ **确定性天然免费**（BFS 用固定邻居顺序 `横={1,0,-1,0}` 右/下/左/上 → 同输入必得同场同方向同轨迹）；④ **元数据只有两个数组**（`距[]` + `方向[]`），无开放表、无堆、无排序 → 好推理、好断言、好缓存。

**落地方案（懒计算 + 按目标格缓存）**：

```
流场服务（Domain，纯 C#）
  场 = { 目标格, 距[10000], 方向[10000], 障碍版本 }
  取方向(世界, 敌格, 目标格):
      1. 没有该目标格的场 → 现算（BFS）
      2. 场.障碍版本 != 世界.障碍版本 → 重算
      3. 返回 方向[敌格]；不可达 → null（敌人停在原地）
```

| 情形 | 目标格 | 重算时机 | 频率 |
|---|---|---|---|
| 有敌人在**追玩家** | 玩家格 | 玩家换格（0.3 现实秒一次） | 只在**真的有人追**时算 |
| 有敌人在**追噪音** | 噪音格（**静止**） | 障碍变了才重算 | 极低（噪音场几乎是一次性投资） |
| 静默 / 巡逻 | — | **完全不用寻路** | 0 |

→ **实际开销**：绝大多数时间是 **0 次 BFS**（没人追）；有人追时是 1 次 BFS / 玩家步。

**✅ 实测（`Tools/大世界敌人验证` 性能插桩，100×100 开阔场 × 各 50 次取均值）**：

| | 耗时 |
|---|---|
| 流场 一次 BFS（服务**所有**动因） | **0.13 ~ 0.18 ms** |
| A\* 单点查询（二叉堆开放表） | 3.2 ~ 3.6 ms |
| 16 只敌人各自 A\* 的等价代价 | ≈ 50 ~ 58 ms |

**但这里必须诚实**：这 20 倍里有一部分**不是算法的功劳**。A\* 那 3.5 ms 绝大部分花在 `网格数据.占位` —— 它是**对全部实体线性扫描**（大世界 600+ 实体，10000 格 × 4 邻 × 600 实体 = 千万级操作）。流场这边把占格物足迹**一次摊平成了位图**（`建挡表`），格查询变 O(1)：**3.481 ms → 0.144 ms（24 倍）**。
→ **A\* 若也预摊平，单动因场景它其实会赢。** 流场真正不依赖实现质量的胜点只有两条：① **随动因数量摊薄**（16 → 160 成本不变）；② **与噪音机制共用同一个数据结构**（设计上的理由，不是性能上的）。

**缓存策略**：目标格键控缓存，上限 **8**（玩家场 + 最近几个噪音场绰绰有余）。噪音场一旦建立就不变，"敌人循声而来"整个过程可复用同一个场；内存恒定（8 × 10000 × 5 字节 ≈ 400 KB）。**障碍（临时建筑）一变就整体清空。**
**敌人算不算流场的障碍？不算。** ① 算了的话一只敌人堵在窄口会让后面的敌人绕远 / 判不可达（自锁）；② 16 只敌人一动就让场失效，缓存全部作废（高频重算）。敌人之间"不重叠"用**廉价的局部规则**处理：**目标格被别的敌人占了就等一步**（断言⑤保证不会叠）→ 与"障碍版本"无关，不污染缓存。
**"玩家 → 营地门口格可达"**：把玩家当作源跑一次 BFS，检查 `距[营地门口格] != -1`。**注意方向**：流场是"到目标的距离"，所以要**以营地门口格为源**算一次（或同一遍 BFS 里双源），才能判"玩家能不能走回去"。这一步独立于追踪场，只在敌人移动后验一次。

**已拍板：流场为主，同时修 A\* 的开放表**：主干 = `Domain/网格/流场.cs`（BFS 积分场），承担追踪玩家与追踪噪音；同时把 `网格寻路.寻路()` 的 `List<int> 开放` 换成**二叉堆**（约 30 行）—— 它是**既有隐患**不是这一刀的新债。为什么顺手修：① `寻路到相邻()` 会连跑 ≤4 次 A\*，**玩家点一下柜子**就走这条路，收益立刻可见；② 留着它，以后任何人再想用 A\* 都会先踩这个坑；③ 与流场共用一套"确定性打破并列"的口径。

### 4.9 分层、数据字段与"不破连通"

```
Data      数据模型.cs                   敌人数据 增 9 字段
Domain    Domain/网格/流场.cs            新建：BFS 积分场 + 方向数组（纯 C#，零 UnityEngine）
          Domain/大世界/大世界敌人AI.cs   新建：三态迁移 + 噪音结算 + 方向决策（纯函数，掷点由调用方给）
Services  大世界探索服务 / 区域探索服务：驱动（玩家步计数 → 敌人步 → 可达校验 → 同步网格）
          各动作点（搜索/撬锁/砸锁/战斗）发布噪音；格子探索服务：噪音事件通道 + 已察觉上移
```

| 字段（`敌人数据` 新增） | 类型 | 缺省 | 用途 |
|---|---|---|---|
| `感知半径` | int | 6 | 视觉 |
| `听觉半径` | int | 10 | 听觉（强度 50 的声音能被听到的距离） |
| `噪音阈值` | int | 50 | 达到这个强度就不只是"看看"，而是"锁定" |
| `巡逻半径` | int | 8 | 巡逻 + 归家偏置的作用范围 |
| `追击上限` | int | 12 | 追出多远就放弃 |
| `警觉步数` | int | 6 | 丢失目标后还追几步 |
| `移动步频` | int | 3 | 玩家走 N 步，敌人走 1 步 |
| `作息` | string | "" | `昼行`/`夜行`/空 = 不眠 |
| `集群半径` | int | 0 | 同类互相唤醒（0 = 不集群） |

全部**带缺省值** → 34 只敌人不必条条手填。`移动步频` 缺省 3：玩家 5 游戏分钟/格，等速会变成"永远追不上也永远甩不掉"（最无聊的结果）；1/3 速 → **能甩掉，也能被堵**。Boss 的 `巡逻半径 = 0` → 天然"守在自己的房间"，不需要额外机制。

**不破连通（活的墙）** —— 敌人一旦会动，"占格物彼此切比雪夫 ≥2 → 凑不出 8 连通屏障"的论证**就失效了**。四条硬保证（服务层与验证器共用同一份）：

| # | 对策 | 说明 |
|---|---|---|
| 1 | 敌人移动后：**以营地门口格为源跑一次早退 BFS**，玩家格不可达就**整体撤销这一步** | 把"不破连通"变成硬保证（而不是"论证"）。⚠ `敌人挡路` 必须是 **true** —— 用"敌人透明"的场去校验等于自欺 |
| 2 | 敌人**永不进入任何门口格的紧邻八格** | 堵住"敌人堵死营地门口 → 玩家出门即死" |
| 3 | `追击上限`（狗 16 / 感染者 14） | 防"全图敌人被引到营地门口堆成一坨" |
| 4 | 敌人**永不站到玩家那一格** ★ | 遭遇判据是"正交相邻"，同格 = 距离 0 = **遭遇永不触发**，玩家会和它叠在一起走 |

**大世界街道敌人的落点**：`世界模板` 增 `敌人[]`，数据填 感染者×6 / 流浪狗×4 / 变异鼠×3；撒在自由格上，**占格 = true**（挡路）。敌人显示名由**服务层**从 `enemies.json` 补（Domain 不认识数据服务，生成器先塞 `定义标识`）。遭遇 → 战斗 → 胜/败 → 回大世界；打赢留在原地一具可搜尸体（与房间层同一套）。

### 4.10 验证（`Tools/大世界敌人验证`）

| # | 断言 | 类型 |
|---|---|---|
| ① | 同模板 + 同种子 → 跑 50 步后**全部敌人位置指纹逐字节一致** | 硬失败 |
| ② | 同种子 → **噪音结算结果一致**（同一串噪音事件 → 状态迁移一致） | 硬失败 |
| ③ | 任意步数之后：以营地门口格为源，**玩家格可达** | 硬失败 |
| ④ | 敌人**永不**停在任何门口格（营地/区域/临时建筑）紧邻八格内 | 硬失败 |
| ⑤ | 同一时刻**没有两只敌人占同一格**；且敌人**永不站到玩家那一格** | 硬失败 |
| ⑥ | 敌人**永不**越界：静默态 ≤ 1 格；巡逻/追踪态 ≤ `max(巡逻半径, 追击上限) + 1` | 硬失败 |
| ⑦ | 敌人**永不**站在别的占格实体上（墙 / 容器 / 障碍 / 建筑 / 区域） | 硬失败 |
| ⑧ | 流场：同世界 + 同目标格 → `距[]`/`方向[]` **逐字节一致**；`方向[]` 恒指"距 −1"的邻格（无环）；不可走格除吸附源外无距离 | 硬失败 |
| ⑨ | **谓词独立自检**（不依赖模拟的真值表）：`能落子` 12 条 / `碰世界门口` 3 条 / `流场.可走` 4 条 / `流场吸附` 1 条 / `玩家能回营地` 3 条 / AI 三态与噪音 12 条。**自检不过就不跑模拟** | 硬失败 |
| ⑩ | 数量守恒：AI 不会让敌人凭空消失 | 硬失败 |
| ⑪ | 性能插桩（记录值，不设阈值）：单次 BFS 耗时、单次 A\* 耗时 | 记录 |

- `⑧` 是最该有的断言：**方向数组一旦出现环，敌人会原地转圈**，而从游戏里很难看出是"路径算错了"还是"敌人只是在巡逻"。
- `⑨` 不是形式主义 —— `门口保护` 文件头明确警告过"共用谓词改坏会**同时**让生成期与验证期变宽，验证器再也测不出漂移"。`能落子 / 落子 / 流场.可走 / 玩家能回营地` 全是服务层与验证器共用的，所以必须有一张不依赖模拟的真值表。

**★ 验证器实际抓到的 3 个真 bug（设计时都没想到）**：

| # | bug | 根因 | 修法 |
|---|---|---|---|
| ① | 敌人沿**切比雪夫等距圈**原地打转，**永远回不了家**（追完人退回来卡在 18 格外不动） | 超出巡逻半径时只禁了"往外走"，**"平距"仍然权重 1** —— 而四邻里总存在保持距离的横/纵步 | 范围外**连平距一起禁**（`有更近` 时权重 0）；但保留"一个更近的都没有（被墙夹住）就退回普通权重"的兜底。另外"不许立刻回头"在范围外**必须失效**（回家那一格常常正是刚来的那一格） |
| ② | **看得见玩家时"追击上限"被整个绕过**：实测流浪狗追到离出生点 **21 格**还在追（上限 16） | `感知与迁移` 里"看见"是**提前 return** 的，缰绳判定写在 else 分支里 | **缰绳先于视觉判定**：超出上限 = 无论看不看得见都在下一步落回巡逻 |
| ③ | **敌人能走到玩家那一格**，于是遭遇**永不触发**（同格 = 距离 0） | `能落子` 只查了"可通行 + 不碰门口"，没查玩家格 | `能落子` 加第 ③ 条约束。**这是静态"敌人必须占格"那条坑的孪生兄弟**：静态敌人不占格 → 玩家从它身上走过去；动态敌人不避让 → 它贴到玩家身上。**两头都得堵** |

**连通硬保证回滚次数 = 0**（20 种子 × 60 步 × 白天/夜晚 = 1200 玩家步里，敌人一次都没能切断通路）。这是"好消息但不算验证"：安全网**没被触发过** → 它的**效果**要等真被触发才算验过；**断言本身**是活的（`玩家能回营地` 在谓词自检里被"一整排敌人封死"的场景证明有牙）。
