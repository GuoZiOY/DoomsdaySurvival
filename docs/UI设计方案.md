> 对齐规范：`docs/ugui搭建指南.md`（命名核对表）

## 0. 项目现状与设计目标

### 现状

| 层 | 状态 |
|---|---|
| 逻辑层 | ✅ 完整：剧情 / 战斗 / 探索 / 设施 / 存档 / 日志事件总线（M1 框架已装配） |
| UI 代码链路 | ✅ 就绪：`UI管理器` 按 `画布.Find("HUD条/生命")` 等路径查找静态元素，动态填充 |
| UI 视觉层 | ❌ 空白：场景中**没有任何 UI 结构**，只有 Main Camera + 框架引导 |
| 素材 | 已有：Silver SDF 中文字体（含系统字体兜底）、像素边框占位图、Hills 背景图 |

### 设计目标

1. **为文字让路**：这是一款纯文字驱动的 RPG，UI 的最高职责是让文字**好读、有氛围、有节奏**——排版与呼吸感优先于装饰。
2. **一次搭好，长期可扩**：按 `ugui搭建指南.md` 的精确命名搭建静态结构，代码链路零改动即可驱动；未来加设施 = 复制面板改名字 + 加一行 switch。
3. **氛围即玩法**：用「余烬」视觉语言强化《小黑屋》式的沉浸——越玩越亮，从废墟中点亮文明。
4. **交互面板化**：按钮区只放剧情分支选项（叙事分支天然少）；商店/训练场/任务板等设施用**内容密集的列表/网格面板**承载，不做"20 个按钮排队"。

## 1. 设计理念（创意想法）

### 1.1 核心意象：「余烬」——黑暗中的最后一簇火

游戏名《灰烬镇 · 余烬传说》已给出全部答案。UI 不是"界面"，而是一堆**尚未熄灭的余烬**：

- **炭黑（背景）** = 被烧毁的世界，占画面 70% 以上——让玩家感到"世界真的毁了"。
- **余烬金（重要信息）** = 篝火里跳动的火光——标题、金币、关键节点。
- **羊皮纸白（正文）** = 火光映亮的皮肤——剧情文字，是主角。
- **血烬红（危险）** = 火星飞溅——战斗、伤害、死亡威胁。
- **苔绿（希望）** = 灰烬里长出的新芽——奖励、正面反馈、成长。

> 一句话：**一簇火胜过满屏火星。** 所有装饰（边框、分隔线、按钮）都应是"火的痕迹"，克制的暗色，只在关键处点亮。

### 1.2 文字即画面

既然游戏是纯文字，UI 就要把文字"做成画面"：

- **节奏感**：正文行高 1.5~1.6，段间距留白，中文用全角标点自然停顿——读起来像翻羊皮卷。
- **信息着色即叙事**：`（内心）`斜体淡紫 = 角色的心；`→`金色 = 玩家的选择；绿色/红色 = 世界的回应。颜色本身就是剧情。
- **打字机即呼吸**：逐字显示让文字"活"起来，点击跳过给玩家掌控感。

### 1.3 渐进揭示（A Dark Room 精神）

UI 从"空"到"满"，与叙事同步"点亮"：

| 游戏阶段 | UI 状态 |
|---|---|
| 主菜单 | 极简：标题 + 两枚按钮 + 一簇火苗意象，几乎全黑 |
| 序章石屋 | 点亮 HUD（生命/金币），日志栏开始记录 |
| 进入灰烬镇 | 点亮设施入口（商店/训练场/任务板面板） |
| 探索 / 战斗 | 主视窗切换"探索/战斗"模式，正文区变战场播报 |
| 结局 | 主视窗全屏落幕文字，金色饰线收束 |

### 1.4 信息层级如篝火

```
火光（余烬金）   → 标题 / 金币 / 关键节点 / 玩家操作    字体最大，最亮
近焰（羊皮纸白） → 剧情正文 / 当前状态                  字体次大，最白
余烬（系统灰）   → 日志辅助 / 时间戳 / 说明文字          字体小，偏灰
黑暗（炭黑）     → 背景 / 面板底 / 未激活区域            占最多面积
```

### 2.3 圆角与边框（像素余烬风）

- 面板：直角或 4px 小圆角，`1px` 发丝线描边（`#2E2E34`），角落可叠加 8px 金色短线做"烧灼痕"。
- 九宫格：优先使用项目内 `Assets/Resources/界面/像素面板边框.png` / `像素按钮边框.png`（Image Type = **Sliced**，拉伸不糊）；若占位图尺寸不够再自绘 4×4 纯色九宫格。
- 分隔线：`像素分隔线.png` 或 1px 高 `#2E2E34` Image。

### 3.2 面板清单与切换规则

| 面板 | 默认显隐 | 职责 | 来源（`UI管理器.cs` 查找路径） |
|---|---|---|---|
| `HUD条` | 常驻 | 生命/魔力/金币/时间/地点 | `HUD条/生命` 等 5 个 TMP |
| `主菜单面板` | 显示 | 标题 + 新游戏/继续 | `主菜单面板/新游戏按钮` `继续按钮` |
| `主视窗面板` | 隐藏 | 剧情/战斗/探索/结局 共用 | `主视窗面板/标题` `正文` `选项区` `返回主菜单` |
| `日志面板` | 常驻 | 类型化信息流水（可折叠） | `日志面板/日志滚动/日志内容` |
| `商店面板` | 隐藏 | 商品列表（补给/武器/防具） | `商店面板/标题` `商品列表` `返回按钮` |
| `训练场面板` | 隐藏 | 技能列表 | `训练场面板/标题` `技能列表` `返回按钮` |
| `任务板面板` | 隐藏 | 任务列表 | `任务板面板/标题` `任务列表` `返回按钮` |

切换规则（沿用代码）：同一时刻仅一个面板显示（主菜单/主视窗/商店/训练场/任务板互斥），日志面板常驻，HUD 常驻。

### 3.3 设施面板 = 内容密集区（交互模型升级）

- **商店**：`商品列表` 竖排可滚动，每行 = 图标区 + 名称/描述 + 价格金（按钮整行可点）。当前商品 8 件（3 恢复 + 2 武器 + 2 防具 + 1 任务），高度足够，无需分页。
- **训练场**：每行 = 技能名（MP 消耗）+ 描述 + 价格，已学技能行置灰显示"已掌握"。
- **任务板**：每行 = 任务名 + 描述 + 奖励 + 进度徽章（接取 / n/m / 已完成），已完成行绿字置灰。

> 设计原则：**行即按钮**（整行可点、悬停整行高亮），鼠标操作面积大、密度高——这正是设计规格要求的"面板化交互"。

## 4. 组件规范

### 4.1 面板（Panel 基样式）

```
[Image] 半透明炭黑 #151519（Alpha 235）+ 1px 发丝线边框（九宫格 Sliced）
        可选：顶部 8px 金色饰线（宽 96，居中）
```

### 4.2 按钮三态

| 变体 | 常态 | 悬停 | 按下 | 文字色 | 用途 |
|---|---|---|---|---|---|
| 主按钮（金） | 金底 `#D9A441` | 提亮 `#E8B65C` | 压暗 `#B8892F` | 深棕 `#1A1404` | 新游戏 / 主要行动 |
| 次按钮（暗） | 暗底 `#1F1F25` | 悬停 `#2A2A33` | 压暗 `#17171C` | 羊皮纸白 | 剧情选项 / 返回 |
| 危险按钮（红） | 红底 `#C7473D` | 提亮 | 压暗 | 白 | 逃跑 / 危险确认 |

- 全部走 Button 的 **ColorTint**（TargetGraphic = 背景 Image），零代码。
- 可选增强：悬停微放大（`OnPointerEnter/Exit` 改 localScale，协程平滑）——确认后加一个轻量组件 `悬停反馈.cs`。

### 4.3 日志条目

```
[08:24] → 你查看四周。          ← 时间戳(灰) + 类型着色文本
```
- 富文本拼装（代码已实现）：`<color=#5a5750>[时间]</color> <color=#日志色>文本</color>`。
- 自动滚动到底，超 200 条裁掉最旧。

### 4.4 滚动条（日志 / 列表）

- 窄（6px），轨道 `#1C1C22`，滑块 `#3A3A42`，滑块悬停 `#D9A441`（金，微弱存在感）。
- 垂直滚动条放面板内右侧，边缘留 8px。

### 4.5 HUD 数值条（增强项）

- 生命/魔力改为**分节色块条 + 数值**：满格亮、掉血变红闪烁（协程）；金币金；时间灰；地点白。
- 现有代码只驱动文本，增强需在 `UI管理器.cs` 加少量订阅代码（确认后做）。

## 5. 交互与动效（纯 uGUI，零第三方依赖）

| 动效 | 实现 | 触发 |
|---|---|---|
| 面板切换 | CanvasGroup 淡入(0.18s) + 上移 12px 回位 | 打开任何面板 |
| 按钮反馈 | ColorTint 三态 + 悬停 scale 1.03 / 按下 0.97 | 鼠标交互 |
| 打字机 | 协程逐字显示（每字 0.03s），**点击正文跳过** | 进入剧情/探索 |
| 日志新条目 | 淡入 0.2s + 自动滚底 | 发布日志事件 |
| HUD 数值变化 | 变化瞬间闪金/闪红 0.3s（增强项） | 生命/金币事件 |
| 结局 | 主视窗正文整体淡入 + 金色饰线收束 | 打开结局事件 |

> 全部用 `Coroutine + CanvasGroup + Color` 实现，不引 DOTween（与现有代码风格一致，后续想换随时可换）。

## 8. 本方案与「UI Toolkit 迁移规划」的关系

项目设计规格（M2）规划了 UI Toolkit（UXML/USS）。本方案**按你的要求先用 uGUI 落地**，但刻意做到：

1. **配色 Token 与 `游戏主题.cs` 同源**——未来迁 UI Toolkit 时 USS 变量直接映射同一套色值；
2. **结构与代码解耦**——UI 全部为静态搭建，代码只按名字驱动，与 UI Toolkit 的"克隆模板+赋数据"哲学一致；
3. **面板命名与交互模型（按钮区只放剧情选项）已对齐规格**——迁移时只换"皮肤"，不动交互逻辑。

即：**uGUI 是现在能玩、能看的版本；视觉资产与交互模型为未来 UI Toolkit 迁移留好接口。**
