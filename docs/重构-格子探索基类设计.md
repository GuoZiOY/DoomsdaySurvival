# 格子探索基类 · 重构设计（为「区域网格」铺路）

> 目标：把**「格子世界运行器」**（令牌 + 寻路 + 逐格推进 + 视野三态 + 图层 + 实体框）从房间层里切出来，
> 让**区域网格**只填"格子上是什么、点它做什么"就能跑 —— 而不是把房间层那 949 行复制一遍。
> 定位：这是**重构**，不是新功能。每一刀只搬代码、不改规则。

---

## 〇、结论（一句话）

抽 **3 个基类 + 2 组钩子 + 1 个通用算法**：

| 抽出来的东西 | 类型 | 谁来继承/调用 |
|---|---|---|
| `格子探索服务` | 服务基类（纯 C#） | `房间探索服务` / `区域探索服务` |
| `探索网格面板 : 网格面板基类` | UI 基类（MonoBehaviour） | `房间网格面板` / `区域网格面板` |
| `探索图层` | UI 图层基类（MonoBehaviour） | `房间图层` / `区域图层` |
| `约束摆放` | Domain 静态算法 | `房间生成器` / `区域生成器` |
| `网格贴图` | 静态图案工具 | `房间贴图` / `区域贴图` 调用 |

**门 / 锁 / 钥匙 / 搜索 / 战斗参战表** 不下沉 —— 它们是房间层的内容，留在派生类。

## 三、服务侧基类：`格子探索服务`

```csharp
public abstract class 格子探索服务
{
    // ===== 通用状态（原样搬上来，行为不变）=====
    public 网格数据 当前世界 { get; protected set; }
    public 网格服务 网格 { get; protected set; }
    public List<(int 列, int 行)> 当前路径 { get; protected set; } = new List<(int, int)>();
    public string 提示 { get; protected set; } = "";
    public int 玩家列 => 当前世界?.玩家列() ?? 0;
    public int 玩家行 => 当前世界?.玩家行() ?? 0;
    public bool 探索中 => 当前世界 != null;

    protected readonly Dictionary<网格实体, 物品堆叠> 框映射 = new();
    protected readonly Dictionary<string, (int 宽, int 高)> 形状表 = new();
    protected readonly HashSet<int> 已探索 = new();      // 迷雾记忆（当前这一"格世界"的）
    protected HashSet<int> 当前可见 = new();

    // ===== 派生类必须给 =====
    protected abstract 网格数据 造世界(int 种子, string 标识, string 来路);   // 房间：房间生成器；区域：区域生成器
    protected abstract string 地点名();                                       // HUD「地点」位

    // ===== 派生类可拦的钩子（默认什么都不做 = 房间层现有行为）=====
    protected virtual bool 点格拦截(int 列, int 行) => false;   // 区域：点建筑 → 进入建筑（true = 这次点击被消费）
    protected virtual void 抵达格(网格实体 占格物) { }          // 房间：踩到"能过的门" → 转移
    protected virtual bool 抵达后检查() => false;                // 房间：遭遇；区域：街道遭遇
    protected virtual 视野档 档(int 列, int 行);                 // 房间 / 区域 都用（要"全亮"的层才覆写）
    protected virtual bool 有迷雾 => true;                       // false → UI 直接不建迷雾层、档 恒为亮
    protected virtual float 每格现实秒 => 0.30f;                 // 房间 / 区域 都用默认（街上单独定速时才覆写）
    protected virtual string 记忆键(string 标识, int 种子) => $"{种子}#{标识}";
    protected virtual string 实例标识(网格实体 实体) => $"{当前种子}#{实体.标识}";
    protected virtual void 世界切换前() { }                      // 房间：存视野记忆 / 写回门锁态
    protected virtual void 世界切换后() { }                      // 房间：装回记忆 / 重放已解锁门

    // ===== 通用实现（照搬现有代码）=====
    public List<(int 列, int 行)> 算路径(int 列, int 行);
    public bool 点格(int 列, int 行);
    public bool 方向移动(int 偏列, int 偏行);
    public bool 推进一步();
    public void 刷新视野();
    public byte 迷雾态(int 列, int 行);
    public bool 可见(int 列, int 行);
    public bool 已探索过(int 列, int 行);
    protected void 同步网格();
    protected void 同步玩家格();
    public void 发布显示();
    public string 信息条();
    protected void 推进游戏分钟(int 分钟);
    protected void 播报(string 文本);
}
```

**要点**

- 现有 `刷新视野()` 里写死了 `当前房间.视野边长 = 规则.核心边长(时段)` → 基类保留；**房间层与区域层都不覆写**（同一份 `视野.json`）。
- `档()` 的三态逻辑（亮/暗记忆/暗中轮廓/全黑）是通用的，**房间与区域共用**（区域落地时的实际做法，见 §12.7；早期设想的"区域 override 全亮"没有采用）。
- 遭遇段（②）上基类，因为区域层也要"街上撞上"；房间层只填 `参战表`（一个敌人 = 一场遭遇那条规则）和"胜利留尸"。

## 四、UI 侧基类：`探索网格面板 : 网格面板基类`

**搬上来（原样）**：`图层()`、`实体框矩形()`、`点格反馈()`（音效 + 落点圈 + 闪红 + 改画路径）、
`左键格/右键格/悬停格/离开格`、`摆满/摆居中/建名称/建线条/是墙/亮底`、`查找实体/格数/实体色/实体描述`、
拖拽三禁（`完成拖拽=false / 允许跨面板=false / 允许开始拖拽=false`）。

**抽象钩子（房间/区域各自填）**

```csharp
protected abstract void 画实体(物品框 框, 网格实体 实体);                    // 建框：贴图 / 名称 / 描边
protected abstract void 更新画实体(物品框 框, 网格实体 实体, 视野档 档);      // 每帧：显示与否 / 换图 / 压暗 / 文本
protected abstract List<(string 文本, Action 动作)> 菜单条目(网格实体 实体);  // 右键菜单内容
protected virtual bool 是结构件(网格实体 实体) => false;                     // 墙/门/楼梯：不画自己的边界线
protected virtual string 菜单标题(网格实体 实体) => 实体?.名称 ?? "";
```

- `房间网格面板` 从此只剩：墙描边、门框（锁着/开着换图）、容器/尸体、敌人、玩家圆盘 + 搜索/开门/查看菜单 ≈ **250 行以内**。
- `区域网格面板` 只剩：建筑块（占地 + 名称 + 状态色）、道路/障碍、封锁线、玩家圆盘 + 「进入建筑 / 查看」菜单。

## 五、图层侧基类：`探索图层`

**搬上来（原样）**：自建层装配（底盘 → 地表 → 交互 → 物品 → 迷雾 → 路径 → 效果）、每帧 `Update` 调度、
`刷新()`、`刷迷雾()`、`刷路径()`、`跟随玩家/推进移动/开段/格位()`（= 令牌自己走路那套插值）、`悬停/闪红/落点`、`格明度()`。

**参数化**

```csharp
protected abstract Sprite 地表贴图();      // 房间：房间贴图.地板()；区域：区域贴图.地面()
protected virtual bool 有迷雾 => true;     // 区域：false → 不建迷雾层、不刷
protected virtual float 每格现实秒 => 0.30f;
```

**留在派生**：`换了房间()/切房间()`（区域层不需要；区域层换成"换建筑高亮"之类）。

> 注意：`房间图层` 是挂在**同一个物体**上、与 `房间网格面板` 并列的组件（`GetComponent<房间网格面板>()`）。
> 抽成基类时必须是**同一个组件换父类**（`房间图层 : 探索图层`），不能变成两个组件。

## 六、Domain 侧两刀

### 6.1 `网格数据` 瘦身（建议最小改）

现在 `门列表/门内侧格/找门通向/大门/通道格` 都在 `网格数据` 里 —— 区域层用不到，但**不值得大动**。
最小改法：把 `通道格()` 从"入口格 + 门格 + 门内侧格"改成
**"入口格 + 所有『占格=false 的结构实体』（门 / 楼梯）及其内侧格"**，`门内侧格()` 泛化成 `结构内侧格(实体)`。
好处：**加楼梯不用再改它**，区域层也能直接用（建筑入口格就是它）。

### 6.2 `约束摆放` 抽取（收益最大的一刀）

`房间生成器` 里与"摆什么"无关的这套（约 250~300 行）：

```
划区块 / 找区块 / 试放 / 试放敌人 / 位置合法 / 保底可放 / 离通道格距离 / 校验 / 保底布局 / 连通校验与重试
```

抽成：

```csharp
public static class 约束摆放
{
    public sealed class 约束
    {
        public List<(int 列, int 行)> 通道格;   // 不许压的格（入口/门/楼梯及其内侧）
        public int 物件距墙 = 1;
        public float 占格占比上限 = 0.35f;
        public bool 大件优先 = true;            // 先 2×2，再长条，再 1×1
        public bool 要求相邻可站且连通 = true;  // 每个占位物至少一个相邻可站格，且与入口连通
    }
    public static bool 摆(网格数据 世界, int 种子, List<占位物> 清单, 约束 约束);
}
```

区域生成器摆"建筑 2×3 块"直接复用同一套（大件优先 + 区块配额 + 连通校验），**不用重写摆放**。

## 七、区域网格需要什么（对照检查：基类够不够）

| 区域层需求 | 基类给不给 | 派生实现 |
|---|---|---|
| 建筑占多格 + 入口格 | 给（占位/覆盖/形状表） | 建筑的 宽×高 + `入口格` |
| 点建筑 → 进建筑 | `点格拦截` 钩子 | `进入建筑(建筑)` → 开建筑/房间面板 |
| 街道遭遇 | `抵达后检查` 钩子 | 相邻敌人 → `开战(敌)` |
| 战争迷雾 / 视野 | 基类直接给（`视野记忆` + `档()` + `刷新视野()`） | 一行都不用写：同一份 `视野.json`，记忆键 = `种子#区域` |
| 移动节奏 | 基类默认 `每格现实秒` | 0.30 秒/格，**与楼里一致**（街上原来 0.12 秒/格，已按拍板取消） |
| 建筑状态（翻过/锁/尸体） | 记忆表 + `记忆键` 虚方法 | 键 = `区域种子#建筑标识#层` |
| 不出楼的战斗 | 复用 `BattleService.开始战斗` | 棋盘标识 = `街上` |
| 回安全屋清临时数据 | 基类已有（订阅 `打开营地事件`） | 区域层的建筑状态一起清 |

**结论：基类够用；区域层只需要 1 个生成器 + 4 个钩子 + 1 个面板子类。**

## 八、事件与面板管理器

- `房间事件.cs` → `探索事件.cs`：`打开探索事件(探索模式 模式, string 标识, int 种子)`、`探索显示事件(信息条, 列, 行)`、`探索提示事件`。

## 十一、红线（Unity + 验证）

1. **绝不移动任何 `[SerializeField]` 字段**（`房间面板.网格面板`、`网格面板基类` 里那一堆）。
   Unity 按字段路径序列化 —— 字段从派生类搬到基类 = 场景里的引用全丢，你得重新手接一遍。
   基类只**新增**字段；派生类的原字段原样留着，用 `protected virtual` 属性暴露给基类用。
2. **组件类名不许改**（`房间网格面板` / `房间图层` 改名 = 场景里挂的组件变 Missing）。
3. **抽取那一刀不改行为**：数值、规则、UI 文案一个都不动（迷雾/移动/门/搜索）。
4. `房间图层` 与 `房间网格面板` 是**同一物体上的两个组件**，抽基类时是"换父类"，不是"多挂一个组件"。
5. 安全网三件套：`Tools/房间验证`（离线 200 种子 + 结构指纹）、`末日/房间/结构自检`（Unity 菜单）、`网格数据.指纹()`。

# 十二、区域层（第 1 刀）落地记录

> 这是"抽取基类"的直接回报：**区域层没有复制房间层的任何一行交互代码**。

## 12.1 形态：地块制（不自由摆放）+ 相机跟随

区域 = 一张格子世界（**西区 32×22 / 东区 28×20**，格子恒 90px → 2880×1980 px；
相机窗口 1720×960 一屏约看 19×10 格，其余靠相机跟随滚动），内区切成 **2×2 个地块**，地块之间留 **2 格街道**，内区最底留 1 行街道：

```
  ##########################
  #   BBBB         BBBB    #     B = 建筑（4×3 占一个 11×6 的地块 → 地块里大片空地）
  #   BBBB         BBBB    #     + = **楼门**：长在建筑自己底边中间那一格（走上去就进楼）
  #   BB+B         BB+B    #     o = 街道障碍（只在自由街道格上撒，撒完还要连通，否则当场撤回）
  #            o           #     @ = 你（从大地图的荒野节点进来）
  #                        #
  #                        #
  #   BBBB         BBBB    #
  #   BBBB         BBBB    #
  #   BB+B         BB+B    #
  #                        #
  #         @              #
  ##########################
```

### 相机跟随（为什么不做"等比缩小到一屏"）

结构：`面板 → 视口（RectMask2D + 透明 Image）→ 内容（= 挂面板/图层组件的那个物体，装着整个网格）`

| 要点 | 做法 |
|---|---|
| 相机怎么动 | 每帧把**内容**的 `anchoredPosition` 移向"令牌落在视口中心"的位置（`Vector2.Lerp` 平滑），到边夹住 |
| 装得下就不动 | 网格 ≤ 窗口（或多出不到一格）→ 视口按网格铺满、内容居中 → **和没有相机时一模一样**（小房间零变化） |
| 不缩放 | 格子恒 90px：字和图保持原尺寸。等比缩到 0.7 倍会把所有文字一起缩糊，所以不用那条路 |
| 视口从哪来 | 没有 RectMask2D 父节点就在运行时补一层，**照抄内容原来的矩形**（位置/尺寸/pivot）→ 手搭的网格容器不会挪位 |
| 点击怎么办 | ⚠ **RectMask2D 只裁画面、不裁 raycast**：被裁掉的格子照样能点到 → `探索图层.在窗口内()` 里自己拒绝；视口上加一张透明白 Image 吃掉"窗口内但没格子"的点击 |
| 视口大小 | 由 面板 的 `视口` 字段决定（默认 1720×960，填 0 = 自动铺满面板）；网格比它大就滚，比它小就铺满 |

> **格子尺寸是项目统一常量**：`网格面板基类.格尺寸 = 90f`（背包/仓库/容器/穿戴/家具/房间/区域 全是 90）。
> 曾经试过"区域用更小的格子（64px）来多看点地图"，已撤回 —— 现在**只有"区域开多大"这一个变量**，
> 想看更多就靠相机跟随（或调大 `视口`）。

两条设计取舍：
- **门开在建筑自己身上**（`网格实体.门口格`：建筑底边中间那格能站能走，`网格数据.占位()` 对这一格放行）
  —— 直觉上"门是楼的一部分"，而不是"站在楼外面那格才算进门"；
- 为什么用地块制而不是自由摆放：**天然连通、入口必在街上、同种子同布局**，一条重试逻辑都不需要
  （自由摆放会踩两个坑：`约束摆放` 的"彼此隔 1 格"规则和街道直接冲突；楼可能被摆到边界上导致入口落在墙里）。

# 十三、建筑层（第 1 刀）落地记录：楼层 + 楼梯"凸"

> 三层结构到这一段就**全通了**：大地图节点 → 区域网格（点楼门口进楼）→ 建筑（楼层）→ 房间（格子一屏）。

## 13.1 形态与三条硬规则

```
        ┌──────────────────────────┐
        │  # # # # # # # # # # # # │      门   = x/y 轴：本层内横向串联（房间模板.门 声明）
        │  #  . . c c . . . . . . #│      楼梯 = z   轴：**在楼梯那一侧把网格往外多长一格**，
        │  #  . . . . . . . . . . #│              长出来那格就是楼梯间（三面围墙、只有内侧一个口），
        │  #  . . . . . . . . . . #│              全楼同一坐标（建筑种子算一次）
        │  #  . . . . . . . . . . =│  ← 往外长出来的那一格
        └──────────────────────────┘
```

| 规则 | 内容 | 为什么 |
|---|---|---|
| ① 全楼同尺寸 | 每层首间房（楼梯间）的模板尺寸 = `建筑模板.列×行` | 楼梯坐标才能在楼上楼下对齐（外扩那一格由模板尺寸 + 楼梯边推出，各层一致） |
| ② 楼梯坐标全楼相同 | `建筑生成器.楼梯位(建筑种子, 模板)` 按**建筑种子**算一次，各层共用 | 上楼后落点 = 目标层的楼梯内侧格，玩家脑子里的"这一格上面还是这一格" |
| ③ 门只在本层 | `门.通向` 必须也在该层 `房间` 列表里（DataService 校验） | 跨层一律走楼梯；否则楼层状态会乱 |

## 13.2 楼梯间怎么做成"往外延伸一格、只包住它自己"

`房间生成器.造空房` 的顺序：**扩楼梯间（长一格）→ 建墙（楼梯那侧内缩一格）→ 取入口格 → 加楼梯间 → 开门 → 摆物件**。

```
  #####+##########x      · 外墙只有**一堵**（第 15 列），楼梯那行留个门洞（+ 是内门）
  #···········cc·##      · 楼梯间 = 第 16 列那一格（凸出去的），它**上下两格补墙**包住
  #·····!·········=      · 第 16 列其余格子填 **界外**（x：挡通行、不画成墙）
  #·cc·····cc····##      · 外侧是网格边缘 → 渲染时描暗边，看着就是"外墙上鼓出一间小屋"
  #····cc······c·#x
  ################x
```

1. **往外长一格**（`扩楼梯间`）：楼梯边 右/左 → `房.列 += 1`；上/下 → `房.行 += 1`；
2. **建墙内缩**（`建墙(房, 楼梯边)`）：外圈墙建在"原来的边界"上（楼梯那一侧内缩 1 格）→
   **外墙只有一堵**（早先那版把隔墙整列填满，看起来是两堵墙夹一条缝，已改）；
3. **挖门洞 + 放楼梯 + 包住它**（`加楼梯间`）：外圈墙上那一格挖掉当门洞；凸出去那格放 `楼梯` 实体
   （`占格=false`，能站能走）；沿边前后两格补墙；
4. **这一侧剩下的格子填 `界外`**：网格是矩形，不填就会多出"能走却走不到"的空列（连通分量会炸）。
   `界外` 占格但不画（面板跳过这一种），所以视觉上就是"楼外"；
5. **门位避让**：`门位可用()` 把楼梯当"同边上的另一扇门"算（相邻 ≥3 格）；
6. **摆放引擎硬规则**：`位置合法/保底可放` 要求**足迹里不能有墙**（隔墙是"后来补的墙"，外圈墙那条捷径管不到它）
   —— 这条对没有楼梯的房间零影响（房间验证与之前逐字一致可证）。

视觉上：`房间网格面板` 就照常把楼梯贴图铺满那一格（不再需要"放大 1.35 倍 + 朝墙外偏移"那套障眼法）。


## 13.3 楼层 Key：一次派生解决三套状态

```csharp
层种子   = 派生(建筑种子, $"F{层}")
房间种子 = 派生(建筑种子, $"F{层}#{序号}")     // 序号 0 = 楼梯间
```
因为「容器实例 id = 当前种子#实体标识」「迷雾记忆键 = 种子#模板」「门锁态 = 实例标识」全都基于**当前种子**，
**楼层进种子 = 三套状态自动分层**：2F 翻过的柜子不会在 1F 显示"✓"，1F 的迷雾记忆也不会糊到 2F。

**楼层缓存**（`Dictionary<"层#序号", 网格数据>`）：同一趟里回楼上楼下看到的是同一批柜子/尸体/敌人
（不清缓存的话，杀过的敌人会复活、尸体消失）。清空时机：进新楼、出楼、回安全屋（与战局数据同一生命期）。
