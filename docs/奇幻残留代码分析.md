> 结论：**82 个脚本中约 30 个是纯奇幻死代码或需大改，其余可按"保留/改造"复用**。没有必须保留才能运行的"宝藏代码"，但有一批通用框架（设施体系/对话引擎/地图渲染器/词缀生成器）值得改造复用而非推倒重来。
> ⚠️ 删除顺序必须按依赖序：**先删无引用死代码 → 再删被引用但可整体替换的（配合同步改引用方）→ 最后重写核心服务（BattleService/地图服务）**。否则会瞬间编译失败。

## 4. 判断标准（为什么这样分类）

1. **机制 vs 皮肤**：五行克制/魔法附魔/三进制货币/章节主线 = 世界观机制，与丧尸末日冲突 → 删；节点图渲染器/设施接口/对话状态机/事件总线 = 传输与交互机制，与题材无关 → 留。
2. **依赖决定顺序**：`五行` 只有 BattleService 引用 → 先重写 BattleService 再删五行；`货币工具` 只有 装备背包 详情价格 引用 → 先改 UI 再删；`主线阶段` 被 3 个服务引用 → 随三服务改造同步删。
3. **数值体系的取舍**：词缀/品质/稀有度 已深深嵌入 玩家档案 派生属性（最大生命/近战伤害/暴击/闪避/潜行 全部含 `词缀总值`）→ **保留改造**比删除省一个数量级的工作量，且"装备随机词条"完全符合末日 loot 体验。
4. **真正的新代码需求**：只有 3 处需要从零写——① BattleService 战斗公式替换（近战/远程/命中/无敌）；② 地图服务 城市→地点 路由；③ 网格背包面板（真 2D 渲染）。其余全部是"剪裁 + 改名 + 换数据"。
