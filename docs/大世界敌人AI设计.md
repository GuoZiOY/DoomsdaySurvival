1. **街上等于没人**：16 只撒在 10000 格（密度 0.16%），横穿全图 500 游戏分钟（≈16.7 现实分钟），路上大概率一只碰不到。危险度全压在区域副本内部。

## §1 三态状态机

```
              ┌──────────────────────────────────────────────┐
              │                  静默                        │
              │  蜷在出生点不动；感知半径 ×0.6（蛰伏迟钝）    │
              └───┬───────────────────────────────▲──────────┘
   定时(每 N 步概率 p) │                     到家 + 定时
   或 听到小噪音       │                              │
              ┌───────▼───────────────────────────────┴──────┐
              │                  巡逻                        │
              │  在出生点 巡逻半径 内走动（带"归家偏置"）      │
              └───┬───────────────────────────────▲──────────┘
   看见玩家 / 听到大噪音(= ≥ 噪音阈值)              │ 到达目标格没找到人
              ┌───▼───────────────────────────────┴──────────┐
              │                  追踪                        │
              │  沿流场朝目标格逼近；相邻 → 遭遇（交给战斗）   │
              └──────────────────────────────────────────────┘
```

### 1.1 关键简化：**"回巢"不是第四个状态，而是巡逻的偏置**
v1 设计里有独立的"回巢"状态（A\* 走回出生点）。v2 收掉，理由：

> **巡逻步进 = 带"归家偏置"的局部随机步进**：从 4 邻可走格中加权选一格，权重偏向
> **离出生点更近**的格；离家 ≤1 格时权重趋于均匀（变成真巡逻）。

一条规则同时表达三件事：在家门口溜达、从远处走回来、被小噪音吸引时往噪音方向偏。
**不需要 A\*、不需要额外状态、不需要额外数据。**

### 1.2 三态的进入/退出

| 迁移 | 触发 |
|---|---|
| 静默 → 巡逻 | 定时（每 N 步掷一次，概率 p）；或听到小噪音（听见但 < 噪音阈值） |
| 静默 / 巡逻 → 追踪 | ① **看见玩家**（§2.5 视觉）② 听到**大噪音**（强度 ≥ `噪音阈值` 且在听觉半径内） |
| 巡逻 → 静默 | 回到出生点附近 + 定时 |
| 追踪 → 巡逻 | ① 到达目标格却**没看见玩家**（噪音引来的空跑）② 丢失目标超过 `警觉步数` |
| 追踪（追玩家）→ 巡逻 | 超出 `追击上限`（离出生点太远，不恋战） |

### 1.3 追踪的"目标格"是**泛化**的
- 追**玩家**：目标格 = 玩家当前格（实时更新 → 流场每玩家步重算）。
- 追**噪音**：目标格 = **噪音发生的那一格**（静止不动 → 这个流场**算一次就能一直用**）。

⚠ 这个泛化是 §3 选 Flow Field 的直接原因之一：**噪音吸引和追踪玩家共用同一套数据结构。**

### 1.4 静默态要有"窗口"
静默不是"装饰性的待机"，它的设计职责是给玩家一个**第一次接近的空档**：
感知半径 ×0.6 + 完全不移动 → 玩家可以在它没站起来之前摸过去或者先手打它。
否则地图上 16 只全部巡逻，玩家每次接近都是"被发现 → 挨先手"。

## §2 噪音系统（本设计的核心）

### 2.1 噪音事件
```
噪音事件 = (列, 行, 强度 0~100, 层)
```
**不累积、不扩散、不做热力图**——每次行为丢一个事件，当场结算一次，结算完就丢。
理由：热力图/扩散场（scent diffusion）每 tick 要跑全图 10000 格并衰减，还要处理"局部极大值把敌人卡住"；
而本作敌人只需要"朝那边走"，一次性事件就够，且**离线可断言**。

### 2.2 玩家行为 → 噪音强度（全部接现有接口）

| 行为 | 强度 | 接口位置 | 备注 |
|---|---|---|---|
| 走一格（点格 / 方向键） | 5 | `格子探索服务.推进一步()` L262 | 最轻，几乎不引人 |
| 搜索容器（首次） | 25 | `房间探索服务.搜索容器()` L617–623 | 已经在扣行动点 |
| 搜索容器（重复翻） | 10 | 同上 | 翻过的地方动静小 |
| 撬锁 | 35 | `房间探索服务` L372 | 金属摩擦 |
| **砸锁** | **80** | `房间探索服务` L337（**占位已留**） | **本设计一落地，这条菜单就能开**（详见 §0） |
| 大世界「搜索」 | 45 | `大世界探索服务.搜索()` L112 | 翻箱倒柜找临时建筑 |
| 开枪（枪械） | 90 | `BattleService.行动执行` 执行攻击 | **全场都听见** |
| 弓弩攻击 | 30 | 同上 | 安静但非无声 |
| 近战攻击 | 25 | 同上 | 闷响 |
| 敌人倒下 | 40 | `BattleService.伤害与结算.检查单位死亡()` L74 | 惨叫 |
| 破坏门 / 家具 | 70 | 尚无实现 | 预留 |
| 制作 / 阅读 / 睡觉 / 种植 / 净化 | 0 | — | 安全屋内，且不该被惩罚 |

**设计意图（三档可读）**：
- **≤10**：只有贴脸才听得见 → 潜行路线可用。
- **25~45**：附近一圈的敌人被惊动 → "翻柜子有代价"，但可控。
- **≥80**：**枪声和砸锁是"全街区广播"** → 带枪的代价第一次真实存在。

### 2.3 两种作用（严格对应你的要求）

| 条件 | 结果 |
|---|---|
| 听得见 且 **强度 < 噪音阈值** | **吸引靠近**：静默 → 巡逻；已在巡逻 → **巡逻方向朝噪音点偏置** |
| 听得见 且 **强度 ≥ 噪音阈值** | **直接进入追踪**（目标格 = 噪音格） |

- **"吸引靠近"不改状态机目标**，只改巡逻的方向权重 → 敌人是"过去看看"，不是"锁定你"。
  到达噪音点附近没发现人 → 继续巡逻（不会永远蹲在噪音点上）。
- **"过阈"是硬升级**：跨过阈值就锁定，朝噪音格走，撞上玩家就开打。

### 2.4 判据（两条，都能离线验）
```
距离        = 切比雪夫(敌, 噪音点)                        // 与视觉同一把尺，全 AI 只用一把尺
听觉半径    = 敌人.听觉半径 × (强度 / 50) × 潜行削弱     // 强度 50 = 基准；枪声 90 → 1.8×
潜行削弱    = 1 − min(0.6, 玩家.潜行值 / 100)             // 封顶 −60%，防堆成隐身
听得见      = 距离 ≤ max(1, 听觉半径)
过阈        = 听得见 && 强度 ≥ 敌人.噪音阈值
```
- **强度 50 = 基准半径**是刻意的：它让"半径"这个字段有物理含义（"50 强度的声音能传这么远"），
  而不是一个玄学系数。
- **潜行削弱同时作用于视觉与听觉**（§2.5 同一条公式）——这样"潜行"是一个统一属性，不是两套。

### 2.5 视觉（与听觉并列的第二条感知通道）
```
视觉半径 = 敌人.感知半径                       // 白天 ×1.0
         × (夜晚 ? 0.5 : 1.0)                  // 与玩家视野 7/3 同向
         × (作息不匹配 ? 0.5 : 1.0)             // 昼行者在夜里、夜行者在白天
         × 潜行削弱
看得见   = 切比雪夫(敌, 玩家) ≤ max(1, 视觉半径)
```
- **玩家永远比敌人看得远**（玩家 7 > 敌人基础 6）→ 这是**设计意图**，见 §5.1 先手。
- **不做遮挡**：与 `网格视野`"方形视野不做遮挡"的既定口径一致。遮挡要连"楼挡住街 + 楼名画在雾之上"一起做，属于后面的刀。

### 2.6 传播范围
| 层 | 噪音在本层传播 | 说明 |
|---|---|---|
| 大世界 | ✅ 主战场 | 100×100，噪音是"赶路张力"的来源 |
| 区域 | ✅ | 32×22 街区，枪声把整条街引过来 |
| 房间 | ✅ 仅本房间/本层 | 房间小，效果是"翻柜子前先看清屋里有几只" |
| 跨层（房间 → 区域街） | ❌ **第一阶段不做** | 需要"楼层 → 区域内建筑入口格"的映射（`区域生成器` 有入口格概念，可行）；列为第二阶段 |

### 2.7 数据字段（噪音相关）

| 字段 | 归属 | 缺省 | 含义 |
|---|---|---|---|
| `听觉半径` | 敌人数据 | 10 | 强度 50 的声音能被听到的距离 |
| `噪音阈值` | 敌人数据 | 50 | 达到这个强度就不只是"看看"，而是"锁定" |
| `作息` | 敌人数据 | "" | `昼行`/`夜行`/空 = 不眠 |

**逐敌人给值的草案**（"选怪谱"就靠这张表）：

| 敌人 | 听觉半径 | 噪音阈值 | 作息 | 性格 |
|---|---|---|---|---|
| 感染者 | 10 | 60 | 不眠 | 迟钝：小动静不理，枪声才来 |
| 流浪狗 | 14 | 30 | 昼行 | **敏感**：一点动静就扑过来 |
| 尸犬 | 12 | 35 | 夜行 | 夜里难缠 |
| 变异鼠 | 8 | 45 | 夜行 | 视野差、听觉一般，但快 |
| Boss | 6 | 90 | 不眠 | 守在自己房间，巡逻半径 0 |

→ **结果**：白天开枪会招来一街的狗；砸锁会引来感染者；而"小动静"对感染者等于没有。
同一套系统天然长出了"什么时间、用什么手段、会招来什么"的决策。

### 2.8 给玩家的反制手段
1. **潜行**（已有）：降低敌人的视觉与听觉半径，封顶 −60%。
2. **投掷诱饵**（**已拍板：刀61 不做，E3 再说**）：把噪音"放到别处"——最经典的潜行玩法。
   ⚠ 已核对 `Assets/Resources/Data` 全表，**没有**玻璃瓶/易拉罐/砖块这类可投掷物
   （只有一处 recipe 描述文字提到"铁罐"）。真要做得新增 1 件物品，并同步进搜刮表 + 过 `[物品用途]` 门禁
   （零来源/无用途是硬失败）——**刀61 不背这个包袱**，潜行靠"轻装 + 选时机"已经成立。
3. **选时机**：夜行/昼行作息 + 7 种天气（雾天视野减半，见循环设计文档）→ 同样的路，不同时间难度不同。

## §3 寻路算法选型（你问的核心技术问题）

### 3.1 需求特征（先说清楚问题长什么样，才谈得上选算法）
| 维度 | 本作的事实 |
|---|---|
| 网格 | 100×100 = **10000 格**，4 连通，**每格代价恒 1** |
| 动因数量 | 大世界 **16 只**（未来加密度也是同一量级） |
| 目标数量 | **少数几个**：玩家格 + 若干静止的噪音格 |
| 更新频率 | 玩家走 1 格（0.3 现实秒）→ 玩家格变；噪音格不变 |
| 移动粒度 | 敌人每 3 个玩家步才走 1 步（离散，不是每帧） |
| 硬约束 | **必须确定性**（`Tools/大世界验证` 逐种子断言"同种子同轨迹"） |
| 分层 | Domain 层，**零 UnityEngine**，与服务端离线验证器跑同一份 |

### 3.2 候选对比

| 算法 | 10k 格 / 16 敌 / 单目标 的实际代价 | 确定性 | 适配度 | 结论 |
|---|---|---|---|---|
| **A\* 每敌每次** | 见 §3.3：**现有实现的开放表是线性扫描**，单次可达百万级比较 ×16 | ✅（固定展开顺序） | 差 | ❌ **不可用**（理由见 §3.3） |
| **Flow Field（BFS 积分场）** | **一次 BFS = 10000 格 × 4 邻 ≈ 4 万次松弛**；每个敌人取方向是 O(1) | ✅（固定邻居顺序） | **极好** | ✅ **选它** |
| Scent diffusion（逐 tick 扩散衰减的热场） | 每 tick 全图 10000 格 + 衰减；且 4 连通梯度爬升**会卡在局部极大值 / 来回抖** | ⚠ 需额外处理并列与抖动 | 一般 | ❌ 本作不需要"气味残留"，只要"朝那边走" |
| JPS（跳点搜索） | 为 **8 连通**设计；4 连通下收益小、实现复杂度高得多 | ✅ | 差 | ❌ 性价比不划算 |
| HPA\*／分层 | 10000 格根本用不上（1000×1000 才值得） | ✅ | 过度设计 | ❌ |
| Dijkstra + 二叉堆（修好 A\*） | 单次 ≈ 4 万次松弛 + 堆操作 | ✅ | 好 | ⚠ **备选**，但仍不如流场（见 §3.4） |

### 3.3 为什么"每敌一次 A\*"在当前代码下是**真的不行**（硬证据）
`网格寻路.寻路()` 的开放表是一个 `List<int>`，取最小是**每次线性扫描**：
```csharp
var 开放 = new List<int> { 起索引 };
...
int 最佳位 = 0;
for (int i = 1; i < 开放.Count; i++)              // ← 每次出队扫整个开放表
    if (估[开放[i]] < 估[开放[最佳位]]) 最佳位 = i;
开放.RemoveAt(最佳位);                             // ← 还是 O(n) 的搬移
```
（`网格寻路.cs` L41–45；同样的写法在 `寻路到相邻` / `寻路到已知边缘` 里没有复用，但 `寻路` 是主力。）

- 开阔场上 A\* 的开放表长度可达 **数千项**（启发式在无障碍时几乎是"直接冲"，但仍会同时展开等距一圈）。
- 每次出队 O(开放表长度) → 单次 A\* 是 **百万级比较**量级。
- ×16 只敌人 = **千万级比较 / 每次敌人移动**（每 ~0.9 现实秒一次）→ 是可感知的卡顿，不是理论担忧。
- 而且这是在**最不该省的地方省**：玩家点一下柜子只跑一次 A\*（完全无所谓），
  而"16 只敌人同时朝你走"是每 0.9 秒一次的高频路径。

> **结论**：不是"流场更快一点"，而是"当前 A\* 实现撑不起多动因高频寻路"。
> 落地前会用验证器插桩把这两个数字**实测**出来写回本文档（不靠估算定案）。

### 3.4 为什么 Flow Field 不只是"更快"，而是**结构上更对**
1. **多动因单目标 = 流场的教科书场景**。一次积分场算完，16 只各读各的格向量，**O(1)/敌**；
   敌人数量从 16 涨到 160，成本**不变**。A\* 是线性乘上去的。
2. **它和噪音机制天然是同一个数据结构**（这是最强的理由）：
   - 追踪玩家 = 以"玩家格"为源的积分场；
   - 追踪噪音 = 以"噪音格"为源的积分场；
   - 而"被噪音吸引靠近"本质就是**朝源走的梯度下降**。
   → **一套机制同时实现"噪音吸引"和"追踪"**，不必写两套移动逻辑。
3. **确定性天然免费**：BFS 用固定邻居顺序（沿用 `网格寻路` 的 `横={1,0,-1,0}` 右/下/左/上）
   → 同输入必得同场、同方向、同轨迹，与项目"可断言"的纪律一致。
4. **元数据只有两个数组**（`距[]` + `方向[]`），无开放表、无堆、无排序 → 好推理、好断言、好缓存。
5. **顺带修掉一个既有隐患**：`寻路到已知边缘()` 其实**已经是一个 BFS + 父指针**——
   说明流场这套东西在本仓库里**不是新概念**，是既有做法的推广。

### 3.5 落地方案（怎么用，别把 10k 格全算一遍）

**核心原则：懒计算 + 按目标格缓存 + 只有真的需要时才算。**

```
流场服务（Domain，纯 C#）
  场 = {
     目标格,
     距[10000],       // int：到目标格的步数（不可达 = -1）
     方向[10000],     // byte：4 邻中"距最小"的那一个（固定顺序打破并列）
     障碍版本,        // 场失效判据
  }

  取方向(世界, 敌格, 目标格):
     1. 没有该目标格的场 → 现算（BFS）
     2. 场.障碍版本 != 世界.障碍版本 → 重算
     3. 返回 方向[敌格]；不可达 → null（敌人停在原地）
```

**什么时候算：**
| 情形 | 目标格 | 重算时机 | 频率 |
|---|---|---|---|
| 有敌人在**追玩家** | 玩家格 | 玩家换格（0.3 现实秒一次） | 只在**真的有人追**时算 |
| 有敌人在**追噪音** | 噪音格（**静止**） | 障碍变了才重算 | 极低（噪音场几乎是一次性投资） |
| 静默 / 巡逻 | — | **完全不用寻路** | 0 |

→ **实际开销**：绝大多数时间是 **0 次 BFS**（没人追）；有人追时是 1 次 BFS / 玩家步。

### ✅ 实测（刀61 已落地，`Tools/大世界敌人验证` 性能插桩，100×100 开阔场 × 各 50 次取均值）

| | 耗时 |
|---|---|
| 流场 一次 BFS（服务**所有**动因） | **0.13 ~ 0.18 ms** |
| A\* 单点查询（二叉堆开放表） | 3.2 ~ 3.6 ms |
| 16 只敌人各自 A\* 的等价代价 | ≈ 50 ~ 58 ms |

**但这里必须诚实**：这 20 倍里有一部分**不是算法的功劳**。
A\* 那 3.5 ms 绝大部分花在 `网格数据.占位` —— 它是**对全部实体线性扫描**（大世界 600+ 实体，
10000 格 × 4 邻 × 600 实体 = 千万级操作）。流场这边把占格物足迹**一次摊平成了位图**（`建挡表`），
格查询变 O(1)：**3.481 ms → 0.144 ms（24 倍）**。

→ 所以：**A\* 若也预摊平，单动因场景它其实会赢。**
流场真正不依赖实现质量的胜点只有两条：
1. **随动因数量摊薄**（16 → 160 成本不变；A\* 是线性乘上去的）；
2. **与噪音机制共用同一个数据结构**（§3.4 第 2 条，这是设计上的理由，不是性能上的）。

**缓存策略**：目标格键控缓存，上限 **8**（实现取整为 8 而非 4：玩家场 + 最近几个噪音场绰绰有余）。
理由：噪音场一旦建立就不变，"敌人循声而来"整个过程可以复用同一个场；内存恒定（8 × 10000 × 5 字节 ≈ 400 KB）。
障碍（临时建筑）一变就整体清空。

**敌人算不算流场的障碍？** **不算。** 理由：
- 算了的话，一只敌人堵在窄口会让后面的敌人绕远 / 判不可达（自锁）；
- 而且 16 只敌人一动就让场失效，缓存全部作废（高频重算）。
- 敌人之间的"不重叠"用**廉价的局部规则**处理：**目标格被别的敌人占了就等一步**（§7.3 断言⑤保证不会叠）。
  → 与"障碍版本"无关，不污染缓存。

**"玩家 → 营地门口格可达"怎么办？** 与 §6 的一致：把玩家当作源跑一次 BFS，
检查 `距[营地门口格] != -1`。**注意方向**：流场是"到目标的距离"，所以要**以营地门口格为源**算一次
（或在同一遍 BFS 里双源），才能判"玩家能不能走回去"。这一步独立于追踪场，只在敌人移动后验一次。

|---|---|
| 主干 | 新建 `Domain/网格/流场.cs`（BFS 积分场），承担追踪玩家与追踪噪音 |

## §5 与战斗 / 分层的接缝

### 5.1 先手要上移（改一处，三层都受益）
现状：只有房间层"≥3 格看清过 → 玩家先手"（`房间探索服务` L37 `已察觉` / L88 `刷新视野之后` / L602）。
改：把 `已察觉` + `刷新视野之后()` 从 `房间探索服务` **上移到 `格子探索服务`**（与刀8 把"遭遇"上移同一理由）。

**为什么是设计必需**：
- 玩家视野 7 > 敌人感知 6 → **玩家理应能先手**；
- 噪音系统让"谁先发现谁"成为核心决策，如果看清了还挨先手，玩家就没有动机用视野与潜行。
- 副作用：`遭遇先手` 从"层语义"变成"层 + 距离"语义（文档同步）。

### 5.2 集群只做"战后堵路口"，不做"多打一"
- **不做**：把周围敌人一起拉进战斗（推翻 v49 定版的"一场遭遇 = 一个敌人"，且棋盘是 1v1 摆位）。
- **做**：战斗发生时按 §2.2 丢一次噪音事件（开枪 90 / 近战 25）→ 战斗结束回大世界时，
  听见的敌人已经在往这边走（枪战尤其明显）。
- 真正的多打一（`敌人组` 展开）**留作后续**，本设计不碰。

### 5.3 逃跑之后必须留痕
`战斗逃跑()`（`格子探索服务` L546）会把玩家退回遭遇前格。补一条：**逃跑后敌人保持追踪且 `警觉步数` 不清零**
（否则"逃跑 = 免费重置"，逃跑成了万能解）。

### 5.4 夜间视野与噪音的联动（顺带收益）
夜晚玩家视野掉到 3，但敌人视觉也 ×0.5、夜行敌人反而 ×1.0 → **同一片街区，白天和夜里是两套难度**。
这是"什么时候出门"的第一个真实决策，而它不需要任何新机制（作息字段 + 已有昼夜系统）。

### 6.2 不破连通（活的墙）
敌人一旦会动，现有"占格物彼此切比雪夫 ≥2 → 凑不出 8 连通屏障"的论证（`大世界生成器` L311–313）**就失效了**。
四条硬保证（全部实现在 `大世界敌人AI.能落子/落子` 与 `大世界生成器.玩家能回营地`，**服务层与验证器共用同一份**）：

| # | 对策 | 说明 |
|---|---|---|
| 1 | 敌人移动后：**以营地门口格为源跑一次早退 BFS**，玩家格不可达就**整体撤销这一步** | 把"不破连通"变成硬保证（而不是"论证"）。⚠ `敌人挡路` 必须是 **true** —— 用"敌人透明"的场去校验等于自欺 |
| 2 | 敌人**永不进入任何门口格的紧邻八格** | 复用现有 `门口保护.碰世界门口`；堵住"敌人堵死营地门口 → 玩家出门即死" |
| 3 | `追击上限`（数据字段，狗 16 / 感染者 14） | 防"全图敌人被引到营地门口堆成一坨" |
| 4 | 敌人**永不站到玩家那一格** ★ | 遭遇判据是"正交相邻"，同格 = 距离 0 = **遭遇永不触发**，玩家会和它叠在一起走。见 §7 的 bug ③ |

**视野外敌人怎么办（必须处理，否则是显眼破绽）**：只在玩家视野内刷新，会让玩家学会"退后两步敌人就冻结"。
→ **实现选择了更简单的等价做法**：不按视野裁剪，**所有敌人一律按自己的 `移动步频` 照常推进**
（16 只 × 每 3 玩家步一次，代价可忽略），所以根本不存在"视野外冻结"这个破绽，
也就不需要"补走"这一步（原设计 §6.2 的这一条被实现取代了）。

## §7 验证（新增 `Tools/大世界敌人验证`，不改既有断言）

| # | 断言 | 类型 |
|---|---|---|
| ① | 同模板 + 同种子 → 跑 50 步后**全部敌人位置指纹逐字节一致** | 硬失败 |
| ② | 同种子 → **噪音结算结果一致**（给定同一串噪音事件，全部状态迁移一致） | 硬失败 |
| ③ | 任意步数之后：以营地门口格为源，**玩家格可达** | 硬失败 |
| ④ | 敌人**永不**停在任何门口格（营地/区域/临时建筑）紧邻八格内 | 硬失败 |
| ⑤ | 同一时刻**没有两只敌人占同一格**；且敌人**永不站到玩家那一格**（同格 = 距离 0 = 遭遇永不触发） | 硬失败 |
| ⑥ | 敌人**永不**越界：静默态 ≤ 1 格；巡逻/追踪态 ≤ `max(巡逻半径, 追击上限) + 1` | 硬失败 |
| ⑦ | 敌人**永不**站在别的占格实体上（墙 / 容器 / 障碍 / 建筑 / 区域） | 硬失败 |
| ⑧ | 流场：同世界 + 同目标格 → `距[]`/`方向[]` **逐字节一致**；`方向[]` 恒指"距 −1"的邻格（无环）；不可走格除吸附源外无距离 | 硬失败 |
| ⑨ | **谓词独立自检**（不依赖模拟的真值表）：`能落子` 12 条 / `碰世界门口` 3 条 / `流场.可走` 4 条 / `流场吸附` 1 条 / `玩家能回营地` 3 条 / AI 三态与噪音 12 条。**自检不过就不跑模拟** | 硬失败 |
| ⑩ | 数量守恒：AI 不会让敌人凭空消失 | 硬失败 |
| ⑪ | 性能插桩（记录值，不设阈值）：单次 BFS 耗时、单次 A\* 耗时 | 记录 |

`⑧`（流场自身的合法性）是这一刀最该有的断言：**方向数组一旦出现环，敌人会原地转圈**，
而从游戏里很难看出是"路径算错了"还是"敌人只是在巡逻"。

`⑨`（谓词自检）不是形式主义 —— `门口保护` 文件头明确警告过"共用谓词改坏会**同时**让生成期与验证期变宽，
验证器再也测不出漂移"。这一刀的 `能落子 / 落子 / 流场.可走 / 玩家能回营地` 全是**服务层与验证器共用**的，
所以必须有一张不依赖模拟的真值表。**它当场就抓到了一个真 bug**（见下表 ③）。

### ★ 验证器实际抓到的 3 个真 bug（设计时都没想到）

| # | bug | 根因 | 修法 |
|---|---|---|---|
| ① | 敌人沿**切比雪夫等距圈**原地打转，**永远回不了家**（追完人退回来卡在 18 格外不动） | 超出巡逻半径时只禁了"往外走"，**"平距"仍然权重 1** —— 而四邻里总存在保持距离的横/纵步 | 范围外**连平距一起禁**（`有更近` 时权重 0）；但保留"一个更近的都没有（被墙夹住）就退回普通权重"的兜底，否则会永久卡死。另外"不许立刻回头"在范围外**必须失效**（回家那一格常常正是刚来的那一格） |
| ② | **看得见玩家时"追击上限"被整个绕过**：实测流浪狗追到离出生点 **21 格**还在追（上限 16） | `感知与迁移` 里"看见"是**提前 return** 的，缰绳判定写在 else 分支里 | **缰绳先于视觉判定**：超出上限 = 无论看不看得见都在下一步落回巡逻 |
| ③ | **敌人能走到玩家那一格**，于是遭遇**永不触发**（遭遇判据是"正交相邻"，同格 = 距离 0） | `能落子` 只查了"可通行 + 不碰门口"，没查玩家格 | `能落子` 加第 ③ 条约束。**这是 `大世界生成器.撒敌人` 里"敌人必须占格"那条坑的孪生兄弟**：静态敌人不占格 → 玩家从它身上走过去；动态敌人不避让 → 它贴到玩家身上。**两头都得堵** |

**连通硬保证回滚次数 = 0**（20 种子 × 60 步 × 白天/夜晚 = 1200 玩家步里，敌人一次都没能切断通路）。
这是"好消息但不算验证"：安全网**没被触发过** → 它的**效果**要等真被触发了才算验过；
**断言本身**是活的（`玩家能回营地` 在谓词自检里被"一整排敌人封死"的场景证明有牙）。

## §10 与 v1 的差异（改了什么、为什么）

| 项 | v1 | v2 | 为什么改 |
|---|---|---|---|
| 状态机 | 游荡/警觉/追击/回巢（4+1） | **静默/巡逻/追踪（3）** | 按用户拍板收敛；"回巢"折叠成巡逻的**归家偏置**，少一个状态少一条规则 |
| 寻路 | 追击用 A\* | **Flow Field 流场** | §3.3 的硬证据（现有 A\* 开放表线性扫描，16 敌撑不起）；且流场与噪音是同一个数据结构 |
| 噪音 | 只是一个"听觉系数表" | **独立成章**：事件 / 强度表 / 双作用（吸引 vs 过阈）/ 判据 / 传播 / 反制 | 用户点明这是核心机制；它同时给了 `潜行值` 和 `砸锁` 占位一个归宿 |
| 巡逻 | 纯随机游走 | 随机 + **归家偏置 + 噪音偏置** | 一条规则同时表达巡逻/回巢/被吸引 |
| 砸锁 | 未提 | **明确接上**（占位代码已在 `房间探索服务` L337） | 那是全仓库唯一一处"等噪音系统"的显式占位 |
