# 核心玩法循环闭路设计

> 状态：**设计稿**。回答"游戏核心玩法流程是否循环闭路"。断点一已作废（"87 天"是随便拟的题），**断点二/三仍未修**。
> 姊妹篇：`docs/设计-大世界.md`（"赶路"那一段的张力来源）。
> 只记**已查实**的现状与断点（数据 + 代码，带位置，不猜）。

---

## §0 结论

**不闭路。** 环与环之间的"管道"绝大多数已经接好了 —— 时间、生存消耗、行动点（趟预算）、成长、消耗水槽、挑战阶梯（7 区域分级 + 7 Boss + 精英）都在跑。

**两个仍然成立的断点**，是同一条病的两个症状：

| # | 断点 | 性质 | 一句话证据 |
|---|---|---|---|
| 二 | **情报系统是悬空器官** | 半成品 | `情报.json` 21 条 + `安全屋管理器.尝试收听()` **零调用方** + `解锁条件["情报"]` 被数据校验直接判错 |
| 三 | **区域门槛是装饰性的** | 结构空洞（已实测） | 5 把区域钥匙**全部**能在开局可进的 2 个区或大世界临时建筑里拿到 → 闭包第 1 轮 7/7 区域全解锁 |

- 断点三 → 去危险区**不需要资格**（钥匙不值钱）。
- 断点二 → 唯一一条"从外界获得信息"的通路是**断的**（收音机不响）。

**断点一（"87 天"倒计时）已作废**：用户拍板"**87 天只是一开始随便拟的题，不用理会**"——
本作当前形态 = **让玩家存活越来越久，没有时间上限**；明确主题 / 剧情模式**后续再确立**。

**用户补充定性**：核心玩法的流程闭路上**还有大量功能与系统缺陷**，本轮不追求"补完"，由后续各刀慢慢补。
本文档的职责是**把已经查实的断点记下来**，不是一次做完。

## §1 逐环审计

| 环 | 现状 | 位置 | 闭合 |
|---|---|---|---|
| **时间成本** | 大世界 5 游戏分/格，楼里/区域 1 分/格；1 现实分 = 30 游戏分 | `大世界探索服务`、`世界时间管理器` | ✅ |
| **生存消耗** | 饱食/水分每游戏时各 −2（体质/天赋修正）；寒潮→感冒；雨→补水；酷暑→耗水 | `世界时间管理器` | ✅ |
| **趟预算（行动点）** | 搜索 10（+4/次）、制作 5、技能消耗；睡觉回满 | `世界搜索参数`、`生存管理器` | ✅ |
| **硬失败** | 战斗倒下 → 掉 10% 价值物资 + 回营地半状态 → **生命保底 1，不会死** | `BattleService.回派`、`生存管理器` | ⚠ **无失败** |
| **提升** | 经验/等级（每级 3 点）/技能/天赋/装备品质/配件 | `成长管理器` | ✅ |
| **消耗水槽** | 食物水、弹药、耐久损坏、制作与家具升级材料 | 各服务 | ✅ |
| **解锁链** | 7 区：2 区开局可进，5 区靠 5 把钥匙 + 第 10 天 | `世界.json` | ⚠ **见 §3（实测穿帮）** |
| **挑战阶梯** | 敌人 Lv1~5 威胁带、7 个 Boss（3F 前室 + 上锁 Boss 房）、精英 | 数据 | ✅ |
| **天气** | 7 种，**只有 寒潮/雨/酷暑 有机械效果**；晴/雾/雷雨/沙暴 纯显示 | `世界时间管理器` | ⚠ **4/7 半闭（见 §4）** |
| **终局** | **无时间上限**（已拍板，非缺陷）；收束方案未定 | — | ⏸ |
| **情报** | 见 §2 | — | ❌ **断** |

## §2 断点二：情报系统是悬空器官

### 2.1 证据

| 事实 | 位置 |
|---|---|
| 数据存在：**21 条**情报，字段只有 `{文本, 等级}` —— **连"标识/标题"都没有** | `情报.json`；`数据模型.情报条目` |
| 加载了：`DataService.加载情报()` → `数据.情报` 列表 | `DataService` |
| **唯一的功能入口零调用方**：`安全屋管理器.尝试收听()` —— 全仓库没有任何地方调它（安全屋面板没有"收听"按钮） | 递归核对确认 |
| 即使调了，也**不读情报池**：它只做 `玩家.预知天气 = Random(...)` | 同处 |
| `预知天气` 是活的：跨天时优先采用，然后清零 | `世界时间管理器` |
| `解锁条件["情报"]` 被判成**数据错误** | `DataService`（"情报系统还没有'已获得'的记录 → 写了就是一道打不开的门"） |
| 情报文本里还写着**过时地名** | 例："东区夜里传来枪声"（现名**城东学区**）、"城北的超市"、"西部安全区"——改区域名时情报没跟 |

**所以现状是**：一个 21 条的叙事系统，数据齐、加载齐、家具齐（收音机 Lv1~3）、天气预知那半条腿是活的，
但**"听广播"这个动作玩家做不到，"听到的内容"代码不读，"拿情报当钥匙"被校验禁止**。

### 2.2 设计

| 步 | 内容 | 规模 |
|---|---|---|
| 1 | `情报条目` 增 `标识` + `标题`（21 条各补一个；**标识是解禁解锁条件的前提**） | 数据 |
| 2 | 安全屋面板加「收听收音机」（调已存在的 `尝试收听()`）→ 按 `收音机` 等级过滤（`等级 ≤ 家具等级`）→ **播报进日志 + 记入 `玩家档案.已获得情报 List<string>`**（新字段） | 小 |
| 3 | 保留"预知明日天气"（已实现，别丢） | — |
| 4 | **解禁 `解锁条件["情报"]`** → 把 1~2 个区域从"物品"改成"情报"（更有味道：你是**听说**那里才去的，不是捡到一张地图） | 小 |
| 5 | 情报文本跟随区域改名更新（城东学区 / 城西政务区 / 户外用品店…） | 数据 |
| 6 | （可选）情报做**地图标记**：播报"纺织厂那边有动静" → 大世界对应区域格在迷雾里亮一个问号 | 中 |

**为什么这条值得做**：它是唯一一条"从外界获得信息"的通路 —— 收音机是这个世界的**唯一活着的器官**；
它不响，玩家就只是在空城里翻柜子。**成本极低，叙事收益极高。**

## §3 断点三：区域门槛是装饰性的（**实测数据，不是推测**）

### 3.1 链路是完整且唯一的（这是好消息 —— 意味着可以做门禁）

```
世界.json 区域[].解锁
  → 区域模板.建筑[] → 建筑模板.楼层[].房间[] → 房间模板.容器池[]
      → (地图类型, 房间) → 搜索_地图类型.容器[].搜索表[].物品标识
  （+ 区域模板.敌人[] → enemies.json.掉落物品/掉落列表）
```

### 3.2 结果

**① 闭包：7/7 区域可达，但全部在"第 1 轮"就解锁**

| 区域 | 危险度 | 解锁条件 | 实际第几轮解锁 |
|---|---|---|---|
| 居民区 | 1 | （开局可进） | 0 |
| 西区 | 3 | （开局可进） | 0 |
| 东区 | 2 | 物品:旧地图 | **1** |
| 商业区 | 2 | 物品:城市地图 | **1** |
| 医院区 | 3 | 物品:账本 | **1** |
| 警察局区 | 4 | 物品:机密文件 | **1** |
| 工厂区 | 5 | 物品:相机 + 天数 10 | **1**（天数不阻断） |

**② 5 把钥匙全部能在开局两区里拿到 → 门一道都没拦住人**

| 钥匙 | 白名单临时建筑能刷出？ | 开局两区（西区/居民区）有来源？ |
|---|---|---|
| 旧地图 | ✅ **9 处** | ✅ 西区 9 处 / 居民区 9 处 |
| 城市地图 | ✅ **10 处** | ✅ 西区 8 处 / 居民区 6 处 |
| 账本 | ✅ **2 处** | ✅ 西区 3 处 / 居民区 2 处 |
| 相机 | ✅ **10 处** | ✅ 西区 11 处 / 居民区 6 处 |
| **机密文件** | ❌ 0 处（白名单刷不出） | ✅ **西区 2 处** |

**③ 门槛与危险度错配**

- **西区危险 3，却开局可进**（玩家 1 级就能进危险 3 的区）。
- 唯一的"天数"门只有工厂区一处（第 10 天）。
- 钥匙的**出现密度并不低**（例：旧地图在西区 9 处 / 1137 条条目，权重 9/2015），
  而这是**单条目权重占比**，一个容器会抽多件 → 实际远比这个比例容易撞上。**"稀有"不足以构成门槛。**

### 3.3 这和 v52 修过的洞是**同一类**

之前修过一次"第 1 天就能在门口刷出手枪弹/血清/军刀图纸"——做法是**给临时建筑加楼型白名单**。
那次堵的是"**楼型**越级"，这次漏的是"**钥匙物品的掉落位置**"越级：白名单楼型本身是干净的，
但**钥匙物品被撒进了这些地图类型的容器里**。

### 3.4 设计

| 步 | 内容 |
|---|---|
| 1 | **钥匙物品改成"区域专属来源"**：每把钥匙只出现在**指定区域的指定容器**里。例：<br>· `旧地图` → 居民区/商业区的 报刊架、后备箱、信箱<br>· `账本` → 医院区的 值班台、分诊台（**只有医院有账本**才对）<br>· `机密文件` → 警察局区的 证物架、值班台<br>· `相机` → 商业区/东区的 收银台、器材抽屉 |
| 2 | **从大世界临时建筑白名单的地图类型里剔掉所有 5 把钥匙**（`允许地图类型` 那 5 类的容器搜索表逐条核对） |
| 3 | **门槛与危险度对齐**：危险 1 开局 → 危险 2 靠 1 把钥匙 → 危险 3 靠 2 把 → 危险 4/5 各加一个**天数门**（危险5 已有第 10 天）<br>· 西区：要么降危险度，要么加天数门（**建议加天数门**，保留"城西政务区危险 3"的定位） |
| 4 | **新门禁 `[解锁钥匙]`**（`Tools/数据引用核对.ps1`）：<br>① 每把钥匙的**来源区域集合**必须 ⊆ {开局可进区} ∪ {该钥匙解锁的区域的下游}（即：不能只在自己解锁的区里刷出来 → 那是死锁）<br>② 每把钥匙的来源里**不得出现**大世界临时建筑的允许地图类型<br>③ 闭包断言：7/7 区域可达，且**解锁轮次 ≥ 1 的区数 ≥ 5**（防止"第 1 轮全解锁"再次发生） |

> 本次审计用的脚本逻辑（区域→建筑→楼层→房间→容器池→搜索表→闭包 BFS）已经跑通，
> 落地时**直接落成 `.ps1` 门禁**，不重新发明：把"一次性审计"变成"永久断言"。

## §4 天气补全（补 §1 表的半闭项）

现状：7 种天气，**只有 3 种有机械效果**（寒潮→感冒判定 / 雨→补水 / 酷暑→耗水），其余 4 种纯显示。

| 天气 | 现在 | 建议 | 为什么是这个效果 |
|---|---|---|---|
| 晴 | 无 | 视野 +1 格 | 通透；也让"晴"不是一个空档期 |
| 雨 | 补水 | **噪音传播 −25%** | 雨声掩蔽 → **雨天是潜行日**（与 `docs/设计-大世界.md` 天然咬合） |
| 雾 | 无 | **视野边长 ×0.5**（最低 3）+ 敌人视觉 ×0.5 | 雾天 = 双方都瞎 → 潜行与遭遇战规则被改写的一天 |
| 雷雨 | 补水 | 同上（雨 + 偶发落雷，落雷先不做） | — |
| 寒潮 | 感冒判定 | 保持 | 已闭 |
| 沙暴 | 无 | 视野 ×0.5 + **大世界每格耗时 5 → 8 游戏分钟** | 让"要不要今天出门"第一次有分量 |
| 酷暑 | 耗水 | 保持 | 已闭 |

**注意**：`视野边长` 现在是 `视野规则`（读 `视野.json`）按"角色 + 时段"算的纯函数。
加天气输入 = 把天气作为**第三个入参**接进去，**一处改三层都变**（房间/区域/大世界共用同一个 `视野规则`）。
⚠ 这会**改变既有验证断言的输入域**（`视野验证` 之类）→ 落地时要同步扩验证（定过"验证规模冻结"，所以是**新增**不是修改）。

| 门禁 | 断言 | 归属 |
|---|---|---|

## §6 待拍板

   门槛立起来之后，"今天够不够格去警察局区"才是一个真问题。
