# 功能面板重设计（面板差异化布局）

> 日期：2026-08-17 ｜ 状态：设计中（逐面板确认，本文档累计记录）
> 背景：现状全部功能面板依赖「通用按钮预制体 + 创建行」的单一列表形态，内容和布局被按钮列表锁死。
> 目标：每个功能面板 = 场景手工搭建的专属结构（Inspector 拖拽绑定），代码只做「填数据 + 订阅事件 + 响应交互」。
> 实施节奏：**一次只做一个面板**，逐面板落地（代码先行，场景由开发者按接线指南手工搭建）。

---

## 1. 总体原则（所有面板通用）

| 原则 | 含义 |
|------|------|
| **基类瘦身** | `设施功能面板基类` 只保留语义：打开上下文注入（逻辑/节点/返回节点）、标题、返回按钮、`回退()`。**移除「内容区 + 渲染列表 + 创建行」的强制形态**，改由子类自定义 `渲染内容()`。 |
| **面板专属结构** | 每个面板在场景手工搭建自己的布局（信息区/导航区/列表区/操作区），代码 `[SerializeField]` 拖入引用，不用路径字符串查找。 |
| **行模板化** | 需要列表的面板，自己做「行模板」预制体（名称/描述/价格/按钮分字段），代码克隆模板 + 填数据。不再是共享按钮预制体。 |
| **数据接口不变** | `买卖功能/训练功能/教学功能/任务功能` 接口保持返回数组；排序/分区/筛选都是面板侧的事。 |
| **共用与差异化** | 同一功能多设施共用（如买卖 = 商店/武馆/学堂），差异化靠设施自己的筛选（`可购商品` 判定），面板结构一套。 |

### 1.1 基类改造目标形态

```csharp
public abstract class 设施功能面板基类 : 面板基类
{
    [SerializeField] protected TMP_Text 标题;
    [SerializeField] private Button 返回按钮;
    protected 设施逻辑 逻辑;
    protected 地图节点 节点;
    protected string 返回节点;

    protected virtual void Awake()
    {
        返回按钮?.onClick.AddListener(返回设施内部);
        // 需要订阅全局事件的子类在此订阅（金币/属性变化等）
    }

    protected override void 刷新(object 上下文)
    {
        if (上下文 is 设施打开上下文 c) { 逻辑 = c.逻辑; 节点 = c.节点; 返回节点 = c.返回节点; }
        if (逻辑 == null) return;
        if (标题 != null) 标题.text = 标题文字();
        渲染内容();          // 子类自建布局、填数据（不再强制清空内容区+创建行）
    }

    protected abstract string 标题文字();
    protected abstract void 渲染内容();
    protected void 返回设施内部() { if (节点 != null) 事件.发布(new 打开节点内部事件(节点, 返回节点)); }
    public override void 回退() => 返回设施内部();
}
```

## 2. 商店面板（买卖面板）—— ✅ 已确认 · 已实现（货架行 + 详情区）

> 服务设施：商店（酒馆）/ 武馆兵器 / 学堂魔法物 —— 结构共用，商品与**收购**内容由各设施决定。
> 已确认决策：**购买/卖出共用同一块区域 + 同一个滚动列表**（Tab 点击只换内容）；货架行只做简洁展示，详细信息与操作按钮在详情区；
> **排序 4 键**（默认/价格/品质/名称），价格/品质/名称点击切换方向（箭头 ↑↓ 换图），再点同键反转；
> **卖出筛选由设施决定**（商店什么都收 / 武馆收装备 / 学堂收魔法物）；行拆专用组件（`商品行`/`卖出行`）。
> 实现：`UI/功能面板/买卖面板.cs` 重写 + `商品行.cs`/`卖出行.cs` + `Services/设施/买卖逻辑.cs`（可卖物品按判定筛选）+ 三设施各自收购筛选 + `UI/系统面板/物品工具.cs`。

### 2.3 行为逻辑

- **共用列表**：购买/卖出 Tab 只切换"显示购买"标志 → 重建同一个 `列表容器`（商品行 ↔ 卖出行），区域与滚动列表不重复。
- **排序 4 键**：默认=数据顺序；价格/品质/名称键点击——若当前就是该键则**反转方向**（箭头 ↑↔↓ 换图），否则切到该键（用其当前方向）。价格默认升、品质默认降（传奇在前）、名称默认升。
- **卖出筛选由设施决定**：`买卖逻辑.可卖物品(判定)` 按判定过滤（且 价格>0）；商店=什么都收（非任务）、武馆=装备类、学堂=恢复/技能书/材料。
- **余额**：订阅 `金币变化事件` 只刷新余额；**背包变化事件** → 重建当前列表（买入入包/卖出扣物后卖出列表实时变）。
- **详情区**：点击行选中（选中图高亮）→ 品质名/名称/描述/数值（`物品工具.数值文本`）/价格 + 操作按钮（买入/卖出）；卖出卖光自动清除选中态。
- 数据来源不变：`买卖功能.可购商品()` / `可卖物品()`（设施筛选）。

### 2.4 实现要点

- 专用行组件 `商品行`/`卖出行`（各含 选中图）；通用 `模板行.cs` 已退役删除。
- `买卖面板.cs`：共用 `列表容器`，`渲染列表()` 按 `显示购买` 建 商品行/卖出行；排序状态 = 当前列 + 各列方向 bool；箭头换图。
- 设施收购：`买卖逻辑.可卖物品(判定)`；商店/武馆/学堂各自传判定（面板侧无感知）。

## 7. 角色面板 —— ✅ 已确认 · 分期实现（全局面板，非设施面板基类）

> 全局：HUD 按钮打开（`打开角色面板事件`），返回回到上个面板（面板管理器 `返回上一面板`）。
> 已确认决策：**2 个 Tab 子按钮切换**——[属性] 一个面板、[装备/背包] 一个面板；不显示经验（只显示等级 + 自由属性点）；行尾 `[+]` 加点；装备槽 + 换装列表。
> **子面板组件化**：每个 Tab 页 = 独立组件（`属性子面板` / `装备背包子面板`），字段内聚在子面板里，**自订阅事件刷新**；父面板 = 薄编排器（标题 + Tab + 返回 + 2 个子面板引用），避免参数暴露过多。
> **属性页 = 静态引用布局（无预制体实例化）**：四维数值文本/加点按钮/派生能力数值文本全部 Inspector 直接引用，原地更新数值。
> **分期**：阶段一（本次）只做 [属性] 子面板新布局，[装备/背包] 暂维持旧列表样式；阶段二再做 [装备/背包]（只改 `装备背包子面板` 内部，父面板零改动）。
> 实现：`UI/角色面板.cs`（薄编排器）+ `UI/属性子面板.cs` + `UI/装备背包子面板.cs` + `UI/面板操作.cs`（加点/换装/技能书/恢复 共用操作）。

### 7.3 行为逻辑

- **刷新职责**：子面板自刷新——`属性子面板` 订阅 `属性/生命/魔力变化事件` 原地更新数值；`装备背包子面板` 订阅 `背包变化事件` 重建列表；父面板只切 Tab。
- **属性页（静态引用）**：`刷新()` 直接写数值进对应 TMP_Text；自由点 > 0 时显示加点按钮，否则隐藏。加点 → `面板操作.加点`（`档案.加点` + 发 `属性变化事件`）→ 事件驱动再刷新。
- **装备页**：顶部两个装备槽（武器/防具）显示当前装备 + 加成；下方背包中武器/防具行 `[装备]` → `面板操作.换装` + 刷新；已装备的行标记 `[已装备]` 不可再点。（阶段二）
- **背包页**：恢复品 `[使用]`、技能书 `[学习]`（`面板操作`，成功才消耗书本）；任务/材料类纯展示。（阶段二）
- **返回**：`面板管理器.返回上一面板()`（回到打开前的面板）；全局右键 = 返回。

### 7.4 实现要点

- 不继承 `设施功能面板基类`，直接继承 `面板基类`（无 设施打开上下文）。
- 打开上下文：`打开角色面板事件`（空载荷）；HUD 的 `打开角色按钮` 发布该事件。
- **子面板组件**：`属性子面板` / `装备背包子面板` 都是普通 MonoBehaviour（挂 Tab 页物体上），自订阅事件 + `OnEnable` 兜底刷新；父面板字段从 ~16 降到 ~5，参数不爆炸。
- **面板操作静态类**：加点/换装/卸下/技能书/恢复品 由 `面板操作` 统一提供，子面板与回退路径共用，无重复实现。
- **属性页零实例化**：固定结构（4 属性行 + 6 能力行）直接引用——「静态引用」面板的示范，区别于商店面板的「行模板克隆」。

### 7.5 背包/装备框架决策（8 槽，已实现）

**已敲定的框架决策：**

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 背包表现 | **行列表（文本）+ 详情区** | 文字游戏身份、零美术成本、长名不截断；与商店面板行风格统一。图标网格留作将来增强（`物品数据.图标` 字段 + 网格视图，存储/存档不受影响） |
| 行组件策略 | **固定结构数组引用 / 无界列表行模板** | 背包列表（数量不定）用 背包行 模板克隆；装备槽（固定 8 槽）直接并入 `装备背包子面板` 的 `装备槽引用[8]` 数组（文本+按钮，索引=槽位顺序）——**不单独拆组件**（数组已收敛参数，避免多余层级）；槽名场景静态标签；属性页同理 `属性行引用[4]` + `能力值[6]` |
| 背包行内容 | **只承载三样：名字（含品质标签）/ 数量 / 选中图** | 品质与名字合并为一个文本（`[稀有] 铁剑`，中间空格，`物品工具.品质名称`）；行本体是 Button（只做点击选中；双击=快速操作）；描述/数值/价格/操作一律由右侧详情区承载 |
| 装备槽交互 | **可点击，进详情区** | 点装备槽 → 选中进详情区（显示已装备 + [卸下]）；双击 = 快速卸下 |
| 装备数据归属 | **转移（装备 = 唯一归属）** | 换装 = 同槽旧件回背包 + 新件入槽 + 背包扣 1；卸下 = 清槽 + 背包加 1（堆叠合并） |
| 商店购买 | **一律入背包，不自动装备** | 商店只做买卖；装备统一走角色面板 [装备]，永不覆盖、不丢装备 |
| **槽位清单（8 槽）** | 主手 / 副手 / 头盔 / 盔甲 / 靴子 / 手套 / 饰品Ⅰ / 饰品Ⅱ | 副手 = 盾（防御）或副武器（攻击）；物品 `槽位` 声明归属，饰品自动分配空槽 |
| **防具数值** | **统一 防御 + 生命** | 头盔/盔甲/靴子/手套/饰品 都是 防御+生命 加成；差异化（暴击/闪避/魔力）留给词缀系统 |
| **存档结构** | `武器标识/防具标识` → `List<装备记录>`（槽位+标识） | 开发初期**不留旧档**：旧档无 装备 列表视为无存档（新游戏），干净利落 |

**行为逻辑：**

- **槽位映射**：物品 `槽位` = 主手/副手/头盔/盔甲/靴子/手套/饰品；`饰品` 装备时自动分配 饰品Ⅰ 空槽 → 饰品Ⅱ → 否则覆盖 饰品Ⅰ。

- **交互**：单击行/装备槽选中（选中框高亮）→ 详情区填充 + 操作按钮；双击行 = 快速操作；双击装备槽 = 快速卸下；右键返回。
- **详情区**：品质名（着色）/ 名称 / 描述 / 数值（攻击/防御/生命合并显示）/ 价格；操作按钮按类型：武器防具饰品→装备、恢复→使用、技能书→学习、已装备→卸下。

### 9.1 按钮清单与作用

### 9.2 取消按钮作用模型（避免错误作用）

- **作用对象**：仅 `面板管理器.当前显示面板`，调用其 `回退()`（与右键同一条链路；右键保留为快捷方式）
- **`回退()` 返回 bool**：true=取消被消费；false=无可取消 → 取消按钮播错误音效（不静默）
- **取消按钮文案动态**：`面板基类.取消文本` 虚属性（默认"取消"），各面板覆写；侧边栏 `Update` 轻量跟随（字符串比对，仅变化时赋值）

| 面板 | 取消语义 | 取消文本 | 不可取消（返回 false） |
|------|---------|---------|----------------------|
| 主菜单 / 大地图 / 主视窗 | 无（顶层） | 取消 | 始终 |
| 对话-主剧情 | 无（线性强制） | 取消 | 始终 |
| 对话-结局 | 回主菜单 | 结束 | — |
| 对话-NPC交谈 | 返回节点内部 | 返回 | 无返回节点时 |
| 战斗 | 取消选目标/子菜单→回行动栏 | 取消 | 行动选择/敌方回合/结算中 |
| 小地图 | 离开城镇回大地图 | 离开 | 非城镇模式 |
| 节点内部 | 回小地图 | 返回 | 无返回节点时 |
| 设施功能面板 | 返回节点内部 | 返回 | 无来源节点时 |
| 角色面板 | 返回上一面板 | 关闭 | 无上一面板时 |

> 取消按钮文案统一为**两字词**：取消 / 跳过 / 离开 / 返回 / 关闭 / 结束。

**边界（不作用）**：不触发剧情选项、不打断地图移动、不取消已确认的战斗行动、不做全局栈回退（仅角色面板自身"返回上一面板"语义）。

**面板内 离开/返回 按钮已全部移除**（小地图 离开按钮、节点内部 返回按钮、设施功能面板 返回按钮、对话 NPC 返回按钮/结局 返回主菜单、角色面板 返回按钮）——统一由侧边栏取消按钮承担；场景里这些按钮物体请手动删除。
