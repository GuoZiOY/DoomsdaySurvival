## 四、怎么复算这些数字

```powershell
# ① 各表条数（UTF8 读，否则中文键会乱码）
$D="Assets/Resources/Data"; function J($p){ [System.IO.File]::ReadAllText($p,[System.Text.Encoding]::UTF8) | ConvertFrom-Json }
"物品   " + ((Get-ChildItem "$D\物品" -Recurse -Filter *.json | ForEach-Object { (J $_.FullName).物品.Count } | Measure-Object -Sum).Sum)
"配方   " + ((J "$D/recipes_工作台.json").配方.Count + (J "$D/recipes_灶台.json").配方.Count + (J "$D/recipes_医疗站.json").配方.Count)
"敌人   " + (J "$D/enemies.json").敌人.Count
"敌人组 " + (J "$D/encounters.json").敌人组.Count
"技能   " + (J "$D/skills.json").技能.Count
"天赋   " + (J "$D/天赋.json").天赋.Count
"家具   " + (J "$D/家具.json").家具.Count
"书籍   " + (J "$D/物品/items_书籍.json").物品.Count
```

```python
# ② 可达率 / 用途 / 单容器 / 成本比（口径见 §二 C —— 这两条最容易写错）
import json, os, collections
D = r"Assets/Resources/Data"
L = lambda p: json.load(open(os.path.join(D, p), encoding='utf-8'))
物品 = {}
for root, _, fs in os.walk(os.path.join(D, "物品")):
    for fn in fs:
        if fn.endswith(".json"):
            for it in L(os.path.relpath(os.path.join(root, fn), D))["物品"]: 物品[it["标识"]] = it
S = L("搜索_地图类型.json")["地图类型"]

来源 = collections.defaultdict(set)
def 记(tag, k):
    if k and k in 物品: 来源[k].add(tag)
for m in S:                                  # 搜刮（字段名坑：池子叫 `搜索表`，不是 `物品池`）
    for r in m["房间"]:
        for c in r["容器"]:
            for e in c["搜索表"]: 记("搜刮", e["物品标识"])
for f in ["recipes_工作台.json", "recipes_灶台.json", "recipes_医疗站.json"]:
    for r in L(f)["配方"]: 记("制作", r["产物"])     # ⚠ 配方【材料】不是来源
for e in L("enemies.json")["敌人"]:
    记("掉落", e.get("掉落物品"))
    for d in (e.get("掉落列表") or []): 记("掉落", d["标识"])
for c in L("职业.json")["职业"]:
    for e in (c.get("初始装备") or []): 记("职业初始", e["标识"])
for r in L("房间模板.json")["房间"]:
```

## 五、以后补数据照抄的手法（本轮实战沉淀）

1. **先自检再动文件：跑「哪些 JSON 能逐字节往返」**
   拿 `json.dumps(o, ensure_ascii=False, indent=2)`（含尾换行与 CRLF 两种）去**逐字节还原**现有文件：
   能还原的（`家具/情报/世界/enemies/recipes_*/物品/**`）→ 允许整份重写；
   还原不了的（**`搜索_地图类型.json`**、`房间模板.json`、`建筑模板.json`、`区域模板.json`、`encounters.json`、
   `敌人特性.json`、`items_任务品.json`）→ **只能就地插/删文本**。
   > `搜索_地图类型.json` 同一类对象有**两种写法**（114 条多行展开 + 562 条紧凑单行）→ 任何改动都要
   > **按括号配对定位整块**，不能只匹配一行。
2. **锚点必须带上下文**：房间标识**不是全局唯一**（`工厂/仓库` vs `体育用品店/仓库`；
   而搜索表里的房间标识是短名 `仓库`）→ 一律**先用地图类型切区块，再找房间，再找容器**。
   改完立刻用 `git diff --numstat` + grep「**纯括号行**」= 0 确认没伤格式（这条逮住过一次 114 行缩进丢失）。
3. **一次改多处的顺序铁律**（本会话踩了**两次**）：同一个文件里既删又插时，**不能把两组偏移算在一起应用** ——
   删除会移动后面所有偏移。做法：**先全删 → 重读文件 → 再全插**；
   连续条目要删就**整段删**（或**重建该数组**：保留每个未删元素的原文，只重排分隔符），
   并且**相邻条目逐个按原偏移删必然错位**。
4. **条数守恒断言**：每次改完立刻断言 ——
   `新增条目数 == 计划数` / `旧条目集合 ⊆ 新条目集合`（该删的除外）/ `既有条目的值一个没变` /
   `整件物品不许凭空消失`。本会话靠它逮住过"重写容器时漏掉一件装备 → 零来源"。
5. **改完的收尾三件套**：`json.loads` 逐段验 → 跑门禁 → 更新文档数字（**脚本逐条替换 + 每条断言只命中 1 次**，
   避免改一半）。文档里**历史叙述保留并加带日期的增量注记**，不要覆盖旧快照。
6. **⚠ 报缺口之前先确认字段名真的存在**（本会话出现过**两次同类错误**）：
   一次把 `搜索表` 写成 `物品池`；一次报"`房间模板.敌人数量` 全空" ——
   其实真字段是 `敌人数量最小` / `敌人数量最大`，一个都不空。**PowerShell 对不存在的属性返回 `$null`**，
   于是"查不到"被当成了"数据是空的"。
   **判据**：报"某字段空缺"之前，先 `($对象.PSObject.Properties.Name -join ",")` 打印一遍字段清单。
7. **门禁加完必须做一次反向测试**：临时塞一条违规数据 → 期望门禁 **exit 1 并逐条点名** → 撤掉 → 期望 **exit 0**。
   本会话给 `[物品用途]` 加完就是这么验的（塞一件"零来源+无用途"的假物品）。
8. **`Tools/*.ps1` 改完要补回 UTF-8 BOM**（编辑工具会吃掉 BOM，脚本里的中文比较会因此失效）。
9. **一次性脚本用完就删**（放系统 temp；**数据文件才是真源**，不要往仓库新增脚本）。
   `.workbuddy` 不在 `.gitignore` 里，临时文件别写进仓库。
10. **提交只 `git add` 明确路径**（`git add -- Assets` 会把 Unity 顺手改的 TMP 字体资源一起提交）。
