## 五、刀51 用的手法（以后再补数据可以直接照抄）

1. **先自检再动文件**：拿 `json.dump(indent=2)` 的两种叶子风格（"叶子压一行 / 全多行"）去**逐字节还原**现有文件；
   能还原的（`房间模板/建筑模板/区域模板`）才允许整份重写，还原不了的（`搜索_地图类型.json` 是**两种风格混排**）
   就走**就地插文本**：锚点定位房间 → 括号配对找 `"容器": [ … ]` 的 `]` → 在最后一个元素后补逗号再贴新块。
   结果：`搜索_地图类型.json` 的 diff 是 **+984 / −0**（旧行一个字节没动）。
2. **锚点要带上下文**：房间标识**不是全局唯一**（`工厂/仓库` vs `体育用品店/仓库`）→ 先用地图类型切区块再找房间。
   第一次跑就栽在这儿（"`"标识": "仓库",` 出现 2 次"）。
3. **幂等**：脚本第二次跑时按容器标识跳过已插入的、按类型/建筑标识跳过已存在的 —— 所以"再补一波"可以直接改表重跑。
4. **跑完自查**：JSON 可解析 + 搜索表物品存在 + 容器池 (地图类型,房间) 存在 + 敌人组/棋盘/门锁存在 + 建筑→房间存在，
   再跑门禁 5 件套（`数据引用核对` + `房间/建筑/区域/大世界验证`）。刀51 的结果：房间验证 5400 间 0 失败、
   建筑 2000 层 0 失败、区域 1400 张 0 失败、大世界 50 个 0 失败。
5. **一次性脚本用完就删**（数据文件才是真源）；脚本里那套"往返自检 + 就地插文本"的写法已经记在上面。
6. **⚠ 报缺口之前先确认字段名真的存在**（这条是给自己记的教训）：我在 §二 B 写过"`房间模板.敌人数量`
   **27 间全空**"，其实是拿一个**不存在**的字段名去取值 —— PowerShell 对不存在的属性返回 `$null`，
   于是"查不到"被我当成了"数据是空的"。真字段是 `敌人数量最小` / `敌人数量最大`，**27 间一个不空**。
   同一类错误在本次体检里出现两次（另一次见 §四 第 ③ 条的 `物品池` vs `搜索表`）。
   **判据**：报"某字段空缺"之前，先 `($对象.PSObject.Properties.Name -join ",")` 打印一遍字段清单。

⚠ 本文提到的 `Resources/Data/story.json`、`Resources/Data/quests.json` **是有意不存在的**（就是缺口的本体），
不要把它们当成"文档写错了路径"。
