## 一、范围

**做**：

1. 一个**完全中空的大房间**（不做安全屋那样的分割），四周有墙，里面**随机摆可搜索容器**。
2. **网格实体层**：玩家与敌人都以"实体令牌"在网格上表现 —— 占格、挡路、可见、可遭遇。
3. **玩家抽象体**（占 1 格）能移动；**容器与敌人都不可穿过**。
4. **A\* 寻路**：玩家点击哪里，就显示到那里的路径，并沿路径走过去。
5. 房间里放 **1~3 只敌人**：看见或撞上 → 遭遇 → 接现有**战斗沙盒**；打赢留下一具**可搜的尸体**。
6. **战争迷雾**：进屋先看不清（入口周围一小圈可见），走过去才揭开。
7. 一个**继承 `网格面板基类` 的房间网格**（与 `家具网格面板` 兄弟）+ 宿主面板 + **房间自己的图层栈**（地表 / 迷雾 / 路径 / 效果 / 交互）。

**不做（第 1 刀明确排除，接口留好）**：

| 不做 | 原因 |
|---|---|
| **敌人的移动 / 巡逻 AI** | 第 1 刀敌人**静态**：占格、挡路、可遭遇，但原地不动。移动 AI 下一刀 |
| 多房间分割 / 走廊 / 户型模板 | **第 2 刀**；本刀先把"单大间"打穿 |
| 楼层 / 楼梯 / 建筑画面 / 区域 / 世界 | 上面三层，后面单独做 |
| 容器物资的"每局刷新"（raid 制） | 本刀容器内容跟着种子走，raid 制后面再定 |

## 三、房间模型（结构）

```
┌────────────────────────────────────┐
│ 墙 墙 墙 墙 墙 墙 墙 墙 墙 墙 墙 墙 │  ← 四周一圈墙（1 格厚）
│ 墙                               墙 │
│ 墙      · 地板（空格 = 可走）     墙 │
│ 墙      ▣ 容器 = 占格，不可穿过   墙 │
│ 墙      ☠ 敌人 = 占格、挡路       墙 │
│ 墙  ◉入口(玩家起始格)            墙 │
└────────────────────────────────────┘
```

- **地板**：全中空，不留结构（第 2 刀再谈分割）。
- **墙**：四周一圈（1 格），**在数据里当"实体"承载**（占格、挡路、挡视线）。
- **入口格**：玩家起始位置，由 `房间模板.入口边` + 种子在边上取一格，默认贴下边中部，必须留空。
- **尺寸**：默认 **`16 列 × 10 行`**。理由：基类里 `格尺寸 = 90` 是**全项目统一的 const**（改它牵动所有网格的字号线宽），一屏上限就是 16×10 = 1440×900 px，正好塞进 1080 高。要更大的房间以后走"缩放 + 字号补偿"或分屏，第 1 刀不做。

## 四、容器与敌人的摆放算法（核心）

### 4.1 目标

8~14 个尺寸不同（1×1 / 1×2 / 2×1 / 2×2）的可搜索容器 + 1~3 只敌人，**随机但讲道理地**摆在中空房间里，保证：

- 不越界、不重叠、不压入口格、不与玩家起始格重叠（容器与敌人也互不重叠）；
- **每个容器至少一个相邻可站格，且该格与玩家起始格连通** —— 硬约束，否则就是"看得见搜不着的死内容"；
- **每个敌人的相邻可站格也必须与玩家起始格连通** —— 否则隔着柜子干瞪眼；
- 不出现"孤岛"；不挤成一堆、不都堆在角落。

### 4.2 算法：三阶段（分区配额 → 约束采样 → 连通校验与重试）

**阶段 0 · 定尺**：按容器池（`{容器, 权重, 数量区间}`）轮盘赌抽出容器清单（含宽×高）；敌人池同理抽 1~3 只。种子确定 → 清单确定。

**阶段 1 · 分区配额（防堆一角）**：内区（去掉四周墙）划成 **4×3 = 12 个区块**，容器按数量平均分配到区块（余数随机塞）；敌人单独占位、**优先分到与入口不同的区块**（避免一进门贴脸）。随机只发生在区块内。

**阶段 2 · 区块内约束采样（防重叠/防贴死）**：区块内抽锚点，要求——
- 离墙 ≥ 1 格（留绕行走道）；
- 与区块内**已放容器/敌人**保持 ≥ 1 格间距（两占位物之间至少隔一格走道，这条消掉大半"走不进去"）；
- 按宽高检查不越界、不重叠、不压入口保留区；
- 放不下就换锚点，锚点用完进"待放队列"最后补位。

**阶段 3 · 连通校验 + 重试（兜底）**：跑一次 BFS——
1. 从玩家起始格算出 `可达集`；
2. 每个容器**至少一个相邻格在可达集内**（不在 → 坏容器）；
3. 每个敌人**相邻可站格在可达集内**（不在 → 坏敌人）；
4. 是否存在"孤岛"；
5. 有坏的 → **移除该物**（不动整间房，避免大改观感），移除到下限 → **整间重掷**（上限 5 次）；5 次还不行 → **保底布局**（容器沿墙均匀摆一圈 + 敌人摆中区空地，必定成功）。

> 全程用 `沙盒种子` 的确定性随机流：**同模板 + 同种子 = 同布局**。自检 200 种子与问题复现都靠它。

### 4.3 布局方式（`房间模板.布局`）

| 布局 | 做法 | 适合 |
|---|---|---|
| **散点**（默认，第 1 刀只做这个） | 分区配额 + 间距采样 | 民居、办公室、便利店 |
| 贴墙 | 只允许贴内墙一圈，中间全空 | 车库、仓库、空旷大厅 |
| 成排 | 沿某方向成排（排间距 2 格、排内 1 格） | 超市货架、药房、图书馆 |

### 4.4 数据

- 容器**不旋转**；容器定义（尺寸/搜索表/搜索时间）**复用现有搜索系统**，模板只引用"标识 + 数量区间"。
- **敌人属性全部来自现有 `enemies.json`**，模板只引用"标识 + 数量区间"。
- 实例标识：`房间标识#序号`（本局有效，不进存档）；**绝不拿定义标识当实例键**（同间房可能两个"货架"）。

## 五、网格实体层（玩家 / 敌人 / 以后的 NPC）

### 5.1 实体字段

| 字段 | 说明 |
|---|---|
| 标识 | 实例 id：`房间标识#实体序号`（不进存档） |
| 阵营 | 玩家 / 敌人 / 中立（幸存者·NPC 留给以后） |
| 定义标识 | 敌人取 `enemies.json` 的标识 |
| 列 / 行 | 所在格 |
| 朝向 | 0下 / 1左 / 2上 / 3右（只影响渲染） |
| 占格 / 挡视线 | 尸体两者皆否；墙与敌人两者皆是；容器占格、且**高家具挡视线**（柜子挡、纸箱不挡） |

### 5.2 玩家

- **占 1 格的令牌**：圆底盘 + 剪影 + 描边 + 朝向三角；青绿。
- **移动**：1 格 = **1 游戏分钟**（走 `世界时间管理器`）；**不耗行动点**（行动点留给搜索）。
- **两种移动**：①点目标格 → A\* → 显示路径 → 沿路径走；②方向键 / WASD 逐格走。
- **步进动画**每格 0.12 秒；**时间按格数一次性结算**。
- **不穿容器、不穿敌人、不穿墙**：可通行 = 该格无任何占格实体（自己除外）。

### 5.3 敌人

- **摆放**：与容器同一套约束采样，吃同一份连通校验。
- **表现**：暗红底盘 + 丧尸剪影 + 描边 + 朝向；头顶细血条 + **警戒环**（未察觉=灰 / 察觉=黄 / 追击=红）。
- **可见性**：**只在"当前可见"时画出来**（迷雾规则见第六节）——已探索但此刻看不见的区域不显示敌人，所以"刚才那只还在不在原地"本身是未知的。
- **行为（第 1 刀：静态）**：不移动，只占格、挡路、挡视线；移动/巡逻 AI 第 2 刀。
- **遭遇规则**（随迷雾调整）：
  - 玩家移动到与敌人**相邻** → 立即遭遇，**敌人先手**（自己撞上去的）；
  - 敌人在玩家**视野内且距离 ≥ 3 格**被看见 → 遭遇时**玩家先手**（先看清再动手）；
  - 遭遇 → 切现有**战斗沙盒**（`BattleService.开始战斗`），打完回调房间探索服务。
- **结果**：胜利 → 敌人从网格消失，**留下一具"尸体格"（= 可搜索容器，复用现有尸体搜索）**；逃跑 → 敌人留原格，玩家退回上一格。

> 闭环：**推门 → 视野只有一小圈 → 试探着走 → 看见/被看见 → 绕开还是打 → 打赢还能翻一具尸体**。

## 六、战争迷雾与视野

| 项 | 决定 |
|---|---|
| 视野（修订） | **由角色与时段决定**（`视野.json` **直接写最终边长**，不做加减）：白天 **7×7**、夜晚 **3×3**（永远单数、玩家在正中）；不再是每间房各写一个值 |
| 视野形状 | **以玩家为中心、边长是单数的正方形**（3/5/7/9…，玩家正好在正中） |
| 记忆（白天/夜晚） | **白天**：已探索区 = **阴影压暗 65% 的淡阴影**（墙/容器/尸体照画但压暗，可看到"已搜 ✓"）；**夜晚**：**没有记忆**。**敌人一律不进记忆** |
| 夜晚弱视野 | 夜晚核心 3×3 之外、**弱视野 5×5** 之内那一圈 = **阴影**：**只看得见建筑（墙）** —— 看不见敌人，也看不见要翻的容器/尸体（那些得走到核心亮区里才看得见）。外圈边长 = `视野.json.夜晚弱视野`（默认 5，会自动奇数化且不小于核心） |
| 时段 | **6:00 之后是白天、18:00 之后是夜晚**（`视野.json` 的 `白天起` / `夜晚起` 可调）；站在屋里不动跨过 6:00 / 18:00 也会立刻切换视野与记忆（订阅 `时间变化事件`） |
| 遮挡 | **方形视野不做遮挡**（单房间是空场）；`房间视野.视线通` 保留给"墙后不可见"/多房间户型 |
| 初始 | 进场只有入口周围那个方形可见（白天看得到房间轮廓，夜晚只有贴脸一圈） |
| 重算时机 | 玩家每走一格重算；**增量**：只更新发生变化的格（对比上次可见集合） |
| 敌人可见性 | **只在"亮"（核心方形）里画** —— 白天记忆区、夜晚弱视野圈里都不画（记忆里的敌人会误导，也让"黑影里有没有东西"保持未知） |
| 路径指示 | 未探索格也能直接点：按 A* 走过去（迷雾只影响看不看得见） |
| 容器可见性 | **亮** 或 **白天的记忆阴影** 里画（已搜的照旧显示"已搜 ✓"）；**夜晚弱视野圈里不画**（要翻的东西得走近） |

> 迷雾顺带解决了一件事：**"屋里就 11 个柜子"这种一眼看光的无聊**。同一间房，第一次进去是黑的，走一圈才亮出来 —— 表现层的紧张感主要靠它。

## 七、与 `网格面板基类` 的接法

### 7.1 数据源：注入一个 `网格服务`

与安全屋**完全同一条路子**（`安全屋管理器.网格()` 建 10×7 的 `网格服务`，`形状解析 = 家具形状`，面板里 `房间网格.数据源 = 网格`）：

```
房间探索服务.网格() →
  new 网格服务 {
      列数 = 房间列, 行数 = 房间行,
      形状解析 = 房间形状,          // 按实例标识前缀解析 宽×高（容器查定义，人/墙/尸体 = 1×1）
      网格物品 = [ 墙…, 容器…, 尸体…, 敌人…, 玩家令牌 ]
  }
面板：房间网格面板.数据源 = 该网格服务
```

### 7.2 实体承载表（房间里的东西 → 基类的"物品堆叠"）

基类的实体槽就是 `物品堆叠`（`家具网格面板` 正是这么装家具的：标识带后缀、数量恒 1、列/行 = 网格位置）。房间照搬：

| 房间里的东西 | 承载 | 标识 | 占格 | 挡视线 |
|---|---|---|---|---|
| **墙** | 物品堆叠 | `墙#序号` | 1×1 | 是 |
| **容器** | 物品堆叠 | `容器定义#序号` | 定义宽×高 | 按定义（高柜挡、纸箱不挡） |
| **尸体** | 物品堆叠 | `尸体#序号` | 1×1 | 否 |
| **敌人** | 物品堆叠 | `敌人定义#序号` | 1×1 | 是 |
| **玩家令牌** | 物品堆叠 | `玩家`（唯一） | 1×1 | 否 |

**白捡的两个好处**：
1. **通行判定 = `服务.该格物品(列,行) == null`** —— A\* 与基类网格算法用的是**同一份真相**，不会两边打架；
2. **玩家移动 = 改玩家令牌的列/行 + `请求刷新()`** —— 基类增量刷新自动只挪那一个框（`更新实体框`），不用我写移动渲染。

### 7.3 要 override 的钩子

| 基类钩子 | `房间网格面板` 的实现 |
|---|---|
| `创建实体框` / `更新实体框` | 按类型建框：墙=墙块；容器/尸体=剪影 + 名称 + 已搜（灰化 + 打勾）；敌人=剪影 + 血条 + 警戒环；玩家=令牌。**更新时按可见性调 alpha**（迷雾联动） |
| `块底格色(块)` | 基类预留的钩子（注释即"家具户型 override：走廊灰 + 房间浅色表"）→ 房间用来上**地板材质色 / 已探索状态色** |
| `单击实体(堆叠, 次数)` | 容器 / 尸体 / 敌人 → 寻路走到其**相邻格**；空格点击走 `房间格点击` |
| `右键实体(堆叠, 框)` | 容器 / 尸体 → `右键菜单.显示动作`（搜索 / 查看）；敌人 → 查看 |
| `允许开始拖拽(堆叠)` | **一律 false** —— 房间里不搬东西，基类拖拽机制自然休眠（投影/跨面板都不用管） |
| `允许跨面板()` | false |
| `完成拖拽` | 不会被调用（保险返回 false） |
| `菜单打开` / `菜单查看详情` | 搜索 / 查看（右键菜单回调；查看走现有 `信息面板`） |

## 八、房间网格的图层栈（本次新增的重点）

### 8.1 层的归属与顺序（z 从下到上）

| # | 层 | 谁建 | 职责 | 刷新时机 |
|---|---|---|---|---|
| 0 | **底盘** | 基类 | 整体衬底（深色 + 外扩） | 重建时 |
| 1 | **底座层** | 基类 | 逐格底图；**`块底格色` 钩子**上地板材质色 | 重建时 |
| 2 | **地表贴图层** | **自建** | 地板**纹理**（程序化 PNG：水泥/瓷砖/木地板），一格一贴 | 重建时一次 |
| 3 | **线层** | 基类 | 格线与块边界（`画块网格线` 可 override） | 重建 / 布局变化时 |
| 4 | **迷雾层** | **自建** | 三态遮罩：未探索 = 黑板，已探索 = 60% 黑，可见 = 透明 | 走一格增量重算 |
| 5 | **路径指示层** | **自建** | 路径格高亮 + 细折线 + 终点准星；走过一段就缩短 | 每次点击 / 每走一步 |
| 6 | **物品层** | 基类 | 实体框：墙 / 容器 / 尸体 / 敌人 / 玩家令牌 | 基类增量刷新 |
| 7 | **效果层** | **自建** | 悬停格高亮、选中描边、搜索进度、遭遇闪红 | 交互 / 状态变化 |
| 8 | **交互层** | **自建** | 每格一个透明 Image（raycast）+ `房间格点击`（列/行） | 重建时一次 |

几条定规矩：

- **迷雾层放在物品层之下**，实体不靠"被遮住"而是**靠自己调 alpha**（未探索不画 / 已探索暗 / 可见亮）。这样"已探索但看不见敌人的实时位置"这条规则才能成立 —— 否则敌人会从迷雾里透出来。
- **路径指示层放在迷雾之上、物品之下**：路径要盖住迷雾（看得见你在往哪走），但不能挡住柜子和人。
- **交互层放在物品层之下**：Unity 取最上层命中，所以**点实体框优先给实体**，没被覆盖的格子才落到交互层 → 空格点击与悬停天然分流。
- **自建的层全部是"逐格 Image"**（160 格/层，Unity UI 完全吃得消），不引 Tilemap / Shader。迷雾的方块感用 **alpha 阶梯**柔化：离可见区 1 格 = 0.25、2 格 = 0.5、更远 = 0.78，观感就不那么硬。

### 8.2 三个必须绕开的坑（都来自读基类源码）

1. **子类不能再写 `void Update()`**。基类的 `Update` 是 `private`，子类再写一个会**隐藏**它 → 基类的刷新调度（`待刷新网格`/`待刷新物品`/拖拽投影/R 旋转）**整个失效**。→ 图层同步放在自建组件 **`房间图层`** 的 `Update` 里，它读面板公开的 `渲染列 / 渲染行` 判断要不要重建。
2. **路径高亮不能蹭基类的"投影格"**。基类 `Update` 在"无拖拽"时会 `隐藏全部投影`，路径会被每帧抹掉。→ 必须自建路径指示层。
3. **基类 `销毁网格结构` 只销毁它自己那四层**（底盘/底座层/线层/物品层）。自建层不归它管 → 由 `房间图层` 检测 `渲染列/渲染行/格尺寸` 变化后自己重建，避免"网格重建了、迷雾层还按旧尺寸铺着"。
4. （附带）**`形状解析` 必须能解析"墙/尸体/敌人/玩家"这类非物品标识**（返回 1×1），否则基类占格算法会算错。

## 九、A\* 寻路

| 项 | 决定 |
|---|---|
| 图 | 房间网格，节点 = 格 |
| 可通行 | `服务.该格物品(列,行) == null`（墙/容器/敌人/尸体之外为空） |
| 邻接 | **四方向**（不做八方向：斜走会让"不可穿过"的判定与视觉都变糊） |
| 移动代价 | 每格恒为 1（将来"门/废墟"可给更高代价） |
| 启发函数 | 曼哈顿距离（与四方向一致 → 最优且展开少） |
| 数据结构 | 开放集用二叉堆；`代价表` + `父格表` 用数组 |
| 展开顺序 | **固定方向顺序（右/下/左/上）** → 同输入必得同路径，测试可断言 |
| 点到容器/敌人 | 目标是**该实体的相邻空格**（≤4 候选），逐候选跑 A\* 取最短 → 表现即"走到柜子旁边" |
| 点到未探索格 | 走到**已知区域边缘离目标最近的可站格**（迷雾规则） |
| 不可达 | 返回空 → 目标格闪一下淡红 + 提示"过不去" |
| 性能 | 16×10 = 160 格，任意点击瞬间出结果 |

**路径显示**：路径格加亮 + 细折线 + 终点准星；玩家移动时路径**逐格缩短**（走过的格恢复原样）。

## 十一、面板设计

### 11.1 组件结构（与「安全屋面板 + 家具网格面板」同构）

```
房间面板（面板基类）                    ← 面板管理器.房间 引用位
├─ 网格容器（RectTransform）            ← 拖到 房间网格面板.网格容器
│   └─ 房间网格面板（网格面板基类）      ← 同物体挂 房间图层（自建层）+ 房间格点击（每格）
│        └─（运行时）底盘/底座层/线层/物品层（基类）+ 地表层/迷雾层/路径层/效果层/交互层（自建）
```

### 11.2 布局

```
┌──────────────────────────────────────────────────────────────┐
│ （顶栏 = 常驻 HUD：生命 / 行动 / 饱食 / 水分 / 时间 / 地点）  │
│   地点位只显示当前地点：便利店门厅                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                        房 间 网 格                           │
│          地板 + 墙 + 容器 + 实体（玩家 / 敌人）+ 路径高亮     │
│                                                              │
│     容器状态直接画在格子上：未搜 = 原色，已搜 = 灰化 + 打勾    │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ （左下 = 常驻日志：你推开了便利店门厅的门 / 你拉开了货架 …）   │
└──────────────────────────────────────────────────────────────┘
```

**不做容器卡，也不做信息条/提示行**：容器交互全走**右键菜单**（搜索 / 查看），状态直接由格子表达（未搜 = 原色，已搜 = 灰化 + 打勾）；**HUD 地点位只显示当前地点名**（如"便利店门厅"；危险度在进门那条日志里说），提示走 **日志**。于是面板上只剩**网格**一样东西。

### 11.3 引用位（场景手动搭建）

| 引用位 | 拖什么 |
|---|---|
| `房间网格面板` | 挂在网格区域上的 `房间网格面板` 组件 |
| `网格容器` | 网格区域 RectTransform（拖到 `房间网格面板.网格容器`） |

`面板管理器` 加 `房间` 引用位（与 `探索`/`营地` 并列），订阅 `打开房间事件` → 显示 `房间面板`。

### 11.4 刷新策略

- **网格与实体**：交给基类增量刷新（走一步只改玩家令牌一个框 + 分隔线判定）。
- **迷雾 / 路径 / 效果**：由 `房间图层` 按需重画自己那三层的**变化格**（对比上次状态集），不做整屏重建。
- 上一次"操作别扭"的技术根因之一就是整屏重建导致点击/悬停抖动，这次明确禁止。

## 十四、验收标准（自动化，不靠肉眼）

**Editor 自检 —— 200 个种子**：

1. 容器/敌人不越界、不重叠、不压入口格、不压玩家起始格；
2. 每个容器至少一个相邻可站格在可达集内（**0 例外**）；
3. 每个敌人的相邻可站格在可达集内；
4. 无"孤岛"（可站格连通分量 = 1）；
5. 数量在模板区间内（含保底布局）；
6. 确定性：同种子跑两次布局完全一致；
7. **视野**：起点视野只覆盖半径内且不穿墙；BFS 与 Bresenham 的可见集一致；增量差分结果 = 全量重算结果。

**寻路测试**：随机 500 组起终点 —— 路径首格 = 起点、末格 = 终点、每步四方向相邻、整条路径都可通行（不穿墙/容器/敌人）；不可达返回空；点未探索格返回"走到已知边缘"的路径。

**运行时冒烟**：进房间 → 断言只有入口一圈可见 → 点容器 → 走位（扣 1 分钟/格）→ 走 5 格断言时间 +5 分钟且迷雾随步揭开 → 右键容器 → 搜索（扣 10 行动点）→ 容器变已搜 → **走到敌人相邻格断言触发一场战斗** → 胜利断言敌人消失且尸体格可搜 → 取消离开。

**接线自检（专治"面板接错"）**：

- 数据源非空且 `列数/行数` = 房间模板；
- 单击/右键钩子确实被调用（点容器 → 发出移动请求 / 弹出菜单）；
- `允许开始拖拽` 返回 false（拖拽被拒）；
- **路径层在无拖拽时连跑 10 帧仍在**（对应 8.2 坑 2）；
- **网格重建后自建层跟着重建**（改尺寸 → 断言迷雾层尺寸 = 新网格尺寸，对应 8.2 坑 3）；
- **基类刷新调度仍活着**（改一个实体的列/行 → 断言其框位置变了，对应 8.2 坑 1）。

**判据一句话**：一屏能看懂"我在哪、哪有柜子和敌人、点了之后我走哪条路"，并且**每个柜子都一定走得到、每只敌人都一定打得着**。
