# 房间层 · 第 2 刀：门与多房间

> 前情：第 1 刀做出一个「完全中空的大房间」（四周墙 + 随机容器/敌人），出口只有 `Esc`。
> 这一刀**在墙上开洞**：门 = 外墙上的一个洞，穿过去就是隔壁房间 —— 房间层第一次有了"多间房"。

---

## 一、原来的问题（代码事实）

| 事实 | 位置 |
|---|---|
| 外圈是**一整圈死墙**：四条边逐格建墙，没有一处缺口 | `房间生成器.建墙()` |
| `入口边` / `入口格` **只是个出生点**：入口格落在**墙内侧一格**（`内左=1` / `内下=行-2`），那格墙仍是实的 | `房间生成器.取入口格()` |
| 所以房间是全封闭的：进去之后只能靠 `Esc`（面板回退）出去，墙上没有任何东西通向别处 | `房间面板.回退()` |

## 二、这一刀的三个定版选择（已确认）

| 问题 | 定版 |
|---|---|
| 门怎么穿 | **走到门口停下 + 右键「开门」再确认**（不做"踩上去就自动切"，防误触） |
| 入口要不要也变成门 | **要**：`入口边` 上开一扇**大门**，从外面进来就站在它内侧；右键「出去」= 出楼 |
| 门通向哪间房 | **模板 JSON 手写互连**（不做随机挑房），并补 4 间新房做示例 |

## 三、数据（全 JSON）

```jsonc
// 房间模板.json
{
  "标识": "便利店_门厅",
  "入口边": "下",                       // 大门开在这条边（也是从外面进来的落点边）
  "门": [                               // 内门：外墙上的洞 → 通向别的房间
    { "边": "上", "通向": "便利店_库房" }
  ],
  ...
}
```

- `房间实体类型` 增 **`门`**；门实体：**占格 = false**（洞能站能走）、**挡视线 = false**（洞是通的）、
  `朝向` = 洞开在哪条外墙上（0 下 / 1 左 / 2 上 / 3 右）、`通向` = 目标房间模板、`是大门` = 是否正门。
- **大门不写进 JSON**：它由 `入口边` 推出来（位置就是入口格外侧那格），而且**只在这一趟出行的起点房**存在
  （否则从库房"出去"就等于凭空出楼，空间上是错的）。
- 新增 4 间房 + 互连（`搜索_地图类型.json` 里本来就有 库房 / 柜台 / 厨房 / 杂物间 这些房间名，正好对上）：

```
便利店_门厅 ──上──▶ 便利店_库房        便利店_库房 ──下──▶ 便利店_门厅
药店_后间   ──左──▶ 药店_柜台          药店_柜台   ──右──▶ 药店_后间
居民房_客厅 ──上──▶ 居民房_厨房        居民房_厨房 ──下──▶ 居民房_客厅
居民房_客厅 ──左──▶ 居民房_杂物间      居民房_杂物间 ──右──▶ 居民房_客厅
```

## 四、生成：在墙上开洞

`房间生成器.开门(种子, 房, 模板, 含大门)`，在 `建墙()` + `取入口格()` **之后**、`摆物件()` **之前**跑：

1. **大门**：位置 = 入口格外侧那格（`边格(边, 入口列/行)`）；`加门()` 会**先把那格墙实体删掉**，再放门实体。
2. **内门**：每条 `模板.门` 一条，位置 = 这条边的中点 + 种子抖动（`派生(种子,"门{i}")`），再按约束**就近找位**。
3. **位置约束**：离墙角 ≥ `门离角 = 2`、同一条边上两扇门 ≥ `门间距 = 3`；排不开就记 `房间.门开不出`（自检会报，不静默吞）。
   - 同边时内门会让开大门（`门位可用()` 会把已存在的门算进去）——所以内门位置在"有没有大门"时可能差一格。
   - `取入口格()` 的横向坐标也收紧到 `[门离角, 长-1-门离角]`，免得大门顶在墙角。
4. **禁区**：`房间数据.通道格()` = 入口格 + 每扇门格 + 每扇门的**内侧格**；摆放容器/敌人时这些格一律不许压
   （`位置合法()` 逐格排除、`保底可放()` 连四邻一起留空、`找中段空格()` 里敌人离通道 ≥3 格）。
5. **连通校验**：每扇门的**内侧格**都必须在入口可达集里 —— 门是结构件，堵住就进不去，只能在摆放阶段避开；
   连着 `连通分量数()==1`、容器/敌人可达一起判，不合格就重掷（≤5 次）→ 保底布局。

## 五、进出：来路、落点、种子

`房间探索服务.进入房间(模板标识, 种子, 来路 = "")`

| 概念 | 规则 |
|---|---|
| 出行种子 | 从外面进来的那一次给的种子（`来路` 为空）→ 记为本趟出行的基准 |
| 房间种子 | `当前种子 = 房间种子.派生(出行种子, 模板标识)` → **同一趟出行里，同一间房永远是同一套布局**（柜子状态才留得住） |
| 含大门 | `模板标识 == 出行起点模板`：一趟里只有起点房在外墙上有大门（走回去也有） |
| 落点 | 从门进来 → 站在**"通回来那扇门"的内侧格**（不是门格本身，否则会被立刻弹回去）；从外面进 → 入口格 |

`开门(门)`：`够得着门()` = **站在门格上 或 正交相邻**（和"够得着容器"同一套手感）
- 大门 / `通向` 为空 → 播报「你从大门走了出去。」+ 发 **`离开房间事件`** → `房间面板` 回上一个面板（服务不碰 UI）；
- 内门 → `进入房间(门.通向, 出行种子, 当前房间.模板标识)`，日志「你推门进了便利店库房。危险…」。

## 六、表现

- **门格不画墙**：洞口铺门槛 + 两侧门框 + 一片半开的门扇（`房间贴图.门(朝向)`：上下边的门框竖着画、左右边横着画）；
  墙的转角闭合逻辑（"只在与非墙相邻的边描暗边"）天然把**门框**勾了出来，不用另写。
- 门和墙一样：**只要 `档 != 全黑` 就画**（黑记忆 / 夜晚弱视野里都看得见轮廓）；门不画实体描边、不画边界线。
- 右键菜单：太远 → 「**移动到此处**」；门口 → 内门「**开门（→ 便利店库房）**」/ 大门「**出去**」；另有「查看」（带描述）。
- 结构打印符号：`@ 你 / # 墙 / C 未搜容器 / x 已搜容器 / y 尸体 / ! 敌人 / + 内门 / D 大门`，并逐扇门打印"通向哪间"。
- HUD 地点位、日志播报随换房自动更新（沿用第 1 刀的链路）。

### 6.1 换房时的"迷雾记忆"与"当帧更新"（换房三坑，已修）

走门换房和"进游戏第一眼"不一样：**上一间房的一切表现状态都挂在屏幕上**，不清就会串味。三处一起改：

| 坑 | 现象 | 修法 |
|---|---|---|
| ① 迷雾记忆只活在"这一次进门"里 | `进入房间` 每次都 `已探索.Clear()` → **走门回来整间又变黑**，一点不记得你探索过 | `房间探索服务.视野记忆`：`房间键 = "种子#模板"` → `HashSet<int>`。换房前 `存视野记忆()`、进房时 `UnionWith(旧记忆)`；`离开()` 也存一次（出楼再进来仍认得）。清空时机 = **回安全屋**（与容器战局数据同一时机） |
| ② 自建图层等下一帧才按新尺寸重建 | 换房瞬间露出**上一间房的地格/迷雾**（尺寸不同时尤其明显），看着像"视野没更新" | `房间图层.换房检测（种子+模板）` + `切房间()`：**当帧**丢掉 令牌视觉位置/路段/悬停/落点/闪红 并**立刻按服务里新房间的尺寸重建图层**；`刷新()` 每次都先查一遍，所以"房间显示事件"这一路同步调到就同步画对 |
| ③ 图层拿 `面板.渲染列/行` 当尺寸 | 换房当帧基类还没重建完，`渲染列/行` 还是旧值 → 图层可能先按旧尺寸建一遍、再建一遍 | 尺寸**以服务里的房间为准**（`服.当前房间.列/行`）：`Update` 的尺寸检测与 `切房间()` 用同一个来源，不会来回重建 |

顺带：`房间面板.刷新网格()`（"房间显示事件"那条路）也补了一次 `数据源 = 服.网格` 重绑 —— 换房时数据源换了，不能只靠 `刷新(上下文)` 那一条路。

> 还没做（记在这）：`已察觉`（≥3 格看清过敌人 → 玩家先手）仍是"每次进门重置"。它存的是**实体引用**，
> 跨房会指向上一批实体，要持久化得改成存 `实体.标识` 再在进房时映射回来 —— 留到下一刀。

## 七、门锁：钥匙 / 撬锁 / 砸锁（留空）

规则：**门可以上锁**。无锁的门**踩上去就转移**；锁着的门是"一扇关着的门"，**站不上去**，只能站在门前那一格开锁。

### 7.1 机械核心：锁 = 占格

```csharp
// 房间生成器.加门：无锁 → 门洞；有锁 → 关着的门
占格 = 有锁, 挡视线 = 有锁,
```

一行之差就把整套交互做对了：**锁着 → 不可通行 → A\* 只会把你送到"门前那一格"**（现有 `寻路到相邻` 自动生效），
解锁 → `占格=false` → 走上去 → 踩门转移（`推进一步` 末尾的 `踩到能过的门()`）。
不用写"锁着时禁止站上去"，也不用改寻路。

### 7.2 三条破解路径

| 路径 | 前提 | 代价 | 结果 |
|---|---|---|---|
| **① 用钥匙** | 包里有这把钥匙（`门.锁` 指定的物品） | **1 游戏分钟**，不耗行动点 | 开锁；**钥匙消耗掉**（每把只认这一扇门） |
| **② 撬锁** | 包里有**撬锁工具**（`物品数据.用途 == "撬锁"`：撬棍 / 螺丝刀 / 钳子） | **3 游戏分钟 + 5 行动点**（失败也照花）；失败再扣**工具耐久 -1** | 成功率 `55 + 敏捷×3 + 智慧×2`（夹 [5,95]）%；失败可反复试 |
| **③ 砸锁** | —— | —— | **本刀留空**：`开锁方式.砸锁` 已占位、菜单不出、调用只回一句"砸锁还没做"（等做"巨响惊动敌人"再接） |

- 工具耐久：**只有"有耐久上限"的工具才扣**（撬棍/螺丝刀是武器 → 有耐久）；
  钳子这类 `有效最大耐久 == 0` 的"材料工具"**用不坏**，所以 `找撬锁工具()` 优先挑它、其次挑当前耐久最高的。
- 数值全在 `房间探索服务` 顶部常量：`钥匙开锁游戏分钟` / `撬锁游戏分钟` / `撬锁行动点` / `撬锁耐久损耗` / `撬锁基础成功率`。
- 菜单文案把结果说在脸上：`用钥匙开锁（库房钥匙）` / `撬锁（撬棍 · 成功率 73%）`；
  两样都没有时给的是**说明项**（点一下把原因写进日志，而不是死按钮）——故意不改共享菜单代码去加"灰项"。

### 7.3 钥匙从哪来：**按种子随机**——本房某个容器里，或本房**某一只**敌人身上

进房时按种子决定（`派生(当前种子, "钥匙来源"+门标识)` 取 50/50；没柜子就只能挂敌人、没敌人就只能进柜子）：

**A. 在柜子里**
- 按种子挑一个容器：`派生(当前种子, "钥匙"+门标识)` → 柜子列表里取模起选；
- 在**这个容器的内容第一次生成时**把钥匙塞进去（走 `搜索服务.打开()` 的缓存视图）：
  一趟里只生成一次 → **不会重复塞**；被玩家拿走了也**不会再刷出来**；
- 这个柜子塞不下 → 顺延下一个柜子。

**B. 在某一只敌人身上**（`敌人身上的钥匙[门标识] = (钥匙, 敌人实体标识)`）
- **一场遭遇只打一个敌人**，所以必须说清"钥匙在哪一只身上"：按种子指定**那一只**；
- 杀了**那一只** → 战斗收尾时把钥匙塞进它的战利品容器（尸体实体随后才创建，正好带着钥匙）→ 翻那具尸体拿到；
- **尸体是硬保证**：这场没产出战利品（很多敌人补给值 < 4 → 面包/水 都是 0、又没有掉落）时，
  `房间探索服务.战斗胜利` 会自己登记一具**空尸体**（`注册尸体容器` 允许空），所以"打死就留尸体"永远成立，
  钥匙也**一定掉在它的尸体里**，不会因为"没尸体"而顺延；
- 杀了别的敌人 → **什么都不掉**（钥匙还在它主人身上）；
- 万一尸体里的格子放不下（正常不会）→ 顺延放本房柜子，钥匙不会凭空消失。

**兜底**：这间房既没柜子也没敌人 → 那扇门**自动不上锁**（打 Console 警告）——**绝不出现"永远打不开的门"**。
钥匙是普通物品（`items_任务品.json`：库房钥匙 / 柜台钥匙 / 杂物间钥匙），走正常的"黑块 → 倒计时 → 揭开"流程；
按定版**不给任何提示**（不提示它在敌人身上还是在柜子里），只有「打印房间结构」这种调试输出会写出来。

### 7.4 锁态的生命期

`房间探索服务.已解锁门`（键 = 实例标识，即 `当前种子#门标识`）：**走门往来、出楼再进来都记得**，
**回安全屋（`打开营地事件`）才清** —— 与容器战局数据、视野记忆同一时机（三套临时数据一条生命期）。

### 7.5 哪几扇门上了锁（数据）

| 门 | 锁 |
|---|---|
| 便利店门厅 →(上) 便利店库房 | 库房钥匙 |
| 药店后间 →(左) 药店柜台 | 柜台钥匙 |
| 居民房客厅 →(左) 居民房杂物间 | 杂物间钥匙 |
| 其余（含所有"回头门"与大门） | 无锁 |

回头门一律**不上锁**（不然开一次锁得配两把钥匙，纯折磨）；大门永远无锁。

## 八、数据校验（`DataService`）

| 级别 | 内容 |
|---|---|
| **错误**（拦进游戏） | `门.边` 只能是 上/下/左/右；内门必须写 `通向`；不能通向自己；`通向` 的模板必须存在；**有锁时钥匙物品必须存在于 items** |
| **警告**（照进，只打 Console） | 「门通向 X，但那边没有门通回来（建议补一扇，否则回不去）」；「门锁用的物品类型不是任务品」；「门有锁但这间房没有容器池：钥匙无处可放，运行时那扇门会自动取消锁」—— 新增 `DataService.校验警告`，`GameBootstrap` 统一打 `LogWarning` |

## 十、已知边界 / 下一刀

- **砸锁留空**：`开锁方式.砸锁` 占了位，菜单不出，调用只回一句"砸锁还没做"。等做"砸锁 = 巨响惊动房间里的敌人
  （遭遇触发距离从 1 格放宽、敌人先手）"时，把菜单那一行和 `开锁()` 的 default 分支接上就行。
- 门是**一格宽**的单开门；双开门 / 两格宽的门要扩 `加门()`（现在固定 1×1）。
- 锁**只有一把钥匙 + 撬锁**两种开法，没有"万能钥匙 / 密码 / 需要特定技能"这类扩展（都只是 `门.锁` 一个字段的事）。
- 房间之间的连接**目前手写在模板里**；以后建筑层接管时，改为由建筑布局生成"哪两间房相邻 → 补一对门"即可，
  房间层这套（门实体 + 来路落点 + 派生种子 + 锁态表）不用动。
- 走大门出楼 = 回上一个面板（现在= 测试面板/上层面板）；以后接地图时改成"回到所在建筑的外面 / 大地图节点"。
  大门**踩上去就出去**（按定版与内门统一），误触风险靠"大门永远在最外圈、路径不会顺路穿过门格"来兜。
- 门后房间的**种子派生**只依赖"出行种子 + 模板标识"：同一趟出行里反复来回看到的是同一间房（柜子、锁态都保留）；
  回安全屋（`打开营地事件`）会清掉容器战局数据 + 视野记忆 + 门锁态 —— 三套临时数据一条生命期。
