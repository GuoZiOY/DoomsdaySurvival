## §1 载荷（v5）

```csharp
[Serializable] class 存档数据 {
    存档头 头;          // 版本 / 保存时间 / 角色名 / 职业 / 等级 / 游戏天数 / 位置 / 是否自动
    玩家档案 玩家;       // v4 那一份，原样
    float 整点基准;      // ★ 必须进档 —— 见 §2.1
    存档战局 战局;       // ★ 战局快照 —— 见 §3
}
```

* **跨天标记故意不进档**：它完全可由 `玩家.游戏分钟数` 推出，多存一份只会多一个"两份数据不一致"的机会。
* `存档头.位置` 由 `存档战局.位置文本()` 出（安全屋 / 大世界 · 标识 / 区域 · 标识 / 楼内 · 建筑 NF / 房间 · 模板）。
* **版本探测单列一个 `存档探测` 类型**：`存档数据.头` 带初始化器（`= new 存档头()`），把 **v4 的 JSON** 直接读成
  `存档数据` 时 `头` 不为 null，会被误判成 v5 而跳过迁移；`存档探测` 不写初始化器 → v4 读出来 `头 == null`、`版本` 是根上那个 4。

## §2 三个必须进档的运行期字段（不进的后果全是静默的）

| 字段 | 不进档的后果 | 现在 |
|---|---|---|
| ★ **`存档数据.整点基准`**（= `世界时间管理器.上次结算分钟`） | **读档即死**：它是纯运行期字段、初值 0，而 `同步整点基准()` 的调用方只有 制作面板/快速测试/睡觉/战斗推进，**读档路径一个都没有** → 读第 5 天的档（7200 分）时同帧补算 **120 次** `结算时间段(60,true)` → 饱食/水分归零 → 扣血到**生命归零**；`腐坏结算(60)` 跑 120 次 → **仓库与随身食物全部腐坏**（"这不是可能，是必然"）。另：`上次天 = -1` 让 `检查跨天()` 在读档首帧必触发 → **存档天气被重掷** | 载荷新增该字段；`读档后对齐(存档基准)`：基准取存档值（保相位）、天取**当前天**；`推进()` 里加 `整点结算.需要重对齐` 的**自愈兜底** |
| **`玩家档案.天赋冷却`** | 原文是 `Dictionary<string,float>`，**JsonUtility 不支持 Dictionary** → 每次存档静默丢掉 → 读档后 `钢铁意志`(10 游戏天)/`医者仁心`(5 游戏天) 冷却清零 → **存档-读档反复触发同一张免死牌** | `List<天赋冷却条>` + `天赋冷却就绪/记天赋冷却` |
| **`玩家档案.已拆墙`** | `拆除墙()` **就地改写** `安全屋户型.格所属块/格可用`，档案却只存 `户型种子` → 读档后墙全部复活，而 `家具` 是进档的 → "家具落在已恢复的墙格里" | 档案新增 `已拆墙`（`"{列},{行}"`，按拆除顺序），生成户型后 `重放拆墙()`（幂等，不写档不发日志） |

## §3 战局快照：位置 + 所有活着的层 + 容器内容 + 敌人 AI 态

`存档战局`（`Assets/Scripts/Domain/存档/存档战局.cs`）：

| 字段 | 内容 |
|---|---|
| `层` | 安全屋 0 / 大世界 1 / 区域 2 / 建筑 3 / 单间 4（玩家存档时在哪） |
| 重建链 | `大世界标识/种子`、`区域标识/种子`、`建筑标识/种子`、`建筑层`、`房间模板`（由外向内，只填到玩家所在那一层）；`玩家列/行` = 玩家在最内层世界里的格 |
| `活层` | **所有活着的层**（由外向内），不止玩家站的这一层 |
| `容器们` | 全局一份：已生成内容（含每件物品的 列/行/旋转/耐久/嵌套容器）+ "已搜"记录 |
| `单间种子` | 单间/临时建筑那个世界的实际种子（**不能**由 世界种子 派生） |

`层快照` = 层类 + 层号 + 模板标识 + 种子 + 迷雾位图 + `网格数据`（实体位置/已搜/门锁/敌人位置）+ 敌人态表。
`战局 == null`（或 `层 == 层安全屋`）= 老档 / 在安全屋存的档 → 走"从安全屋出发"那条老路。

**为什么必须是"真快照"而不是"增量 + 种子重建"**：

| 事实 | 含义 |
|---|---|
| 四层生成器**零无种子随机**，实体标识 = "模板标识 # 局部序号"、**无成员计数器** | 结构可只存增量、按**稳定标识**回填 |
| **柜子内容来自无种子 `System.Random`**（`搜索服务`）；一次性临时建筑内部用 `UnityEngine.Random` 播种、标识依赖 `搜索次数` | ⚠ 两者都**不可复现** → 必须真存内容 + 存实际种子 |
| **三层世界的敌人同时在跑**（进楼/进区域时上层 `当前世界` 并不清空） | 要存"所有**活着的**层"，不只是当前层 |
| `网格实体.容器定义` 是指向 DataService 模板的**共享引用**（`房间生成器`） | ⚠ **快照前必须置空、读后按 `定义标识` 回填**，否则整张搜索表被复制进存档 |
| `敌人AI态` 缺 `[Serializable]`，实例表是 `Dictionary<网格实体, …>` | 补 attribute + 拍平成"实例标识 → 态"的数组 |

## §4 存档门禁（`存档门禁.cs` = "什么时候不许存 / 不许读"的唯一真相）

| 路 | 检查 | 判据 |
|---|---|---|
| **存** | `存前检查()` | 必须**已开局**（`档案.当前节点` 非空）**且不在战斗中** |
| **读** | `读前检查()` | **只拦战斗中 → 读档允许未开局**（主菜单「继续」正是在未开局状态下读的） |

* 战斗中既不存也不读：档案不含战斗状态，且战斗期 `游戏分钟数` 已被推过一段
  → "战斗存档 → 读档" = **必败战免费逃跑**，读回来的时间与状态也对不上。
* 战斗态不进档 ⇒ **战局快照只覆盖"探索中"的层**，不需要处理战斗。
* 正确性必须在**代码层**：存档面板是运行期全屏叠层，它开着时世界时间照走、遭遇会在面板背后打起来（"按钮隐藏"挡不住）。
* `Tools/存档接线核对.ps1` 段[9] 断言：存与读都走这里 + 读档不再有"失败就开新游戏"的兜底。

## §5 文件、槽位与分工

| 项 | 决定 | 为什么 |
|---|---|---|
| 位置 | `Application.persistentDataPath/存档/槽N.json` | 与资源目录分开（重装不碰玩家的档）；文本 JSON 可直接看 |
| 槽位 | `槽0.json` 自动 + `槽1..3.json` 手动 | 自动档**绝不覆盖**手动档 |
| 原子写 | 写 `.tmp` → `File.Replace` → 旧文件成 `.bak` | 最坏是"这次没存上"，而不是"档变成半截 JSON" |
| 删除 | 删正式文件 + `.tmp`，**`.bak` 故意留下** | 玩家后悔时还能手动改回来 |
| v4 迁移 | 装配期一次性：旧键存在 **且** 槽1 无文件 → 搬进槽1 | **不覆盖**已有的新档；**迁移后不删旧键**（兜底） |
| 版本检查 | `存档版本.检查(版本)`：比本作新 → **明确拒收**（写进 `存档摘要.损坏原因`） | JsonUtility 对"同键但结构变了"的档**不抛异常** → 坏档会以"关键值是 0"静默进游戏 |
| 路径唯一出口 | 只有 `存档文件.cs` 能出现 `persistentDataPath` | 路径散开会写出两个互不相认的存档目录 |

**分工** —— 判据：**能离线测的那一半必须搬进没有 UnityEngine 的那一半**。

```
Domain/存档/存档模型.cs / 存档战局.cs   纯 C#：规格 / 头 / 载荷 / 摘要 / 版本检查 / 迁移链 / 指纹 / 战局快照载荷
Domain/时间/整点结算.cs                 纯 C#：整点结算次数 + 自愈判据
Services/存档/存档文件.cs               Unity IO：路径 / 原子写 / .bak（唯一允许出现 persistentDataPath 的地方）
Services/存档/SaveService.cs            组装载荷→落盘；读文本→校验→迁移；列槽位摘要（门禁另见 存档门禁.cs）
Services/存档/自动存档器.cs             关键点自动存 → **只写自动槽**
UI/浮层/存档面板.cs                     槽位列表 + 保存/读取/删除（二次确认）；运行期搭 uGUI，不改场景、不依赖 SerializeField
```

`Tools/存档验证` 用 `<Compile Include>` 直接链接 `存档模型.cs` / `整点结算.cs` / `玩家档案.cs` —— 验的就是游戏跑的那份源码。

## §6 验证（三道关，别互相替代）

| 关 | 在哪 | 验什么 |
|---|---|---|
| 行为（离线） | `Tools/存档验证` | 版本真值表 · 迁移幂等 · 槽位规格 · **整点结算**（含"基准 0 + 第 5 天 = 120 次"这条把 bug 变成断言的用例）· **档案每个标量字段都被指纹覆盖**（反射扫）· 战局快照的深副本与 `容器定义` 剥离/回填 |
| 形状（源级） | `Tools/存档接线核对.ps1` | 段[1] 载荷不许是 Dictionary/HashSet/元组/裸委托 · [2] 读档对齐整点基准 · [3] 未开局冻结 · [4] 路径单一出口 · [5] 无死 API · [6] 自动槽独立 · [7] 面板入口唯一 · [8] 拆墙进档 · [9] 战斗中不存不读 · [10] 战局快照要抓且剥离 `容器定义` |
| 真 JsonUtility | 游戏内 快速测试面板 →「存档」→ **★ 存档往返自检** | 真 `SaveService` + 真 `JsonUtility` + 真原子写盘：存 → 读 → 比指纹（内存 + 磁盘两段），不一致时打印**第一个不同的字符位置** |

判据备忘：`整点结算.单次上限` 是**防呆上限**（`365*24`），不是语义上限 —— 写小了会把"读档即死"藏起来。

## §7 已知边界（诚实清单）

* **不验数值手感**：`整点基准` 只保证"不重复结算"，不保证"生存消耗速率合不合口味"；`SaveService.往返自检()` 也不验版本迁移语义与数值。
* **`.bak` 只保留一份**：连续两次覆盖会覆盖掉再上一份。"多版本回滚"要靠手动多槽。
* **槽位列表把整份文件读进来**（JsonUtility 没有"只解析一部分"）；单档涨到 MB 级时需把 `存档头` 拆成独立的 `.head.json`（届时看实测）。
* **主菜单「继续」打开存档面板而不是直接读最近档** —— 多一次点击，换"看得见有哪些档"。
