# 核心玩法循环闭路设计（刀61 设计稿）

> 状态：**设计稿，未实施**。回答"游戏核心玩法流程是否循环闭路"。
> 姊妹篇：`docs/大世界敌人AI设计.md`（"赶路"那一段的张力来源）。
> 审计基线：`HEAD` 当时的工作区（数据 + 代码现状，全部带位置，不猜）。

---

## §0 结论

**不闭路。** 环与环之间的"管道"绝大多数已经接好了——时间、生存消耗、行动点（趟预算）、成长、消耗水槽、挑战阶梯（7 区域分级 + 7 Boss + 精英）都在跑。
但有**三个真正的断点**，性质各不相同：

| # | 断点 | 性质 | 一句话证据 |
|---|---|---|---|
| 一 | ~~没有收束~~ → **无时间上限（已澄清，不是缺陷）** | **已拍板：暂不做** | 用户 2026-02 澄清：**"87 天只是一开始随便拟的题，不用理会"**。本作当前形态 = **让玩家存活越来越久，没有时间上限**；明确主题 / 剧情模式**后续再确立**。→ §2 降级为"记录在案，非本轮工作" |
| 二 | **情报系统是悬空器官** | **半成品** | `情报.json` 21 条 + `安全屋管理器.尝试收听()` **零调用方** + `解锁条件["情报"]` 被数据校验直接判错 |
| 三 | **区域门槛是装饰性的** | **结构空洞**（已实测） | 5 把区域钥匙**全部**能在开局可进的 2 个区或大世界临时建筑里拿到 → 闭包第 1 轮 7/7 区域全解锁 |

**用户补充定性（2026-02）**：核心玩法的流程闭路上**还有大量功能与系统缺陷**，本轮不追求"补完"，
由后续各刀慢慢补。本文档的职责是**把已经查实的断点记下来**，不是一次做完。

两个仍然成立的断点是同一条病的两个症状：
- 断点三 → 去危险区不需要资格（钥匙不值钱）；
- 断点二 → 唯一一条"从外界获得信息"的通路是断的（收音机不响）。

（断点一若将来重新确立主题，本文档 §2 的完整分析与三件套方案仍然可用。）

## §1 循环现状（带证据）

```
                   ┌────────────────────────────────────────────────┐
                   │            安全屋（唯一重置点）                 │
                   │  睡觉：行动点/生命/疲劳回满（生存管理器 L57）    │
                   │  制作（行动点 5/次）· 建造/升级家具（材料）      │
                   │  自动转化：种植箱 / 晾晒架 / 净水器（挂机走）    │
                   └──────────┬───────────────────────▲─────────────┘
                    出门（5 游戏分钟/格）               │ 回安全屋
                              ▼                        │ 清战局：柜子/门锁/街上敌人
        ┌───────────────────────────────────────────────┴───────────┐
        │ 大世界 100×100 · 16 只静态敌人 · 200 障碍 · 永久迷雾        │
        │ 「搜索」翻临时建筑（行动点 10 +4/次，枯竭半径 8）            │
        │ 7 个区域门口 ← 解锁条件：物品 / 天数                        │
        └──────────┬────────────────────────────────────────────────┘
                   ▼ 进区域（危险度 1~5）
        ┌───────────────────────────────────────────────────────────┐
        │ 区域 32×22：街上敌人 · 建筑入口 → 楼层（1F/2F/3F）          │
        │ 房间：门/锁/搜索容器/敌人 → 击倒留可搜尸体                  │
        │ 3F 前室 + 上锁 Boss 房（钥匙靠 钥匙投放）                   │
        └──────────┬────────────────────────────────────────────────┘
                   ▼ 物资 + 经验 + 技能书/配方书 + 区域钥匙物品
        ┌───────────────────────────────────────────────────────────┐
        │ 成长：经验→等级（每级 3 自由属性点）· 书籍→技能/配方         │
        │ 配方→装备/家具 · 家具→容量/效率 · 配件改装（无随机词缀）      │
        └───────────────────────────────────────────────────────────┘
                              然后呢？→ 没有然后
```

## §2 断点一：收束——**项目承诺了 87 天，但一行都没实现**

### 2.1 证据（这一条最硬，因为它是项目自己说的）

| 证据 | 位置 |
|---|---|
| 游戏名《最后87天》 | `主菜单面板` L4、`角色创建面板` L6、`面板管理器` L6；存档键 `last87days_save_v4`（`SaveService` L8） |
| **开场文案明写倒计时**："第一天的太阳落下去的时候，你还在呼吸。……**从今天算起，还有八十七天。**" | `对话面板.渲染结局()` L115–116 |
| 注释把 87 天当成**已存在**的机制在引用 | `大世界探索服务` L14（"配合'87 天'倒计时形成取舍"）、L39（"重新摸一遍纯粹是从 87 天里扣时间"） |
| **`87` 在逻辑代码里出现 0 次** | 全仓库 `87` 命中处只有：存档键、4 处注释/名称、一处颜色常量 `0.4941f`。**没有任何上限判定、倒计时、第 87 天判定** |
| `游戏天数` 的消费者只有 4 处，全都不是"上限" | `任务管理器`（日常刷新日）、`生存管理器`（睡觉跳时间）、`自动存档器`（跨天存档）、`大世界探索服务`（解锁条件"天数"） |

### 2.2 一个重要的澄清（这决定了方案怎么选）

`数据模型` L973–978 写着"本作**不要通关这个概念**"。**那条否掉的是"区域级通关门"，不是"整局终局"**：

> · **没有"前置区域"** —— 曾经的设想是"通关某片区域才开下一片"，但那要求"标记区域已通关"，
>   而本作**不要这个概念**（资源靠"回安全屋重置"反复刷，没有"通关"这回事）。

它反对的是**区域**被打上"已通关"标记。而"整局 87 天到期"与"每天可以反复刷"**在结构上并不矛盾**——
这正是经典结构：**天数卡总产出上限，回安全屋重置提供日内的重试循环。**

所以我之前的判断（"①天数上限会推翻用户拍板"）是**错的**。① 不是推翻，是**补上项目一直承诺却没做的那一块**。

### 2.3 断点的真实后果（为什么这是"不闭路"的根因）

1. **时间免费** → 没有取舍。大世界的 5 分钟/格、搜索的 30 分钟、睡觉跳 18 小时，全部**零机会成本**：
   反正第 100 天和第 10 天一样。§1 表里那些"时间成本"的机制**全都空转**。
2. **跑步机感**：玩家的最优策略是无限刷（回安全屋 → 重置内容 → 再刷），而"变强"没有尽头。
   危险度/Boss/精英只是"更肥的怪"，不构成压力。
3. **开场就在撒谎**：玩家在前 15 秒被告知"还有八十七天"，然后发现这个数字永远不会变。
4. ⚠ **顺带**：这个开场面板目前**根本到不了**——`打开结局事件` 的唯一发布方是 `DialogueService` L70 的
   `"__结束"` 分支，而 `DataService` 加载的 `Data/story` **文件不存在**（项目规则：剧情/任务不做）
   → `数据.剧情` 恒空 → 永远没有对话节点 → **开场文案从来没见过玩家**。
   （机制本身是接好的：`面板管理器` L129 订阅 → `对话面板` L37 `渲染结局()`。**缺的只是触发源**。）

### 2.4 设计：三件套，缺一不可

| 件 | 内容 | 为什么必须有 |
|---|---|---|
| **① 87 天硬上限（被动结局）** | `游戏天数 ≥ 87` → 结算结局（活满）。HUD「地点/时间」位从"第N天 HH:MM"改成"**第N天 · 还剩M天**" | 兑现项目承诺；给"时间"装上价格，让 §1 里所有时间成本机制开始工作 |
| **② 主动出口（发报机）** | 集齐部件 → 组装 → **提前**脱出（主动结局） | 纯硬上限会逼玩家"来不及体验完就结束"。主动出口把"变强"接到一个**出口**上，而不是给时间再加一道墙 |
| **③ 压力阶梯** | 每 N 天（建议 10/20/30……）敌人等级带 +1，或新增夜行精英 | 让"拖延"真的花钱。没有它，87 天只是一个"慢慢刷就行"的沙漏 |

**为什么不能只做 ①**：87 天 × 每天约 11 次搜索（行动点卡的上限）+ 7 区，玩家会因为"怕浪费天数"而**不敢探索**——
这是最差的结果（把开放世界玩成资源焦虑）。② 让"高效的变强"有回报，③ 让"低效的拖延"有代价。

### 2.5 ②的部件从哪来（**待你拍板**）

方案的骨架（8 个区域各 1 件，**强制打穿全部区域**，每片区的独立设计都有存在理由）：
```
馆长→真空管     包工头→铜线圈     收银台屠夫→电解电容   器材店老板→天线杆
主刀→信号滤波器  防暴队长→军用电池  巨型变异体→发报机机壳
      ↓ 集齐 8 件
安全屋新家具「发报机」（工作台配方）→ 组装（耗行动点 + 游戏时间）→ 主动结局
```
⚠ **这里与一条既定口径冲突**：你之前拍过"boss 掉落和 boss 房可搜索容器，**使用已有的物品即可，不需要额外新增**"。
但"终局收集件"必须是**唯一、可追踪、不参与任何配方**的物品，否则会被当材料消耗掉。
→ 三个选项（**需要你选**）：
- **(a)** 新增 8 件**任务品**（`items_任务品.json` 现在 9 件 → 17 件）。它们不参与任何配方，只做"收集位"。
- **(b)** 复用现有 9 件任务品 + 7 把 Boss 房钥匙（**零新增**，但钥匙本来就会被用掉/占位，语义混）。
- **(c)** 不做②，只做 ①+③（**零新增**，但 87 天只能被动等待，玩家没有"提前赢"的目标）。

## §3 断点二：情报系统是悬空器官

### 3.1 证据

| 事实 | 位置 |
|---|---|
| 数据存在：**21 条**情报，字段只有 `{文本, 等级}` —— **连"标识/标题"都没有** | `情报.json`；`数据模型.情报条目` L686 |
| 加载了：`DataService.加载情报()` → `数据.情报` 列表 | `DataService` L130–135 |
| **唯一的功能入口零调用方**：`安全屋管理器.尝试收听()` L281 —— 全仓库没有任何地方调它（安全屋面板没有"收听"按钮） | 递归核对确认 |
| 即使调了，也**不读情报池**：它只做 `玩家.预知天气 = Random(...)` | 同 L284 |
| `预知天气` 是活的：跨天时优先采用，然后清零 | `世界时间管理器` L365–368 |
| `解锁条件["情报"]` 被判成**数据错误** | `DataService` L620（"情报系统还没有'已获得'的记录 → 写了就是一道打不开的门"） |
| 情报文本里还写着**过时地名** | 例："东区夜里传来枪声"（现名**城东学区**）、"城北的超市"、"西部安全区"——刀59 改了区域名，情报没跟 |

**所以现状是**：一个 21 条的叙事系统，数据齐、加载齐、家具齐（收音机 Lv1~3）、天气预知那半条腿是活的，
但**"听广播"这个动作玩家做不到，"听到的内容"代码不读，"拿情报当钥匙"被校验禁止**。

### 3.2 设计

| 步 | 内容 | 规模 |
|---|---|---|
| 1 | `情报条目` 增 `标识` + `标题`（21 条各补一个；**标识是解禁解锁条件的前提**） | 数据 |
| 2 | 安全屋面板加「收听收音机」（调已存在的 `尝试收听()`）→ 按 `收音机` 等级过滤（`等级 ≤ 家具等级`）→ **播报进日志 + 记入 `玩家档案.已获得情报 List<string>`**（新字段） | 小 |
| 3 | 保留"预知明日天气"（已实现，别丢） | — |
| 4 | **解禁 `解锁条件["情报"]`** → 把 1~2 个区域从"物品"改成"情报"（更有味道：你是**听说**那里才去的，不是捡到一张地图） | 小 |
| 5 | 情报文本跟随刀59 的区域改名更新（城东学区/城西政务区/户外用品店…） | 数据 |
| 6 | （可选）情报做**地图标记**：播报"纺织厂那边有动静" → 大世界对应区域格在迷雾里亮一个问号 | 中 |

**为什么这条值得做**：它是唯一一条"从外界获得信息"的通路，而末日题材里"收音机"就是这个世界的**唯一活着的器官**。
它现在不响，玩家就只是一个在空城里翻柜子的人。**成本极低（面板一个按钮 + 一个字段 + 数据补标识），叙事收益极高。**

## §4 断点三：区域门槛是装饰性的（**实测数据，不是推测**）

### 4.1 我把整条链跑了一遍

链路是完整且唯一的（这是好消息——意味着可以做门禁）：
```
世界.json 区域[].解锁
  → 区域模板.建筑[] → 建筑模板.楼层[].房间[] → 房间模板.容器池[]
      → (地图类型, 房间) → 搜索_地图类型.容器[].搜索表[].物品标识
  （+ 区域模板.敌人[] → enemies.json.掉落物品/掉落列表）
```

### 4.2 结果

**① 闭包：7/7 区域可达，但全部在"第 1 轮"就解锁**

| 区域 | 危险度 | 解锁条件 | 实际第几轮解锁 |
|---|---|---|---|
| 居民区 | 1 | （开局可进） | 0 |
| 西区 | 3 | （开局可进） | 0 |
| 东区 | 2 | 物品:旧地图 | **1** |
| 商业区 | 2 | 物品:城市地图 | **1** |
| 医院区 | 3 | 物品:账本 | **1** |
| 警察局区 | 4 | 物品:机密文件 | **1** |
| 工厂区 | 5 | 物品:相机 + 天数 10 | **1**（天数不阻断） |

**② 5 把钥匙全部能在开局两区里拿到 → 门一道都没拦住人**

| 钥匙 | 白名单临时建筑能刷出？ | 开局两区（西区/居民区）有来源？ |
|---|---|---|
| 旧地图 | ✅ **9 处** | ✅ 西区 9 处 / 居民区 9 处 |
| 城市地图 | ✅ **10 处** | ✅ 西区 8 处 / 居民区 6 处 |
| 账本 | ✅ **2 处** | ✅ 西区 3 处 / 居民区 2 处 |
| 相机 | ✅ **10 处** | ✅ 西区 11 处 / 居民区 6 处 |
| **机密文件** | ❌ 0 处（白名单刷不出） | ✅ **西区 2 处** |

**③ 门槛与危险度错配**

- **西区危险 3，却开局可进**（玩家 1 级就能进危险 3 的区）。
- 唯一的"天数"门只有工厂区一处（第 10 天）。
- 钥匙的**出现密度并不低**（例：旧地图在西区 9 处 / 1137 条条目，权重 9/2015），
  而这是**单条目权重占比**，一个容器会抽多件 → 实际远比这个比例容易撞上。**"稀有"不足以构成门槛。**

### 4.3 这和 v52 修过的洞是**同一类**

v52 已经修过一次"第 1 天就能在门口刷出手枪弹/血清/军刀图纸"——做法是**给临时建筑加楼型白名单**。
那次堵的是"**楼型**越级"，这次漏的是"**钥匙物品的掉落位置**"越级：
白名单楼型（居民房/便利店/药店/图书馆/街区）本身是干净的，但**钥匙物品被撒进了这些地图类型的容器里**。

### 4.4 设计

| 步 | 内容 |
|---|---|
| 1 | **钥匙物品改成"区域专属来源"**：每把钥匙只出现在**指定区域的指定容器**里。例：<br>· `旧地图` → 居民区/商业区的 报刊架、后备箱、信箱<br>· `账本` → 医院区的 值班台、分诊台（**只有医院有账本**才对）<br>· `机密文件` → 警察局区的 证物架、值班台<br>· `相机` → 商业区/东区的 收银台、器材抽屉 |
| 2 | **从大世界临时建筑白名单的地图类型里剔掉所有 5 把钥匙**（`允许地图类型` 那 5 类的容器搜索表逐条核对） |

## §5 天气补全（补 §1 表的半闭项）

现状：7 种天气，**只有 3 种有机械效果**（寒潮→感冒判定 / 雨→补水 / 酷暑→耗水），其余 4 种纯显示。

| 天气 | 现在 | 建议 | 为什么是这个效果 |
|---|---|---|---|
| 晴 | 无 | 视野 +1 格 | 通透；也让"晴"不是一个空档期 |
| 雨 | 补水 | **噪音传播 −25%** | 雨声掩蔽 → **雨天是潜行日**（与 `大世界敌人AI设计.md` 天然咬合） |
| 雾 | 无 | **视野边长 ×0.5**（最低 3）+ 敌人视觉 ×0.5 | 雾天 = 双方都瞎 → 潜行与遭遇战规则被改写的一天 |
| 雷雨 | 补水 | 同上（雨 + 偶发落雷，落雷先不做） | — |
| 寒潮 | 感冒判定 | 保持 | 已闭 |
| 沙暴 | 无 | 视野 ×0.5 + **大世界每格耗时 5 → 8 游戏分钟** | 让"要不要今天出门"第一次有分量 |
| 酷暑 | 耗水 | 保持 | 已闭 |

**注意**：`视野边长` 现在是 `视野规则`（读 `视野.json`）按"角色 + 时段"算的纯函数。
加天气输入 = 把天气作为**第三个入参**接进去，**一处改三层都变**（房间/区域/大世界共用同一个 `视野规则`）。
⚠ 这会**改变既有验证断言的输入域**（`视野验证` 之类）→ 落地时要同步扩验证（用户定过"验证规模冻结"，所以是**新增**不是修改）。
