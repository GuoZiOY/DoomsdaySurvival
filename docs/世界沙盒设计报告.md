## 一、概述

世界沙盒是末日求生版的「废土探索」主舞台，是**战前准备 → 探索搜刮 → 战斗 → 带物资回家**的核心载体。

四个关键词：

| 关键词 | 含义 |
|---|---|
| **网格驱动** | 世界/区域/建筑 全部基于网格，复用网格面板基类体系 |
| **程序化生成** | 世界由「确定性种子 + 生成算法」展开，非手工拼接 |
| **战争迷雾** | 三态迷雾 + 视野，探索有信息差 |
| **时间耦合** | 探索移动推进世界时间，与生存/腐坏/生长/净化联动 |

与战斗沙盒（节点式轨道，1 维战线）不同，世界沙盒是**真正的 2D 网格探索**。

## 二、四层世界结构（层层下钻）

```
世界层（节点地图）      世界地图上的「地区」节点，选择前往
   │ 进入某地区
区域层（城区沙盒）      单个地区的废土网格：街道 + 多个建筑入口 + 敌人 + 搜索点 + 陷阱
   │ 进入某栋楼
建筑层（楼层结构）      一栋楼含多个楼层（1F/2F/…/地下室），楼梯上下连接
   │ 楼梯切换楼层
楼层层（房间沙盒）      单层 BSP 房间网格：多个搜索容器（符合该建筑类型）+ 敌人
```

| 层 | 是什么 | 进入/切换方式 | 生成方式 |
|---|---|---|---|
| 世界层 | 地区节点图（含安全屋出生点） | 点节点选择前往 | 程序化（地区随机排布） |
| 区域层 | 一片城区/废土网格 | 从世界节点进入 | 程序化（主题模板） |
| 建筑层 | 一栋楼的楼层结构 | 从区域网格「建筑入口」进入 | 程序化（楼层数 + 各层参数） |
| 楼层层 | 单层房间沙盒 | 楼梯上下切换 | 程序化（BSP） |

## 三、随机边界（确定性设计核心）

**一条线划清「什么固定、什么随机」：**

| 层 | 固定（模板写死） | 随机（世界种子决定，生成后永久固定） |
|---|---|---|
| 世界层 | 地区类型集合、每个地区的核心标志建筑 | 地区节点在地图上的位置排布、道路连接 |
| 区域层 | 中心标志建筑（如警察局） | 周边配套建筑（权重池）、街道布局 |
| 建筑层 | — | 楼层数、各层布局 |
| 楼层层 | — | 房间布局（BSP）、搜索容器/敌人散布 |

**设计原则**：
- 地区「有什么」固定（叙事/任务锚点稳定），地区「在哪」随机（重玩差异）
- 玩家体感：每次出发，**同一套地区、同一批核心建筑，但地图长不一样**

## 四、种子体系（确定性生成机制）

### 4.1 世界种子（建世界一次，永久不变）

开档创建世界时掷「世界种子 S」并保存；S 决定整个世界的**结构**（地区/建筑/楼层/房间/容器位置与类型），永久不变：

```csharp
long 世界种子 = Random 生成;   // 建世界一次；永久恒定，决定地形结构
```

- 世界种子决定「**结构**」：地区在哪、建筑/楼层/房间怎么排、容器摆哪个房间、是什么类型
- 世界只有「这一个」：地形结构永久不变，玩家可记忆路线（北边警察局、地下室在入口左）
- 未来可支持手动输入种子分享

**结构 vs 物资分开**：地形结构用世界种子重建（不存档）；容器里的物资/敌人分布**每局刷新**，不归世界种子管（见第八章）。

### 4.2 种子派生公式

```csharp
// 稳定字符串哈希（31 进制滚动哈希，跨平台一致、无碰撞短串）
static int 混合种子(params object[] 部分)
{
    unchecked
    {
        int h = 17;
        foreach (var p in 部分)
            foreach (char c in p?.ToString() ?? "")
                h = h * 31 + c;
        return h;
    }
}
```

```
世界层在地图上的排布   ：seed = S
区域层 X 的城区        ：seed = 混合种子(S, "区域", X.标识)
建筑层（X 区内的楼 Y）  ：seed = 混合种子(S, "建筑", X.标识, Y.坐标)
楼层层（Y 楼的 F 层）   ：seed = 混合种子(S, "楼层", X.标识, Y.坐标, F)
```

### 4.3 种子原理（为什么小种子能展开大世界）

- 种子不是「压缩包」，是「启动键」：世界由**生成算法（代码+模板）+ 确定性随机流**展开
- `new Random(种子)` = 确定性 PRNG，同种子永远吐同一串随机数（要多少取多少）
- 世界的丰富度来自算法（万花筒的碎片），种子的位数决定「有多少种不同世界」（转动的角度）

**信息流**：`小种子 → 递推展开 → 确定性随机流 → 剧本逐数翻译 → 完整世界`。

## 五、程序化生成算法

### 5.1 世界层：地区排布

- 世界 = N×N 节点图（如 10×10）
- 安全屋固定出生点（如 (5,0)）
- 地区集合固定（警察局区、医院区、商业区、住宅区、工厂区…），按固定顺序随机散布坐标
- 道路连接：最小生成树保证关键地区连通

### 5.2 区域层：主题模板 + 权重池

区域层外观由「地区主题模板」决定——先落中心地标，再按配套建筑池撒楼，街道串起来。

```json
{
  "标识": "警察局区",
  "名称": "警察局区",
  "危险度": 3,
  "中心建筑": "警察局",
  "配套建筑池": [
    { "建筑": "居民楼", "权重": 4, "数量": [2, 5] },
    { "建筑": "药店",   "权重": 2, "数量": [1, 2] },
    { "建筑": "便利店", "权重": 2, "数量": [1, 2] },
    { "建筑": "停车场", "权重": 1, "数量": [0, 1] }
  ]
}
```

- **中心建筑**：主题决定，必存在（叙事/目标锚点）
- **配套建筑池**：权重 + 数量区间，进入时随机抽取组合（轮盘赌）

### 5.3 建筑 → 楼层 → BSP 递归二分

建筑含多个楼层（`层数` 由建筑模板决定），**每一层独立跑一次 BSP**，楼梯格连接上下层：

```
1. 完整空间 → 随机横/竖切一刀，分成两半
2. 对每半递归，直到尺寸 < 阈值
3. 叶子 = 房间（内缩生成）
4. 每对兄弟节点之间连一条走廊（天然保证连通）
5. 每层按房间类型撒搜索容器（柜子/箱子/尸体…）+ 敌人 + 楼梯格
```

- 房间类型决定搜索容器模板池（办公室→文件柜、厨房→储物柜、枪械库→军火箱…）
- 产出：规整矩形房间，适合住宅/办公楼/警察局/医院等
- **续用预留**：CA（元胞自动机）留给坍塌楼/下水道/洞穴等废墟场景，用 `生成器` 字段路由

## 六、战争迷雾与视野

三态网格，每格一个状态：

| 状态 | 含义 | 渲染 |
|---|---|---|
| 未探索 | 从未见过 | 纯黑 |
| 已探索 | 见过、当前不在视野 | 灰（静态地形记忆） |
| 可见 | 当前视野内 | 亮（物体/敌人实时） |

**视野算法**：玩家周围半径 R 格可见，用**阴影投射（shadow casting）**判断墙是否挡视野（比 Bresenham 更准更快）；敌人同理。

**「谁先看见谁」决定遭遇先手**（复用 偷袭/被偷袭/遭遇 三态，替换旧手动先手参数）。

## 七、探索交互

纯网格对象交互，无文字事件卡：

| 对象 | 交互 |
|---|---|
| 搜索点 | 走进/点击 → 打开搜索容器面板（复用搜索服务） |
| 建筑入口 | 进入 → 切建筑层房间网格 |
| 敌人 | 占格 + 视野，进入其视野/相邻 → 触发战斗（切节点式轨道） |
| 障碍物/墙 | 占格不可通过（掩体，远程需视线） |
| 陷阱 | 触发即结算（耗血/行动点/警报） |
| 出口 | 离开区域回世界层 |

**移动**：走 1 格 = 固定分钟 + 消耗行动点，逐格推进世界时间（天黑/天气/生存压力随走随来）。

## 八、探索生命周期（唯一世界 + 每局物资刷新）

### 8.1 两个层次分开（核心）

| 层次 | 是什么 | 生命周期 | 持久化 |
|---|---|---|---|
| **世界结构** | 地形/建筑/楼层/房间/容器位置与类型 | 建世界一次，永久不变 | 世界种子重建，不存 |
| **世界状态** | 容器物资/敌人分布/迷雾 | **每次出发重置** | 不存，撤离即弃 |

### 8.2 核心循环（塔科夫 raid，结构不变、物资刷新）

```
建世界一次 → 世界种子 S 定下整个结构（永久）
                │
从安全屋出发 ──▶ 同一张地图（结构不变）
   │ 容器打开 → 随机生成物资（本局内容）
   │ 探索 / 搜刮 / 战斗
返回安全屋（撤离）──▶ 清空本局状态（物资/迷雾/搜刮全弃，结构不变）
   │
下次出发 ──▶ 又是同一张地图 → 新一轮物资刷新
```

### 8.3 持久化边界（极简）

| 内容 | 持久化？ |
|---|---|
| 世界种子 S + 玩家属性/物资/安全屋 | ✅ 存档 |
| 地形结构 | ❌ 用世界种子重建 |
| 容器物资/迷雾/搜刮标记 | ❌ 每局刷新 / 撤离即弃 |

**结论**：探索状态一律不存档——结构靠种子永远一致，物资每局刷新。复用现有 `搜索服务.打开()`（首开随机生成）+ `清空战局()`（撤离清空），零改动。

### 8.4 按需生成 + 导航栈

世界结构由世界种子「一次确定」，内存按需加载（进哪层生成哪层，离开销毁，种子随时重跑还原同一结构）：

```
[世界层] ← 本局入口，始终存在（节点图，数据小）
  │ 进入区域A
  ├─ [区域A]       生成入栈
  │    │ 进入建筑B
  │    └─ [建筑B]  生成入栈（B 的各楼层数据已由种子确定）
  │         │ 楼梯上 2F
  │         └─ [2F] ← 楼层层生成入栈
  │    │ 楼梯回 1F → 弹栈销毁 2F
  │    └─ 退出建筑B → 弹栈销毁建筑
  │ 退出区域A
  └─ 弹栈销毁区域A，回世界层
```

内存占用 = 导航深度（最多 4 层：世界→区域→建筑→楼层）× 单层网格，极小。

## 十三、关键决策记录

| 决策 | 结论 |
|---|---|
| 世界层随机性 | 地区类型固定 + 位置随机（核心建筑固定） |
| 种子策略 | 世界种子：建世界一次定结构（永久不变）；物资每局刷新 |
| 持久化 | 结构=种子重建不存；物资/迷雾/搜刮=每局刷新不存；仅世界种子+玩家家底存档 |
| 生成时机 | 世界种子一次定结构 + 内存按需加载 + 导航栈（世界→区域→建筑→楼层） |
| 建筑算法 | 逐层 BSP（CA 留作废墟场景扩展） |
| 种子载体 | long 或 string（可输入复盘/分享） |
