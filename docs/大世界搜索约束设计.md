## 一、问题量化（动手前实测）

| 项 | 当时的值 | 出处 |
|---|---|---|
| 搜索代价 | 10 行动点 + 30 游戏分钟 | `世界.json` |
| 出现概率 | 60% | 同上 |
| 搜索半径 | 4 格 | 同上 |
| 行动点上限 | `100 + 体质×2 + 等级×2` ≈ **110** → 一趟约 11 次 | `生存管理器.cs:85` |
| 睡觉 | **行动点回满**，跳到次日 6:00 | `生存管理器.cs:57` |
| 临时建筑楼型 | **从 `数据.建筑模板` 全表等概率抽** —— 含 `市立医院`／`城西分局`／`纺织厂` | `大世界探索服务.挑临时建筑定义` |
| 营地周围敌人 | 营地 (50,50)，13 只敌人撒在 9600 格里，半径 4 内期望 ≈ **0.06 只** | 算 |

**一天的产量**：11 次 × 60% ≈ **6.6 间楼／天**；每间楼 2 层 3~4 间房、每间约 4.8 个容器 → **每天约 104 个容器位**。
代价只有 330 游戏分钟（一天 1440 分钟）+ 睡一觉。

**对比**：进一片区域拿 4 栋楼 ≈ 60~76 个容器位，**还要走路、打街上敌人、过 `天数≥3/6/10` 的解锁门**。
→ 站在安全屋门口刷搜索 = **每天白拿一趟区域探索，零风险、零解锁门槛**。

三个互相独立的洞：

1. **零风险**：营地半径 4 内基本没敌人，门口搜索除了时间没有代价。
2. **奖励越级**：全表等概率抽 → **第 1 天就能刷出市立医院**（抗生素/血浆）、**城西分局**（手枪弹/步枪弹/军刀图纸）、**纺织厂**（火药/电路板），把三个区的解锁门**整个架空**。这个洞与"刷不刷"无关，走远点照样能刷出来。
3. **以量取胜没有惩罚**：`搜索次数` 只拿来当种子，搜第 10 次和搜第 1 次一样容易、一样好。

## 二、目标

1. **门口的零风险水龙头关掉** —— 搜索变成"在路上"的动作。
2. **奖励天花板压回去** —— 枪弹 / 血清 / 图纸 / 火药这类**区专属产出只在区域里出**。
3. **"多搜"收益递减** —— 一趟里第 1 间划算、第 5 间不值得。
4. **不改玩法内核** —— 还是"翻出一间能进去探索的临时建筑"（用户定的口径不动），只是它从**主粮仓**变成**路上的小补给**。

## 三、三条约束

### 3.1 ★ ① 局部枯竭（用户的方案，取代距离门槛）

**规则**：一次成功的搜索会以**翻出来的那间临时建筑**为中心，把周围 `枯竭半径` 格标成**"已翻过"**。
站在"已翻过"里再搜，成功率掉到 `枯竭概率`；枯竭格本身也不给放新建筑。

**为什么它比"距离门槛"好**：

| | 距离门槛 | 局部枯竭 |
|---|---|---|
| 玩家感受 | "凭什么这儿不能搜" —— 一条看不见的线 | "这一带我翻过了" —— **自解释** |
| 对站桩刷 | 关掉，但只是换到 15 格外继续站桩 | **直接让"站着不动"变成无效动作** |
| 与玩法气质 | 像规则补丁 | 像世界本来的样子 |

**自带一个漂亮的连锁**：翻出来的建筑一定落在搜索半径（4 格）内 → 你必然走进枯竭区里去开它 → **出来时你还站在枯竭区里** → 再搜就是白费。
"找到 → 进去 → 出来 → 再搜"这个循环本身就会把玩家逼着挪地方，不需要任何额外提醒。

**实际走多远才恢复**（`枯竭半径 = 8`、`半径 = 4`）：

- 刚翻出时玩家离建筑 d ≤ 4 → 搜索范围（9×9）**整块**都在枯竭区里（d + 4 ≤ 8）→ **几何上就搜不出**。
- 走到 d ≥ 5 才重新有干净的候选格（这时候概率仍是 12%）。
- 走出 d > 8 才回到 60% → 从刚翻出的位置算，**走 5~7 格（25~35 游戏分钟）**。

**记忆存哪 / 什么时候清**：

- 存在 `大世界探索服务` 的**本趟列表**（`本趟翻出的`），`清战局()`（= 回安全屋）清掉。
- ⚠ **必须和实体分开记**：临时建筑**进去一趟就塌了**（`清掉用过的临时建筑`），但"这一带翻过了"得留着 ——
  挂在实体上会随着坍塌一起忘掉。
- 跟着回安全屋清 → 同一片街区下一趟又能翻。**局部枯竭不是产量阀门，是"别站桩"的阀门**（产量上限由 ② 卡）。

### 3.2 ★★ ② 越翻越累 —— 这一条才是产量阀门（也是本设计最关键的推理）

**先说清楚一个反直觉的事实**：**产量上限是行动点卡的，不是地点卡的**。

> 搜索一次 10 点、行动点上限 ≈ 110 → **一趟就是 11 次**，跟你在哪儿搜没关系；11 × 60% ≈ 6.6 间/天。

所以**只做局部枯竭**的后果是：

> 站桩刷 → 变成 **"走直线刷"**：每走出枯竭区就又能搜出一间，一天照样 ~6.6 间、**~104 个容器位**，
> 只是你整天都在走路。而**大世界上只有 13 只敌人**撒在 9600 格里 —— 走一天的直线几乎碰不到东西，
> 花掉的只是 87 天里的一天。

也就是说：局部枯竭能把搜索从"免费"变成"要付出一整天"（这已经很有价值，它把"顺手刷两下"变成"今天什么都不干"），
但**它没法把 6.6 降到 3**。要压产量，必须给**代价**加码：

```
第 N 次搜索的行动点 = 行动点 + (N-1) × 每多一次多花行动点
```

- 次数从 1 起，且**不管上一次成没成功**（失败不涨价 = 等于没约束）。
- 实测（`行动点 = 10`、`每多一次多花行动点 = 4`）：**第 1 次 10 点 → 第 5 次 26 点；110 点一趟最多 5 次**（不加价是 11 次）。
- 为什么用**行动点**递增而不是"概率递减"：概率递减的表现是"你搜了、什么也没翻到"（花了时间还是空的，手感差）；
  行动点递增的表现是"精力不够了"（清楚、可预期、HUD 上看得见）。

### 3.3 ③ 楼型白名单 + 禁区清单 + 允许地图类型

**白名单**（`搜索.临时建筑`）：临时建筑只能出这几个楼型，按权重抽。实测当前 = 4 个普通楼型。

**禁区清单**（`搜索.禁区楼型`）：显式写出**区专属楼型**。白名单里一旦出现它们 → **校验错误**（不是警告）。
以后新增区专属楼，忘了加进禁区清单也会被交叉核对抓出来。

**允许地图类型**（`搜索.允许地图类型`）：白名单楼型的房间容器池**只许**引用这些地图类型。
为什么还要这一层：白名单只保证"楼型不是区专属的"，防不住"有人把医院房间塞进便利店"——
那样临时建筑照样能拉出抗生素/血浆。这条把"奖励越级"从数据层面彻底焊死。

实测的界线天然干净（已核对）：4 个普通楼型的容器池**只用** `居民房/便利店/药店/街区`，3 个区专属楼型**全用到** `医院/警察局/工厂`。

## 四、数据字段（`世界.json.世界[].搜索`）

```jsonc
"搜索": {
  "行动点": 10, "游戏分钟": 30, "半径": 4, "出现概率": 60,

  "枯竭半径": 8,            // ① 翻出过一间 → 以它的占地为中心、这么大一块算"已翻过"（0 = 关掉这条）
  "枯竭概率": 12,           // ① 站在"已翻过"里时的成功率
  "每多一次多花行动点": 4,   // ② 一趟里第 N 次 = 行动点 + (N-1)×它（0 = 不加价）

  "临时建筑": [             // ③ 白名单 + 权重（空 = 兜底：全部楼型里滤掉禁区）
    { "建筑模板": "西街便利店", "权重": 3 },
    { "建筑模板": "临街门面房", "权重": 3 },
    { "建筑模板": "西区公寓A",  "权重": 2 },
    { "建筑模板": "围合住宅楼", "权重": 2 }
  ],
  "禁区楼型": ["市立医院", "城西分局", "纺织厂"],
  "允许地图类型": ["居民房", "便利店", "药店", "街区"]
}
```

`数据模型.世界搜索参数` 里加同名 6 个字段 + 新类 `临时建筑候选{建筑模板, 权重}`。
**全部字段都有缺省值** → 老档/老 JSON 不填也能跑（`枯竭半径 = 0` + 空白名单 = 行为退回 v51）。

## 五、预期效果

| | 改动前 | 改动后 |
|---|---|---|
| 能不能站桩刷 | 能 | **不能**（一处一趟最多出 1 间：枯竭盖住整个搜索半径） |
| 一趟搜索次数（110 行动点） | 11 | **5** |
| 每间楼容器位 | ≈ 15.7 | ≈ 15.7（这刀不矮化） |
| 每天期望间数 | 6.6 | **≈ 3.0**（要边走边搜；每间之后得走出枯竭区） |
| **每天容器位** | **≈ 104** | **≈ 47** |
| 第 1 天能刷出枪弹/血清/图纸 | 能 | **不能** |
| 代价 | 330 分钟 + 睡一觉 | 330 分钟 + 睡一觉 + **来回赶路 5~7 格/次** |

算"≈3.0"的口径：5 次尝试 × 60%，前提是**每次翻出之后都走出枯竭区**（这正是要的：把搜索和移动绑在一起）。
玩家确实可以"5 次都失败"或"5 次都成功"—— 但**同一处只可能出 1 间**，所以想多拿就必须多走。

## 六、验证方案与实测

### 6.1 顺手修掉一个验证缺陷

原来成功率和代价直接写在 `大世界探索服务.搜索()` 里、掷的是 `UnityEngine.Random` → **曲线离线验不了**（能验的只有几何）。
这一刀把算式抽成 `Domain/大世界/搜索规则.cs`（纯 C#，零 UnityEngine），**只有"掷"留在服务层**
（`搜索规则.挑临时建筑(…, 掷点)` 把掷点当参数收）。于是曲线可以逐点扫。

### 6.2 `Tools/大世界验证` 新增断言（⑨~⑬）

| # | 断言 | 为什么 |
|---|---|---|
| ⑨ | 搜索落点**永远不在"已翻过"里** | 局部枯竭的几何保证 |
| ⑩ | 玩家站在**刚翻出的那一间的门口格**上再搜 → **必须搜不出** | "站桩刷"被彻底堵死的证据（成立条件 `枯竭半径 ≥ 半径+1`，门口格在占地外一格） |
| ⑪ | 枯竭区在远处时，落点必须与"没有枯竭"时**逐字节一致** | 局部枯竭不许影响远处（别把整张图都变难搜） |
| ⑫a | 代价单调递增；**加价生效 → 一趟可搜次数严格变少** | 这条约束存在的意义就是"次数变少" |
| ⑫b | 非枯竭成功率 == 出现概率；枯竭成功率**只许更低** | 数据写反了不许变成"越翻越多" |
| ⑫c | 建筑自己那格必在枯竭区；超出 `枯竭半径` 一格必在区外；`半径 = 0` 时彻底关掉 | 边界别算错 |
| ⑬ | **掷遍所有掷点也抽不到禁区楼型**，且白名单里每个楼型都抽得到 | 奖励越级 + 权重别被吃掉 |

实测（`-- 5`）：

```
—— 搜索自检（以营地门口为玩家位置）——
  翻出 5 间 / 附近太挤 0 次 / **枯竭挡住 25 次** / 失败 0 处
—— 搜索规则自检（纯函数）——
  代价：第 1 次 10 点 → 第 5 次 26 点；行动点 110 一趟最多 **5** 次（不加价 11 次）
  概率：不在枯竭区 60% → 站在枯竭区 12%
  楼型：白名单 4 个（总权重 10）；禁区 3 个 —— 掷遍 10 个点，一个都没抽到
  搜索规则失败 0 处
```

「5 种子 × 6 次尝试 → 只翻出 5 间」= **每种子恰好 1 间**，其余 25 次全被枯竭挡住 —— 正是"一处一趟只出 1 间"。

### 6.3 `Tools/数据引用核对.ps1` 新增

白名单楼型存在 / **不在禁区清单里** / 权重为正；禁区楼型存在；允许地图类型存在；
**白名单楼型的房间容器池 ⊆ 允许地图类型**；枯竭半径/枯竭概率/加价 的区间 + `枯竭概率 < 出现概率`；
两条防刷约束**都关着**时打一行警告。

**这一条断言做过反向验证**（把 `市立医院` 故意塞进白名单 → 工具立刻报两条错，还原后恢复通过）：
断言必须证明它**会响**，不然就是摆设。

## 七、明确不做（别以为漏了）

| 不做 | 为什么 |
|---|---|
| **距离门槛**（离营地 N 格不给搜） | 被 ① 局部枯竭取代 —— 用户方案更自解释，且不制造"看不见的线" |
| **临时建筑矮化成 1 层棚屋** | 用户明确不要；先看 ①②③ 的手感，产出还是太多再回来砍每间产量 |
| **每趟/每天硬上限** | 与 ② 重叠；"数着次数玩"的体验不好。想更狠就调 `每多一次多花行动点` |
| **冷却计时器** | 项目在"重置计时"上栽过一次（`大世界网格与副本设计.md` §3.1）：多一个计时器就多一套随档状态、多一条时间流，全是白造 |
| **枯竭随档永久保存** | 会把地图逐渐耗尽，与"内容可重复刷（回安全屋重置）"冲突 |
| **搜索的昼夜/天气修正** | 不在这刀范围内；数据字段留了口子（要给"夜里更难搜"再加一个乘数即可） |

## 九、以后可以接着做（不在本刀）

1. **如果 47 个容器位/天还是太多** → 做"矮化棚屋"（新增 1 层楼型，纯数据 + 白名单加两项）。
2. **把建材的正路做厚**：堵掉门口搜索之后，建材应该来自 `居民区/商业区`（木板/钉子/布料）和 `工厂区`（铁皮/金属零件/火药）。
