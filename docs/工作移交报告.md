## 三、工作流程（信息链路）

### 1. 状态变化链路（数据 → 事件 → UI）

```
玩家档案（数据源）
   ↓ 修改（生存管理器/世界时间管理器/效果结算…）
EventBus（事件总线）
   ↓ 发布
HUD面板 / 各浮动面板（订阅事件：生命/精力/生存状态/时间/背包变化…）
   ↓ 兜底
Update 轮询（对比档案缓存；净水器面板 0.5s 刷净化进度）
```

### 2. 时间链路（统一走 世界时间管理器）

```
世界时间管理器（唯一入口）
├── 推进(现实秒)        ← 挂机驱动（每帧）→ 净化推进 + 生长推进
├── 结算时间段(分,含饱水) ← 整点结算 / 制作补副作用 → 腐坏 结算（生长/净化 不在此——已逐帧）
├── 跳时(游戏分钟)      ← 制作动画 → 净化推进 + 生长推进（两条时间流都覆盖）
└── 同步整点基准()      ← 外部跳时/取消回滚
        ↓
玩家档案.游戏分钟数 + 饱食度/水分度(float) + 堆叠.新鲜/生长/净化分钟
        ↓
事件发布 → HUD 刷新
```

### 3. 制作链路（会话版，两步 + 动画）

```
选配方 → 拖材料入 输入网格（真实移入会话）
   ↓ 点制作（数量 = 滑条/输入框）
开始制作_会话（校验 输入网格×数量 + 扣精力×数量）
   ↓ 动画（进度条 0→100% + 跳时推进时间）
结算制作_会话（输入网格扣料×数量 → 产物入 输出网格 ×数量）
   ↓ 输出区满 → 回滚（材料退回输入区/精力/时间/饱水全返还）
   ↓ 关闭面板 → 输入剩料+输出成品 自动返还玩家（背包/仓库）；背包满 → 拒绝关闭
```

### 4. 净化链路（时间驱动，无按钮）

```
世界时间管理器 推进/跳时
   ↓ 净化推进(净水器.净化分钟 -= 时间；惰性初始化补满)
材料齐（脏水区有脏水 且 过滤区有木炭）且 净水区可放 → 倒计时
   ↓ 到 0 → 自动：脏水-1 + 木炭-1 → 净水区 +水1 → 自动续下一批
缺料/净水区满 → 冻结进度（条件恢复继续，不浪费）
   ↓ 出水面板 0.5s 轮询刷新（滑条 + 距下批出水 X 分钟）
```

### 5. 服务装配链路（GameBootstrap）

```
EventBus → DataService（校验）→ SaveService → PlayerService（初始化+解析器接线）
→ 世界时间管理器 → 容器/搜索/安全屋/制作/对话/任务/战斗/技能/天赋/词缀
→ 格子探索三层：大世界探索服务 / 区域探索服务 / 房间探索服务
→ 自动存档器 → 挂载时间驱动
```
> ⚠ `DataService` 校验不过 → **中止装配业务服务**（`校验错误` 挡进游戏；`校验警告` 只 `Debug.LogWarning`）。
> v51 起「职业/天赋悬空引用」走**警告**（内容没补是已知状态），「解锁条件写了 `情报`」「`楼梯边` == 首间房 `入口边`」走**错误**。

### 6. 存档链路

```
保存：玩家档案 → JsonUtility → PlayerPrefs(v4 键)
读取：反序列化 → 接线解析器 → 清理非法值 → 发布初始状态
版本：v4（饱食/水分 float；物品堆叠 新增 新鲜/生长/净化分钟——缺省 0 惰性初始化，无需升档）
      v51 新增 `玩家档案.世界种子`（缺省 0 → 读档时补一个随机值，**别让 0 当种子用**，0 会让派生结果退化）
```
> **大世界不另存位置**（v51 定版口径）：读档 → `世界种子` 恢复 → `打开默认世界()` 用同一种子重建同一座废城 →
> 玩家落在**营地门口格**。也就是"读档 = 从安全屋出发"，与"每次从安全屋出发、回安全屋重置"的设计口径一致。
> 要看"读档回到离开那一格"才需要存 `世界标识 + 令牌列/行`（见 §五 准备做 #12）。

### 7. 日志链路（v39 后）

```
各系统 发布 日志事件(类型, 文本, 过程?)
   ├─ 类型：8 类 → 徽章色（游戏主题.日志色/日志标签）
   ├─ 过程=true：战斗逐条 —— 仅展示 不沉淀历史
   └─ 非过程：显示 + 沉淀 会话历史（内存，不随档）
        ↓ 日志面板（左下消息流）
   显示壳(alpha=1) → 条目 创建 → 停留 6s → 淡出销毁
        ↓ 条目全空
   壳自动隐藏（alpha=0）
调试/接线错误 → 不走日志事件，直接 Console（Debug.Log/Warning）
```

## 四、数据框架（核心字段约定）

### 物品数据（十大类型）

```
标识(唯一=显示名=图标) / 描述 / 类型(10) / 种类(二级) / 槽位
攻击距离（近战1/远程N） / 攻击/防御/生命/负重/抗性 / 恢复量/恢复目标
形状宽×高 / 重量 / 堆叠上限 / 最大耐久 / 品质
是容器 / 容器列行 / 容器允许类型 / 容器形状(块) / 价值
保质期(游戏小时) / 生长时间 / 成熟产物      ← 腐坏/种植 用
书籍种类(技能书|配方书|蓝图) / 书籍级别(低中高顶传奇) / 阅读时间分 / 配方池[] / 技能 / 熟练度点   ← 书籍系统
```

### 物品堆叠（随档实例）

```
标识 / 数量 / 列行 / 旋转 / 当前耐久 / 词缀 / 品质
容器列行 / 容器物品（嵌套/分区）
新鲜分钟   ← 腐坏（≤0 变质为 腐坏食物）
生长分钟   ← 种植（≤0 成熟替换产物）
净化分钟   ← 净水器 本批剩余时间（时间驱动递减）
```

### 配方数据

```
标识 / 名称 / 描述 / 类型(工作台|灶台|医疗站)
产物 / 产物数量 / 材料[] / 解锁图纸 / 需习得 / 需要等级(1~3) / 品质
制作时间分 / 消耗倍率(0.5倍数) / 消耗精力
需习得 = 书籍·配方书 阅读 习得 才解锁；品质 = 配方书 池 权重（普通5/优秀4/稀有3/史诗2/英雄1）
```

### 家具数据

```
标识 / 名称 / 描述 / 材料[] / 最大等级 / 功能类型(睡觉|制作|仓库|情报|取暖|…|净化)
形状宽高 / 升级[](材料+容器列行) / 效果[](按等级)
容器列行 / 容器允许类型(类型|类型) / 容器允许种类(种类|种类) / 保质期倍率[3,5,8]
容器分区[]（名称/列行/允许类型/允许种类）   ← 分区容器（净水器 3 区）
净化间隔分 / 净化材料A / 净化材料B / 净化产物 / 净化产物数量   ← 自动净化
0级=破损（可用但效率减半）；未建=无效果；储物箱例外不缩水
```

### 家具升级需求（v38 新增字段）

```
材料 / 形状宽高(-1=不变) / 容器列行(-1=不变) / 容器分区[]（升级后 分区容器 各 子区 尺寸）
净水器 等 分区容器 升级：按 升级需求.容器分区 更新 子容器 网格 列/行（容器服务.更新分区尺寸）——允许 类型/种类 沿用 家具定义.容器分区
```

### 关键约定

- **图标 = 标识**（`Resources/物品图标/<标识>.png`）

- **网格格尺寸 = 90**；**块缝隙宽 = 10**；容器物品必须落单块内

- **浮动面板**：锚点居中、宽高以预制体为准（代码不覆盖）；显隐用父节点

- **时间速率**：1 现实分 = 30 游戏分；一天 48 现实分

- **基础消耗**：每游戏时 饱食2 / 水分2（float 精确 0.1）

- **制作动画**：时长 = 制作时间分 ÷ 10 现实秒

- **净化速率**：净水器 = 每 60 游戏分钟 1 单位（家具数据可调）

- **场景搭建**：UI 全场景手动搭建 + `[SerializeField]` 引用位（无代码找路径）

## 六、开发注意事项（坑与约定）

1. **编码**：全中文命名；JSON/C# 必须 UTF-8 无 BOM；pwsh 读写中文需显式编码；字符串插值中文用 `${变量}`
2. **场景**：UI 手动搭建 + 引用位；浮动面板 宽高以预制体为准、锚点居中；代码不覆盖 sizeDelta
3. **数据**：改物品标识 → 同步 配方/图标文件名/快速测试面板/搜索容器引用；json+meta 成对（GUID 固定）；家具字段名变动会断预制体引用（抽壳时引用留子类原名）
4. **时间**：任何推进时间必须走 世界时间管理器（禁止直接改 游戏分钟数）；腐坏 在 结算时间段（整点批量）、**生长/净化 在 推进+跳时**（两条时间流都覆盖，逐帧平滑；勿把 生长/净化 放回 结算时间段——会与逐帧双扣）
5. **存档**：物品堆叠新增字段缺省 0 → 惰性初始化兼容（无需升档）；结构破坏性变动才升版本
6. **动态面板**：动态创建/销毁的面板（浮动面板/网格）必须 OnDestroy 取消 EventBus 订阅，否则残留订阅撞已销毁实例（MissingReferenceException）
7. **网格**：改渲染前先查 块偏移 链路（计算块偏移→格x/格y→定位→投影）；**物品边界线画在物品自己身上**（`网格面板基类.建边界线`），线层只有统一淡网格、**不按物品变色加粗**（所以物品一动不必重画整层线）；浮层命中判定找 `浮动宿主`（GetComponentInParent<浮动面板基类>）防穿透
8. **验证**：Unity 刷新运行验证；数据校验看 GameBootstrap 日志（校验错误停装）
9. **HUD 调控**：HUD 须挂 Canvas 顶层独立（非任何面板子物体），由 面板管理器.HUD 引用位 控制显隐（主菜单/角色创建 隐藏）；场景 未 接线 需 手动 拖 引用
10. **分区容器升级**：净水器 等 升级 改 子区 尺寸 走 家具升级需求.容器分区（升级时 容器服务.更新分区尺寸）；允许 类型/种类 沿用 家具定义.容器分区
11. **快速测试面板**：动态 布局（屏宽高 自适应 + 双列 + 按钮 300px 居中）；分区 半透明块 + 组标题
12. **日志语义**：日志类型 8 类（徽章色 游戏主题.日志色/标签）；调试/接线错误 走 Console 不发布日志事件；战斗逐条 = 过程消息（日志事件 第三参 true），结果摘要才入历史；物品名着色用 品质工具.名称着色
13. **日志面板壳显隐**：空日志自动隐藏用 **CanvasGroup alpha**（勿 SetActive 含脚本的根——会停脚本，activeInHierarchy 检查将永久拦截事件，面板再也无法恢复显示）；`面板壳` 引用可拖根或子容器
14. **out var 短路**：`bool ok = a != null && TryGetValue(..., out var x)` 编译器视为 x 可能未赋值（CS0165）——先声明 `T x = null` 再 `TryGetValue(out x)`
15. **书籍系统**：阅读 走 世界时间管理器.阅读推进（推进+跳时 两流，同 生长/净化）；耐久 复用 最大耐久(=40)+当前耐久（读满 一次 扣 耐久 不论成败）；已习得配方 永久存档（区别于 持有图纸）；书籍 堆叠上限=0（不可堆叠）+ 保质期=0（不腐坏）；配方 需习得=true 需 读书 习得 才解锁；技能书 数据 依赖 skills.json（当前 缺失，技能 字典 空）
16. **网格基类三条硬约定**：① 子类**不许再写 `void Update()`**（基类 Update 是 private，会被隐藏 → 刷新调度/拖拽全废；每帧逻辑放独立组件，如 `房间图层`）；② 基类 `销毁网格结构` 只销毁它自己那四层（底盘/底座层/线层/物品层），自建层要自己跟着尺寸重建；③ 路径/悬停这类临时高亮**不能蹭基类的 投影格**（基类无拖拽时会 隐藏全部投影）——自建层画
17. **格尺寸全项目统一 90px**（`网格面板基类.格尺寸`）：不许按面板覆写、也不做"等比缩小到一屏"——大地图靠**相机跟随**（视口 RectMask2D + 夹边）解决
18. **能吃点击的只有**：交互层每格透明图 + **非楼实体**的框根（墙/容器/门/楼梯/敌人…）。**玩家令牌与楼必须 `raycastTarget = false`** —— 令牌会盖住脚下那一格（站在楼梯上就点不到楼梯、踩在尸体上搜不了），楼会盖住自己的每一格（面板就拿不到"被点的是哪一格"）
19. **RectMask2D 只裁画面、不裁 raycast**：窗口外的格子照样接得到点击 → 点击/悬停一律先问 `探索图层.在窗口内(列,行)`（`点格反馈` 与 `悬停格` 里已做）
20. **图层 z 序**（自下而上）：底盘 → 底座层 → 地表层 → 线层 → 交互层 → 物品层 → **迷雾层** → 路径层 → 效果层。**"看得见看不见"不由层级决定**，而是 `更新实体框` 里按 `服务.档(列,行)` 算的显示规则；迷雾只负责"压暗/盖黑"，且 `raycastTarget = false` 不挡点击
21. **形状数据纪律**：`凹` 的凹口必须朝街（用 `朝向` 转，否则死格 → 连通分量炸）；`区域生成器.复制外形()` 加了新形状参数**必须同步补**（漏拷 → 楼被缩到地块大小时悄悄变形）；楼**别贴区域外墙**（`凸` 会出封闭死角）
22. **校验分两层**：`DataService` 只做**数据级**交叉校验（标识存在 / 尺寸 / 门在本层内 / 棋盘），"摆出来连不连通、楼门可不可达"交给**离线验证器**（`区域验证` 每颗种子都断言）；`建筑验证` 的"数据标识核对"还会拦"房间门上写着通向某间房、但那间房不在本层"这类数据错
23. **什么时候跑什么**：改任何 C# → 先 `& ".\Tools\编译校验.ps1"`（不打开 Unity 就能编游戏程序集，加 `-含Editor` 连 Editor 一起编）；改 Domain 生成逻辑 → `区域验证 / 建筑验证 / 房间验证`；改数据 JSON → 至少 `建筑验证`（含标识核对）。`.ps1` 必须带 **UTF-8 BOM**（PS 5.1 否则按 GBK 读）

48. **★ 短路类优化的前提必须变成红灯**（v51 刀18，格子层 UI）：
   "没变就不重画"这类去重，风险**不是性能而是"该重画时没重画"** —— 表现成"雾停在上一格"
   "路径画的是老路线"，而且**不报任何错**。所以规矩是三条：
   ① **把前提写全**（`档()` 的输入是哪些、谁在改它们 —— 这次是 `当前可见/已探索/当前时段`）；
   ② **把前提钉成红灯**（`Tools/探索接线核对.ps1`：写入点必须在 `刷新视野()` 附近 / 去重键必须在 `重建()` 里作废 /
   池重排必须强制重画）；③ **"图全新建"的路径必须让去重键作废**，否则重建之后那一层**永远是空的**。
   一句话：**去重是拿"正确性"换性能，所以去重的判据要当不变量来守。**
49. **`Vector2.Lerp` 在 float 下会收敛到定点**（v51 刀18，一条被我自己证伪的优化）：
   我原本要改 `跟随相机()`（"贴近目标就吸附 + 值没变就不写"），理由写好了："指数插值永远差一点点
   → 每帧写一个略不同的值 → 内容 RectTransform 每帧置脏 → 整个网格每帧重建画布"。
   **离线按单精度模拟 60fps：第 84 帧（≈1.4 秒）值就不再变化**（收敛到距目标 3e-8 px，
   低于 float 在该量级的分辨率 ≈2e-8）→ 静止时并不会持续置脏。**这条优化不成立，没有改**。
   要记的是：**性能论断和"已删/已改"一样，都得先量再写**（同 #41 / #42）。
   这次量的方式是"把算术从注释里拎出来跑一遍"——几行 PowerShell 就能省掉一次无谓改动。
50. **"看不见的图"和"永不生效的组件"也要按 bug 对待**（v51 刀19，网格基类）：
   它们不会报错、不会画错，只在你进图时白建几百上千个对象 —— 所以没人会去查。
   这一刀收了两处，判据都是**可证的**而不是"估计的"：
   · **底格**：探索层的地表是**不透明且逐格盖满**的，而 `定位()` 与 `探索图层.摆格()` 用**同一套锚点/pivot**
     → 被盖住的底格一个像素也露不出来（区域层 704 张 → 只留界外那十几张）。
     ⚠ 反过来说：**界外格的地表是故意不铺的**，那里的底格是唯一地色，去掉就变成底盘色 —— 收口时要留。
   · **物品拖拽 组件**：`开始拖拽()` 第一行 `if (!允许开始拖拽(堆叠)) return;`，探索层该钩子恒 false
     → 组件挂上去永远走不到任何一行（区域层几百个实体框 = 几百个白挂的 MonoBehaviour）。
   **通用判据**：新加一层"每格/每实体一个对象"的东西之前，先问一句"它被谁盖住 / 它什么时候会被执行"；
   答案若是"被盖住""永远不会"，那它现在就是白建。
51. **★ 负向测试的"还原"不许用 `git checkout -- <文件>`**（v51 刀21b，我自己踩的）：
   做负向测试时我先改了文件（注入缺陷），跑完想还原就 `git checkout -- 大世界网格面板.cs` ——
   而那个文件里**同时还有我未提交的真实改动**（"把 更新实体框/整体档 上提到基类"），
   于是 `checkout` 把**真改动和注入一起丢了**：编译照样过（因为基类也有那两个方法），
   但守门人立刻报了 2 处 —— 是**守门人**把这次事故兜住的，不是我看出来的。
   → 规矩：① 负向测试优先用**手工反向编辑**（把注入的那几行改回去），不要用 checkout/restore；
     ② 非要用 `git stash`/`checkout`，先确认"这个文件里有没有别的未提交改动"（`git diff -- <文件>`）；
     ③ 做完负向测试，**必须重跑守门人**确认回到 0 —— 它其实是"我的改动还在不在"的检查。
   顺带：这也是本仓库第 2 次"守门人抓住作者自己的错"（第 1 次见 #43 的断言漏判）。
