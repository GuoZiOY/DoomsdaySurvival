| **图层栈调整：迷雾挪到物品层之上** | 原来 z 序是「…线层 → **迷雾** → 路径 → 交互 → 物品 → 效果」，实体的暗靠**每个实体自己** `CanvasGroup.alpha = 0.55`（同一条规则写两遍：新加实体忘了写就会在暗处亮着）。现在 z 序 = **底盘 → 底座层 → 地表层 → 线层 → 交互层 → 物品层 → 迷雾层 → 路径层 → 效果层**：雾在实体之上统一压 `阴影压暗`，实体不再自压；雾图 `raycastTarget = false` 所以**不挡点击**；交互层仍压在物品层之下（点实体优先给实体 → 右键菜单/搜索/开门靠这条）。**"看得见看不见"不由层级决定**：敌人"只在亮区画"的显示规则保留，所以"记得屋子、看不见敌人实时位置"依旧成立 |
| **门锁（钥匙 / 撬锁；砸锁留空）** | `房间门项.锁` 写钥匙物品标识（空 = 无锁）。**机械核心：有锁 → `占格=true` + `挡视线=true`**，于是 A* 只会把你送到"门前那一格"（锁定"只能站在门前"）；解锁 → 占格=false → **踩上去就转移**（`推进一步` 末尾 `踩到能过的门()`；无锁的门同样踩上去就过，大门也踩上去就出楼）。三条路径：**① 钥匙**（1 分钟、不耗行动点、**用掉即消耗**）/ **② 撬锁**（3 分钟 + 5 行动点，成功率 `55+敏捷×3+智慧×2` 夹 [5,95]，失败扣工具耐久 -1——只有有耐久的工具才扣，钳子这类"用不坏"的最优先）/ **③ 砸锁留空**（`开锁方式.砸锁` 占位、菜单不出）。**钥匙投放（按种子随机的两种来源）**：进房时按种子决定这把钥匙在**敌人身上**还是**柜子里**（`派生(当前种子,"钥匙来源"+门标识)` 取 50/50；没柜子就只能挂敌人、没敌人就只能进柜子）——**柜子** = 那个容器内容第一次生成时把钥匙塞进视图（一趟只生成一次 → 不重复塞、拿走了不再刷）；**敌人** = 记在 `本房尸体钥匙`，打赢这一场时在 `战斗结束响应` 里塞进**战利品容器**（尸体实体随后才创建，正好带着钥匙；战利品为空没生成尸体 → 顺延放本房柜子）。两种来源都没有（既无柜子也无敌人）→ 那扇门自动取消锁（打警告），绝不出现"永远打不开的门"。**锁态生命期**：`已解锁门[当前种子#门标识]` —— 走回头路记得、**回安全屋才清**（与容器战局数据、视野记忆同一时机）。数据：`房间模板.门[].锁`；物品新增 库房/柜台/杂物间钥匙（任务品）+ `物品数据.用途`（撬锁：撬棍/螺丝刀/钳子）；3 扇门上了锁（回头门与大门一律不上锁）；自检/离线验证加锁断言（锁着必占格挡视、可通行性与锁态一致、锁着时房间必须有容器或有敌人放钥匙） |

| **修复：打死敌人不留尸体** | 两道闸门叠加：`BattleService.结束战斗` 里 **`if (胜利 && 尸体战利品.Count > 0)` 才注册尸体容器**，`搜索服务.注册尸体容器` 里又有 **`if (视图.网格物品.Count == 0) return ""`**。而战利品是按 `货币奖励/4`（面包）`/8`（水）算的——房间里的敌人几乎全是"补给值 < 4 且无掉落"（感染者 3 / 变异鼠 1 / 流浪狗 2 / 野猫 1 → 面包 0、水 0），于是**战利品为空 → 没有尸体容器 → 房间层根本不建尸体实体**。**修法**：① `注册尸体容器` **允许空尸体**（`物品` 传 null/空也照样登记定义 + 空视图）；② `房间探索服务.战斗胜利` **硬保证**：这一场没产出战利品就自己登记一具空尸体（搜索时间 0.5 秒，翻一下就知道啥也没有），**打赢必定在原地留一具可搜尸体**；③ 钥匙投放从 `战斗结束响应` 移到 `战斗胜利`（先把尸体容器备好，再决定钥匙放哪）—— 钥匙挂在敌人身上时**一定掉在它的尸体里**，不再因为"没尸体"而顺延到柜子 |
| **修复：房间战斗打完不回房间面板** | 战斗结算走 `BattleService.返回()` → `房间探索服务.战斗胜利()`，但那里只发了 **`房间显示事件`**（房间面板用它刷网格），而 `面板管理器` 只订阅了 `打开房间事件`（进房时切一次）→ **没人把面板切回来，战斗面板留在最上面**。（对比"探索"那条链路：`探索服务.战斗胜利 → 探索显示事件`，而 `面板管理器` **订阅了** `探索显示事件` → 天然切回。）**修法**：① 新增 **`回到房间事件`**，由 `战斗胜利` / `战斗逃跑` 发布，`面板管理器` 订阅 → `显示(房间)`；**不能用 房间显示事件 顶替**（它每走一步都发，还发在"打开容器搜索面板"之后，拿它切面板会把搜索面板顶掉）。② 顺手修连带毛病：`面板基类` 增 **`瞬时面板`**（战斗面板覆写为 true），`面板管理器.显示` 在**从瞬时面板切走时不覆盖"上一个面板"** —— 否则打完战斗回到房间后，房间按 Esc 会跳回已经打完的战斗结算面板；③ **房间 / 探索 的战斗不再需要点[继续]**：`结束战斗` 末尾发现结果节点是 `__` 开头就直接 `返回()`（幂等：`返回()` 先清空结果节点），剧情战斗与测试沙盒仍由面板按钮触发 |
| **修复：房间敌人"一个标识 → 战斗里变多只"** | 房间生成时按 `敌人数量最小/最大` 裁剪（**一只一个标识**：`模板#敌人0` / `#敌人1`…），但遭遇时房间层传的是**敌人组标识**，`BattleService` 又按组内每项的 `数量` 重新展开了一遍 → 房间显示 2 只、打起来 4 只（例：鼠群 组内展开 4 只 vs 居民房客厅裁剪 1~2 只）。**修法（三条一起）**：① `BattleService.开始战斗` 增可选参数 **`IList<(string 定义标识, string 实例标识)> 指定敌人`** —— 列表里有几项就打几只，**不再乘 敌人组.数量**；② 房间层**一次遭遇只传一项** = 你碰上的那一只（`一个标识 = 一个敌人`：解决掉它，再碰到下一个标识才是另一场战斗），并把它带进战斗单位的 **`实例标识`**（房间实体标识；其余入口 = `定义标识#序号`，同一入口内绝不重复）；③ **胜利只移除被解决的那一只**并在它原位留一具可搜尸体（原来写的是"敌人全灭"），屋里其它敌人原封不动，战斗收尾文案按"还有没有别的东西在动"分两句。战利品尸体随"真实参战的那一只"产出；遭遇时打一条 `[房间] … 遭遇 X[标识]：参战 1 只` 日志，数量对不上立刻看得见 |

### 核心玩法闭环
```
主菜单 → 角色创建（职业/五维/天赋）
   ↓
营地（安全屋）→ 睡觉/制作/储物/收音机预知天气
   ↓        └ 冰箱保鲜 / 种植箱种菜 / 净水器净化脏水（时间驱动）
大地图（节点网图；`map.json` 还没画）→ 城镇 / 荒野
   ↓  荒野 = **区域网格**（地块制摆 4 栋楼 + 街道障碍 + 区域迷雾）
走到楼门那一格 → **进楼**（建筑楼层；楼梯上下楼，全楼同位）
   ↓
房间（一屏格子：三态迷雾 + 视野 + 搜索 / 战斗 / 门锁 / 上下楼）
   ↓
物资 / 生鲜 / 脏水 / 种子 / 图纸 → 走大门出楼 → 回区域 → 回大地图 → 营地
   ↓
回营地 → 做饭(灶台)/制作/进食/睡觉 → 推进时间 → 生存结算 + 腐坏/生长/净化
   ↓
物资循环 + 时间压力（一天48现实分钟）= 末日生存节奏
```

```
世界时间管理器（唯一入口）
├── 推进(现实秒)        ← 挂机驱动（每帧）→ 净化推进 + 生长推进
├── 结算时间段(分,含饱水) ← 整点结算 / 制作补副作用 → 腐坏 结算（生长/净化 不在此——已逐帧）
├── 跳时(游戏分钟)      ← 制作动画 → 净化推进 + 生长推进（两条时间流都覆盖）
└── 同步整点基准()      ← 外部跳时/取消回滚
        ↓
玩家档案.游戏分钟数 + 饱食度/水分度(float) + 堆叠.新鲜/生长/净化分钟
        ↓
事件发布 → HUD 刷新
```

### 3. 制作链路（会话版，两步 + 动画）

```
选配方 → 拖材料入 输入网格（真实移入会话）
   ↓ 点制作（数量 = 滑条/输入框）
开始制作_会话（校验 输入网格×数量 + 扣精力×数量）
   ↓ 动画（进度条 0→100% + 跳时推进时间）
结算制作_会话（输入网格扣料×数量 → 产物入 输出网格 ×数量）
   ↓ 输出区满 → 回滚（材料退回输入区/精力/时间/饱水全返还）
   ↓ 关闭面板 → 输入剩料+输出成品 自动返还玩家（背包/仓库）；背包满 → 拒绝关闭
```

### 4. 净化链路（时间驱动，无按钮）

```
世界时间管理器 推进/跳时
   ↓ 净化推进(净水器.净化分钟 -= 时间；惰性初始化补满)
材料齐（脏水区有脏水 且 过滤区有木炭）且 净水区可放 → 倒计时
   ↓ 到 0 → 自动：脏水-1 + 木炭-1 → 净水区 +水1 → 自动续下一批
缺料/净水区满 → 冻结进度（条件恢复继续，不浪费）
   ↓ 出水面板 0.5s 轮询刷新（滑条 + 距下批出水 X 分钟）
```

### 5. 服务装配链路（GameBootstrap）

```
EventBus → DataService（校验）→ SaveService → PlayerService（初始化+解析器接线）
→ 世界时间管理器 → 容器/搜索/安全屋/制作/对话/任务/战斗/探索/技能/天赋/词缀/地图

```

### 7. 日志链路（v39 后）

   ├─ 类型：8 类 → 徽章色（游戏主题.日志色/日志标签）

## 六、开发注意事项（坑与约定）

1. **编码**：全中文命名；JSON/C# 必须 UTF-8 无 BOM；pwsh 读写中文需显式编码；字符串插值中文用 `${变量}`
2. **场景**：UI 手动搭建 + 引用位；浮动面板 宽高以预制体为准、锚点居中；代码不覆盖 sizeDelta
3. **数据**：改物品标识 → 同步 配方/图标文件名/快速测试面板/搜索容器引用；json+meta 成对（GUID 固定）；家具字段名变动会断预制体引用（抽壳时引用留子类原名）
4. **时间**：任何推进时间必须走 世界时间管理器（禁止直接改 游戏分钟数）；腐坏 在 结算时间段（整点批量）、**生长/净化 在 推进+跳时**（两条时间流都覆盖，逐帧平滑；勿把 生长/净化 放回 结算时间段——会与逐帧双扣）
5. **存档**：物品堆叠新增字段缺省 0 → 惰性初始化兼容（无需升档）；结构破坏性变动才升版本
6. **动态面板**：动态创建/销毁的面板（浮动面板/网格）必须 OnDestroy 取消 EventBus 订阅，否则残留订阅撞已销毁实例（MissingReferenceException）
7. **网格**：改渲染前先查 块偏移 链路（计算块偏移→格x/格y→定位→投影）；**物品边界线画在物品自己身上**（`网格面板基类.建边界线`），线层只有统一淡网格、**不按物品变色加粗**（所以物品一动不必重画整层线）；浮层命中判定找 `浮动宿主`（GetComponentInParent<浮动面板基类>）防穿透
8. **验证**：Unity 刷新运行验证；数据校验看 GameBootstrap 日志（校验错误停装）
9. **HUD 调控**：HUD 须挂 Canvas 顶层独立（非任何面板子物体），由 面板管理器.HUD 引用位 控制显隐（主菜单/角色创建 隐藏）；场景 未 接线 需 手动 拖 引用
10. **分区容器升级**：净水器 等 升级 改 子区 尺寸 走 家具升级需求.容器分区（升级时 容器服务.更新分区尺寸）；允许 类型/种类 沿用 家具定义.容器分区
11. **快速测试面板**：动态 布局（屏宽高 自适应 + 双列 + 按钮 300px 居中）；分区 半透明块 + 组标题
12. **日志语义**：日志类型 8 类（徽章色 游戏主题.日志色/标签）；调试/接线错误 走 Console 不发布日志事件；战斗逐条 = 过程消息（日志事件 第三参 true），结果摘要才入历史；物品名着色用 品质工具.名称着色
13. **日志面板壳显隐**：空日志自动隐藏用 **CanvasGroup alpha**（勿 SetActive 含脚本的根——会停脚本，activeInHierarchy 检查将永久拦截事件，面板再也无法恢复显示）；`面板壳` 引用可拖根或子容器
14. **out var 短路**：`bool ok = a != null && TryGetValue(..., out var x)` 编译器视为 x 可能未赋值（CS0165）——先声明 `T x = null` 再 `TryGetValue(out x)`
15. **书籍系统**：阅读 走 世界时间管理器.阅读推进（推进+跳时 两流，同 生长/净化）；耐久 复用 最大耐久(=40)+当前耐久（读满 一次 扣 耐久 不论成败）；已习得配方 永久存档（区别于 持有图纸）；书籍 堆叠上限=0（不可堆叠）+ 保质期=0（不腐坏）；配方 需习得=true 需 读书 习得 才解锁；技能书 数据 依赖 skills.json（当前 缺失，技能 字典 空）
16. **网格基类三条硬约定**：① 子类**不许再写 `void Update()`**（基类 Update 是 private，会被隐藏 → 刷新调度/拖拽全废；每帧逻辑放独立组件，如 `房间图层`）；② 基类 `销毁网格结构` 只销毁它自己那四层（底盘/底座层/线层/物品层），自建层要自己跟着尺寸重建；③ 路径/悬停这类临时高亮**不能蹭基类的 投影格**（基类无拖拽时会 隐藏全部投影）——自建层画
17. **格尺寸全项目统一 90px**（`网格面板基类.格尺寸`）：不许按面板覆写、也不做"等比缩小到一屏"——大地图靠**相机跟随**（视口 RectMask2D + 夹边）解决
18. **能吃点击的只有**：交互层每格透明图 + **非楼实体**的框根（墙/容器/门/楼梯/敌人…）。**玩家令牌与楼必须 `raycastTarget = false`** —— 令牌会盖住脚下那一格（站在楼梯上就点不到楼梯、踩在尸体上搜不了），楼会盖住自己的每一格（面板就拿不到"被点的是哪一格"）
19. **RectMask2D 只裁画面、不裁 raycast**：窗口外的格子照样接得到点击 → 点击/悬停一律先问 `探索图层.在窗口内(列,行)`（`点格反馈` 与 `悬停格` 里已做）
20. **图层 z 序**（自下而上）：底盘 → 底座层 → 地表层 → 线层 → 交互层 → 物品层 → **迷雾层** → 路径层 → 效果层。**"看得见看不见"不由层级决定**，而是 `更新实体框` 里按 `服务.档(列,行)` 算的显示规则；迷雾只负责"压暗/盖黑"，且 `raycastTarget = false` 不挡点击
21. **形状数据纪律**：`凹` 的凹口必须朝街（用 `朝向` 转，否则死格 → 连通分量炸）；`区域生成器.复制外形()` 加了新形状参数**必须同步补**（漏拷 → 楼被缩到地块大小时悄悄变形）；楼**别贴区域外墙**（`凸` 会出封闭死角）
22. **校验分两层**：`DataService` 只做**数据级**交叉校验（标识存在 / 尺寸 / 门在本层内 / 棋盘），"摆出来连不连通、楼门可不可达"交给**离线验证器**（`区域验证` 每颗种子都断言）；`建筑验证` 的"数据标识核对"还会拦"房间门上写着通向某间房、但那间房不在本层"这类数据错
23. **什么时候跑什么**：改任何 C# → 先 `& ".\Tools\编译校验.ps1"`（不打开 Unity 就能编游戏程序集，加 `-含Editor` 连 Editor 一起编）；改 Domain 生成逻辑 → `区域验证 / 建筑验证 / 房间验证`；改数据 JSON → 至少 `建筑验证`（含标识核对）。`.ps1` 必须带 **UTF-8 BOM**（PS 5.1 否则按 GBK 读）
