# 《最后 87 天》项目现状评价

> 日期：2026-08-23（v5 之后，工作区未提交状态）
> 方法：静态代码盘点（82 个自有脚本 / 2 个 JSON / 4 篇文档）+ git 历史 + 依赖关系扫描
> 结论先行：**架构骨架优秀，但项目处于"领域层已末日化、服务层与 UI 层半奇幻化"的转型中途**——能编译不等于能玩，当前实际可玩内容接近零。

## 2. 完成度盘点（按层）

### 2.1 领域层（约 90%）

已末日化：
- 五维属性（体质/力量/智慧/敏捷/意志，职业 25 点直给 + 自由 10 点）
- 生存状态（饱食度/水分度 0~100）、伤病 6 种（0~100）
- 网格背包（物品堆叠：列/行/旋转/形状）、装备 8 槽
- 天赋列表 + 天赋冷却字典、安全屋等级/家具、天气、幸存者、抉择记录、已清空地点
- 战斗单位：无敌回合（新增）

残留（兼容字段，防断用）：
- `已学技能`/`技能熟练`（职业初始技能仍引用）→ 建议转正为「生存技能熟练度」而非删除
- `日常 List<日常任务>`（委托系统占位）→ 建议改名为 委托
- `主线阶段`（纯兼容，末日不使用）→ 最终删除
- 装备 `词缀`/`品质`（暗黑式随机词条）→ **建议保留**（末日装备稀有度/随机词条系统，派生属性已依赖 `词缀总值`）

## 3. 数据一致性硬伤清单（必须先修）

1. 职业.json 的 技能/天赋/装备 三字段全部悬空（见 2.4）。
2. 职业天赋命名冲突：设计文档 v0.1（战术本能/铁骨/…） vs 已实现的框架（钢铁意志/医者仁心/美食家）——**需定稿统一**（新 GDD 已定：退役军人→钢铁意志、消防员→烈火雄心、厨师→美食家、记者→真相之眼、大学生→学霸、医生→医者仁心）。
3. 事件定义.cs 混有奇幻事件：`魔力变化事件`/`金币变化事件`/`任务进度/任务完成/日常任务变更`——HUD 用 魔力 显示行动点、金币 显示水分，属临时 hack，需清。
4. 玩家档案 派生属性仍依赖 词缀总值/品质——若砍词缀需连带改公式；**建议保留词缀**，避免二次返工。
5. `新游戏()` 硬编码 面包×2/水×1/绷带×1，与职业初始装备叠加逻辑未定——items.json 必须包含这三个标识。

## 4. 风险与建议

### 风险
- **回归风险**：工作区 30+ 文件未提交、未编译验证（v5 之后的全部改动）。
- **删库风险**：若直接删奇幻代码，BattleService/地图服务/装备背包等仍引用它们的地方会瞬间编译失败——必须按依赖序清理。
- **内容断档**：即使代码清干净，没有物品/丧尸/地点数据，游戏仍不可玩。

### 建议的推进顺序（与 残留分析.md 配套）
1. **P0 编译与提交**：先把当前工作区（天赋框架+属性重构+UI 清理）验证编译并提交，作为干净基线。
2. **P1 数据定稿**：按新 GDD 重写 职业.json/天赋.json，新建 items.json/丧尸.json/技能.json（生存技能）/地点.json/事件表.json/委托.json/天气.json/家具.json/词缀.json/配方.json。
3. **P2 死代码删除**：按依赖序删五行/货币/主线阶段/附魔/镶缀/合成/技能行/章节标题行，重写 BattleService 与 地图服务。
4. **P3 核心循环闭合**：探索→战斗→搜刮→回营地→睡觉→跨天→第 N 天，制作设施发事件，天赋钩子全接。
5. **P4 内容生产**：短事件卡批量生产（这是转型的核心优势）。
