# 《最后87天》— 末日文字丧尸生存 RPG

> 城市陷落后的第 87 天。水与电早已消失，街上只剩丧尸与废墟。你是安全屋最后醒着的人——活下去，是唯一的任务。

Unity 6（6000.4.8f1）｜ 塔科夫式网格背包 ｜ 即时制战斗 ｜ 五层格子世界 ｜ 全 JSON 数据驱动 ｜ **全项目中文编码**（类/方法/字段/参数/注释/数据键名均为中文）

玩法建议塔科夫式背包玩法，题材为**现代末日丧尸求生**：以「营地建设 + 时间管理 + 外出搜刮 + 即时战斗」为闭环的文字生存游戏。

---

## 核心玩法

- **87 天期限（时间压力）**：`1 现实分钟 = 30 游戏分钟`，一天 = 48 现实分钟。搜刮、制作、睡觉都会推进时间——食物会腐坏、作物会生长、净水器会产水，你与丧尸都在和时钟赛跑。
- **生存循环**：生命 / 精力 / 饱食 / 水分 / 疲劳 / 伤病 / 天气。每游戏时基础消耗饱食与水分；睡觉推进次日；寒潮需灶台取暖，伤病持续恶化。
- **五层格子世界**：**大世界（100×100 的废城）→ 区域副本（32×22）→ 建筑（楼层）→ 房间** 共用同一套「格子探索服务」：逐格走、三态迷雾、相机跟随。大世界走 1 格 = 5 游戏分钟；街上会撞上敌人，走到区域门口进副本、走到楼门那一格进楼。
- **塔科夫式网格背包**：弹挂 / 腰封 / 背包 3 个穿戴容器 + 仓库 + 任意嵌套容器；物品按「形状块」占格，可**拖拽 / R 旋转 / 换位 / 堆叠 / 存入容器**，带格子投影逐格贴合口袋形状。
- **安全屋建设**：程序化随机户型；家具建造 / 升级 / 修复 / 拆除（储物箱扩容、净水器 3 分区升级、冰箱保鲜、种植箱种菜、**晾晒架晾肉干与硝皮**、灶台做饭、工作台/医疗站制作）。
- **即时制战斗**：行动条由世界时间驱动填充，满条自动执行「运动模式（前进/等待/后退）+ 行动模式（攻击/防御）」；主动操作（6 技能槽 / 弹挂腰封道具 / 切武器）可即时打断重置行动条；**节点式轨道**贴脸/射程/风筝走位；技能有**蓄力读条（可被打断）**与眩晕。
- **弹匣与自动换弹**：枪械有弹匣容量（配件可改造容量），打空自动换弹 1.5 秒（期间行动条冻结）；弓弩与近战不走弹匣。
- **配件改装（塔科夫式）**：装备**没有随机魔法词缀**，改成真实物品的**配件**（枪口/瞄具/弹匣/枪托/握把/刃口/插板，27 件），带取舍（消音器潜行↑攻击↓…）；在**工作台**用「制作 / 其他」两个模式装/卸，产物与拆下来的东西都进输出网格。
- **敌人词缀（变异体）**：开战时逐只随机（走后端可播种随机源 → 同种子可复现），只显示 `[强壮]` 这样的标签，敌人名字不变。8 条属性型特性。
- **时间驱动的世界**：生鲜按游戏时间**腐坏**（冰箱减速）、种子在种植箱**生长**、净水器每 60 游戏分钟自动产水——全部挂 `世界时间管理器`（推进/跳时两条时间流），全程无需手动按钮。
- **日志系统**：左下角 8 类彩色徽章消息流（探索/战斗/生存/获得/警告/系统/内心/角色），空日志自动隐藏；物品名按品质着色。
- **数据驱动**：全部内容都在 `Assets/Resources/Data` 下的 JSON 里，改数据不改代码（物品 **284** / 配方 **67** / 家具 **12** / 敌人 **34** / 敌人组 **27** / 技能 **31** / 天赋 **24** / Buff **14** / 配件 22 / 书籍 **12** / 搜索容器 **106** / 房间模板 **41** / 建筑模板 **10**（7 栋三层）/ 区域模板 7）。

## 如何运行

1. 用 **Unity 6000.4.8f1**（Unity 6 LTS 系）打开本项目，首次打开等待导入完成。
2. 打开场景 `Assets/Scenes/SampleScene.unity`。
3. 直接按 **Play**。

> 无需任何一键搭建：UI 已按「场景手动搭建 + `[SerializeField]` 引用位」接好；TMP Essential Resources 与中文字体（Silver SDF 等）均已入库，开箱即用。

## 架构

```
Assets/Scripts/                     （153 个源文件）
├── Core/        组合根：GameBootstrap 装配根、ServiceRegistry、EventBus
├── Data/        数据模型 + DataService（Resources.Load + 全量交叉校验）+ 建筑外形 + 配件槽/配件加成
├── Domain/      纯 C# 领域逻辑（零 UnityEngine）：玩家档案/生存/成长/效果结算 · 网格（数据/寻路/视野/可见性/门口保护）·
│                容器（容器/持有/装备管理）· 战斗（战斗单位/敌人特性/随机源）· 大世界/区域/建筑/房间 四个生成器 · 任务
├── Services/    业务服务：探索（格子基类 + 大世界/区域/房间）/ 战斗（BattleService 8 个 partial）/ 玩家（Player/技能/天赋/书籍）·
│                世界（时间/制作/图标/音效）· 剧情（Dialog/Quest）· 存档（Save/自动存档）
├── Events/      事件定义（事件定义/剧情/导航/战斗/房间/区域/大世界）
├── UI/          面板层（场景手动搭建 + 引用位）：框架（面板基类/管理器/主题）· 网格（共用网格框架）· 物品（网格/面板/组件/工具）·
│                探索（三层网格面板 + 图层）· 战斗（沙盒/轨道/单位视图/技能槽）· 角色/HUD/主菜单/功能面板/浮层/工具
└── Editor/      编辑器工具（不进游戏程序集）
```

- **五层数据流**：`UI ← Events ← Services ← Domain ← Data`（`Core` 是组合根，`Editor` 豁免）；一切修改走 `玩家档案` → 发布 EventBus → UI 订阅刷新。
- **装配顺序**（GameBootstrap）：EventBus → DataService(校验) → SaveService → PlayerService → 世界时间管理器 → 各服务 → 自动存档器 → 挂载时间驱动。**数据校验失败则不装配业务服务**（不静默崩）。
- **硬约定**：任何推进时间必须走 `世界时间管理器`；动态面板销毁必须 `OnDestroy` 退订 EventBus；每帧推进游戏状态的代码不许写在面板的 `Update` 里。

## 编码与协作约定

- **全中文标识符**：类、方法、字段、参数、注释、JSON 键名全中文；仅 Unity 生命周期与框架 API 保留英文。
- **编码**：JSON / C# 一律 UTF-8 无 BOM；**`.ps1` 必须带 UTF-8 BOM**；pwsh 读写中文用 `[IO.File]::ReadAllText/WriteAllText` 显式编码（`Get-Content` 会把中文按 GBK 读坏）。
- 场景 UI 手动搭建 + 引用位；浮动面板宽高以预制体为准，代码不覆盖。
- 提交纪律：**只 `git add` 明确的文件路径**（别 `git add -- Assets`，Unity 会顺手改 TMP 字体资源）；改完数据先 `git diff --numstat` 核对增删数。
